# G.E.M.S. Architecture

Detailed architecture reference for **G.E.M.S.**, imported into context by [CLAUDE.md](CLAUDE.md) (via its `@ARCHITECTURE.md` line), so it is always loaded alongside it. See CLAUDE.md for the project overview, build & run, asset-creation workflow, code style, and the **GMRT-Safe Idioms** that always apply — those live there (kept always-in-context) and are referenced by name in code comments.

## Demo Layer — `obj_game`, `Scene` & `SceneManager`

`obj_game` is the unified controller — it drives global system ticks each event and **delegates the scene lifecycle to `SceneManager`** (held as `this.scenes`).

```
Create_0 → display/GPU setup; Log.clear/info; Settings defaults + load; I18n.load for `Settings.language`; this.scenes = new SceneManager(); scenes.start(SCENES.lobby) + SceneTransition.reveal()
Draw_0   → draw_clear(background), this.scenes.draw()
Step_0   → Time.update(), UIPointer.poll(), UI.update(), SlotDrag.update(), SystemMenu.update(this), UINav.update(), Dialogue.update(), this.scenes.update() [pending→SceneTransition.start + SceneTransition.update()], this.scenes.step() [skipped while SystemMenu open, except a one-frame Step], Log.flush()
Draw_75  → UI.draw(), UINav.draw(), SlotDrag.draw(), Tooltip.draw(), Toast.draw(), Dialogue.draw(), SceneTransition.draw(), F5 screenshot
CleanUp  → Log.info("game end"); this.scenes.destroy() (before UI.destroy — it removes the scene's UI roots), UI/Input/I18n cleanup; Log.flush() last (Step_0's flush won't run again, so teardown logs would otherwise be lost)
Other_75 → Async - System (event-driven, not per-frame): gamepad connect/disconnect — reads `async_load` `event_type` ("gamepad discovered"/"gamepad lost") + `pad_index` and logs it
```

GameMaker's built-in per-instance events: **Create** (`Create_0`) runs once at boot; **Step** (`Step_0`) every frame (game logic); **Draw** (`Draw_0`) every frame to the `application_surface` (camera-transformed world view); **Draw GUI End** (`Draw_75`) every frame on the **GUI layer** (own resolution, not camera-transformed — so HUD / windows / overlays live here; it's the *End* sub-event because `screen_save()` is only permitted there). **Clean Up** (`CleanUp_0`) fires at game end (single room, no transitions). The **Async System Event** (`Other_75`) is the lone non-per-frame event: the OS triggers it on a system-level callback (here, a gamepad being plugged in or removed), passing a `ds_map` in `async_load`. It only fires because the project already calls `gamepad_*` functions (`UINav`/`UITable`/`SystemMenu`/`Dialogue`) — the runner skips initialising the pad subsystem otherwise — so read the map via `ds_map_find_value` (the `[? ]` accessor is GML-only).

**`SceneManager`** (`scripts/SceneManager/SceneManager.js`, Core) owns all scene lifecycle: the live scene (`current`), a queued swap, the restart factory + display label, and the fade-coordinated transition. `obj_game` delegates `update()`/`step()`/`draw()`/`destroy()` to its `this.scenes` instance; `SystemMenu` reads/restarts/quits the live scene through the manager (`scenes.current`, `scenes.label()`, `scenes.restart()`, `scenes.request(factory)`) rather than reaching into `obj_game` fields. A plain instance class (one per controller), not a static singleton (GMRT static-getter quirk). `request(factory)` is the `openScene` callback handed to each scene's `create()`.

**`Scene`** (`scripts/Scene/Scene.js`) is the base class for all demo scenes (`label`, `create()`, `step()`, `draw()`, `destroy()`). Scenes are **factory functions** returning a fresh instance each time they open. `create(openScene)` receives the navigation callback (`SceneManager.request`); `destroy()` tears down UI and resources.

**Scene navigation**: call `openScene(factory)` to queue a transition (applied after the current UI update completes). The only **built-in scene** (`scripts/sceneLobby/sceneLobby.js`) is `SCENES.lobby` — the merged **title + lobby** the app boots into: a G.E.M.S. header, a **tabbed** scene catalogue (registry categories grouped into RPG / Showcase tabs), and a footer of global actions (Settings → SystemMenu, Credits → SystemMenu's About tab, Quit). There is no separate title or credits scene; Settings/Pause are the **`SystemMenu`** overlay, not scenes (see Genre UI managers below).

**`SceneRegistry`** (`scripts/demo/demo.js`) is the lobby catalogue. Register at the top level of a scene's script:

```js
SceneRegistry.add(() => new MyScene(), {
  label: "My Scene",
  category: "SCENE_CAT_FOO",
});

class MyScene extends Scene {
  label = "My Scene";
  create(openScene) {
    /* build UI; openScene(SCENES.lobby) to go back */
  }
  destroy() {
    /* remove UI, clean up */
  }
}
```

`SceneRegistry.byCategory()` returns entries grouped by category string. To add a scene: create the script asset (see Asset Creation), define the class, then `SceneRegistry.add(...)`.

**GemsUI kit** (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`): a themed factory library so scenes build UI declaratively instead of hand-wiring `UIElement`/`UIPanel`/`UIText`. Factories are assigned via `globalThis.X = function X(…)` and split across small files (large-file global-hoisting fault). All visual constants live in **`GemsTheme`** (colors as hex, geometry as numbers); the `gems*` functions parse + compose them.

- **Containers**: `gemsRoot` (full-screen scene root), `gemsList` (vertical stack), `gemsGrid` (horizontal wrap row), `gemsPanel`/`gemsCard` (rounded panel; card adds gradient+border+shadow), `gemsHeader` (title bar), `gemsSection` (titled card with divider), `gemsRow(label, control)`, `gemsDivider`, `gemsCatBar(categories, opts?)` (a bar of category buttons; clicking one toggles a pop-up flyout of its items above the bar — one open at a time; selecting an item highlights it + fires `onSelect`. Driven by structural insert/remove, not flex mutation; `root.catbar` exposes `open/close/select`. Shared by the RPG build-mode HUD + level-editor palette).
- **Widgets**: `gemsLabel`, `gemsHint` (one-line help on a readable card, for overlays over a scene's render), `gemsButton(label, onClick, opts?)` (`opts.primary` accent CTA; `opts.disabled` a bool **or live `() => bool`** evaluated each frame; `opts.selected` a live `() => bool` tints toward the accent for an active toggle/palette button — hover/press win on top), `gemsIconButton`, `gemsToggle` (renders `label: ON/OFF`), `gemsCheckbox` (`opts.style` `"check"`/`"switch"`), `gemsProgress` (non-interactive 0–1 bar), `gemsSlider`/`gemsSelect`/`gemsDropdown` (Settings-bound) + `gemsSelectCustom`/`gemsDropdownCustom` (caller-driven; the `*Dropdown*` pair opens a navigable popup list rather than cycling in place — the fit for many options like resolutions/locales, scrolls past `opts.maxVisible`), `gemsTable(columns, opts?)` (a sortable/filterable `UITable` sized to `opts.rows` whole rows; reach the component via `el.getComponent(UITable)`).
- **Tooltips**: `gemsTooltip(element, label, opts?)` attaches a hover `UITooltip`; every interactive factory also takes `opts.tooltip` (string or `() => string`).

`label`/`onText`/`offText` accept a string or `() => string` (live `I18n.textRef`); color opts accept a `GemsTheme` key, hex string, or color int. Styling lives in `GemsTheme` + **`UIPanel`** options: `color2` (edge tint; `draw_roundrect`'s two colors run center→edge/radial), `border`/`borderColor`, soft multi-pass `shadow`/`shadowColor`/`shadowAlpha`, `highlight`/`highlightColor`/`highlightAlpha` (inner top-bevel sheen) — all default off. `UIButton` eases color/glow/shadow between hover/press on `Time.raw`; `UISlider`/`UISelect`/`UIProgress`/`UICheckbox` render directly in `onDraw` (`UISelect` shows `< value >` arrows, steps by click side). **`teardownScene(scene)`** releases the `world`/`renderer`/`camera`/`ui` a scene holds on `this`, in dependency order (missing fields skipped) — call from `destroy()` after releasing scene-specific resources (controllers, levels).

## ECS Core — `World`

`World` (`scripts/World/World.js`) is the instance-based ECS core, owning all component storage and the generational ID allocator. Each scene holds its own as `this.world` (there is no `WORLD` global). **`Entity` is deprecated** — its functionality moved to `World`.

```js
const world = new World(maxEntities, tickrate, opts); // opts: { gravity? } overrides GravitySystem.strength

// Entity lifecycle
const id = world.create(); // allocate generational ID
world.remove(id); // mark for removal (deferred)
world.flush(); // commit queued removals
world.isValid(id); // generational validity check

// Component storage
world.register(Position); // allocate storage (optional; add auto-registers)
world.add(id, Position, { x: 0, y: 0, z: 0 }); // set data
world.get(Position, id); // → data object or undefined
world.detach(id, Position); // remove one component

world.query(Position, Velocity); // → ids that have ALL listed components
world.forEach([Position, Velocity], fn); // calls fn(id) per match, no id array allocated

// Fixed-rate tick
const ticks = world.update(); // # ticks to run this frame; advances accumulator, computes alpha
world.alpha; // [0, 1) interpolation factor for rendering
world.maxTicks; // tick cap per frame (default 5) — spiral-of-death guard:
// under overload the sim slows instead of freezing

// Snapshot
world.export(); // plain object, components keyed by string token, sparse entries
world.import(s); // restores ids + registered components; unknown keys ignored
world.componentsOf(id); // { token: data } of every component this entity has
```

## `EntitySnapshot`

`EntitySnapshot` (`scripts/EntitySnapshot/`, Core) is the single-entity serialize/migrate primitive — the counterpart to `World.export` for one entity. `capture(world, id, components?)` → `{ components: { token: data } }` (a component-token subset, or all via `world.componentsOf`); `apply(world, id, snapshot)` adds those components onto an **existing** entity; `restore(world, snapshot, overrides?)` `world.create`s a fresh entity, applies the snapshot, then applies `overrides` (e.g. a new `Position`/zeroed `Velocity`). Data objects are **referenced, not deep-copied** — for an in-memory migration the old world is destroyed right after capture, so the same objects re-attach to the new one (matching the player-sheet carry). It's the substrate for migrating an entity across a `World` rebuild (the RPG party + followers crossing a map portal — see `sceneRpg.loadMap`) and the seed for disk saves + chunk streaming (a chunk un/load is the same capture/restore over a region's entities). Serialize the record yourself for disk (mind the `JSON` nested-value fault + `Set` fields).

## `IdPool`

`IdPool` (`scripts/IdPool/IdPool.js`) is the generational ID allocator owned by `World` as `world.ids`. IDs encode index (lower 20 bits) + generation (upper 12 bits). Static helpers: `IdPool.getIndex(id)`, `IdPool.makeId(index, gen)`, `IdPool.getGeneration(id)`. Instance methods (`world.ids.*`): `alloc()`, `free(id)`, `isValid(id)`, `reset()`, `export()`, `import()`.

## Component Pattern

Components are **string tokens** — a global name used as a `Map` key and for serialization. Data shape is defined at the call site; there are no static arrays, `defineComponent`, or static component classes (all deprecated).

```js
globalThis.Position = "Position";
/** @typedef {Object} Position @property {number} x @property {number} y @property {number} z */
// usage: world.add(id, Position, { x, y, z })
```

## System Pattern

Systems are **plain objects** with an `update(world)` method:

```js
globalThis.MovementSystem = {
  update(world) {
    for (const id of world.query(Position, Velocity)) {
      const pos = world.get(Position, id);
      const vel = world.get(Velocity, id);
      pos.x += vel.x * world.tickDuration;
      pos.y += vel.y * world.tickDuration;
    }
  },
};
```

On-demand utility systems (e.g. cursor methods on `PathfindingSystem`) expose named methods instead of `update(world)`.

## Fixed-Rate Simulation (ECS Scene Pattern)

Scenes running an ECS simulation dispatch systems explicitly inside `step()`:

```js
step() {
  const ticks = this.world.update();
  for (let t = 0; t < ticks; t++) {
    InterpolationSystem.snapshot(this.world); // first: record pre-move positions for render lerp
    GravitySystem.update(this.world);
    SolidSystem.update(this.world);       // integrates + resolves solid bodies
    SeparationSystem.update(this.world);  // pushes overlapping bodies apart
    StateSystem.update(this.world);
    LifetimeSystem.update(this.world);
    this.world.flush();
  }
}
draw() { this.renderer.draw(this.world); }
```

Genre scenes compose these into a **`Pipeline`** (`scripts/Pipeline/`): `this.physics = new Pipeline().add(SystemA).add(stepFn)`, then `this.physics.update(world)` each tick. A step is any `{ update(world) }` object or a bare function. Per genre: platformer `Gravity → clampFall → SolidSystem`; top-down `SolidSystem → ProjectileSystem`; RTS `SolidSystem → SeparationSystem`.

**Motion integrators are exclusive per body**: `MovementSystem` integrates _free_ movers (no collision response), `SolidSystem` is move-and-collide for solid bodies, `ProjectileSystem` is move-and-raycast for projectiles. A given mover is integrated by exactly one of them.

**`Time`** (`scripts/Time/Time.js`): `Time.delta` (scaled seconds), `Time.raw` (wall-clock), `Time.scale` (time dilation). Updated by `obj_game` in `Step_0` before `scene.step()` — always available in scene code.

## Genre Controllers & Template Gameplay Systems

The Core systems above are genre-agnostic. A playable genre scene layers a **controller** plus **gameplay systems** on top — these live in the genre's folder (`Platformer`/`RTS`/`Map` under **Showcase**; the genre lives in the top-level **RPG** folder (`RPG/Scene`) alongside the shared RPG layer) and are orchestrated by the scene's `step()`, not auto-run by `World`.

**Genre controllers** (`PlatformerController`, `RpgController`) own player input registration + entity setup and expose a three-phase lifecycle, not an `update(world)`. **`RpgController`** (the RPG genre) spawns its player via **`RpgPlayer`** (`scripts/RpgPlayer/`, top-level RPG): `RpgPlayer.spawn(world, spawn, { bbox, dir, speed })` builds the RPG player entity (transform + `Collision` + `Health`/`Stats`/`Inventory`/`Equipment`/`Encumbrance`/`Visual`) and `RpgPlayer.fireBullet(world, shooterId, { speed, damage, muzzleY? })` spawns the cursor-aimed bullet and returns the normalized aim `{ nx, ny }`. **`PlatformerController`** is a movement showcase — it builds a plain player itself (transform + `Collision` + `Direction`/`Grounded`/`Visual`, **no** RPG components) and has no firing. Each controller then adds its genre-only bits (platformer `Grounded`, top-down `Animator`) and its own movement.

- `create(world, spawn)` — registers the keymap (`Input.bindAll`), spawns the player (the RPG scene via `RpgPlayer.spawn` + genre components; platformer builds a plain entity), returns a plain `ctrl` state bag (`{ id, facing, ... }`). The `"bullet"` `EntityPreset` is registered by `RpgPlayer.spawn` (RPG only now — kinematic + bbox-less so `GravitySystem` skips it and it can't be a raycast self-target; top-down has no gravity).
- `pollInput(ctrl)` — call **once per frame, before `world.update()`**, outside the tick loop. Samples _edge-triggered_ input (jump `pressed()`/`released()`) into buffers so presses aren't lost on 0-tick frames or double-counted on multi-tick frames.
- `update(world, ctrl)` — call **once per physics tick**. Reads _continuous_ input (movement) and applies acceleration/jump to `Velocity` (before `SolidSystem` integrates it).
- `destroy()` — unregisters input. Plus genre verbs like `respawn`.

Read flags like `Grounded.isGrounded` live off the component each use (boolean-local clobber idiom).

**Template gameplay systems** are stateless `globalThis` objects like Core systems but expose _named query/resolve methods_ (not `update(world)`), called from `step()` after physics resolves: `EnemySystem` (`update` patrol + `resolveStomp` jump-kill + `resolveTouch` side-hit) and `CollectibleSystem` (`hitSpike`). They read `col.hits` (filled by `TriggerSystem`) or do their own overlap test, and return values the scene applies to player state. (Platformer-only; the RPG combat/loot systems live in the RPG layer.)

`scenePlatformer` (a movement showcase, no RPG) is a compact reference orchestration: per tick → `snapshot` → `controller.update` → `physics` Pipeline (`Gravity → clampFall → SolidSystem → TriggerSystem`) → `EnemySystem.update` → `resolveStomp` (bounce the player on a kill) else `resolveTouch`/`hitSpike` → respawn → void-fall respawn → `flush`. One open hand-built level.

**Lobby categories** are `SCENE_CAT_*` i18n keys: `ACTION`, `RPG`, `STRATEGY`, `MAP`. `SceneRegistry.add(factory, { label, category })` slots a scene under one.

## Gameplay / RPG Layer

The **RPG** scene (`sceneRpg`) is the action-RPG (the platformer is a movement showcase with no RPG layer). The pieces below live under the top-level **RPG** folder (organized into `Component`/`System`/`Content`/`UI`/`Scene`/`Editor` subfolders, like Core) and are driven explicitly from the scene's `step()`, never auto-run by `World`. The design constraint throughout is **composition over inheritance** (GMRT can't do `super`/subclassing): "kinds of item" are a flat `Item` carrying a `components: []` array of standalone capability/marker classes queried by `instanceof` — exactly the `UIElement.getComponent` pattern.

**Items & registry.** `Item` (`scripts/Item/`) is a definition registry (`Item.register([...])`, `Item.get(id)`), like `Rarity`. A definition is identity + universal scalars (`name` i18n key, `sprite`, `stack`, `weight`, `value`, `rarity`) plus `components` — capability/marker instances attached via `addComponent` and read via `getComponent(Class)`/`hasComponent(Class)`:

- `Equippable` (`{ slot, mods }`) — wearable in an `Equipment` slot (`weapon`/`armor`/`trinket`/`backpack`); `mods` are flat `Stats` deltas applied while worn.
- `Weapon` (`{ damage, fireCd?, bulletSpeed?, melee?, reach? }`) — attack profile. A `melee` weapon swings a hitbox `reach` px in the facing direction (`MeleeSystem`); a ranged weapon fires a cursor-aimed bullet (`ProjectileSystem`). The **`RpgController`** honors the `melee` flag (swing vs fire path).
- `Consumable` (`{ heal }`) — usable from the bag (one unit consumed for an instant effect).
- `Container` (`{ capacity }`) — while equipped, grows the wearer's `Inventory.capacity` (e.g. a backpack pairs `Equippable` + `Container`).

`Rarity` (`scripts/Rarity/`) is a parallel registry of tiers (`{ id, name, color, valueMod }`); rarity color drives loot/inventory tinting. **`RpgContent`** (`scripts/RpgContent/`, RPG) registers **all** shared RPG content — the rarity tiers, the **full item set** (consumables, weapons `wood_sword` (melee) + `blaster` (ranged), armor/trinket/backpack, currency `coin`/`gem`/`key`, crafting materials), and the workbench recipes. The RPG scene's own content is **`RpgQuests`** — its quests + achievements. `sceneRpg` calls `RpgContent.register()` once from `create()` (via `RpgQuests.register()`, which calls it first), **not** at top level, to dodge GMRT load-order issues.

**Inventory & equipment (pure systems over components).** Components are string tokens; their systems take the component (or `world` + entity id) directly, with no world tick:

- `Inventory` = `{ slots: [{ itemId, qty }], capacity, maxWeight? }` — every player, enemy (its loot table), and storage chest owns one. `InventorySystem` (`add`/`remove`/`has`/`weight`) stacks per `Item.stack`, and `add` is gated first by `maxWeight` then by `capacity`, returning the amount that did **not** fit.
- `Equipment` = `{ slots: { weapon, armor, trinket, backpack } }` of itemId strings (flat → `world.export`-safe). `EquipmentSystem.equip`/`unequip` keep the item in the `Inventory` (it still counts toward capacity/weight) and add/remove its `Equippable.mods` to the live `Stats` (and any `Container.capacity` to the `Inventory`). Deltas always pair, so no recompute-from-base pass is needed. `EquipmentSystem.weaponProfile` reads the equipped `Weapon` for the controller's fire logic.
- `ConsumableSystem.use` applies a `Consumable`'s effect and removes one unit; it refuses to waste an item that would do nothing (e.g. healing at full HP).
- `Encumbrance` (`{ threshold, minScale }`) + `EncumbranceSystem.scale(world, id)` → a speed multiplier from carried weight, read **live** by the mover (`RpgController.update`) rather than mutating `Stats.speed` (so it composes with equipment mods instead of fighting their balanced deltas).

**Combat & stats.** `Health` = `{ hp }`; `Stats` = the session-scoped character sheet (`level`, `xp`, `xpNext`, `maxHp`, `attack`, `defense`, `speed`). `MeleeSystem.swing(world, attackerId, dirX, dirY, reach, damage)` resolves a melee hit immediately (no projectile): an AABB hitbox extends `reach` in the facing **direction** (snapped to the dominant axis → 4-way) and damages every body with `Health` **except the attacker** and its faction allies (the slimes — player excluded; NPCs/furniture carry no `Health`), removing it at ≤ 0 hp and returning the struck ids. Ranged attacks go through **`ProjectileSystem`** (RPG/System) over `Projectile = { damage, owner }`: move-and-raycast — casts the per-tick segment via `Raycast`, applies `damage` to a hit `Health` (despawn at ≤ 0 hp; a `FactionSystem`-allied body is spared and blocks the shot), then despawns the bullet, range bounded by `Lifetime`. It lives in RPG (not Core) because it needs `Health`/`FactionSystem`; `TurretSystem` feeds it like `RpgController` does. `SlimeAI.attach(world, id, level)` wires an Idle→Chase→Attack machine onto a slime via `StateSystem` (its `Brain` holds `home`/`aggro`/`deAggro`/`attackRange` + a `pathCd` replan throttle; targets the nearest hostile by faction); slimes are dynamic solid bodies, so `SolidSystem` integrates + collides them for free. **Chase is line-of-sight-first** — a clear shot is a straight seek; a wall between slime and player triggers an A\* detour over the `NavGrid` (see _Pathfinding Flow_).

**Loot, progression & dialogue.** `ItemDrop` = `{ itemId, qty }` on a non-solid sensor entity the player collects on overlap; enemy deaths spill their `Inventory` as drops. `QuestLog` (`scripts/QuestLog/`) holds quest defs + active progress (objectives `{ kind: "kill"|"collect"|"reach", target, count }`, rewards `{ xp?, items? }`); the scene calls `QuestLog.report(kind, target)` after gameplay events and turns in on NPC interaction. `NPC` = `{ name, lines, questId? }` — the scene proximity-checks the player and opens a dialogue panel that can offer/turn in the linked quest. `Animator`/`AnimationSystem` are a data-driven sprite state machine: `Animator` holds a `graph` of named `AnimState`s (`{ sprite, frames, fps, loop }`); the controller picks `state`, `AnimationSystem.update` advances playback into the entity's `Visual` (clamps `frames ≥ 1` for the SVG-sprite quirk).

**Genre UI managers** (in Core, RPG, and Showcase) — gameplay overlays that are not the GemsUI scene panels:

- `SystemMenu` — the app's **one menu**: a global, open-anytime, near-fullscreen multi-tabbed overlay. Built on a `UIModal` root sized from `display_get_gui_height()` at open (flexpanel can't resize after layout). It **pauses all game + behind-UI logic** while open: `SceneManager.step()` skips `scene.step()` whenever `SystemMenu.isOpen()`, the menu forces `Time.scale=0`/`Time.delta=0` each frame (UI runs on `Time.raw`), and the `UIModal` blocks pointer + nav beneath it. It also **owns the gameplay pause + nav**: a scene opts in with `this.gameplay = true` in `create()` (a subclass field initializer wouldn't run — GMRT), and while closed over such a scene `update()` holds `UINav.suspended = true`. **F1** opens it anywhere, **gamepad Start** during gameplay, and **Esc** during gameplay is context-aware — the scene's optional `handleEscape()` hook gets first refusal (e.g. `sceneRpg` closes an open window, then exits build mode) and Esc opens the menu only if the scene didn't consume it. Tabs: **System** (live readouts — scene label, FPS, entity count — a `Speed` time-scale select, and `Resume`/`Step Frame`/`Restart Scene`/`Quit to Lobby`), **Settings** (the `Settings`-bound form with explicit Save), **About** (project/engine info, reuses `CREDITS_*`). API: `open(tabIndex=0)` (lobby Credits passes `2` → About) / `close()` / `isOpen()` (a method, not a `static get` — GMRT) / `scale()` / `consumeStep()` (one-shot frame-step) / `reset()`. `obj_game` drives `SystemMenu.update(this)` in `Step_0` before `UINav.update` (receives the controller so the System tab reads/restarts/quits the live scene via the `SceneManager` interface — `game.scenes.current`/`.label()`/`.restart()`/`.request()`); `SceneManager.step()` gates `scene.step()` on `!isOpen() || consumeStep()`, and `SceneManager._apply` calls `SystemMenu.reset()` on each scene swap. Entry points: lobby footer (Settings + Credits), `F1`, gameplay Start, gameplay Esc.
- `StorageUI` — storage-chest transfer window for the RPG scene. Any entity tagged `"storage"` with an `Inventory` is a chest; walk near + press `interact` (E) to open a two-column Bag↔Chest transfer window (a draggable `gemsWindow`). Each side: a header (title + bulk button), a live **Slots/Weight usage line**, then a **`UITable`** whose columns mirror the inventory's Settings-driven set (the `invCol*` toggles; `_applyColumns` re-applies on open, and `RpgInventoryUI._applyColumns` pokes both tables live when a toggle flips). **Double-click** a row (or a gamepad/keyboard confirm in browse mode) moves the whole stack to the other side (single click selects); the per-column **Store All / Take All** button bulk-moves everything that fits (greedy, halting at the destination's cap) and disables itself live when its side is empty. Both tables are built once; a transfer only swaps rows via `setRows`, so the column sort survives every move (a row sort is view-only — never reorders the `Inventory`). Per-open state lives on the scene (`_store*`), cleaned up by `teardownScene`. Contract: `build(scene)` once after player + ui exist, `refresh(scene)` when dirty (driven by `Interactable.update`), set `scene._storeDirty` when the bag changes elsewhere.
- `BuildMode` — **RPG grid build mode** (stateless singleton, like `Interactable`). `build(scene)` once in `create()`, `update(scene)` each frame after `Interactable.update` (outside the tick loop), `drawWorld(scene)` in `draw()`. `B` toggles. The palette is a categorized bottom-center HUD bar (`gemsCatBar`) over a status line, driven by a data-driven `BuildMode.CATALOG` (**Tiles** wall/floor · **Furniture** crate/barrel/fence · **Lighting** torch · **Stations** chest/workbench · **Defense** turret); clicking an item sets `scene._buildItem`. An item is a **tile** (`kind:"tile"` — edits a wall/floor `TileLayer` via `TileEdit`) or an **entity** (`kind:"entity"` — `make()` returns a descriptor built through `RpgSpawn.spawnEntity`, so a built prop/station/torch is identical to a file/streamed one; the torch carries a `Light`, the turret `Health`+`Faction`+`Turret`). LMB places (per-item wood `cost`, via `UIPointer.pressed`), RMB deconstructs (refunds); `_overHud` skips world edits while the cursor is over the bar. Building is gated to a **claimed buildable `Zone`**: press `E` at a **Survey Post** (`Station` kind `"claim"`; `Interactable._open` routes it to `BuildMode.claim`, which `paintRect`s the `"buildable"` `ZoneMap` channel around the post then **detaches the post's `Station`** so it can't be re-claimed). Tile edits go through the Core **`TileEdit`** service (`set`/`clear` + `remesh` for seam-free walls; floor edits touch no collider; `occupied` tests). Per-scene state: `_built` (`"gx,gy" → tile item id`), `_builtEnts` (`"gx,gy" → { ent, itemId }`, scene-tracked — **not** chunk-managed, so `ChunkManager` leaves them alone like the party), `_buildItem`, `_buildActive`, plus a static `BuildMode.active` mirror (set only while the `"build"` input context owns input) that `drawWorld` reads to gate the cursor highlight. **Built tiles + entities persist across map reloads**: `RpgMap.load` captures built entities (via `EntitySnapshot`, keyed by cell + catalog id) into the map cache alongside the `Level.export`'d tiles before teardown, restoring them on revisit.
- `RpgWorldOverlay` — the RPG scene's **world-space** overlay (`drawWorld(scene)`, called from `sceneRpg.draw()` inside the camera view, **after `renderer.draw()`** — the chunked overworld's `RenderChunks` pass paints an opaque ground fill that would hide overlay content drawn first): item-drop rarity squares, bullets, and (when the scene exposes `reachZone`) the reach-quest zone. `_rarityColor` is shared with the inventory rows. The HUD, dialogue, and inventory window are real UI panels drawn on the GUI layer (`Draw_75`). **The RPG scene's walls are a real tilemap** (`RpgLevel` keeps a wall + floor `TileLayer` on the `Level`), drawn by a `RenderDebugTileMap` pass with the buildable region by a `RenderZone` pass — both world-space passes under the entity passes.

**World time & day/night.** **`WorldClock`** (`scripts/WorldClock/`, RPG) is the in-game clock — a static class like `Time` (one world clock), holding `hour` (0–24 float) + `day` (1-based), advanced once per frame from `sceneRpg.step()` by `Time.delta` (sim time — pauses with the game, dilates with `Time.scale`). `dayLength` (real seconds per in-game day, default 240) sets the pace. The scene `reset()`s it once in `create()` — **not** per map — so a portal trip keeps the hour. API: `reset()`, `update(dt)`, `clockText()` (`"HH:MM"`), `phase()` (`night`/`dawn`/`day`/`dusk`), `tint()` → `{ color, alpha }` interpolated from a keyframe table (deep blue at night → clear by morning, warm at dawn/dusk; alpha 0 in full daylight). The HUD shows `Day N HH:MM` (read live), and the **`RenderLighting`** pass consumes `tint()` as its **ambient term** (day/night is the light map with no lights).

**Seasons & temperature.** `WorldClock` also derives the **season** purely from `day` (no stored state, like `phase()` from `hour`): `daysPerSeason` (default 7) days each, the four cycling forever over a `_SEASONS` literal (`{ id, name }`). API: `season()`, `seasonDay()` (1-based day-within-season). The HUD time row reads `Season · Day N  HH:MM`. Season biases the `Weather` transition + the `Temperature` baseline. **`Temperature`** (`scripts/Temperature/`, RPG) is the ambient temperature in **Kelvin** (`toCelsius`/`toFahrenheit` convert) — a **pure derivation, not a stored sim**: `now()` = `ZERO_C` (273.15) + season baseline (`_BASE`, authored in °C, keyed by `season().id`) + a time-of-day swing (`diurnal()`, a cosine of the hour peaking mid-afternoon) + the live `Weather.tempMod()` (which already folds in the active climate zone's offset). The Kelvin/Celsius scales share one increment, so all the deltas are scale-agnostic — only the baseline is offset. Kept **off** `WorldClock` so the clock stays the pure temporal authority. The HUD shows the weather condition + temperature via **`Temperature.display()`**, which formats `now()` in the `tempUnit` Setting (`"K"`|`"C"`|`"F"`, default `"K"`; toggled in the inventory **Settings** tab); the bundled locale fonts carry the `°` glyph, so `°C`/`°F` render.

**Weather.** **`Weather`** (`scripts/Weather/`, RPG) is the global sky — a static singleton like `WorldClock` (one sky), holding the current condition + a **season-biased transition**. Conditions are a fixed built-in literal table (`_COND` — `clear`/`cloudy`/`rain`/`storm`/`snow`), each carrying its render look (`{ c, a }` tint + `particle`/`density`) and a **Kelvin `temp` delta** (scale-agnostic, folded into `Temperature.now()`). `update(dt)` (driven from `sceneRpg.step()` by `Time.delta`, so weather **freezes when the game pauses** and dilates with `Time.scale`, like the clock) counts down a 25–70 s hold then re-rolls the next condition by `_WEIGHTS[season]` (winter favors snow + bans rain, summer favors clear + the odd storm, …), **excluding** the current one so a change always changes the weather. A change **cross-fades** over `_fadeTime` (2.5 s): `previous()`/`current()`/`blend()` let the render pass + `tempMod()` lerp the outgoing→incoming conditions so weather eases in/out instead of snapping. `reset()` (scene `create()` once, like `WorldClock.reset()`) settles a clear sky and survives map changes. The **`RenderWeather`** pass (see Renderer) draws it; the HUD reads `current().name`.

**Climate zones (regional weather).** A **climate `ZoneMap` channel** lets a region **override** the open sky. `Weather.enterRegion(zone)`/`exitRegion()` read the zone's flat `data` — `weather` (a forced condition id) + `tempMod` (a Kelvin offset) — into an `_override`/`_regionTemp` slot; the *displayed* condition is the effective one (`override ?? ambient`), so the season-rolled ambient keeps running underneath and resumes on exit (the cross-fade handles both edges). Climate zones are **data-driven** from a level file's optional `meta.climate` array (`[{ name, rect: [gx1,gy1,gx2,gy2], weather?, tempMod?, color? }]`), painted into the `"climate"` channel by `RpgMap.load` (before the persistence import, so they round-trip like the buildable zone). `sceneRpg._updateClimate()` tracks the **player's** climate cell directly each frame (a single-entity `ZoneMap.idAt` lookup — cheaper than `ZoneSystem`'s all-entity sweep) and fires enter/exit on a border cross; `RpgMap.teardown` calls `exitRegion()` so a portal trip clears it. The reference is `overworld.json`'s **Frostlands** (`weather: "snow"`, `tempMod: -15`) — walking in turns the sky to snow and drops the temperature ~23 K. **Indoor maps** (`meta.indoor`, e.g. `interior_01`) skip the `RenderWeather` pass entirely — no open sky inside a cave (the global `Weather` keeps running; only its visual is suppressed).

The combat/loot plumbing the RPG scene (`sceneRpg`) uses lives in **`RpgScene`** (`scripts/RpgScene/`, RPG) — free functions taking the scene (composition; no class inheritance on GMRT): `trackDamage(scene, yOffset)`, `resolveDeaths(scene, { onKill?, spill? })`, `spillLoot`/`spawnDrop`, `collectDrops(scene, onCollect?)`, `checkPlayerDeath(scene, onRespawn)`. Scene-specific side effects (quest/profile counters, the respawn action, FloatingText height) are the callbacks/options; the scene supplies the contract fields `world`/`ctrl`/`_hpTrack`/`_invDirty` (the enemy set is derived live by `Tag "enemy"`, not stored).

The draggable **character window** is centralized in **`RpgInventoryUI`** (`scripts/RpgInventoryUI/`, RPG) — a wider **`gemsTabs`-based** panel (built once in `build(scene)` on `scene._invWin`) with five tabs: **Items** (the bag `UITable` over a usage line + a category-filter `gemsSelectCustom` + a free-text name-search `gemsInput` composing into one `table.setFilter` via `_applyFilter` — search lowercases via an ASCII char-code map, since `toLowerCase()` is broken on GMRT — plus a select/action row: click selects, double-click / the context **Use/Equip/Unequip** button / a gamepad confirm acts on the row), **Equipment** (worn-slot rows, click to unequip — `scene._invEquipHost`), **Stats** (the live sheet + the genre's extra records — `scene._invExtraHost`), **Quests** (a live `gemsQuestTracker` bound to `QuestLog`), **Settings** (per-column toggles). The Items columns are gated by the **Settings** toggles (`gemsCheckbox` → `Settings.set`/`save`, persisted across launches): worn-marker / Name / Qty always; **Rarity** / Type / Weight / Value optional. A toggle calls `_applyColumns` → `UITable.setColumns`, which remaps the active sort by each column's stable `key` (the sort stack stores indices, which shift when columns change). `rebuild(scene, { equipSlots, extraRows? })` only refreshes live data: `table.setRows` (re-applies the current sort/filter, so view + scroll + active tab survive every equip/use), re-maps the selection by `itemId`, repopulates the equipment + extra sections. `equipSlots` is the rows to show (RPG adds `backpack`); `extraRows(scene, host)` appends genre lines (RPG Profile records). The scene keeps only `invOpen` (toggled on the `inventory` key) and calls `build` in `create()` + `rebuild` when `_invDirty`. (The HUD stays per-scene — `sceneRpg._buildHud` = HP + quest tracker.)

`sceneRpg.step()` is the reference RPG orchestration: edge-toggle the inventory window → per tick: `snapshot` → `controller.update` → `physics` Pipeline → `RpgScene.trackDamage` → `RpgScene.resolveDeaths` (quest/profile counters via `onKill`) → `RpgScene.checkPlayerDeath` → `RpgScene.collectDrops` → reach/quest/achievement checks → `flush`; then once per frame: `AnimationSystem.update`, NPC proximity + dialogue, `Interactable.update`, `BuildMode.update`, `camera.update`, an inventory rebuild when `_invDirty`, and finally `_checkPortals()` **last** (a door swaps the world out from under everything). (No pause gate in `step()` — `obj_game` skips `scene.step()` entirely while the `SystemMenu` overlay is open.)

**Map graph (overworld / sub-levels / side-islands).** Maps are discrete level files connected by portals, not one streamed world (the deliberate fit for the `JSON.parse`-on-large-files limit and the one-`World`-per-scene model). The world graph is the seed registry **`RpgLevel.MAPS`** (`{ mapId → "levels/x.json" }`) + `RpgLevel.START`; extract to a `maps.json` manifest if it grows. A level file gains two things over the base format: `meta.entries` (a named-point map, e.g. `{ default, from_interior }` — the matching side of a door; `RpgLevel.build(world, data, entryId)` resolves the spawn from it, falling back to `entries.default` then legacy `meta.playerSpawn`) and a **`portal`** spawn preset (`{ toMap, toEntry, label?, color? }` → a non-solid sensor entity, returned in `RpgLevel.spawn`'s `portals[]`). `sceneRpg.create()` builds the **persistent** UI once (HUD/dialogue/inventory/Interactable/BuildMode — they read `world`/`ctrl` live, so they survive a map swap), then calls **`RpgMap.load(scene, mapId, entryId)`**, which: snapshots the player's character sheet (`Stats`/`Health`/`Inventory`/`Equipment`/`Encumbrance` — plain objects that outlive `world.destroy()`), tears down the old map (`RpgMap.teardown`: controller/camera/renderer/world/level), builds the new world/level/player/zone/spawns/pipeline/renderer/camera, and re-`add`s the carried sheet onto the new player (equip mods already baked in — no re-equip pass). The player-centered radar (`RadarArrows`) reads `world`/`ctrl` live, so it needs no per-map rebuild. `RpgMap.checkPortals` (step's last line) travels through the first portal the player overlaps. The editor's Test Play still works: a `playtestFile` is registered under a synthetic `_playtest` map id and booted as a single portal-less map. `_updateNpc`/`_checkReach` guard the no-NPC / no-reach-marker maps (interiors). The reference graph is `overworld` ⇄ `interior_01` (a cave door).

**Map persistence (`meta.persistent`, default true).** A map's player edits — the claimed buildable zone + built tiles — survive leaving and returning, so a door transition can't wipe a player's base. `loadMap` keeps an in-memory `scene._mapCache` keyed by mapId: leaving a persistent map snapshots `level.export()` (TileLayers + the buildable `ZoneMap`, a detached copy that outlives the level's destroy) + the `_built` deconstruct tracking; revisiting `level.import`s that over the freshly-built level (same dims/layer order → clean round-trip; the cached buildable zone keeps id 1, matching the fresh `define`), re-meshes wall colliders from the restored layer (`TileEdit.remesh`), and restores `_built`. Set `meta.persistent: false` on a level file to opt out (a dungeon that resets each entry). Scope is the play session — enemies/loot/quest state are deliberately **not** cached (they live on the global `Profile`/`QuestLog`, and slimes are meant to respawn); the cache is `Level.export()`-shaped, so a future on-disk save serializes it next to the carried character sheet.

**Followers & the party (dynamic-world entities).** A companion either travels with the player or waits in a place — the forcing-function for entity migration. `Follower` (`scripts/Follower/`, `{ state: "follow"|"wait", speed, range, homeMap }`) marks it; `FollowerSystem.update(world, playerId, followers)` is the per-tick seek (a `"follow"` companion steers toward the player, easing to a stop within `range`; a `"wait"` one holds still). The player id is **passed in, never stored on the follower**, so a migrated companion needs no entity-id re-link. It's a dynamic solid body; `RpgLevel.spawnFollower(world, x, y, opt)` builds it (shared by the `follower` preset + the scene's seed). Migration realizes the **three persistence scopes** over `EntitySnapshot`: in `RpgMap.load`, each follower is partitioned — `"follow"` → **party scope** (captured, re-spawned around the new entry), `"wait"` → **map scope** (captured into `_mapCache[mapId].entities`, restored where it was left). The player's character sheet is party member 0. `sceneRpg` seeds the starting companion **programmatically once** in `create()` (a file-authored follower in a persistent map would duplicate — see reconcile); the `F` key flips the nearest companion between follow and wait.

**File-scope reconcile (`id` → spawn-once).** File spawns default to **respawning** every visit (generic enemies are meant to come back). A spawn carrying an authored **`id`** is a **unique** entity, spawn-once: it gets a Core `Persistent { uid }` component, and the scene remembers its fate per map. The ledger is `_mapCache[mapId].gone` (a `{ uid: true }` set, loaded into `scene._gone` on enter, written back on leave); `RpgLevel.spawn(..., { gone })` **skips** any id'd spawn whose uid is in it, so a killed boss / recruited NPC doesn't re-spawn while id-less spawns still do. The scene marks a uid gone via `_markGone(id)` — wired into `RpgScene.resolveDeaths`'s `onKill`, reading `Persistent.uid` while the entity is alive. Scope follows map persistence (a non-persistent map's `gone` resets each entry). This closes the file-authored-follower duplication and is the seam for recruitable NPCs. **Deferred:** preserving a *survivor's modified state* (a partially-looted chest re-filling on revisit) needs snapshotting surviving unique entities on leave; only the removed/`gone` case is handled now.

**Chunk streaming & sim-LOD (scalable overworld).** A **chunked map** (`meta.chunked: true` in the level file) streams its terrain + entities around the player so the `World` only ever holds what's nearby — entity count + per-tick cost stay bounded no matter how far the player roams (the overworld; interiors keep the plain build-everything path). The engine is the Core **`ChunkManager`** (`scripts/ChunkManager/`, a plain instance class owned by the scene as `this.chunks`, like `SceneManager`); content comes from a **`source`** it's handed — the RPG **`ChunkSource`** (`scripts/ChunkSource/`). Built on `EntitySnapshot` (the capture/restore foundation) + `Portal` (`scripts/Portal/`, `{ toMap, toEntry }` on the doorway entity, so a streamed door resolves via a live `Tag "portal"` query).

- **Two-ring sim-LOD** (Chebyshev chunk distance from the player's chunk): `d ≤ simRadius` → **SIM ring** (entities live in the World, walls have colliders, full simulate + render); `simRadius < d ≤ loadRadius` → **LOAD ring** (entities held as snapshots, **not** in the World / not simulated, drawn statically by `RenderChunks`; walls drawn, no colliders); `d > loadRadius` → **UNLOADED** (snapshots parked in an in-session cache keyed by chunk, restored on return so hurt/killed/moved entities persist). `ChunkManager.update(centerX, centerY)` (called once per frame from `step()`, outside the tick loop) diffs the rings on a chunk-border crossing and **promotes** (restore → World + mesh colliders) / **demotes** (capture → snapshot + drop colliders) / loads / unloads, then `world.flush()`es its own removals. The **party (player + followers) is never chunk-managed** — the scene keeps it in the World always.
- **Resident grid vs streamed terrain.** A chunked map's `Level` is a large **resident** grid (`meta.worldCols/worldRows`, built by `RpgLevel.buildChunked`) whose `wallLayer`/`floorLayer` hold **player builds only** (build mode + `TileEdit` colliders, unchanged) — the streamed terrain (authored hub + procedural wilderness) is owned by the `ChunkManager` with its own colliders + `RenderChunks` pass, never written into those layers, so the two never conflict. The world is a **finite `worldCols × worldRows` rectangle** (the resident-grid extent, anchored at cell 0): `ChunkManager` clamps streaming to chunks inside it (`opts.worldCols/worldRows` → it skips out-of-bounds chunks, so the active set shrinks near an edge — e.g. 9 at a corner vs the usual 25), and `RpgLevel.buildWorldBorder` rings it with 4 always-present kinematic-solid edge colliders so the player/slimes can't leave (procedural fills the rectangle out to the border; building is gated to the claimed origin zone). `IdPool` reuses freed indices, so streaming churn keeps the high-water mark bounded.
- **`ChunkSource` (router) → `OverworldGen` (generator) → `Prefab` (templates).** Generation is **not fixed** — it's split into three pieces so a different world is a swap, not a rewrite:
  - **`ChunkSource`** (`scripts/ChunkSource/`, RPG/System) is the `source` the `ChunkManager` holds, and is purely a **router**: chunks inside the **authored origin box** (the `overworld.json` walls + spawns indexed by chunk, so the hand-built hub — Elder, cave portal, chest, workbench, survey post — appears in its chunks and stays procedural-free) come from the overlay; everything else is delegated to its `generator`. `generate(cx,cy) → { walls, spawns }` (absolute grid coords; `gridToWorld` handles negatives); `spawn(world, level, desc, playerId)` delegates to **`RpgLevel.spawnEntity`** — the per-spawn entity constructor extracted from `RpgLevel.spawn` so streamed + up-front spawns build through one code path.
  - **`OverworldGen`** (`scripts/OverworldGen/`, RPG/System) is the swappable procedural algorithm (inject a different `generator` — cave/desert/… — with the same `generate(cx,cy)` contract). It emits a loose random scatter (rocks + slimes) **plus** an optional stamped **prefab**, deterministic from `(cx, cy, seed)` so a chunk regenerates identically (the contract terrain relies on). Its PRNG is a Park–Miller MINSTD LCG, not xorshift32 (see the xorshift GMRT-Safe Idiom).
  - **`Prefab`** (`scripts/Prefab/`, RPG/Content) is a registry of reusable hand-authored mini-layouts (walls + spawns in **prefab-local** grid coords + a `cols/rows` footprint + scope `tags`), mirroring `Item`/`Rarity`. `OverworldGen` weighted-picks one tagged `"overworld"` and **stamps** it at a deterministic interior offset (translating local→absolute coords, kept off the chunk border so its walls can't merge across a seam); item arrays (`loot`/`items`) are deep-copied per stamp so instances never share-and-mutate the registry def. Defaults (`boulder_cluster`/`slime_den`/`ruin`) are registered in `RpgContent.register()` alongside items/recipes.
  - Slimes survive capture/restore because `SlimeAI` keeps its world/target/level as shared statics (refreshed on each `attach`) and `State`/`Brain` carry no self-id.
- **Scene wiring** (`sceneRpg`): `RpgMap.load` branches on `meta.chunked` — chunked builds the resident grid + creates `this.chunks`/`this.source` + an initial `chunks.update(spawn)` + inserts `RenderChunks`; plain is unchanged. The scene reads NPC / portal / enemy handles **live by tag** (`Query.nearest({tag:"npc"})`, `world.query(Portal)`, `RpgScene._enemies`) rather than stored id lists, so chunk churn never dangles a handle. `RpgMap.teardown` drops the manager (clearing `this.chunks` so a following plain map's `step()` skips streaming). Verified flat (~74 ents / 25 chunks at `simRadius 1`/`loadRadius 2`) across a ~15-chunk traverse, clamping near a world edge. **Deferred:** per-chunk *build* persistence + on-disk chunk saves, throttled distant ticks, carrying the chunk cache across portal trips.

## Pathfinding Flow

1. `world.add(id, PathRequest, { startX, startY, goalX, goalY })` — request in grid coords.
2. `PathfindingSystem.update(world)` resolves → writes `PathResponse: { path, index }` (`index` = cursor).
3. `PathfindingSystem.current(world, id)` → current waypoint `{x, y}` or `undefined`.
4. `PathfindingSystem.advance(world, id)` → `true` if more waypoints remain; `false` (and detaches `PathResponse`) when complete.
5. After any grid change: `PathfindingSystem.invalidate(world)` — detaches all `PathResponse`.

**Streamed-world pathfinding (`NavGrid`).** `MotionPlanner` plans over one `MotionPlanningGrid`; on the chunked overworld the obstacles aren't in `Level.mpg` — the terrain is collider _entities_ owned by `ChunkManager` (+ world border + player builds), the world is large, and only nearby chunks are loaded. **`NavGrid`** (`scripts/NavGrid/`, Core) is the adapter: a small fixed window (default 32×32) re-centered on the player each frame (`rebuild(world, gx, gy)` from `sceneRpg.step`, before the tick loop) by rasterizing every kinematic-solid collider's `AABB.of` footprint into blocked cells, exposing the `MotionPlanningGrid` interface in **absolute level-cell coords** so paths return level cells. `size()` is constant, so `MotionPlanner.setGrid(scene.nav)` is called **once per map**; only occupancy/origin change per frame. One cheap grid unifies streamed terrain + border + player builds + interior walls. The consumer is **`SlimeAI.CHASE`**: line-of-sight-first — a clear shot (`Raycast`) is a straight seek; only a wall triggers a throttled `PathRequest` → `PathfindingSystem` → `PathResponse`. `RpgMap` inserts a default-off `RenderDebugPath` pass for the Debug **paths** toggle.

## Level & Map Layers

`Level` (`scripts/Level/Level.js`) manages the tile grid and pathfinding grid, **separate from `World`** (the ECS).

```js
const LEVEL = new Level({ cellWidth: 32, cellHeight: 32 }); // cols/rows derived from room size
const terrain = new TileLayer(LEVEL.cols, LEVEL.rows, { emptyCost: Infinity }); // blocking base
LEVEL.insert(terrain); // append a LevelLayer (LEVEL.remove to detach)
PathfindingSystem.setGrid(LEVEL.mpg); // wire up after layers are ready
LEVEL.syncAll(); // recompute all pathfinding costs (or syncAt(x, y) for one cell)
PathfindingSystem.invalidate(world); // call separately after any grid change
LEVEL.worldToGrid(wx, wy);
LEVEL.gridToWorld(gx, gy); // ↔ { x, y } (gridToWorld returns cell center)
```

**`LevelLayer` interface**: `get(x,y)`, `set(x,y,v)`, `getNavData(x,y) → { cost }`, `export()`, `import()`, `destroy()`. The one built-in is **`TileLayer`** (`scripts/TileLayer/`), wrapping a `Grid` of **`TileType`** values. Later-added layers have higher nav-cost priority. Empty cells report the layer's `emptyCost`: `undefined` (default) passes through to lower layers; `Infinity` makes a blocking base. `TileType` (`scripts/TileType/`) holds `{ id, name, pathCost }` (`pathCost: null` → `Infinity`, default `1`).

**`TileEdit`** (`scripts/TileEdit/`, Core) is the genre-agnostic tile-editing service that keeps a layer's **derived data** (nav cost + solid colliders) in sync with edits, so the "edit a solid tile → resync nav + rebuild colliders" invariant lives in one place. `occupied(layer,gx,gy)` (truthy read — `Grid.get` returns `0`, not `undefined`, for an empty in-bounds cell), `set(level,layer,gx,gy,type)` / `clear(level,layer,gx,gy)` (write + `level.syncAt`), `meshSolid(world,level,layer,out)` (greedy-mesh the solid cells into the fewest kinematic-solid colliders — extend right for width, then down while the whole row is solid — so straight walls become single seamless colliders, avoiding the per-cell-seam snag bug; box size = `level.cellWidth/Height`, ids pushed onto `out`), and `remesh(world,level,layer,colliders)` (remove old + re-`meshSolid` after a solid-tile edit). Shared by `RpgLevel.build` (initial mesh) and `BuildMode` (per-edit set/clear/remesh); the seed for a future in-engine tile editor.

### Zones

**`Zone`** / **`ZoneMap`** / **`ZoneSystem`** add named, tagged spatial regions on top of the level grid — the substrate for build-mode buildable area, faction territory, in-game events, quest regions, weather areas, etc. (Separate from tile layers and from nav cost; a zone is metadata, not a tile.)

- **`Zone`** (`scripts/Zone/`) — a flat definition object `{ id, name, tags, data }`. `tags` is a **`string[]`** (`hasTag(t)` via `indexOf`), never a `Set` (Set iteration crashes GMRT); `data` is a flat scalar payload (`{ factionId, weather, questId, color, … }`) to stay JSON-safe.
- **`ZoneMap`** (`scripts/ZoneMap/`) — one zone **channel**: a `Grid` of zone-id ints (`0` = none) plus a registry of `Zone`s, exactly as `TileLayer` wraps `Grid<TileType>`. A cell belongs to **at most one zone within a map**, so lookup is O(1) and storage is one int per cell; purposes that can overlap (faction vs. weather vs. event) live in **separate maps**. API: `define(opt) → Zone` (auto-assigns id), `zone(id)`, `byTag(tag)`, `paint(id,gx,gy)`/`paintRect(id,x1,y1,x2,y2)`, `erase`/`eraseRect`, `idAt(gx,gy)`, `at(gx,gy) → Zone`, `contains(gx,gy,tag)`, `cells(id) → {x,y}[]`, `export`/`import`/`destroy`.
- **`ZoneSystem`** (`scripts/ZoneSystem/`) — the entity↔zone glue, a stateless system object with named methods (no World tick): `update(world, level, map, { tag?, onEnter?, onExit? })` fires enter/exit edges as entities cross borders (mark-and-sweep over `map._inside`, so leaving to an empty cell _or_ being removed both fire `onExit`); `zoneOf(world, level, map, id) → Zone`; `entitiesIn(world, level, map, id, { tag? }) → id[]`. Drive `update` from a scene's `step()` for events/weather/quests.

Zones live on the **`Level`** (they are level data): `level.addZoneMap(key, map?)` (sized to the grid by default), `level.zoneMap(key)`, and `level.zoneAt(key, wx, wy) → Zone` (world-space convenience). `Level.export`/`import` round-trip zone maps under a `zoneMaps` key, emitted only when non-empty so existing serialized levels are unaffected; `Level.destroy` tears them down.

To **visualize** a channel, add a `RenderZone` pass (see Renderer) to the scene's renderer: `renderer.insert(new RenderZone(level, "faction"))`; for the zone names add a `RenderZoneLabel` pass after it: `renderer.insert(new RenderZoneLabel(level, "faction", { font }))`.

The reference consumers are the RPG scene's **build mode** (`BuildMode`, see Genre UI managers) — a `"buildable"` channel whose region a Survey Post claims (`paintRect`), gating where tiles may be placed, drawn by a `RenderZone` pass — and its **`"climate"` channel** (see _Climate zones_ under Weather): regions that override the global `Weather` (forced condition + temperature offset) while the player is inside.

## Renderer

`Renderer` (`scripts/Renderer/Renderer.js`) is an ordered list of `RenderPass` objects (`{ draw(world), destroy() }`). `insert(pass, index?)` / `remove(pass)` manage the list; `draw(world)` runs every pass; `destroy()` tears them down. Each scene owns its renderer and calls `this.renderer.draw(this.world)` in `draw()`.

Built-in passes:

- **`RenderEntity`** — draws entities with `Visual` + `Position` via `draw_sprite_ext`. Interpolates between `PrevPosition` and `Position` by `world.alpha` when present (see `InterpolationSystem`); falls back to raw `Position` otherwise.
- **`RenderDebugBox`** — draws each entity as a filled `Visual.color` rectangle + black outline (GMRT can't render the SVG character sprites); interpolates via `InterpolationSystem.lerp`. **One concern — just the box.** The gameplay templates use it as the entity pass, pairing it with the single-concern overlays below inserted _after_ so each layer toggles independently (`enabled`): `RenderDebugName` (Name labels), `RenderDebugDirection` (facing dot), `RenderDebugAnimator` (animator state), `RenderDebugEntity` (lime bbox outline). For debug passes informativeness beats sharing a draw loop, so each cue is its own pass rather than baked into the box.
- **`RenderDebugName`** — `Name` labels (white) centered just above each entity's box top, for entities with `Name` + `Position`. Split out of `RenderDebugBox`; insert _after_ the box pass.
- **`RenderDebugDirection`** — a small facing dot offset from each entity's box center toward its `Direction` (skips zero-direction / invisible entities). Split out of `RenderDebugBox`; insert _after_ it. Only scenes whose entities carry `Direction` (platformer, RPG) add it.
- **`RenderDebugAnimator`** — each entity's current `Animator.state` as a yellow label below its box, so the sprite state machine is legible. RPG-only (Animator is the RPG layer). Split out of `RenderDebugBox`; insert _after_ it.
- **`RenderTileMap`** (`new RenderTileMap(layer, level, sprite, opt?)`) — hardware-accelerated tiles via `VertexBuffer`. `opt`: `{ autotile: 0|16|47|"dual", alpha, color, softEdge }`. Call `.markDirty()` after tile changes to rebuild the VBO. Autotile: `0` = raw frame id, `16` = blob4, `47` = blob8, `"dual"` = dual-grid corner sampling. Neighbor bits: `N=1, E=2, S=4, W=8` (blob8 adds `NE=16, SE=32, SW=64, NW=128`), so a blob4 tileset's frame index equals its cardinal-neighbor mask. `spr_tile16` is the project's 16-frame blob4 tileset; the **Tile Inspector** scene (`scripts/sceneTileInspect/`) lays out all 16 frames against this rule to validate frame order (`sceneTileInspect47` does the same for the 47-frame blob8 set).
  - **`"dual"` (dual-grid)** — the blob modes draw one centered tile per _filled cell_ and cannot show two materials meeting (binary occupancy: a 2×2 filled block renders as a donut with blob4). Dual-grid instead renders a half-cell-**offset** grid where each display tile samples the 4 cells touching a grid _corner_; corner bits `TL=1, TR=2, BR=4, BL=8` → 16-frame index = mask (like blob4 but corner-keyed). Because a tile's empty corners stay transparent, **stacking several `"dual"` passes — one `TileLayer` per terrain, lowest priority first** — makes each upper terrain's border reveal the one beneath it, i.e. RPG-Maker-style A-over-B transitions with only a 16-frame corner tileset per terrain (no hand-drawn transition art). This is how the project supports _terrain-to-terrain_ blending; the priority stack is just ordered `Renderer` passes (no new class). Validate corner art with `sceneTileInspectDual`; see `sceneTileTerrain` (water < sand < grass) for the reference composition. `softEdge` is ignored in dual mode. `spr_tiledual` is the project's 16-frame corner tileset (frame N fills the corners of mask N); both dual demos use it.
- **`RenderDebugEntity`** — `BBox` outlines (lime) for all entities with `Position` + `BBox`. Interpolates via `PrevPosition` + `world.alpha` like `RenderEntity`.
- **`RenderDebugPath`** (`new RenderDebugPath(level)`) — active `PathResponse` paths (yellow) + pending `PathRequest` goals (red cross).
- **`RenderZone`** (`new RenderZone(level, key, opt?)`) — world-space overlay for one **zone channel** (see Zones): fills each zone's cells by color and outlines region borders (only edges where the neighbor differs, so map edges outline too). `opt`: `{ alpha, border }`. Color is `zone.data.color` (`"#rrggbb"`) when set, else a stable hue from the zone id. Reads `level.zoneMap(key)` live each frame — a no-op until that channel exists, so it's safe to insert before zones are painted. Uses plain `draw_line` for borders (`draw_line_width_color` renders nothing on GMRT).
- **`RenderZoneLabel`** (`new RenderZoneLabel(level, key, opt?)`) — zone-name labels (white) at each zone's centroid for one channel. `opt`: `{ font }`. Split out of `RenderZone` so labels toggle independently; insert _after_ the zone pass.
- **`RenderGrid`** (`new RenderGrid(level, opt?)`) — cell boundary lines for a Level's grid. `opt`: `{ color, alpha, camera? }`. Split out of `RenderDebugTileMap` so the grid toggles independently; insert it wherever the grid is wanted (the tile scenes pair it with the debug tilemap pass). Plain `draw_line` (`draw_line_width_color` renders nothing on GMRT).
- **`RenderChunks`** (`new RenderChunks(chunkManager, opt?)`) — world-space pass for a `ChunkManager`'s streamed terrain (see Chunk Streaming & Sim-LOD below). Per active chunk: an opaque ground fill (a subtle checker by chunk parity, so chunk seams + streaming read at a glance; unloaded area stays the dark scene background = a visible "edge of the loaded world"), the chunk's wall rects, and — for LOAD-ring (frozen) chunks — each held entity **snapshot** as a dimmed box + name (matching `RenderDebugBox`/`Name`). SIM-ring entities are live in the World and drawn by the normal entity passes, so insert this **before** them (ground under everything). The active set is already tiny (bounded by `loadRadius`), so no per-chunk view cull. `opt`: `{ font, ground0, ground1, wallColor, frozenAlpha }`.
- **`RenderWeather`** (`new RenderWeather(opt?)`, RPG) — world-space weather pass driven by `Weather` (see _Weather_): a flat condition tint plus falling **rain** (`draw_line` streaks — `draw_line_width_color` renders nothing on GMRT) / drifting **snow** (`draw_rectangle` flakes), **cross-faded** by `Weather.blend()` (outgoing + incoming conditions both drawn during a change). Particles are screen-space over the view rect and animate on **`Time.raw`** (wall-clock — a visual effect, so they keep falling while the sim is paused); **no trig** (straight diagonal fall + a fixed per-particle base offset + uniform wind — `Math.sin`/`cos` are `undefined` on GMRT). Inserted **just before `RenderLighting`** so the night/light tint also darkens the rain. `opt`: `{ camera, maxParticles }`. Reads the view rect from the held `Camera`'s **own fields** (not `camera_get_view_*`; see CLAUDE.md); the scene assigns `pass.camera` after building the camera.
- **`RenderLighting`** (RPG) — world-space 2D **light-map** pass: the RPG's lighting + day/night in one. Per frame it builds an off-screen surface cleared to `WorldClock.tint()` mapped to a **multiply** model (white in daylight → night hue when dark, scaled by `opt.darkness`, default 1.5), `bm_add`s a soft radial blob (`draw_circle_color`, hue→black) for every **`Light`** + `Position` entity, then composites it over the world **multiplicatively** (`gpu_set_blendmode_ext(bm_dest_colour, bm_zero)` → `scene × light`; no `bm_multiply` constant). So **day/night is "lighting with no lights"** and point lights (the player's lantern, torches) reveal the night. **Self-balancing:** in full daylight the ambient is white, so lights clamp to white and the multiply is a no-op — the pass early-outs (zero surface work). Lights are the **`Light`** component (`scripts/Light/`, RPG — `{ radius, color, intensity?, flicker? }`); the player carries a lantern `Light` (`RpgPlayer.spawn`). **Falloff only — no shadows yet.** Inserted **last** in the RPG renderer (over tiles + entities + weather). `opt`: `{ camera, darkness }`; reads the view rect from the Camera's own fields (not `camera_get_view_*`), scene assigns `pass.camera`. The light surface is volatile (lost on resize/focus) — the pass guards `surface_exists` + recreates it on a size change.
- **`RenderDayNight`** (RPG, **currently unused** — superseded by `RenderLighting`, which absorbs day/night as its ambient term) — a cheap flat-tint day/night fallback driven by `WorldClock.tint()`: the `sh_daynight` shader (flat tint + vignette) with a plain-rectangle fallback, no-op in full daylight. Kept for reuse; reads the Camera's own fields like the other view-culling passes. `opt`: `{ camera, vignette }`.
- **`RenderDebugTileMap`** (`new RenderDebugTileMap(level, opt?)`) — overlay: cost shading, tile id/name + coordinate labels (grid lines are a separate `RenderGrid` pass). `opt`: `{ cost, tiles, coords, names, alpha, font, camera? }`. Call `level.syncAll()` first. Like `RenderGrid`, an optional **`camera`** (a `Camera` instance, settable later via `pass.camera`) culls iteration to the view rect (read from the Camera's `toX`/`toY`/`width`/`height` fields — `camera_get_view_*` returns 0 for the matrix-driven Camera; see CLAUDE.md), required for a large grid; omit for full-grid (small inspector grids).

**`VertexBuffer`** (`scripts/VertexBuffer/`) wraps GameMaker vertex buffers with a fixed `position + texcoord + colour` format: `.begin()`, `.addQuad(x,y,w,h,u0,v0,u1,v1,color?,alpha?)`, `.addQuadV(...)` (per-corner alpha), `.end(freeze?)`, `.submit(texture)`, `.destroy()`.

## UI System

The GUI layer is a **fixed design resolution** (`UI.designW`×`UI.designH` = 1920×1080) divided by the `uiScale` Setting, set via `UI.applyScale()` in `obj_game` `Create_0` — **not** `display_set_gui_maximise`. So UI lays out the same on every monitor and GameMaker scales the GUI to the window; the SDF locale fonts keep text crisp at any GUI→window ratio. The `uiScale` slider applies **live**: it calls `UI.applyScale(v)`, which resizes the GUI layer and `markDirty`s every root so they reflow. For that reflow to be clean, full-screen chrome must fill via flex rather than snapshot `display_get_gui_height()` at build — the lobby and `SystemMenu` use `gemsTabs({ grow: true })` (root + content host flex-grow) over `gemsScroll({ grow: true })`, so they re-lay-out to the new GUI size with no rebuild (fixed-size windows like the RPG inventory keep `gemsTabs({ height })`). World cursor picking uses GameMaker's `mouse_x`/`mouse_y` (camera-space, GUI-independent); the one place mixing GUI-mouse with the application surface (`cameraPan`) scales GUI→surface explicitly.

- **`UIElement`** (`scripts/UIElement/`): tree node backed by `flexpanel` (GameMaker Flexbox). `insertChild`, `removeChild`, `addComponent(c)`, `getComponent(Class)`, `getComponents(Class)`, `removeComponent(c)`. `markDirty()` propagates to root; `refresh()` calls `flexpanel_calculate_layout`.
- **`UI`** (`scripts/UI/`): static root registry. `UI.insert(root, index?, enabled?)`, `UI.remove(root)`, `UI.setEnabled(root, bool)`. `update()` traverses in reverse (highest index blocks lower); `draw()` forward.
- **`UIComponent` interface**: `{ onUpdate?(element, block), onDraw?(element), onDestroy?(element) }`. Built-ins: `UIButton`; `UIText`; `UIRichText` (markup → colored spans `[c=#hex]…[/c]` + inline icons `[spr=name]`; self-sizes like `UIText`, host stacked lines in fixed-height rows); `UIImage`; `UIPanel`; `UITrigger`; `UISlider` (always-on value readout — `format`/`showValue`); `UISelect` (`< value >` cycler); `UIDropdown` (combobox field + chevron → popup list; the popup is an injected `onOpen(dropdown, field)` so Core stays theme-agnostic — `gemsDropdown` supplies a `UIModal` one, `UINav`-navigable + scrolling); `UIInput`; `UIRebind` (key-rebind row — click to arm "press a key…", next press rebinds); `UIProgress` (0–1 fill bar); `UICheckbox` (`style:"check"` box+tick or `"switch"` pill+knob); `UITooltip` (self-detecting hover tooltip, feeds the global `Tooltip`); `UIStepper` (`< n >` over min/max/step); `UISlots` (inventory-slot grid; `draggable` opts into `SlotDrag`; immediate-mode); `UITabs` (tab strip — one focus stop, swaps content by `enabled`, no reflow); `UIAccordion` (collapsible; confirm expands); `UIScroll` (vertical scroll for a `clip` viewport — draw-time `scrollY`, never flex mutation); `UIModal` (full-screen exclusive backdrop, blocks pointer + nav, Esc/backdrop close; built by `gemsModal`); `UIDrag` (window drag handle — accumulates into `target.dragX/dragY`, offset-not-mutation); `UINineSlice` (sprite-skinned panel; source needs nine-slice in the IDE); `UIMinimap` (radar-blip view of a `World`, `rules` `[{ tag, color }]`); `UIQuestTracker` (live list bound to `QuestLog`; immediate-mode, resolves `I18n.font(key)` at draw time); `UITable` (data table — declarative columns with text/color/icon accessors, a multi-key sort stack (click a header → primary key, re-click flips), external `setFilter`, `setColumns` (remaps the sort by each column's stable `key`), identity row-selection, sticky header, row-based scroll, zebra striping. Immediate-mode over ONE element so re-sort/filter never reflows; draw geometry recomputed each `onDraw` so it stays glued to a dragged window. **Browse mode**: `navActivate` enters it, then the table owns the arrows via a per-frame `UITable.active` claim that `UINav.consume()`s. Built by `gemsTable`; public reads are METHODS (`getView`/`getRows`/`getSelected`) — an external `table.view` faults on GMRT).
- **`Tooltip`**: standalone static class (not a `UIComponent`). `Tooltip.set(str)` from anywhere; renders once per frame at mouse position via `Tooltip.draw()` in `Draw_75`.
- **`Toast`**: standalone static class (not a `UIComponent`), same pattern as `Tooltip`. `Toast.push(str, opts)` from anywhere; `Toast.draw()` in `Draw_75` (after `Tooltip`) ages the stack by `Time.raw` and renders a bottom-center timed stack (newest at bottom). `opts`: `{ duration, type ("info"|"success"|"warn"|"error"), accent }` — `type` picks the left accent-stripe color; entries fade/slide in+out and are culled when expired (`Toast.maxItems` cap drops the oldest).
- **`UIPointer`**: standalone static class (not a `UIComponent`) — the UI's frame-latched pointer state. `UIPointer.poll()` runs in `Step_0` before `UI.update` and latches the left-button edges + level + wheel once per frame into `UIPointer.pressed`/`released`/`down`/`wheel`. Every UI widget + UI-layer reader (`SlotDrag`/`BuildMode`/`DebugInspector`/`Dialogue`) reads those static fields instead of calling `mouse_check_button*`/`mouse_wheel*` directly — those are realtime-sampled on GMRT, so re-reading the same query in a frame can diverge, and a per-widget `const pressed = …` is also the cached-bool clobber pattern (see GMRT-Safe Idioms). One query/frame, shared.
- **`SlotDrag`**: standalone static class (not a `UIComponent`) backing drag-and-drop between `UISlots` grids (built with `draggable: true`). Reads the latched pointer edges from `UIPointer` (never `mouse_check_button*` directly — see the realtime-sampling note in GMRT-Safe Idioms). A grid calls `SlotDrag.begin(grid, i)` on `pressed` over a filled slot (picks it up; source slot empties, floating icon drawn in `SlotDrag.draw()` in `Draw_75`), then `SlotDrag.hover(grid, j)` each frame the cursor is over one of its slots to **record** the drop target. `SlotDrag.update()` (`Step_0`, after `UI.update`) resolves on the release edge: drop onto the last-recorded slot (swaps occupants, works across grids), or — if none was ever hovered — restore to source. The recorded target is _persisted_ (not cleared when the cursor leaves a slot), so a small drift off the slot as the button comes up still drops. (Note: `UISlots.onUpdate` keeps the hit-test in instance fields `this._inside`/`this._hover`, not boolean local consts — those get clobbered mid-function on GMRT; that was the long drag-drop bug.)
- **`VirtualKeyboard`**: standalone static class (not a `UIComponent`) — on-screen keyboard for gamepad/mouse text entry into a `UIInput`. `VirtualKeyboard.open(input)` pops a `gemsModal` (exclusive backdrop, blocks background nav, Esc/backdrop cancels) whose body is a preview line + a grid of character keys; the keys are ordinary `gemsButton`s, so the whole keyboard is `UINav`-navigable for free (dpad/stick to move, A/Enter to type). Keys edit an in-memory buffer; **Done** commits to the field (`setValue` + `onConfirm`), Cancel/Esc/backdrop discard — the field is untouched until Done. Shift toggles letter case via live key labels (no relabel). `VirtualKeyboard.isOpen()` is a **method, not a `static get`** — a static getter with a comparison body miscompiles on GMRT 0.20 (verified; see CLAUDE.md), and yielded `undefined` outright on 0.19.
- **`UINav`**: standalone static class — keyboard/gamepad menu navigation, touching neither `UI` nor `UIElement`. An element is **focusable** by duck-typing: a component implements `navActivate(element)` (confirm) and/or `navAxis(element, dir)` (horizontal adjust, `dir` = ±1). `UINav.update()` (`Step_0`, after `UI.update`) walks the enabled roots, collects focusables with a valid on-screen rect, and routes input: arrows/dpad/stick move focus to the geometrically nearest focusable in that direction (edge-aware `_pick` — the perpendicular term is the gap between rects, ties broken by collection order, so Down lands on the leftmost item below); a horizontal press over a `navAxis` widget tweaks it; Enter/Space/`gp_face1` → `navActivate`; Esc/`gp_face2` disengages. `UINav.draw()` (`Draw_75`) draws a pulsing focus ring. Collection **stops at an exclusive root** (`navExclusive() → true`, e.g. an open `UIModal`), mirroring the modal's pointer block. Focusables scrolled out of a `UIScroll` stay collectable; when focus lands on one, `_scrollIntoView` nudges each `UIScroll` ancestor so it comes into view. Engagement: the first nav input only engages + focuses; moving the mouse disengages; while a field is typed (`UIInput.active`) or a `UITable` is in browse mode (`UITable.consume()`), nav is suspended so the caret keeps the keys. `obj_game` calls `UINav.reset()` on each scene swap and seeds `UINav.color` from the theme. Nav hooks live on `UIButton`/`UICheckbox`/`UISelect`/`UIDropdown`/`UIStepper`/`UISlider`/`UITabs`/`UIAccordion`/`UITable`/`UIInput`; any new widget becomes navigable by adding `navActivate`/`navAxis` (a blocking root by adding `navExclusive`). **Debug**: hold `UINav.debugKey` (Tab) to draw every focusable boxed + numbered with direction lines from the focused element.
- **`SceneTransition`**: standalone static singleton — full-screen fade between scenes, replacing `obj_game`'s hard cut on `openScene`. `start(applyFn)` fades OUT to a solid cover, swaps the scene at full cover (`applyFn` rebuilds the UI hidden under the cover), then fades back IN. Wiring: `SceneTransition.update()` in `Step_0` (drives the timer + fires the swap at mid-fade, gated by `isBusy()`); `SceneTransition.draw()` **last** in `Draw_75` so the cover veils the UI teardown/rebuild too. Timer uses `Time.raw`.
- **`Dialogue`**: standalone static singleton — RPG paged dialogue box with typewriter reveal. `Dialogue.start(pages, opts)` (a page is a string or `{ speaker, text }`); reveals at `opts.speed` chars/sec (`Time.raw`), advances on Enter/Space/`gp_face1`/click. `Dialogue.update()` in `Step_0`, `Dialogue.draw()` in `Draw_75` (over the UI). Static fields are initialized with literals, not `Dialogue.x` self-references (the static-initializer self-reference quirk in CLAUDE.md).
- **`FloatingText`**: standalone static singleton — **world-space** floating combat numbers (damage/heal) that rise + fade. `FloatingText.push(x, y, value, opts)`; drawn from a **scene's own `draw()`** (inside the camera view), _not_ `Draw_75`. `obj_game` calls `FloatingText.clear()` on each scene swap (a number must not survive into the next scene). Ages by `Time.delta` (sim time — slow-mo slows the numbers too), unlike the GUI singletons on `Time.raw`.
- Many `flexpanel_node_style_*` setters in `UIElement` stay commented to keep the class under the 50-method ceiling (#15065); enable one on demand (see the flexpanel GMRT-Safe Idiom).

## Input System

**`Input`** / **`InputAction`**: `Input.register(key, action)`, `Input.get(key)` → `InputAction`. Query: `.down()`, `.pressed()`, `.released()`, `.value()`. Bind: `.bindButton(source, button)` / `.bindAxis(mode, axis)`. Bulk: `Input.bindAll({ key: [source, button], … })` registers a whole keymap in one call; `Input.unbindAll([keys])` removes them — used by the genre controllers. **All four query methods return falsy while a text field owns the keyboard** (`UIInput.active !== null`, via `InputAction.captured()`): typing in a UI field (e.g. the RPG inventory search) must not also drive gameplay hotkeys/movement — pressing `i` while typing "Hi" can't toggle the inventory. This is the same `UIInput.active` signal that suspends `UINav`; `UIInput` clears it on blur **and on destroy** (so tearing a focused field down at a scene change can't strand the capture).

**`InputContext`** (`scripts/InputContext/`, Core) — a named-context **stack** over the Input layer that generalizes `captured()` from "a text field mutes everything" to "the active context decides which actions are live." The active context is the top of the stack (base is always `"default"`); `push(name)`/`pop()`/`set(name)` (replace top — auto-pushes if only the base remains, so a forgotten `push` can't clobber `"default"`)/`reset()` (back to `["default"]`)/`active()`/`is(name)`. An `InputAction` may declare the contexts it is live in via `action.inContext(["play","window"])` — or, declaratively, an **optional 3rd element** in a `bindAll` spec entry (`fire: [INPUT_SOURCE.MOUSE, mb_left, ["play"]]`). The query methods then add `_blocked()` (`contexts !== null && !InputContext.allows(contexts)`) to the existing `captured()` guard. An action with **no** declared contexts (the default, `contexts === null`) is live in every context, so all existing keymaps (platformer/RTS/UI) are unaffected — only opt-in tagged actions are gated. `captured()` still wins (a focused field mutes regardless of context). Contexts/tags are **not serialized** (`Input.export`/`import` ignore them) — a controller re-applies them in `create()` each scene, so a saved/rebound keymap never loses its tags.

The **RPG scene** is the reference consumer: `RpgController.create` tags its keymap — movement live in `["play","build","window"]` (the player keeps walking with a window open), `fire` `["play"]` only (so it **self-mutes** while building — LMB places tiles — or with a gameplay window open — clicks don't shoot — replacing the old `!BuildMode.active` reach-in), `interact` `["play","window"]` (open in play, close a station window in window; inert while building), `build`/`follow` `["play","build"]`. `sceneRpg` pushes `"play"` in `create()`, resets in `destroy()`, and each `step()` (before the tick loop, so the tick's movement/fire reads see it) calls `_resolveContext()` → `InputContext.set(...)` with **window > build > play** priority (`invOpen`/`_storeOpen`/`_craftOpen` → `window`; else `_buildActive` → `build`). A window thus **pauses** build mode (`BuildMode.update` gates `active` on `InputContext.is("build")`, so LMB/RMB on the window can't place/remove tiles) and resumes it on close. The single `E` press is arbitrated in one place — `sceneRpg._dispatchInteract()`: a station window open → `E` closes it; else pick station-vs-NPC by **cursor (`Interactable.isCursorOver`), then nearest to the player**, and call `Interactable.activate(scene)` or `scene._npcActivate()`. `Interactable.update`/`_updateNpc` only do proximity/prompt/dialogue text — no input reads.

## `EntityPreset`

`EntityPreset` (`scripts/EntityPreset/`) spawns entities from named presets:

```js
EntityPreset.register([
  {
    id: "enemy",
    components: { Velocity: { x: 0, y: 0, z: 0 }, Lifetime: { ticks: 120 } },
  },
]);
const id = EntityPreset.spawn("enemy", world, x, y, z);
EntityPreset.has("enemy");
EntityPreset.get("enemy"); // → boolean / preset or undefined
```

## `Query` — Spatial Entity Lookup

`Query` (`scripts/Query/`) searches entities with `Position`:

```js
Query.nearest(world, x, y, opts); // → id or -1
Query.farthest(world, x, y, opts); // → id or -1
Query.inRect(world, x1, y1, x2, y2, opts); // → id[]
Query.inRadius(world, x, y, radius, opts); // → id[]
```

`opts`: `{ tag?, maxDist?, hasCollision? }`. `tag` filters by `Tag` component (`{ tags: Set }`).

## Utility Modules

- **`Settings`**: persists to `settings.json` (`Settings.PATH`). `registerDefaults({...})` before `load()` at startup (calls merge additively). `get(key)` falls back to defaults; `set(key, val)` updates memory; `save()` writes only keys present in defaults.
- **`Color`**: `Color.rgb(r,g,b)`, `Color.hsv(h,s,v)`, `Color.merge(c1,c2,t)`, `Color.parse("#rrggbb")` → GameMaker color ints; `Color.alpha(color)` → alpha byte `[0,1]`.
- **`I18n`**: `I18n.load(manifestPath)` reads a `manifest.json` listing text-file masks (e.g. `text/*.json`), fonts, images, sounds; flat `{ key: value }` text JSON is merged into `I18n.texts`. `I18n.text(key, ...params)` or `I18n.textRef(...)` (a `() => string` for live-updating UI labels); fonts via `I18n.font(key)`. Ships `en-US` (default, loaded in `obj_game` `Create_0`) and `ko-KR`, each declaring its own Noto Sans in its `manifest.json` (en-US `Noto Sans`, Latin-1 range; ko-KR `Noto Sans KR`; both SIL OFL 1.1, SDF). Strings are split by genre under each locale's `text/`: `common`, `platformer`, `rpg`, `rts`, `map` (the `text/*.json` mask merges them all). Fonts are keyed by role, not size: `default` (Regular 12), `header` (Bold 16), `description` (Regular 10). Both locales declare all three, so `I18n.font(...)` resolves to the bundled Noto Sans (an undeclared key still falls back to `draw_get_font()`).
- **`Camera`** / **`cameraFollow`** / **`cameraFollow2d`** / **`cameraPan`**: `Camera` wraps a `camera_*` handle (ORTHO, PERSPECTIVE, PERSPECTIVE*FOV). `cameraFollow({ world, followTarget, followLerp?, followHeight?, ... })` — 3D perspective follow; `cameraFollow2d({ world, followTarget, followLerp?, width?, height?, ... })` — 2D orthographic (pixel-snapped); `cameraPan({ ... })` — drag-to-pan + wheel-zoom orthographic camera (RTS/map scenes). All read from `world` where relevant. Call `.update()` each step and `.assign(viewIndex)` to attach to a viewport. Note: `view_camera[]` is not exposed in GMRT — hold the `Camera` instance and read the view rect from its own fields (`toX`/`toY`/`width`/`height`), **not** `camera_get_view_*` (which returns 0 for the matrix-driven Camera; see GMRT-Safe Idioms).
- **`Tween`**: static easing + frame-rate-independent smoothing helper for UI motion (pure methods; callers keep their own state). Two families: `approach`/`approachColor` (exponential smoothing toward a _moving_ target, no fixed duration — UIButton's hover/press easing) and the easing _curves_ (`easeOutCubic`/`easeInOutQuad`/…) mapping `t∈[0,1]` for _timed_ 0→1 motion (Toast/modal enter, FloatingText pop).
- **`MotionPlanner`**: static A\* on `MotionPlanningGrid`. `MotionPlanner.plan(start, goal, algorithm?, opt?)` → `{x,y}[]`. Options: `allowDiag`, `cornerCutting`, `heuristicWeight`, `maxIter`.
- **`AABB`**: world-space box geometry that owns the non-uniform `BBox`-anchor convention (see Component Pattern note). `AABB.edges(pos, box)` / `AABB.of(world, id)` → `{ x1, y1, x2, y2, cx, cy }`; `AABB.overlap(a, b)` → strict overlap (touching edges don't count). Every collision/geometry system derives edges through this, never inline `pos.x + box.x` — consumers: `SolidSystem`, `SeparationSystem`, `TriggerSystem`, `BlockSystem`, `EnemySystem`, `Raycast`, `RenderDebugEntity`. (`Query` is _not_ a consumer — it does point-vs-rect tests on `Position` only.)
- **`Broadphase`** (`scripts/Broadphase/`): Uniform-grid broadphase for O(n) physics pair queries. `new Broadphase(worldWidth, worldHeight, cellSize)` — `cellSize` must exceed entity full diameter so center-based bucketing guarantees all overlapping pairs are in adjacent cells. `clear()`, `insert(id, cx, cy)`, `pairs(fn)` (calls `fn(a, b)` per candidate pair, no duplicates). Assign to `world.broadphase` to opt `SeparationSystem` and `TriggerSystem` into the broadphase path; scenes without it fall back to O(n²). Apply selectively — crowd/RTS scenes benefit; scenes with few interacting bodies (platformer) don't need it.
- **`Raycast`**: static segment-vs-AABB cast over all collider entities. `Raycast.cast(world, x0, y0, x1, y1, opts)` → nearest hit `{ id, x, y, nx, ny, t }` or `null`. `opts`: `{ ignore?, solidOnly? (default true), mask? }`. Shared by `ProjectileSystem` (bullets) and line-of-sight queries.
- **`File`**: sync I/O. Text: `File.find(mask)` → `string[]`, `File.read(fname)` → `string|undefined` (NUL-terminates the loaded buffer so `buffer_text` can't over-read past EOF into uninitialized memory — that over-read corrupts `JSON.parse` non-deterministically, the bug that long looked like a runtime memory fault), `File.write(fname, data)` → `boolean`. Binary: `File.readBuffer(fname)` → buffer handle (caller owns it, must `buffer_delete`) or `undefined`, `File.writeBuffer(fname, buffer)` → `boolean` (saves only the _used_ bytes via `buffer_save_ext` + `buffer_get_used_size`, so a `buffer_grow` buffer's over-allocation doesn't pad the file). Use the binary path for tile grids / dense or large data — JSON text both hard-faults on nested values and has an O(n²) serialize cost for big inline arrays.
- **`Log`**: text-based behavior verification (there are no tests). `Log.info/warn/error/debug(msg)` buffer timestamped lines; `obj_game` calls `Log.clear()` at startup and `Log.flush()` once per frame (only rewrites `game.log` when dirty). Read `game.log` to confirm runtime behavior without watching the window. `Log.exception(ex)` is the unhandled-exception handler `obj_game` registers via `exception_unhandled_handler` in `Create_0` — an uncaught runtime fault is written to `game.log` (`UNHANDLED EXCEPTION: <message>`) and flushed before the runner closes the game (it returns a non-zero exit code). Without it a mid-frame crash just stops the log at its last flush with no reason recorded. GMRT populates only `ex.message` for JS runtime faults (`script`/`line`/`stacktrace` come through empty), so only the message is logged.
- **`Debug`** (`scripts/Debug/`, Core): the **back-end** of the debug system — a registry of named panels that does **not** render, so a human and an agent debug the same state through different front-ends. `Debug.panel(name, (p) => …)` populates a panel via emit closures: `p.watch(label, fn)` / `p.watch(label, obj, key)` / `p.slider` / `p.checkbox` / `p.dropdown` / `p.input` (editable scalar) / `p.button` / `p.text`. Each entry is a **live binding** — a getter fn (read-only) or an `(obj, key)` pair (read/write live); the discriminator is whether a `key` arg was passed, **not** `typeof` (a class like `Time` is itself a function, so `typeof`-routing would mis-bind and later call `Time()` — a crash). Two front-ends: (1) **text** — `Debug.update()` (in `Step_0`) periodically writes `Debug.snapshot()` to **`debug.txt`** (the agent-readable view); (2) **ImGui** — `DebugImGui` (Core), the human overlay (toggle **F3**) via `show_debug_overlay` + `dbg_view`/`dbg_*` + `ref_create`. Since `ref_create` needs a `(struct, "field")` pair but an entry is often a getter fn, each gets a plain **mirror** `{ v }`; `refresh()` syncs it each frame (pull for read-only, change-detected push for editable, so an external write like the pause `Time.scale=0` isn't clobbered by a stale slider). Agent control: `Debug.set(panel, label, value)` / `Debug.press(panel, label)` from a temp harness, then verify on the game surface. Built-in panels `Time`/`Perf`/`Log` + **`DebugRender`**'s `Render` (per-pass overlay toggles, each finding the live scene's pass by `instanceof` and flipping `enabled`) register in `obj_game` `Create_0`. `DebugImGui` rebuilds on a `Debug.version()` change into **two windows** kept independent so one's churn doesn't move the other: a stable **Debug** view (Time/Perf) and a live **Inspector** view (the `Entity` panel), the latter kept alive across picks (only its `dbg_section` is swapped — there's no `dbg_set_view` on GMRT). Each panel is an explicit `dbg_section` (else GM bleeds the first control onto an auto "Default" header).
- **`DebugInspector`** (`scripts/DebugInspector/`, Core): the ECS entity inspector over `Debug`. While the overlay is open, left-clicking a world entity (`Query.nearest` from a cursor→world unproject via the scene camera's `toX/toY/width/height`) selects it; `select(world, id)` reads `world.componentsOf(id)` and registers an **`Entity`** panel exposing every component's scalar fields — numbers/strings as editable `input`s, booleans as `checkbox`es — bound LIVE to the component data objects, so an edit (in the overlay, or `Debug.set("Entity", "Health.hp", …)`) mutates the real entity. `draw(game)` highlights the selection on the GUI layer (reprojecting its `Position`). The Entity panel stays **registered at all times** (a placeholder line when nothing is selected) so its Inspector window is present from the moment the overlay opens, like Time/Perf; Deselect or a stale selection (entity removed / scene swapped) empties it to the placeholder rather than removing it. Wired in `Step_0` (`update`) + `Draw_75` (`draw`). While the overlay is open, `InputAction._debugMuted` mutes gameplay **mouse** input (so a pick-click can't fire the weapon) and **keyboard** input only while `is_keyboard_used_debug_overlay()` (typing in a `dbg_text_input`), so WASD still roams while inspecting.
- **Utils** (`scripts/Utils/`): global helper grab-bag — `noop()`, `uuid()` → UUID v4, `rem(value)` → pixel size relative to current font size.
