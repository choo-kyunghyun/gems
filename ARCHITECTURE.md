# G.E.M.S. Architecture

Detailed architecture reference for **G.E.M.S.**, imported into context by [CLAUDE.md](CLAUDE.md) (via its `@ARCHITECTURE.md` line), so it is always loaded alongside it. See CLAUDE.md for the project overview, build & run, asset-creation workflow, code style, and the **GMRT-Safe Idioms** that always apply — those live there (kept always-in-context) and are referenced by name in code comments.

## Demo Layer — `obj_game`, `Scene` & `SceneManager`

`obj_game` is the unified controller — it drives global system ticks each event and **delegates the scene lifecycle to `SceneManager`** (held as `this.scenes`).

```
Create_0 → display/GPU setup; Log.clear/info; Settings defaults + load; I18n.load for `Settings.language`; this.scenes = new SceneManager(); scenes.start(SCENES.lobby) [the lobby is the boot scene + dev launcher; F2 returns to it] + SceneTransition.reveal()
Draw_0   → draw_clear(background), this.scenes.draw()
Step_0   → Time.update(), UIPointer.poll(), UI.update(), SlotDrag.update(), SystemMenu.update(this), UINav.update(), Dialogue.update(), this.scenes.update() [pending→SceneTransition.start + SceneTransition.update()], this.scenes.step() [skipped while SystemMenu open or Debug-paused, except a one-frame Step], Log.flush()
Draw_75  → UI.draw(), UINav.draw(), SlotDrag.draw(), Tooltip.draw(), Toast.draw(), Dialogue.draw(), SceneTransition.draw(), F5 screenshot
CleanUp  → Log.info("game end"); this.scenes.destroy() (before UI.destroy — it removes the scene's UI roots), UI/Input/I18n cleanup; Log.flush() last (Step_0's flush won't run again, so teardown logs would otherwise be lost)
Other_72 → Async - Save/Load (event-driven): completion of File.saveAsync/loadAsync — reads `async_load` `id` + `status` and calls File._resolve to fire the request's callback
Other_75 → Async - System (event-driven, not per-frame): gamepad connect/disconnect — reads `async_load` `event_type` ("gamepad discovered"/"gamepad lost") + `pad_index` and logs it
```

GameMaker's built-in per-instance events: **Create** (`Create_0`) runs once at boot; **Step** (`Step_0`) every frame (game logic); **Draw** (`Draw_0`) every frame to the `application_surface` (camera-transformed world view); **Draw GUI End** (`Draw_75`) every frame on the **GUI layer** (own resolution, not camera-transformed — so HUD / windows / overlays live here; it's the *End* sub-event because `screen_save()` is only permitted there). **Clean Up** (`CleanUp_0`) fires at game end (single room, no transitions). The two **Async events** (`Other_72` Save/Load, `Other_75` System) are event-driven, not per-frame — the runtime triggers them on a callback and passes a `ds_map` in `async_load`, read via `ds_map_find_value` (the `[? ]` accessor is GML-only). `Other_75` (System) fires on a system-level callback (here, a gamepad being plugged in or removed) and only because the project already calls `gamepad_*` functions (`UINav`/`UITable`/`SystemMenu`/`Dialogue`) — the runner skips initialising the pad subsystem otherwise. `Other_72` (Save/Load) fires on a `File.saveAsync`/`loadAsync` completion (see _Utility Modules → File_).

**`SceneManager`** (`scripts/SceneManager/SceneManager.js`, Core) owns all scene lifecycle as a **stack** of scenes (a persistent base + transient guests pushed on top), plus a queued base swap and the fade-coordinated transition. **Only the top scene is stepped + drawn**; a scene below it is *suspended* (its UI hidden, viewport released) so it keeps its full context while a guest runs in front. `current` (an instance getter over the stack top — instance getters are GMRT-safe, unlike static computed ones) + `depth()` expose the live frame. `obj_game` delegates `update()`/`step()`/`draw()`/`destroy()` to its `this.scenes` instance; `SystemMenu` reads/restarts/quits the live scene through the manager (`scenes.current`, `scenes.label()`, `scenes.restart()`, `scenes.request(factory)`). A plain instance class (one per controller), not a static singleton (GMRT static-getter quirk).

- **Base navigation** — `request(factory)` (the `openScene` callback handed to each `create()`) queues a faded swap that **collapses the whole stack** first; `_apply` resets the cross-scene singletons (`UINav`/`SystemMenu`/`Dialogue`/`FloatingText`/`ParticleFx`). The app **boots into the lobby** (`scenes.start(SCENES.lobby)`) — the dev launcher / scene catalogue, also reached via **F2** (gated by `DEV_MODE`); from it the RPG + other genres open.
- **Guest minigames** — `push(factory, { onResult })` suspends the host and runs a guest in front (no fade — an instant in-world switch); `pop()` reads the guest's optional `result()`, destroys it, resumes the host, and fires `onResult(result)`. The world-space singletons (`FloatingText`/`ParticleFx`/`Dialogue`) are cleared across both boundaries so a host's leftovers don't bleed into the guest. The reference consumer is the RPG **arcade cabinet** (an `Interaction` of kind `"arcade"` → `sceneRpg._openArcade` → `push(ScenePlatformer)`, rewarding coins from the run's `result()` score). A guest is exited with **Esc / gamepad-B** — `SystemMenu` pops it when `depth() > 1`, before falling through to the pause menu. The genre showcases (`scenePlatformer`, …) are thus reusable as embedded minigames unchanged; the host depends on a guest only via the factory it pushes.

**`Scene`** (`scripts/Scene/Scene.js`) is the base class for all demo scenes (`label`, `create()`, `step()`, `draw()`, `destroy()`, plus the stack hooks `suspend()`/`resume()`). Scenes are **factory functions** returning a fresh instance each time they open. `create(openScene)` receives the navigation callback (`SceneManager.request`); the manager also sets `scene.manager` (the back-ref a host uses to `push` guests). `destroy()` tears down UI and resources. **`suspend()`/`resume()`** pause/restore a scene while a guest runs in front — the defaults hide the single UI root + re-claim viewport 0; a host with extra state overrides them (the RPG re-binds its keymap on `resume`, since a guest controller's `destroy` unbinds shared action names like `moveLeft`/`moveRight`). GMRT doesn't reliably inherit non-overridden methods, so a host defines its own hooks rather than relying on the base default.

**Scene navigation**: call `openScene(factory)` to queue a base transition (applied after the current UI update completes). The only **built-in scene** (`scripts/sceneLobby/sceneLobby.js`) is `SCENES.lobby` — the merged **title + lobby**, the **boot scene** + dev launcher (also reached via **F2**): a G.E.M.S. header, a **tabbed** scene catalogue (registry categories grouped into RPG / Showcase tabs), and a footer of global actions (Settings → SystemMenu, Credits → SystemMenu's About tab, Quit). There is no separate title or credits scene; Settings/Pause are the **`SystemMenu`** overlay, not scenes (see Genre UI managers below).

**`SceneRegistry`** (`scripts/demo/demo.js`) is the lobby catalogue. Register at the top level of a scene's script:

```js
SceneRegistry.add(() => new MyScene(), {
  label: "My Scene",
  category: "SCENE_CAT_FOO",
});

class MyScene extends Scene {
  label = "My Scene";
  create(openScene) {
    /* build UI; openScene(SCENES.lobby) to go back */
  }
  destroy() {
    /* remove UI, clean up */
  }
}
```

`SceneRegistry.byCategory()` returns entries grouped by category string. To add a scene: create the script asset (see Asset Creation), define the class, then `SceneRegistry.add(...)`.

**GemsUI kit** (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`): a themed factory library so scenes build UI declaratively instead of hand-wiring `UIElement`/`UIPanel`/`UIText`. Factories are assigned via `globalThis.X = function X(…)` and split across small files (large-file global-hoisting fault). All visual constants live in **`GemsTheme`** (colors as hex, geometry as numbers); the `gems*` functions parse + compose them.

- **Containers**: `gemsRoot` (full-screen scene root), `gemsList` (vertical stack), `gemsGrid` (horizontal wrap row), `gemsPanel`/`gemsCard` (rounded panel; card adds gradient+border+shadow), `gemsHeader` (title bar), `gemsSection` (titled card with divider), `gemsRow(label, control)`, `gemsDivider`, `gemsCatBar(categories, opts?)` (a bar of category buttons; clicking one toggles a pop-up flyout of its items above the bar — one open at a time; selecting an item highlights it + fires `onSelect`. Driven by structural insert/remove, not flex mutation; `root.catbar` exposes `open/close/select`. Shared by the RPG build-mode HUD + level-editor palette), `gemsWindow(title, opts?)` (a centered, **draggable + resizable** floating window — title bar with `UIDrag` + optional close, a `body` callers fill. Resizable by default via a bottom-right `UIResize` grip clamped to `opts.minWidth`/`opts.minHeight` (opt out with `resizable:false`); the card + body flex-grow so content fills the resized frame. Pass `opts.height` for a fixed starting size when the content itself flex-grows (a grow `gemsTabs`/`gemsTable`), else the window opens content-sized and fixes its size on first resize. Size is within-session only — not persisted. Used by the RPG inventory + `StorageUI`).
- **Widgets**: `gemsLabel`, `gemsHint` (one-line help on a readable card, for overlays over a scene's render), `gemsKeyHints(entries, opts?)` (a **live, context-aware key-bind hint bar** — replaces a hardcoded "WASD: Move · …" string. Each entry `{ label, contexts?, actions? | text? }` shows an action's i18n name next to its CURRENT binding, read **live** from `Input.get(action).label()` each frame — so a future key remap updates the hint with zero wiring — or a literal `text` key for non-rebindable hints (raw build-mode `LMB`/`RMB`, `Esc`). `contexts` gates an entry to the matching `InputContext`, so the bar swaps its hints as the scene changes context (play / build / window). Multi-key `actions` join to "WASD" when single-glyph else "Up/Left/…". Built on `gemsLabel`), `gemsButton(label, onClick, opts?)` (`opts.primary` accent CTA; `opts.disabled` a bool **or live `() => bool`** evaluated each frame; `opts.selected` a live `() => bool` tints toward the accent for an active toggle/palette button — hover/press win on top), `gemsIconButton`, `gemsToggle` (renders `label: ON/OFF`), `gemsCheckbox` (`opts.style` `"check"`/`"switch"`), `gemsProgress` (non-interactive 0–1 bar), `gemsSlider`/`gemsSelect`/`gemsDropdown` (Settings-bound) + `gemsSelectCustom`/`gemsDropdownCustom` (caller-driven; the `*Dropdown*` pair opens a navigable popup list rather than cycling in place — the fit for many options like resolutions/locales, scrolls past `opts.maxVisible`), `gemsTable(columns, opts?)` (a sortable/filterable `UITable` sized to `opts.rows` whole rows, or `opts.grow` to flex-fill the parent's height — `UITable` then reflows its visible-row count to the live layout height, so a table in a resizable `gemsWindow` shows more/fewer rows as it resizes; reach the component via `el.getComponent(UITable)`).
- **Tooltips**: `gemsTooltip(element, label, opts?)` attaches a hover `UITooltip`; every interactive factory also takes `opts.tooltip` (string or `() => string`).

`label`/`onText`/`offText` accept a string or `() => string` (live `I18n.textRef`); color opts accept a `GemsTheme` key, hex string, or color int. Styling lives in `GemsTheme` + **`UIPanel`** options: `color2` (edge tint; `draw_roundrect`'s two colors run center→edge/radial), `border`/`borderColor`, soft multi-pass `shadow`/`shadowColor`/`shadowAlpha`, `highlight`/`highlightColor`/`highlightAlpha` (inner top-bevel sheen) — all default off. `UIButton` eases color/glow/shadow between hover/press on `Time.raw`; `UISlider`/`UISelect`/`UIProgress`/`UICheckbox` render directly in `onDraw` (`UISelect` shows `< value >` arrows, steps by click side). **`teardownScene(scene)`** releases the `world`/`renderer`/`camera`/`ui` a scene holds on `this`, in dependency order (missing fields skipped) — call from `destroy()` after releasing scene-specific resources (controllers, levels).

## ECS Core — `World`

`World` (`scripts/World/World.js`) is the instance-based ECS core, owning all component storage and the generational ID allocator. Each scene holds its own as `this.world` (there is no `WORLD` global). **`Entity` is deprecated** — its functionality moved to `World`.

```js
const world = new World(maxEntities, tickrate, opts); // opts: { gravity? } overrides GravitySystem.strength

// Entity lifecycle
const id = world.create(); // allocate generational ID
world.remove(id); // mark for removal (deferred)
world.flush(); // commit queued removals
world.isValid(id); // generational validity check

// Component storage
world.register(Position); // allocate storage (optional; add auto-registers)
world.add(id, Position, { x: 0, y: 0, z: 0 }); // set data
world.get(Position, id); // → data object or undefined
world.detach(id, Position); // remove one component

world.query(Position, Velocity); // → ids that have ALL listed components
world.forEach([Position, Velocity], fn); // calls fn(id) per match, no id array allocated

// Fixed-rate tick
const ticks = world.update(); // # ticks to run this frame; advances accumulator, computes alpha
world.alpha; // [0, 1) interpolation factor for rendering
world.maxTicks; // tick cap per frame (default 5) — spiral-of-death guard:
// under overload the sim slows instead of freezing

// Snapshot
world.export(); // plain object, components keyed by string token, sparse entries
world.import(s); // restores ids + registered components; unknown keys ignored
world.componentsOf(id); // { token: data } of every component this entity has
```

## `EntitySnapshot`

`EntitySnapshot` (`scripts/EntitySnapshot/`, Core) is the single-entity serialize/migrate primitive — the counterpart to `World.export` for one entity. `capture(world, id, components?)` → `{ components: { token: data } }` (a component-token subset, or all via `world.componentsOf`); `apply(world, id, snapshot)` adds those components onto an **existing** entity; `restore(world, snapshot, overrides?)` `world.create`s a fresh entity, applies the snapshot, then applies `overrides` (e.g. a new `Position`/zeroed `Velocity`). Data objects are **referenced, not deep-copied** — a captured component re-attaches by reference. The player-sheet carry uses this across a portal: capture the sheet from the outgoing player and `apply` it onto the target world's player. With the map pool the outgoing world is kept **alive** (parked), so those sheet objects are briefly shared between the parked player and the active one (harmless while the source is dormant; re-synced on return); when a parked world is instead freed (chunk un/load, cold eviction) the objects survive its `world.destroy()` since only the storage map is dropped. It's the substrate for migrating an entity between Worlds (the RPG party crossing a portal — see `RpgMap.go`/`resume`) and the seed for disk saves + chunk streaming (a chunk un/load is the same capture/restore over a region's entities). Serialize the record yourself for disk (mind the `JSON` nested-value fault + `Set` fields).

## `IdPool`

`IdPool` (`scripts/IdPool/IdPool.js`) is the generational ID allocator owned by `World` as `world.ids`. IDs encode index (lower 20 bits) + generation (upper 12 bits). Static helpers: `IdPool.getIndex(id)`, `IdPool.makeId(index, gen)`, `IdPool.getGeneration(id)`. Instance methods (`world.ids.*`): `alloc()`, `free(id)`, `isValid(id)`, `reset()`, `export()`, `import()`.

## Component Pattern

Components are **string tokens** — a global name used as a `Map` key and for serialization. Data shape is defined at the call site; there are no static arrays, `defineComponent`, or static component classes (all deprecated).

```js
globalThis.Position = "Position";
/** @typedef {Object} Position @property {number} x @property {number} y @property {number} z */
// usage: world.add(id, Position, { x, y, z })
```

## System Pattern

Systems are **plain objects** with an `update(world)` method:

```js
globalThis.MovementSystem = {
  update(world) {
    for (const id of world.query(Position, Velocity)) {
      const pos = world.get(Position, id);
      const vel = world.get(Velocity, id);
      pos.x += vel.x * world.tickDuration;
      pos.y += vel.y * world.tickDuration;
    }
  },
};
```

On-demand utility systems (e.g. cursor methods on `PathfindingSystem`) expose named methods instead of `update(world)`.

## Fixed-Rate Simulation (ECS Scene Pattern)

Scenes running an ECS simulation dispatch systems explicitly inside `step()`:

```js
step() {
  const ticks = this.world.update();
  for (let t = 0; t < ticks; t++) {
    InterpolationSystem.snapshot(this.world); // first: record pre-move positions for render lerp
    GravitySystem.update(this.world);
    SolidSystem.update(this.world);       // integrates + resolves solid bodies
    SeparationSystem.update(this.world);  // pushes overlapping bodies apart
    StateSystem.update(this.world);
    LifetimeSystem.update(this.world);
    this.world.flush();
  }
}
draw() { this.renderer.draw(this.world); }
```

Genre scenes compose these into a **`Pipeline`** (`scripts/Pipeline/`): `this.physics = new Pipeline().add(SystemA).add(stepFn)`, then `this.physics.update(world)` each tick. A step is any `{ update(world) }` object or a bare function. Per genre: platformer `Gravity → clampFall → SolidSystem`; top-down/RPG `SolidSystem → SeparationSystem → ProjectileSystem` (separation unstacks crowding slimes/followers, equal-mass push-apart).

**Motion integrators are exclusive per body**: `MovementSystem` integrates _free_ movers (no collision response), `SolidSystem` is move-and-collide for solid bodies, `ProjectileSystem` is move-and-raycast for projectiles. A given mover is integrated by exactly one of them.

**`Time`** (`scripts/Time/Time.js`): `Time.delta` (scaled seconds), `Time.raw` (wall-clock), `Time.scale` (time dilation). Updated by `obj_game` in `Step_0` before `scene.step()` — always available in scene code.

## Genre Controllers & Template Gameplay Systems

The Core systems above are genre-agnostic. A playable genre scene layers a **controller** plus **gameplay systems** on top — these live under the merged top-level **Demo** folder (the `Platformer` minigame in `Demo/Platformer`; the action-RPG in `Demo/Scene` alongside the shared RPG layer) and are orchestrated by the scene's `step()`, not auto-run by `World`.

**Genre controllers** (`PlatformerController`, `RpgController`) own player input registration + entity setup and expose a three-phase lifecycle, not an `update(world)`. **`RpgController`** (the RPG genre) spawns its player via **`RpgPlayer`** (`scripts/RpgPlayer/`, Demo): `RpgPlayer.spawn(world, spawn, { bbox, dir, speed })` builds the RPG player entity (transform + `Collision` + `Health`/`Stats`/`Inventory`/`Equipment`/`Encumbrance`/`Visual`) and `RpgPlayer.fireBullet(world, shooterId, { damage, penetration?, pierce?, range, muzzleY?, nx?, ny? })` fires an instant **hitscan** shot (`Combat.hitscan` — no projectile entity) and returns the normalized aim `{ nx, ny }`. **`PlatformerController`** is a movement showcase — it builds a plain player itself (transform + `Collision` + `Direction`/`Grounded`/`Visual`, **no** RPG components) and has no firing. Each controller then adds its genre-only bits (platformer `Grounded`, top-down `Animator`) and its own movement.

- `create(world, spawn)` — registers the keymap (`Input.bindAll`), spawns the player (the RPG scene via `RpgPlayer.spawn` + genre components; platformer builds a plain entity), returns a plain `ctrl` state bag (`{ id, facing, ... }`). Firing is **hitscan** (`Combat.hitscan`, see _Combat & stats_) — there is no bullet entity or `EntityPreset`.
- `pollInput(ctrl)` — call **once per frame, before `world.update()`**, outside the tick loop. Samples _edge-triggered_ input (jump `pressed()`/`released()`) into buffers so presses aren't lost on 0-tick frames or double-counted on multi-tick frames.
- `update(world, ctrl)` — call **once per physics tick**. Reads _continuous_ input (movement) and applies acceleration/jump to `Velocity` (before `SolidSystem` integrates it).
- `destroy()` — unregisters input. Plus genre verbs like `respawn`.

Read flags like `Grounded.isGrounded` live off the component each use (boolean-local clobber idiom).

**Template gameplay systems** are stateless `globalThis` objects like Core systems but expose _named query/resolve methods_ (not `update(world)`), called from `step()` after physics resolves: `EnemySystem` (`update` patrol + `resolveStomp` jump-kill + `resolveTouch` side-hit) and `CollectibleSystem` (`hitSpike`). They read `col.hits` (filled by `TriggerSystem`) or do their own overlap test, and return values the scene applies to player state. (Platformer-only; the RPG combat/loot systems live in the RPG layer.)

`scenePlatformer` (a movement showcase, no RPG) is a compact reference orchestration: per tick → `snapshot` → `controller.update` → `physics` Pipeline (`Gravity → clampFall → SolidSystem → TriggerSystem`) → `EnemySystem.update` → `resolveStomp` (bounce the player on a kill) else `resolveTouch`/`hitSpike` → respawn → void-fall respawn → `flush`. One open hand-built level.

**Lobby categories** are `SCENE_CAT_*` i18n keys: `ACTION`, `RPG`, `STRATEGY`, `EDITOR`, `UI`. `SceneRegistry.add(factory, { label, category })` slots a scene under one.

## Gameplay Kit

The **`Gameplay`** pillar is the reusable, genre-agnostic gameplay kit between `Core` and `Demo` — the systems a second genre reuses unchanged. The placement rule across the four pillars (`Core` / `Gameplay` / `GemsUI` / `Demo`): references only engine concepts → **Core**; imposes a gameplay model but names **no** specific content → **Gameplay**; names specific content/scenes/`Rpg*` → **Demo**. Every kit module depends only on `Core` + sibling kit modules — **never on `Demo`** (so the demo could be deleted and the kit still builds; this is exactly why `Downed` is in `Combat`, since `FollowerSystem` reads it, while `Portal` stays in `Demo`, since only `RpgMap`/`RpgSpawn` do).

Grouped by **feature module** (component + system colocated, unlike Core's type-split):

- **`Combat`** — the shared damage applier `Combat.applyDamage` (over an injectable `Combat.mitigate` hook), plus `Health`, `Stamina`(+`StaminaSystem`), `Faction`(+`FactionSystem`), `Mortal` + `Downed`, `Projectile`(+`ProjectileSystem`), `MeleeSystem`. Every path lands hp through `Combat.applyDamage`, which subtracts after `mitigate` (default identity — the kit stays stat-agnostic; a game injects its formula, the RPG a `Stats.defense` one). The attack side (weapon + attacker stat) is composed by the consumer. All paths only SUBTRACT hp; the reaction at ≤0 hp is the `Mortal` death pass (see _Death_).
- **`Items`** — the `Item` + `Rarity` registries and the per-item capability components (`Weapon`, `Consumable`(+`ConsumableSystem`), `Container`). "Kinds of item" are a flat `Item` carrying a `components: []` queried by `instanceof` (composition over inheritance — GMRT can't `super`).
- **`Inventory`** — `Inventory`(+`InventorySystem`), `ItemDrop`, `Encumbrance`(+`EncumbranceSystem`).
- **`Equipment`** — `Equipment`(+`EquipmentSystem`), `Equippable`, `AppearanceSystem` (rebuilds the Core `Appearance` paper-doll layer stack from worn gear — see _Gameplay / RPG Layer → Paper-doll appearance_).
- **`Animation`** — `Animator`, `AnimationSystem`, `RenderDebugAnimator` (a data-driven sprite state machine).
- **`Lighting`** — `Light` + `RenderLighting`. The day/night ambient is **injected**: `RenderLighting` takes `opt.ambient: () => { color, alpha }` (default full daylight = inert, early-outs), so the pass carries no day/night opinion; the demo wires `WorldClock.tint` in `RpgMap.build`.
- **`Quest`** — `QuestLog` (quest defs + progress; the Core `UIQuestTracker` widget binds to it via an injected source, so Core never references the kit).
- **`Crafting`** — `CraftSystem` + `Recipe`.
- **`Party`** — `Follower`(+`FollowerSystem`) (companion follow/wait + carry bonus).
- **`NPC`** — the `NPC` dialogue-character component (pairs with Core's `Dialogue` singleton).
- **`Status`** — the buff/debuff layer: `Status` (def registry) + `StatusEffects` (component) + `StatusSystem`. Stat-model-agnostic: a `mods`-bearing status folds into the derived sheet via an **injected** `StatusSystem.onStatsChanged` hook (the demo wires `StatModel.recompute`), mirroring `Combat.mitigate`. See _Gameplay / RPG Layer → Buffs & statuses_.
- **`Survival`** — the needs layer: `Thirst`/`Hunger`/`Drowsiness` components, their per-need systems (`ThirstSystem`/`HungerSystem`/`DrowsinessSystem`) over a shared `Survival` core. A need is a "rising meter" that, at its `critical` threshold, applies a debuff **`Status`** (depends on the `Status` sibling module); restored by drinking/eating/sleeping. See _Gameplay / RPG Layer → Survival needs_.
- **`Interaction`** — the "walk near + press E to do something" layer: the `Interaction` component (`{ kind, ...params }`, marks an entity interactable) + the **`InteractAction`** registry (`register([{ id, prompt, run(ctx) }])`, mirrors `Item`/`Status`/`Prefab`). The `kind` names a registered action; `run(ctx)` does anything — open a UI window, feed/hydrate/buff the player, claim a zone — so the mechanism is data, not a hardcoded switch. Genre-agnostic: the registry holds no concrete actions (the RPG registers its set in `RpgInteractions`), and the generic pick/prompt/dispatch **engine** is Demo/UI `Interactable` (it reads Demo windows, so it stays in Demo). Replaces the old Core `Station` component. See _Gameplay / RPG Layer → Interactions_.
- **`Trade`** — the merchant layer: `Merchant` (a trade-config component that pairs with the entity's own `Inventory` = its stock) + `TradeSystem` (price/buy/sell/restock). Currency-agnostic: the money is the `Merchant.currencyId` item (a fungible the buyer carries), so the kit names no specific currency. Two modes by a `Merchant.infinite` flag — **infinite** (bottomless stock + wallet; buying never depletes, selling discards) or **finite** (real stock + a `credits` wallet that gates buying your goods, with `TradeSystem.update` restocking toward a `template` every `restockSecs`). Prices: `marketValue = round(Rarity.modify(rarity, value))`, buy `= ceil(market·buyMargin)`, sell `= floor(market·sellMargin)`. The demo opens **`TradeUI`** (Demo) on a merchant NPC — the kit↔Demo split mirrors `Crafting`/`CraftingUI`. See _Gameplay / RPG Layer → Genre UI managers → TradeUI_.

The per-module **behavior** is documented in detail in _Gameplay / RPG Layer_ below (the RPG scene is the reference consumer); this section is the membership + the kit→Core dependency contract.

## Gameplay / RPG Layer

The **RPG** scene (`sceneRpg`) is the action-RPG (the platformer is a movement showcase with no RPG layer). The pieces below split across two pillars — the genre-agnostic modules in the **`Gameplay` kit** (`Combat`/`Items`/`Inventory`/`Equipment`/`Animation`/`Lighting`/`Quest`/`Crafting`/`Party`/`NPC`/`Status`/`Survival`/`Trade`; see _Gameplay Kit_), and the content/model-specific glue in **`Demo`** (`Stats`, all `Rpg*`, `CombatAI`, the `WorldClock`/`Weather`/`Temperature` world-sim, build mode) — and are driven explicitly from the scene's `step()`, never auto-run by `World`. The design constraint throughout is **composition over inheritance** (GMRT can't do `super`/subclassing): "kinds of item" are a flat `Item` carrying a `components: []` array of standalone capability/marker classes queried by `instanceof` — exactly the `UIElement.getComponent` pattern.

**Items & registry.** `Item` (`scripts/Item/`) is a definition registry (`Item.register([...])`, `Item.get(id)`), like `Rarity`. A definition is identity + universal scalars (`name` i18n key, `sprite`, `stack`, `weight`, `value`, `rarity`) plus `components` — capability/marker instances attached via `addComponent` and read via `getComponent(Class)`/`hasComponent(Class)`. **Definition vs instance** (`item.isInstanced()` → has `Equippable`): a *fungible* item (potions/materials/currency) is a shared definition with stacking `qty`; an *instance* (all equippable gear) is unique — an `Inventory` slot of `{ itemId, qty:1, uid, mods }` (a gun instance also carries `ammo`/`rounds`) carrying **per-instance state inline** (a minted `uid` + a named-slot **attachment map** `mods` — plus, for a gun, the loaded `ammo` itemId + magazine `rounds`), so two `wood_sword`s can differ and `Equipment`/drops/etc. reference the specific one by `uid` (see _Inventory & equipment_):

- `Equippable` (`{ slot, mods, worn? }`) — wearable in an `Equipment` slot (`weapon`/`armor`/`trinket`/`backpack`); `mods` are flat `Stats` deltas folded onto the wearer's attribute-derived base by `StatModel.recompute` while worn. `worn` (a sprite NAME, default `""` = invisible) is the item's paper-doll overlay sheet, shown on the wearer while equipped (see _Paper-doll appearance_).
- `Weapon` (`{ slots, fireCd?, damage?, reach? }`) — the **universal** weapon profile that **fully drives the action** (the controller hardcodes no built-in attack): the named, typed attachment **`slots`** (`[{ id, accepts }]`, the unified slot model — `accepts` is an attachment category or `"*"`), the melee numbers (`damage`/`reach`), and the shared cadence `fireCd`. **Melee vs gun is decided by a sibling `Gun` component, NOT a flag** — an item that also carries `Gun` (`item.hasComponent(Gun)`) is ammo-driven ranged (`composeWeapon`'s gun branch); else it's melee (`MeleeSystem` swings a `reach`-px hitbox in the facing dir). The **`RpgController`** reads the equipped profile (or, when unarmed, a weak melee **fist** fallback — a pre-composed melee profile `ctrl.fist`, so being unarmed never fires a free bullet) and runs whatever it describes. The player spawns with a `wood_sword` (melee; slots `edge`/`pommel`) equipped (`sceneRpg.create`).
- `Gun` (`{ caliber, magazine, ops }`) — presence ⇒ the weapon is an **ammo-driven gun**. It fires the **loaded `Ammo`'s base stats** run through an OPERATOR pipeline: ammo base → the gun-base `ops` layer → each installed attachment's `ops` (`EquipmentSystem.composeWeapon`/`_applyOps`: `final = (base + Σadd)·Πmul` per field). `caliber` gates which `Ammo` chambers; `magazine` is the base clip. The composed **power is kinetic** — `power = ammoPower + KIN_K·mass·(velocity/KIN_REF)²` (fast/heavy rounds hit harder) **+ the wielder's `Stats.attack`**; the round's **`penetration`** rides the shot and lowers target defense at the hit. Ammo is **consumed** per shot from the magazine; **R** (or auto-on-empty) reloads from the bag (`EquipmentSystem.reload`/`loadAmmo`, + the `*Slot` variants the panel uses). The HUD shows `rounds/magazine`. (`KIN_K`/`KIN_REF` are tunable constants on `EquipmentSystem`.)
- `Ammo` (`{ caliber, mass, velocity, power, penetration }`) — a fungible round; its four stats are the BASE of a gun's firing pipeline (mass + velocity → kinetic power; `penetration` vs defense). `velocity` also scales the hitscan **reach** (the shot is instant — no travel time). Three demo rounds — `ammo_light` (fast/low-pen), `ammo_heavy` (slow/punchy), `ammo_ap` (armor-piercing), all `caliber:"standard"`.
- `WeaponMod` (`{ slot, ops, stat }`) — marks a (fungible) `Item` as an installable **attachment**. `slot` is the category it fits (matched vs a weapon slot's `accepts`); `ops` are per-field **operators** (`{ field: { add?, mul? } }`) over the composed profile (gun: velocity/mass/power/penetration/fireCd/magazine; melee: damage/reach/fireCd); `stat` deltas fold into the wearer's derived `Stats` (`StatModel._foldInstanceMods`). A weapon instance's `mods` is a **map** `{ slotId → attachmentItemId }`; installed/removed into a matching named slot at a **workbench with the Toolkit module slotted** (the `WeaponModUI` panel). The consumed item *is* the definition (no parallel registry); an op on a field the weapon doesn't expose is inert. Demo set: gun attachments `mod_scope`/`mod_long_barrel`/`mod_extended_mag`/`mod_grip`/`mod_suppressor`, melee `mod_sharp` (edge) / `mod_heavy` (pommel).
- `WorkbenchModule` (`{ kind }`) — marks a (fungible) `Item` as a **workbench upgrade** slotted into a bench's single module slot (`Interaction.module`). Rather than a station per category, one bench is upgraded by swapping modules (removable freely). `kind:"recipes"` (default) unlocks the recipes that declare `requires: <this itemId>` (base recipes — no `requires` — are always available); `kind:"weaponmod"` (the **Toolkit**) switches the bench window into the weapon-mod panel. The four demo modules (`forge`/`alembic`/`hearth`/`toolkit`) are crafted at the **bare** bench, so the bench bootstraps its own upgrades. See _Genre UI managers → CraftingUI_.
- `Consumable` (`{ heal }`) — usable from the bag (one unit consumed for an instant effect).
- `Container` (`{ capacity }`) — while equipped, grows the wearer's `Inventory.capacity` (e.g. a backpack pairs `Equippable` + `Container`).

`Rarity` (`scripts/Rarity/`) is a parallel registry of tiers (`{ id, name, color, valueMod }`); rarity color drives loot/inventory tinting. **`RpgContent`** (`scripts/RpgContent/`, Demo) registers **all** shared RPG content — the rarity tiers, the **full item set** (consumables, weapons `wood_sword` (melee) + `blaster` (ammo-driven **gun**), the **`Ammo`** rounds (`ammo_light`/`ammo_heavy`/`ammo_ap`), armor/trinket/backpack, currency `coin`/`gem`/`key`, crafting materials, the `mod_*` **`WeaponMod`** attachment items, the `forge`/`alembic`/`hearth`/`toolkit` **`WorkbenchModule`** items), and the workbench recipes (base + per-module, gated by `Recipe.requires` — the Forge module crafts the gun, ammo, and attachments). The RPG scene's own content is **`RpgQuests`** — its quests + achievements. `sceneRpg` calls `RpgContent.register()` once from `create()` (via `RpgQuests.register()`, which calls it first), **not** at top level, to dodge GMRT load-order issues.

**Inventory & equipment (pure systems over components).** Components are string tokens; their systems take the component (or `world` + entity id) directly, with no world tick:

- `Inventory` = `{ slots: [{ itemId, qty }], capacity, maxWeight? }` (an *instance* slot adds `uid` + `mods`; see the definition-vs-instance split above) — every player, enemy (its loot table), and storage chest owns one. `InventorySystem` (`add`/`remove`/`has`/`weight`) stacks fungibles per `Item.stack`; an **instanced** item never stacks — `add` mints one slot per unit with a fresh `uid` + an empty `mods` **map** (a gun's `ammo`/`rounds` are added lazily by the firing path), `addSlot` re-inserts a pre-existing instance preserving its `uid`/`mods` (transfer/drop), and `findByUid`/`removeByUid` reach a specific one. `sort` keeps instance slots individual (only fungible stacks merge). `add` is gated first by `maxWeight` then by `capacity`, returning the amount that did **not** fit.
- `Equipment` = `{ slots: { weapon, armor, trinket, backpack } }` of **instance `uid` strings** (the equipped item is unique — two of one itemId may differ by mods, so an itemId can't say "which one"; flat → `world.export`-safe). `EquipmentSystem.equip(world,id,uid)` (or `equipFirst(...,itemId)` for the itemId-keyed entry points — the starting-gear seed + the hotbar) keeps the item in the `Inventory` (it still counts toward capacity/weight) and **re-derives the wearer's `Stats` from source** via `StatModel.recompute` (which folds every equipped instance's `Equippable.mods` **+ installed `WeaponMod.stat`** onto the attribute base — so there's no +/- delta to keep balanced; a re-derive can't drift). A `Container.capacity` bonus stays a direct `Inventory.capacity` delta. `EquipmentSystem.weaponSlot`/`weaponProfile` resolve the equipped weapon `uid` → instance slot and return a **fresh composed profile** via `composeWeapon` (a melee weapon's damage/reach numbers, or a gun's ammo-driven kinetic profile + clip), or `null` when unarmed → the controller falls back to its `ctrl.fist`.
- `ConsumableSystem.use` applies a `Consumable`'s effect and removes one unit; it refuses to waste an item that would do nothing (e.g. healing at full HP). A `Consumable` carries three independent effects: `heal` (HP, clamped to `Stats.maxHp`), a **permanent attribute grant** `{ attr, amount }` (the `*_shard` items) applied through the **injected `ConsumableSystem.grantAttr` hook**, and a **status grant** `status` (a `Status` id, e.g. the Tonic→`regen` / Elixir→`fortify` items) applied via `StatusSystem.apply` — kit default no-ops, the Demo wires the `Attributes`+`StatModel.recompute` policy in `sceneRpg.create` (the same injection idiom as `Combat.mitigate`, keeping the `Gameplay/Items` kit free of the Demo stat model).
- `Encumbrance` (`{ threshold, minScale }`) + `EncumbranceSystem.scale(world, id)` → a speed multiplier from carried weight. The **penalty is delivered through the Buff/Status system**, not by the mover directly: `EncumbranceSystem.update` maintains an `"encumbered"` status (`StatusSystem.maintain`) whose live `{ speed }` mult is this gradient, and the mover reads `StatusSystem.scale(world, id, "speed")` — so encumbrance composes with any other speed status and shows in the HUD. This module still owns the weight→penalty mechanic (the gradient + the on/off decision); only how the slow reaches the entity moved to the status layer. See _Buffs & statuses_ below.

**Combat & stats.** `Health` = `{ hp }`; `Stats` = the session-scoped character sheet — `maxHp`/`attack`/`defense`/`speed`/`maxStamina`, all **derived from `Attributes`** (see _Attributes & derivation_ below). There is **no `level`/`xp`**: the RPG is deliberately **item- + skill-driven, not playtime-driven** — permanent power comes from equipment and attribute-granting consumables, never an XP grind. `MeleeSystem.swing(world, attackerId, dirX, dirY, reach, damage)` resolves a melee hit immediately (no projectile): an AABB hitbox extends `reach` in the facing **direction** (snapped to the dominant axis → 4-way) and damages every body with `Health` **except the attacker** and its faction allies (the slimes — player excluded; NPCs/furniture carry no `Health`), returning the struck ids. Ranged attacks (player guns + turrets) are **instant hitscan** via **`Combat.hitscan(world, x0, y0, x1, y1, { owner, damage, penetration?, pierce? })`** (`Gameplay/Combat`): it casts the shot with **`Raycast.castAll`** and walks every solid body along the ray in order — each hostile `Health` takes `damage` (with the round's `penetration`, default 0), the shot **passing through up to `pierce` of them** (default 1 = single target; a future sniper sets it higher) until a wall or a `FactionSystem`-allied body **blocks** it (an ally just eats the shot like a wall) — and returns the impact endpoint (for a tracer) + the struck ids. (The travel-time `Projectile`/`ProjectileSystem` path is **retained** in the kit for lobbed/grenade projectiles — it's simply no longer how guns fire; it despawned its bullet on first impact too, so hitscan with `pierce:1` is behaviorally identical.) All three paths land damage through the shared **`Combat.applyDamage(world, target, amount, penetration?)`** (`Gameplay/Combat`): the kit applier subtracts hp after an **injected `Combat.mitigate(world, target, amount, penetration)`** (default identity; `sceneRpg.create` sets it to `max(1, amount − max(0, defense − penetration))`), so defense, armor penetration, and a min-1 floor apply uniformly while the kit stays stat-agnostic — the *attack* side (`weaponPower + attacker.Stats.attack`) is composed by the callers (`RpgController` for the player, `CombatAI._attackPower` for a monster, whose weapon part is 0; melee/turret callers pass penetration 0). **Every combatant carries a `Stats` sheet** (slime/turret/follower, not just the player), so damage is genuinely stat-driven for all actors. The paths only **SUBTRACT** hp — the reaction at ≤ 0 hp is decided centrally by the `Mortal` death pass (see _Death_ below). `Combat.hitscan` lives in the `Gameplay/Combat` kit (not Core) because it needs `Health`/`Faction`; both `RpgController` (the player) and `CombatAI` (turrets) call it (the retained `ProjectileSystem` lives there for the same reason). **`CombatAI`** (Demo) is the one AI for every non-player combatant — `CombatAI.attach(world, id, level, opt?)` wires an Idle→Chase→Attack machine via `StateSystem` onto a flat `Brain` whose `mobile` + `ranged` flags pick the behavior: a **slime** is `mobile` melee (the default) — a dynamic solid body `SolidSystem` integrates + collides for free; a **turret** is `{ mobile:false, ranged:true }` — an immovable, player-faction actor that stands and fires a hitscan shot, replacing the old per-kind `SlimeAI` + `Turret`/`TurretSystem`. The `Brain` holds `home`/`aggro`/`deAggro`/`attackRange`/`bulletSpeed` + a `pathCd` replan throttle (damage is the actor's `Stats.attack`, not on the `Brain`); targets are the nearest hostile by faction. **Chase is line-of-sight-first** — a clear shot is a straight seek; a wall between slime and player triggers an A\* detour over the `NavGrid` (see _Pathfinding Flow_).

**Attributes & derivation.** The derived combat `Stats` are computed from a data-driven primary-attribute layer (Demo, like `CombatAI` — the kit reads only the derived `Stats`, via `Combat`'s injected `mitigate`). **`Attributes`** (`scripts/Attributes/`) is a flat `{ key: number }` bag (opt-in: the player carries one, monsters author `Stats` directly); **`StatModel`** (`scripts/StatModel/`) is the swappable model — `ATTRS` (this RPG's lean set: `POW`→attack, `VIT`→maxHp (+ a little defense), `AGI`→speed, `END`→maxStamina, each with a default) + `derive(attrs)` (the rules, tuned so the defaults reproduce the legacy sheet `10/1/0/220/100`) + `recompute(world, id)`. **`recompute` is recompute-from-source**: derived `Stats` = `derive(attrs)` + Σ equipped `Equippable.mods` + Σ active status `mods` (`_foldStatuses` — buffs like `fortify`), rebuilt from scratch each call (so it can't drift); a no-op without `Attributes`, it clamps `Health`/`Stamina` to the new maxima. It runs on `RpgPlayer.spawn`, on equip/unequip (`EquipmentSystem`), and on an **attribute change** — which, with leveling removed, comes from **attribute-granting consumables** (the `*_shard` items: `power`/`vitality`/`agility`/`endurance`, one per `ATTRS` key, each `+1` forever via `Consumable { attr, amount }`). Using one runs the kit's `ConsumableSystem.use` → its **injected `grantAttr` hook** (set in `sceneRpg.create`, mirroring `Combat.mitigate` — the kit can't reach the Demo stat model) → raise the bag key + `recompute`. Shards are obtained by **crafting** (workbench recipes, gem + a material) and **quest reward** (the ruins quest), so growth is gated on gathering/exploring, not playtime. `Attributes` ride the carried sheet across a map change (`RpgMap.go`), so a re-derive on the new map uses the grown attributes (without this, shard gains would silently reset). **Swapping the model** (to D&D-6, SPECIAL, …) is a `StatModel`-only edit — rewrite `ATTRS` + `derive`; combat, equipment, and save/migration all read the derived `Stats`. The inventory **Stats** tab lists the attributes (data-driven from `ATTRS`).

**Buffs & statuses.** The **`Status`** module (`Gameplay/Status`) is the generic buff/debuff layer — a swap-in for poison/regen/slow/haste/fortify/encumbrance, stat-model-agnostic like the rest of the kit. Three pieces: **`Status`** (`scripts/Status/`) is the def registry (`Status.register([...])`/`get`/`all`, like `Item`/`Rarity`); **`StatusEffects`** (`scripts/StatusEffects/`) is the per-entity component holding the active list (`{ id, remaining, accum, mult? }` — flat, `world.export`/`EntitySnapshot`-safe); **`StatusSystem`** (`scripts/StatusSystem/`) runs them. A def carries up to **three effect kinds**, each routed the idiomatic way: **`dot`/`hot`** (HP per second, applied every `interval` by `StatusSystem.update` straight to `Health` — DoT bypasses `Combat.mitigate`, the `≤0` reaction stays the `Mortal` pass; floating numbers come free from `RpgScene.trackDamage`); **`mult`** (live multiplicative factors read at point of use via `StatusSystem.scale(world, id, key)` — the mover reads `"speed"`, so encumbrance/slow/haste compose by multiplication, never folded into the sheet); and **`mods`** (flat additive `Stats` deltas folded into the derived sheet by `StatModel._foldStatuses`, mirroring `_foldEquipment`). The `mods` path needs a re-derive on apply/expire, so it goes through the **injected `StatusSystem.onStatsChanged` hook** (kit default no-op; `sceneRpg.create` wires `StatModel.recompute`, exactly like `Combat.mitigate`/`ConsumableSystem.grantAttr`) — keeping the kit free of the Demo stat model. API: `apply(world, id, statusId, opts?)` (timed — `opts.duration` overrides the def; refresh keeps the longer remaining, no magnitude stacking yet), `remove`, `maintain(world, id, statusId, mult|null)` (a LIVE-driven permanent status whose per-instance `mult` a driver refreshes each tick — the encumbrance path; carries no `mods`, so no re-derive), `has`/`list` (the HUD reads `list`), `scale`, and the per-tick `update`. Content is **`RpgStatuses`** (Demo, registered by `RpgContent.register`): `encumbered` (maintained debuff, live speed mult from `EncumbranceSystem`), `regen` (HoT buff — the Tonic consumable), `fortify` (timed `mods` +attack/+defense buff — the Elixir consumable). `sceneRpg.step` ticks `StatusSystem.update` then `EncumbranceSystem.update` at the top of the tick loop (before the mover reads `scale`); the HUD card lists active statuses tinted by each def's `color` (rich-text `[c=#hex]` spans, read live). A DoT debuff (poison) is the symmetric counterpart of `regen` — one def + an applier away.

**Survival needs.** The **`Survival`** module (`Gameplay/Survival`) is the needs layer — `Thirst`, `Hunger`, `Drowsiness`, each a **"rising meter"** component `{ value, max, rate, critical, status }`: `value` climbs by `rate`/sec (0 = fine, `max` = critical). Each has its own thin system (`ThirstSystem`/`HungerSystem`/`DrowsinessSystem`) over a shared **`Survival`** core: `Survival.tick(world, token)` raises + clamps the meter and, at `value/max >= critical`, **applies the named debuff `Status`** (`StatusSystem.apply`/`remove` — reusing the Buff/Status kit, so the consequence shows in the HUD), while `Survival.restore(comp, amount)` lowers it (returning whether it changed, so a no-op drink/food is refused). Opt-in like `Stamina`/`Encumbrance` (only the player carries them — `RpgPlayer.spawn`), and — like `Stamina` — they ride the carried sheet across a map change (`RpgMap.go`'s capture list), so a need doesn't reset or diverge per map. Restores: a **`Consumable`** with `thirst`/`hunger` (the Water Bottle / Bread / Cooked Meat — `ConsumableSystem` routes them to `ThirstSystem`/`HungerSystem.restore`); Drowsiness is restored by **sleeping**. Demo content (`RpgStatuses`): `dehydrated`/`starving` (a `dot`) + `drowsy` (a speed `mult`). `sceneRpg.step` ticks the three systems in the tick loop (after `StatusSystem`/`EncumbranceSystem`). **Sleep (bed):** a built **`bed`** carries an `Interaction` kind `"bed"`; the `"bed"` `InteractAction` routes its E to `sceneRpg._sleep`, which sets `_sleeping` → `step()` raises `Time.scale` to `RPG_SLEEP_SCALE` (fast-forwarding `WorldClock`/`Weather`/needs) and drains `Drowsiness` each tick (`DrowsinessSystem.restore` instead of `update`); any key/click wakes (`_wakeInput`, checked before the tick loop) and restores `Time.scale = 1`. So sleeping skips time + restores rest but **costs water/food** (those needs keep rising while fast-forwarded). The HUD shows the three needs as **reserve bars** (`1 - value/max`).

**Death (`Mortal` / `Downed`).** What happens when an entity's `Health` hits 0 is **configured per spawn preset** by an opt-in **`Mortal`** component (`scripts/Mortal/`, `Gameplay/Combat`), resolved in one place — `RpgScene.resolveHealth` (the instant reaction) + `RpgScene.updateDowned` (the down-timer) — so the damage systems just subtract hp and a body with `Health` but **no** `Mortal` (e.g. a built turret, removed by `BuildMode.reapDestroyed`) is left alone. Kinds: **`despawn`** (slimes) spills the entity's `Inventory` as ground drops then removes it; **`respawn`** (player) refills to `Stats.maxHp` and repositions; **`down`** (companions) incapacitates — it **detaches `Health`** (so `FactionSystem.nearestHostile` stops targeting it and the death scan skips it), zeroes velocity, dims the sprite, and attaches **`Downed { timer }`** (`scripts/Downed/`); after `Mortal.recoverSecs` of sim time `updateDowned` re-adds `Health` (`reviveHp`), un-dims, and teleports it to the recovery spot — `sceneRpg._recoverSpot()` = the claimed build zone centroid, else the map spawn. The scene injects the side effects as handlers (`onDespawn`/`onRespawn`/`onDown`/`downSpot`/`onRecover` — quest/profile counters, the player respawn reset, down/recover toasts). `FollowerSystem` holds a `Downed` companion still; the inventory Party tab shows its **Down (recovering)** status and disables Dismiss; the carry bonus is untouched (it tracks `Follower.state`, which a down→recover cycle doesn't change). A downed companion round-trips a map change via `EntitySnapshot` (it carries `Downed`, not `Health`) and recovers in the new map.

**Loot, progression & dialogue.** `ItemDrop` = `{ itemId, qty }` on a non-solid sensor entity the player collects on overlap; enemy deaths spill their `Inventory` as drops. `QuestLog` (`scripts/QuestLog/`) holds quest defs + active progress (objectives `{ kind: "kill"|"collect"|"reach", target, count }`, **item-only rewards** `{ items? }` — there's no XP, so a quest grants items, e.g. the ruins quest gives a `vitality_shard`); `RpgProgression.applyReward` is the single apply path (adds the items to the bag). The scene calls `QuestLog.report(kind, target)` after gameplay events and turns in on NPC interaction. `NPC` = `{ name, lines, questId? }` — the scene proximity-checks the player and opens a dialogue panel that can offer/turn in the linked quest. `Animator`/`AnimationSystem` are a data-driven sprite state machine: `Animator` holds a `graph` of named `AnimState`s (`{ sprite, start?, frames, fps, loop }`); the controller picks `state`, `AnimationSystem.update` advances playback into the entity's `Visual` (clamps `frames ≥ 1` for the SVG-sprite quirk). `start` offsets the state into a **shared strip** (`vis.subimg = start + frame`) — how the unified humanoid sheet packs walk + attack into one sprite (see _Paper-doll appearance_).

**Paper-doll appearance (`Appearance` / `AppearanceSystem`).** Humanoids are one **unified, tintable body sprite** with worn gear drawn as **overlay layers**, not a baked sprite per outfit. Three pieces: **`spr_human`** is the canonical humanoid strip — a hand-authored **white Rayman-style template** (a 48×48 authored source imported into a **64×48 cell** — widened so a punch-thrust hand + held weapon never clip; foot-anchored, hard alpha; head/torso/hands/feet as **disconnected floating blobs**, chosen because full-figure pixel animation was the bottleneck) whose animation is **generated, not drawn**: `tools/pixel-art-kit/gm-import/human_sprites.py` segments the blobs from the source template (`tools/pixel-art-kit/templates/human/base.png` — edit THAT and re-run; the sprite folder is importer-owned) and applies a per-part offset table → frames 0–1 = walk contact poses (idle plays them slower), 2–3 = attack windup/punch. The white base is **tinted per entity via `Visual.color` = the skin tone** (`RpgPlayer.SKIN`, a literal GM color int — a top-level `Color.parse` would race script load order). The graph is defined once in `RpgPlayer.animGraph()` (offset-based `AnimState.start` over the one strip). **`Appearance`** (`scripts/Appearance/`, Core/Component — Core because `RenderBillboard` reads it) is the layer stack `{ back: [{sprite,color}], front: [...] }`: `RenderBillboard` draws `back` layers, the body (`Visual`), then `front` layers, all at the **same subimg/matrix** — the layers are coplanar, and since every layer sheet shares the body's exact cell size + anchor, the quads have identical per-pixel depth and the default `cmpfunc_lessequal` lets each later layer paint over the previous (verified on 0.20; `sh_alphatest` keeps transparent texels from writing depth). Overlay layers keep their **own** color — the body's `Visual.color` is the skin tint and must not bleed into outfit colors; whole-doll effects (the downed dim) ride `Visual.alpha`, which layers share. **`AppearanceSystem`** (`scripts/AppearanceSystem/`, Gameplay/Equipment) rebuilds the stack **derived-from-source** like `StatModel.recompute`: it walks `Equipment` slots (order policy: `backpack` → back; `armor`/`trinket`/`weapon` → front) and pushes each worn item's `Equippable.worn` sprite (resolved via `asset_get_index` + `sprite_exists`). Rebuild runs at the same chokepoints as the stat re-derive — `EquipmentSystem.equip`/`unequip`, plus after the carried sheet lands via `EntitySnapshot.apply` in `RpgMap.go`/`resume` (Equipment arrives there outside `equip()`); `Appearance` itself is never serialized. **The invariant: every overlay sheet mirrors `spr_human`'s strip layout** (frame count/order, cell, foot anchor) — so overlays are **generated by `human_sprites.py` from the same parts/offset table** (never freehand) and can't desync. Reference overlays: the armored vest (`worn: "spr_wear_vest"` — a torso-shaped garment with a neckline, tracking the torso's per-frame offsets) and the **held weapons** (`spr_held_pipe`/`spr_held_blaster` — the weapon drawn at the **right hand's per-frame position**, so the equipped weapon rides the hand through walk/windup/punch; wired as `worn` on the weapon `Equippable`, the `weapon` slot being last in `FRONT_SLOTS`). Item **icons** auto-wire by the `spr_item_<id>` naming convention with a legacy-name fallback (`RpgItems.ICONS` alias table, `sprite_exists`-guarded) — an unmatched id keeps the UI's colored-box fallback. Non-humanoids (rat, props, chests) keep the plain single-`Visual` path; `spr_hero`/`spr_heroAttack` remain for NPCs/followers until they migrate to the doll. **Entity size is a baked per-preset scale factor**: `RpgSpawn.SCALE` (raider/rat/npc/follower bases; a spawn descriptor's `scale?` multiplies on top) and `RPG_PLAYER_SCALE` (via `RpgPlayer.spawn`'s `opts.scale`) multiply **both** `Visual.xscale/yscale` and the `BBox` at spawn — so the foot shadow (`RenderEntityShadow`, BBox-driven) and the paper-doll layers (drawn at the body's `xscale/yscale`) follow with no extra plumbing, and per-preset size variety is a one-table tune. Because `|xscale|` now carries size, the facing flip must preserve magnitude (`vis.xscale = ±Math.abs(vis.xscale)` — `RpgController`), never assign bare `±1`.

**Interactions (`Interaction` / `InteractAction`).** "Walk near an entity + press E to do something" is a two-piece, data-driven system (`Gameplay/Interaction` kit — see _Gameplay Kit → `Interaction`_). An entity carries an **`Interaction`** component `{ kind, ...params }` (`kind` names a registered action; the flat params are per-instance data an action reads, e.g. `{ kind: "buff", status: "regen" }`). The **`InteractAction`** registry holds the behaviors — `register([{ id, prompt, run(ctx) }])`, mirroring `Item`/`Status`/`Prefab`; `run(ctx)` (with `ctx = { scene, world, id, comp, playerId }`) does anything, so adding an interaction is a data entry, not an engine edit. The RPG registers its set in **`RpgInteractions`** (Demo, called by `RpgContent.register`): **window** actions open a UI + set `scene._interOpenId` so the engine range-closes/refreshes them (`storage`→`StorageUI`, `workbench`→`CraftingUI`); **instant** actions act once per E press (`claim`→`BuildMode.claim`, `arcade`→`_openArcade`, `bed`→`_sleep`, and the survival trio `hydrate`/`feed`/`buff` that act on the **player** — `ThirstSystem`/`HungerSystem.restore`, `StatusSystem.apply`). The generic pick/prompt/dispatch **engine** is `Interactable` (Demo/UI): each frame `_pick` chooses one target `Interaction` (cursor-in-range, else nearest-in-range), the prompt pill reads the def's `prompt`, and E → `_open` looks up `InteractAction.get(comp.kind).run(ctx)` (no per-kind switch). E is arbitrated once by `sceneRpg._dispatchInteract` (station vs NPC). The survival trio is buildable (`BuildMode.CATALOG` **Survival** — tinted props) and authorable in the level editor (`RpgCatalog`'s Interaction field). Replaces the old Core `Station` component + hardcoded `_open`/`_promptText` switches.

**World time & day/night.** **`WorldClock`** (`scripts/WorldClock/`, Demo) is the in-game clock — a static class like `Time` (one world clock), holding `hour` (0–24 float) + `day` (1-based), advanced once per frame from `sceneRpg.step()` by `Time.delta` (sim time — pauses with the game, dilates with `Time.scale`). `dayLength` (real seconds per in-game day, default 240) sets the pace. The scene `reset()`s it once in `create()` — **not** per map — so a portal trip keeps the hour. API: `reset()`, `update(dt)`, `clockText()` (`"HH:MM"`), `phase()` (`night`/`dawn`/`day`/`dusk`), `tint()` → `{ color, alpha }` interpolated from a keyframe table (deep blue at night → clear by morning, warm at dawn/dusk; alpha 0 in full daylight). The HUD shows `Day N HH:MM` (read live), and the **`RenderLighting`** pass (now in the `Gameplay/Lighting` kit) consumes `tint()` as its **injected ambient term** (`RpgMap.build` passes `ambient: () => WorldClock.tint()`; day/night is the light map with no lights).

**Seasons & temperature.** `WorldClock` also derives the **season** purely from `day` (no stored state, like `phase()` from `hour`): `daysPerSeason` (default 7) days each, the four cycling forever over a `_SEASONS` literal (`{ id, name }`). API: `season()`, `seasonDay()` (1-based day-within-season). The HUD time row reads `Season · Day N  HH:MM`. Season biases the `Weather` transition + the `Temperature` baseline. **`Temperature`** (`scripts/Temperature/`, Demo) is the ambient temperature in **Kelvin** (`toCelsius`/`toFahrenheit` convert) — a **pure derivation, not a stored sim**: `now()` = `ZERO_C` (273.15) + season baseline (`_BASE`, authored in °C, keyed by `season().id`) + a time-of-day swing (`diurnal()`, a cosine of the hour peaking mid-afternoon) + the live `Weather.tempMod()` (which already folds in the active climate zone's offset). The Kelvin/Celsius scales share one increment, so all the deltas are scale-agnostic — only the baseline is offset. Kept **off** `WorldClock` so the clock stays the pure temporal authority. The HUD shows the weather condition + temperature via **`Temperature.display()`**, which formats `now()` in the `tempUnit` Setting (`"K"`|`"C"`|`"F"`, default `"K"`; toggled in the inventory **Settings** tab); the bundled locale fonts carry the `°` glyph, so `°C`/`°F` render.

**Weather.** **`Weather`** (`scripts/Weather/`, Demo) is the global sky — a static singleton like `WorldClock` (one sky), holding the current condition + a **season-biased transition**. Conditions are a fixed built-in literal table (`_COND` — `clear`/`cloudy`/`rain`/`storm`/`snow`), each carrying its render look (`{ c, a }` tint + `particle`/`density`) and a **Kelvin `temp` delta** (scale-agnostic, folded into `Temperature.now()`). `update(dt)` (driven from `sceneRpg.step()` by `Time.delta`, so weather **freezes when the game pauses** and dilates with `Time.scale`, like the clock) counts down a 25–70 s hold then re-rolls the next condition by `_WEIGHTS[season]` (winter favors snow + bans rain, summer favors clear + the odd storm, …), **excluding** the current one so a change always changes the weather. A change **cross-fades** over `_fadeTime` (2.5 s): `previous()`/`current()`/`blend()` let the render pass + `tempMod()` lerp the outgoing→incoming conditions so weather eases in/out instead of snapping. `reset()` (scene `create()` once, like `WorldClock.reset()`) settles a clear sky and survives map changes. The **`RenderWeather`** pass (see Renderer) draws it; the HUD reads `current().name`.

**Climate zones (regional weather).** A **climate `ZoneMap` channel** lets a region **override** the open sky. `Weather.enterRegion(zone)`/`exitRegion()` read the zone's flat `data` — `weather` (a forced condition id) + `tempMod` (a Kelvin offset) — into an `_override`/`_regionTemp` slot; the *displayed* condition is the effective one (`override ?? ambient`), so the season-rolled ambient keeps running underneath and resumes on exit (the cross-fade handles both edges). Climate zones are **data-driven** from a level file's optional `meta.climate` array (`[{ name, rect: [gx1,gy1,gx2,gy2], weather?, tempMod?, color? }]`), painted into the `"climate"` channel by `RpgMap.build` (before the persistence import, so they round-trip like the buildable zone on a cold rebuild). `sceneRpg._updateClimate()` tracks the **player's** climate cell directly each frame (a single-entity `ZoneMap.idAt` lookup — cheaper than `ZoneSystem`'s all-entity sweep) and fires enter/exit on a border cross; `RpgMap.suspend` calls `exitRegion()` so a portal trip clears it (the resumed/built map re-detects on its first step). The reference is `overworld.json`'s **Frostlands** (`weather: "snow"`, `tempMod: -15`) — walking in turns the sky to snow and drops the temperature ~23 K. **Indoor maps** (`meta.indoor`, e.g. `interior_01`) skip the `RenderWeather` pass entirely — no open sky inside a cave (the global `Weather` keeps running; only its visual is suppressed).

The combat/loot plumbing the RPG scene (`sceneRpg`) uses lives in **`RpgScene`** (`scripts/RpgScene/`, Demo) — free functions taking the scene (composition; no class inheritance on GMRT): `trackDamage(scene, yOffset)` (now also pops numbers for `scene.followers`), the `Mortal`-driven death pair `resolveHealth(scene, handlers)` + `updateDowned(scene, handlers)` (see _Death_ above — these replace the old `resolveDeaths`/`checkPlayerDeath`), `spillLoot`/`spawnDrop`, `collectDrops(scene, onCollect?)`. Scene-specific side effects (quest/profile counters, the player respawn reset, the companion recovery spot, down/recover toasts) are the handlers; the scene supplies the contract fields `world`/`ctrl`/`followers`/`_hpTrack`/`_invDirty` (the enemy set is derived live by **`Faction`** — Health-bearing bodies hostile to the player — not stored, and not a marker/tag).

The **character window** is centralized in **`RpgInventoryUI`** (`scripts/RpgInventoryUI/`, Demo) — a **near-fullscreen, fixed** (non-draggable, non-resizable) **`gemsTabs`-based** overlay modeled on the `SystemMenu` panel: an absolute full-screen host with a dim backdrop (shown/hidden via `scene._invWin.enabled`, **not** a `UIModal`) centering a full-height card whose tab host flex-grows, built once in `build(scene)` on `scene._invWin`, with six tabs: **Items** (the bag `UITable` over a usage line + a category-filter `gemsSelectCustom` + a free-text name-search `gemsInput` composing into one `table.setFilter` via `_applyFilter` — search lowercases via an ASCII char-code map, since `toLowerCase()` is broken on GMRT — plus a select/action row: click selects, double-click / the context **Use/Equip/Unequip** button / a gamepad confirm acts on the row), **Equipment** (worn-slot rows, click to unequip — `scene._invEquipHost`), **Party** (the companion roster — one `gemsCard` per `scene.followers` entry into `scene._invFollowerHost`, with the follower's name + a **live** follow/wait status & carry-bonus line + a **Dismiss to base** button (`scene._dismissFollower`, live-disabled unless following) + a binding-aware recall hint; the host is repopulated per `rebuild` since the present companions change across maps, but each row's text/disabled-state reads the live `Follower` so an F-toggle/dismiss updates with no rebuild), **Stats** (the live sheet + the genre's extra records — `scene._invExtraHost`), **Quests** (a live `gemsQuestTracker` bound to `QuestLog`), **Settings** (per-column toggles). The Items columns are gated by the **Settings** toggles (`gemsCheckbox` → `Settings.set`/`save`, persisted across launches): worn-marker / Name / Qty always; **Rarity** / Type / Weight / Value optional. A toggle calls `_applyColumns` → `UITable.setColumns`, which remaps the active sort by each column's stable `key` (the sort stack stores indices, which shift when columns change). `rebuild(scene, { equipSlots, extraRows? })` only refreshes live data: `table.setRows` (re-applies the current sort/filter, so view + scroll + active tab survive every equip/use), re-maps the selection by `itemId`, repopulates the equipment + extra sections. `equipSlots` is the rows to show (RPG adds `backpack`); `extraRows(scene, host)` appends genre lines (RPG Profile records). The scene keeps only `invOpen` (toggled on the `inventory` key) and calls `build` in `create()` + `rebuild` when `_invDirty`. (The HUD stays per-scene — `sceneRpg._buildHud` = HP + quest tracker.)

`sceneRpg.step()` is the reference RPG orchestration: edge-toggle the inventory window → per tick: `snapshot` → `controller.update` → `physics` Pipeline → `RpgScene.trackDamage` → `RpgScene.resolveHealth` (despawn/respawn/down by `Mortal`) → `RpgScene.updateDowned` (revive timer) → `RpgScene.collectDrops` → reach/quest/achievement checks → `flush`; then once per frame: `AnimationSystem.update`, NPC proximity + dialogue, `Interactable.update`, `BuildMode.update`, `camera.update`, an inventory rebuild when `_invDirty`, and finally `_checkPortals()` **last** (a door swaps the world out from under everything). (No pause gate in `step()` — `obj_game` skips `scene.step()` entirely while the `SystemMenu` overlay is open.)

**Map graph (overworld / sub-levels / side-islands).** Maps are discrete level files connected by portals, not one streamed world (the deliberate fit for the `JSON.parse`-on-large-files limit and the one-`World`-per-scene model). The world graph is the seed registry **`RpgLevel.MAPS`** (`{ mapId → "levels/x.json" }`) + `RpgLevel.START`; extract to a `maps.json` manifest if it grows. A level file gains two things over the base format: `meta.entries` (a named-point map, e.g. `{ default, from_interior }` — the matching side of a door; `RpgLevel.build(world, data, entryId)` resolves the spawn from it, falling back to `entries.default` then legacy `meta.playerSpawn`) and a **`portal`** spawn preset (`{ toMap, toEntry, label?, color? }` → a non-solid sensor entity, returned in `RpgLevel.spawn`'s `portals[]`). `sceneRpg.create()` builds the **persistent** UI once (HUD/dialogue/inventory/Interactable/BuildMode — they read `world`/`ctrl` live, so they survive a map swap), then calls **`RpgMap.go(scene, mapId, entryId)`** — the portal-travel orchestrator. Rather than destroy + rebuild on every door, `go` keeps each visited map's `World` **alive and suspended** in a per-scene **pool** (`scene._maps`): it **parks** the current map (`suspend` → stash its `world`/`level`/`renderer`/`camera`/`pipeline` references into the pool, no teardown) and then either **resumes** the target's parked world (a revisit — no file reload, no rebuild) or **builds** it from file (`RpgMap.build` — a first visit, or a cold-cache restore after eviction). Only the **party** crosses worlds: `go` captures the player's character sheet (`Attributes`/`Stats`/`Health`/`Stamina`/`Inventory`/`Equipment`/`Encumbrance` + the survival needs `Thirst`/`Hunger`/`Drowsiness`) + the `"follow"` companions via `EntitySnapshot` and re-applies them onto the target-world player; everything else (stationed companions, built tiles/entities, the buildable zone, dead enemies) just stays resident in its parked world, so nothing has to be hand-marked for persistence. A resume re-points the resident (dormant) player to the portal's named entry (`scene.entries`, honoring `entryId` with no file reload) and re-binds the map-context statics (`MotionPlanner` grid + `CombatAI.bind`). The player-centered radar (`RadarArrows`) reads `world`/`ctrl` live, so it needs no per-map rebuild. `RpgMap.checkPortals` (step's last line) travels through the first portal the player overlaps. The editor's Test Play still works: a `playtestFile` is registered under a synthetic `_playtest` map id and booted as a single portal-less map. `_updateNpc`/`_checkReach` guard the no-NPC / no-reach-marker maps (interiors). The reference graph is `overworld` ⇄ `interior_01` (a cave door).

**Map persistence (the map pool; `meta.persistent` gates only the cold path).** A map's player edits — the claimed buildable zone + built tiles + placed entities — *and* its in-place state (stationed companions, dead enemies, moved/hurt bodies) survive leaving and returning because the map's `World`/`Level` are **kept alive** in the pool (`scene._maps`), not destroyed — so a door trip can't wipe a player's base, and **persistence is the default** (nothing has to be marked). The old per-leave `level.export()`/`import` round-trip is now the **cold path**: only an **LRU eviction** (past `RpgMap.POOL_MAX` parked maps — `_evict`) serializes a map into `scene._mapCache` (`level.export()` = TileLayers + buildable `ZoneMap`; the `_built` deconstruct tracking; built entities; stationed companions; the `gone` ledger) and frees its resources; a later revisit then `build`s it from file and `import`s that cache (same dims/layer order → clean round-trip; the cached buildable zone keeps id 1; `TileEdit.remesh` rebuilds wall colliders). `meta.persistent: false` opts the **eviction serialize** out (a dungeon that resets if it ever falls out of the pool). Live enemies/loot are **not** serialized on eviction — they respawn on that cold rebuild (the one place dead enemies come back; within the pool they stay dead). The `_mapCache` is `Level.export()`-shaped, so a future on-disk save serializes the pool + cache next to the carried character sheet.

**Followers & the party (dynamic-world entities).** A companion either travels with the player or waits in a place — the forcing-function for entity migration. `Follower` (`scripts/Follower/`, `{ state: "follow"|"wait", speed, range, homeMap, bonusCapacity, bonusWeight }`) marks it; `FollowerSystem.update(world, playerId, followers)` is the per-tick seek (a `"follow"` companion steers toward the player, easing to a stop within `range`; a `"wait"` one holds still). The player id is **passed in, never stored on the follower**, so a migrated companion needs no entity-id re-link. It's a dynamic solid body; `RpgLevel.spawnFollower(world, x, y, opt)` builds it (shared by the `follower` preset + the scene's seed). Migration is partitioned per follower in `RpgMap.go`: a `"follow"` companion is **party scope** — captured via `EntitySnapshot`, removed from the parked world, and re-spawned around the target entry; a `"wait"` companion is **map scope** — it simply stays resident in its (now parked) world, in place on revisit with no capture (only an eviction serializes it into `_mapCache[mapId].entities`). The player's character sheet is party member 0. `sceneRpg` seeds the starting companion **programmatically once** in `create()` (a file-authored follower in a persistent map would duplicate — see reconcile); the `F` key flips the nearest companion between follow and wait. A companion now carries `Health` + a `down`-kind `Mortal`, so it's an **attackable combatant** (slimes aggro it); at 0 hp it goes **Down** and later revives at base instead of dying (see _Death_).

A companion also **helps carry**: while following it grants the player **`bonusCapacity`/`bonusWeight`** (extra `Inventory` slots + weight cap) via `FollowerSystem.applyBenefit(world, playerId, f, sign)` — a balanced +/- delta exactly like `EquipmentSystem`'s `Container` bonus, applied/removed at each follow-state transition (the seed, the `F` toggle, dismiss). Because the bonus is baked into the player's live `Inventory`, it rides the carried sheet snapshot across a map change with **no re-apply** (a traveling companion stays `"follow"`; a stationed one already had its bonus removed) — the same equip/unequip-pair invariant. Only the programmatic seed grants a bonus; the `follower` preset leaves it 0, so file-authored followers stay benefit-free (no migration imbalance). Beyond the in-place `F` wait, a following companion can be **dismissed to base** from the inventory **Party** tab (`sceneRpg._dismissFollower`): it stops carrying (bonus removed), becomes `"wait"` stationed in the current map (so it stays resident in that map's parked world), and is relocated to the **claimed buildable zone**'s centroid (`_buildZoneSpot`; refused with a toast if nothing is claimed yet). It's **re-hired** by walking up to it there and pressing the follow key — the existing `F` toggle (wait → follow, re-applying the bonus).

**File-scope reconcile (`id` → spawn-once).** File spawns default to **respawning** every visit (generic enemies are meant to come back). A spawn carrying an authored **`id`** is a **unique** entity, spawn-once: it gets a Core `Persistent { uid }` component, and the scene remembers its fate per map. The ledger is `scene._gone` (a `{ uid: true }` set) carried on the map's pool bundle; `RpgLevel.spawn(..., { gone })` **skips** any id'd spawn whose uid is in it on a **build**, so a killed boss / recruited NPC doesn't re-spawn while id-less spawns still do. The scene marks a uid gone via `_markGone(id)` — wired into `RpgScene.resolveHealth`'s `onDespawn`, reading `Persistent.uid` while the entity is alive. With the pool a revisit is a *resume* — the killed unique is simply still gone from the live world — so the ledger only applies on the cold rebuild after eviction (restored from `_mapCache[mapId].gone`). This closes the file-authored-follower duplication and is the seam for recruitable NPCs. **Deferred:** preserving a *survivor's modified state* (a partially-looted chest re-filling on revisit) needs snapshotting surviving unique entities on leave; only the removed/`gone` case is handled now.

**Chunk streaming & sim-LOD (scalable overworld).** A **chunked map** (`meta.chunked: true` in the level file) streams its terrain + entities around the player so the `World` only ever holds what's nearby — entity count + per-tick cost stay bounded no matter how far the player roams (the overworld; interiors keep the plain build-everything path). The engine is the Core **`ChunkManager`** (`scripts/ChunkManager/`, a plain instance class owned by the scene as `this.chunks`, like `SceneManager`); content comes from a **`source`** it's handed — the RPG **`ChunkSource`** (`scripts/ChunkSource/`). Built on `EntitySnapshot` (the capture/restore foundation) + `Portal` (`scripts/Portal/`, `{ toMap, toEntry }` on the doorway entity, so a streamed door resolves via a live `world.query(Portal)`).

- **Two-ring sim-LOD** (Chebyshev chunk distance from the player's chunk): `d ≤ simRadius` → **SIM ring** (entities live in the World, walls have colliders, full simulate + render); `simRadius < d ≤ loadRadius` → **LOAD ring** (entities held as snapshots, **not** in the World / not simulated, drawn statically by `RenderChunks`; walls drawn, no colliders); `d > loadRadius` → **UNLOADED** (snapshots parked in an in-session cache keyed by chunk, restored on return so hurt/killed/moved entities persist). `ChunkManager.update(centerX, centerY)` (called once per frame from `step()`, outside the tick loop) diffs the rings on a chunk-border crossing and **promotes** (restore → World + mesh colliders) / **demotes** (capture → snapshot + drop colliders) / loads / unloads, then `world.flush()`es its own removals. The **party (player + followers) is never chunk-managed** — the scene keeps it in the World always.
- **Resident grid vs streamed terrain.** A chunked map's `Level` is a large **resident** grid (`meta.worldCols/worldRows`, built by `RpgLevel.buildChunked`) whose `wallLayer`/`floorLayer` hold **player builds only** (build mode + `TileEdit` colliders, unchanged) — the streamed terrain (authored hub + procedural wilderness) is owned by the `ChunkManager` with its own colliders + `RenderChunks` pass, never written into those layers, so the two never conflict. The world is a **finite `worldCols × worldRows` rectangle** (the resident-grid extent, anchored at cell 0): `ChunkManager` clamps streaming to chunks inside it (`opts.worldCols/worldRows` → it skips out-of-bounds chunks, so the active set shrinks near an edge — e.g. 9 at a corner vs the usual 25), and `RpgLevel.buildWorldBorder` rings it with 4 always-present kinematic-solid edge colliders so the player/slimes can't leave (procedural fills the rectangle out to the border; building is gated to the claimed origin zone). `IdPool` reuses freed indices, so streaming churn keeps the high-water mark bounded.
- **`ChunkSource` (router) → `OverworldGen` (generator) → `Prefab` (templates).** Generation is **not fixed** — it's split into three pieces so a different world is a swap, not a rewrite:
  - **`ChunkSource`** (`scripts/ChunkSource/`, Demo/System) is the `source` the `ChunkManager` holds, and is purely a **router**: chunks inside the **authored origin box** (the `overworld.json` walls + spawns indexed by chunk, so the hand-built hub — Elder, cave portal, chest, workbench, survey post — appears in its chunks and stays procedural-free) come from the overlay; everything else is delegated to its `generator`. `generate(cx,cy) → { walls, spawns }` (absolute grid coords; `gridToWorld` handles negatives); `spawn(world, level, desc, playerId)` delegates to **`RpgLevel.spawnEntity`** — the per-spawn entity constructor extracted from `RpgLevel.spawn` so streamed + up-front spawns build through one code path.
  - **`OverworldGen`** (`scripts/OverworldGen/`, Demo/System) is the swappable procedural algorithm (inject a different `generator` — cave/desert/… — with the same `generate(cx,cy)` contract). It emits a loose random scatter (rocks + slimes) **plus** an optional stamped **prefab**, deterministic from `(cx, cy, seed)` so a chunk regenerates identically (the contract terrain relies on). Its PRNG is a Park–Miller MINSTD LCG, not xorshift32 (see the xorshift GMRT-Safe Idiom). The value-noise **terrain biome** (`OverworldGen.TERRAIN`, water/sand/grass) carries a `pathCost` per material (TileType convention: `null` → impassable): `solidTerrain(cx,cy)` greedy-meshes the impassable cells (water) into `solid` rects in `generate()`'s output, which `ChunkManager` turns into **collide-only** colliders (not rendered — `TerrainStream` already draws the water) so impassable terrain physically blocks the player **and** feeds `NavGrid` pathfinding; walkable materials (cost 1) stay render-only. Spawn placement skips impassable cells (a dynamic body dropped into a water collider would snag).
  - **`Prefab`** (`scripts/Prefab/`, Demo/Content) is a registry of reusable hand-authored mini-layouts (walls + spawns in **prefab-local** grid coords + a `cols/rows` footprint + scope `tags`), mirroring `Item`/`Rarity`. `OverworldGen` weighted-picks one tagged `"overworld"` and **stamps** it at a deterministic interior offset (translating local→absolute coords, kept off the chunk border so its walls can't merge across a seam); item arrays (`loot`/`items`) are deep-copied per stamp so instances never share-and-mutate the registry def. Defaults (`boulder_cluster`/`slime_den`/`ruin`) are registered in `RpgContent.register()` alongside items/recipes.
  - Slimes survive capture/restore because `CombatAI` keeps its world/target/level as shared statics (refreshed on each `attach`, and re-pointed by `CombatAI.bind` when a parked map is *resumed* without re-attaching — see _Map graph_) and `State`/`Brain` carry no self-id.
- **Scene wiring** (`sceneRpg`): `RpgMap.build` branches on `meta.chunked` — chunked builds the resident grid + creates `this.chunks`/`this.source` + an initial `chunks.update(spawn)` + inserts `RenderChunks`; plain is unchanged. The scene reads NPC / portal / enemy handles **live by tag** (`Query.nearest({tag:"npc"})`, `world.query(Portal)`, `RpgScene._enemies`) rather than stored id lists, so chunk churn never dangles a handle. A map switch **parks** the manager with its world (a suspended chunked map just stops streaming; `resume` re-centers it on the entry), and `RpgMap._free` drops it only on eviction / scene end. Verified flat (~74 ents / 25 chunks at `simRadius 1`/`loadRadius 2`) across a ~15-chunk traverse, clamping near a world edge. **Now retained by the pool:** the chunked overworld's chunk cache survives a portal trip (its world is parked, not torn down). **Deferred:** per-chunk *build* persistence + on-disk chunk saves, throttled distant ticks.

## Pathfinding Flow

1. `world.add(id, PathRequest, { startX, startY, goalX, goalY })` — request in grid coords.
2. `PathfindingSystem.update(world)` resolves → writes `PathResponse: { path, index }` (`index` = cursor).
3. `PathfindingSystem.current(world, id)` → current waypoint `{x, y}` or `undefined`.
4. `PathfindingSystem.advance(world, id)` → `true` if more waypoints remain; `false` (and detaches `PathResponse`) when complete.
5. After any grid change: `PathfindingSystem.invalidate(world)` — detaches all `PathResponse`.

**Streamed-world pathfinding (`NavGrid`).** `MotionPlanner` plans over one `MotionPlanningGrid`; on the chunked overworld the obstacles aren't in `Level.mpg` — the terrain is collider _entities_ owned by `ChunkManager` (+ world border + player builds), the world is large, and only nearby chunks are loaded. **`NavGrid`** (`scripts/NavGrid/`, Core) is the adapter: a small fixed window (default 32×32) re-centered on the player each frame (`rebuild(world, gx, gy)` from `sceneRpg.step`, before the tick loop) by rasterizing every kinematic-solid collider's `AABB.of` footprint into blocked cells, exposing the `MotionPlanningGrid` interface in **absolute level-cell coords** so paths return level cells. `size()` is constant, so `MotionPlanner.setGrid(scene.nav)` is called **once per map**; only occupancy/origin change per frame. One cheap grid unifies streamed terrain + border + player builds + interior walls. The consumer is **`CombatAI.CHASE`**: line-of-sight-first — a clear shot (`Raycast`) is a straight seek; only a wall triggers a throttled `PathRequest` → `PathfindingSystem` → `PathResponse`. `RpgMap` inserts a default-off `RenderDebugPath` pass for the Debug **paths** toggle.

## Level & Map Layers

`Level` (`scripts/Level/Level.js`) manages the tile grid and pathfinding grid, **separate from `World`** (the ECS).

```js
const LEVEL = new Level({ cellWidth: 32, cellHeight: 32 }); // cols/rows derived from room size
const terrain = new TileLayer(LEVEL.cols, LEVEL.rows, { emptyCost: Infinity }); // blocking base
LEVEL.insert(terrain); // append a LevelLayer (LEVEL.remove to detach)
PathfindingSystem.setGrid(LEVEL.mpg); // wire up after layers are ready
LEVEL.syncAll(); // recompute all pathfinding costs (or syncAt(x, y) for one cell)
PathfindingSystem.invalidate(world); // call separately after any grid change
LEVEL.worldToGrid(wx, wy);
LEVEL.gridToWorld(gx, gy); // ↔ { x, y } (gridToWorld returns cell center)
```

**`LevelLayer` interface**: `get(x,y)`, `set(x,y,v)`, `getNavData(x,y) → { cost }`, `export()`, `import()`, `destroy()`. The one built-in is **`TileLayer`** (`scripts/TileLayer/`), wrapping a `Grid` of **`TileType`** values. Later-added layers have higher nav-cost priority. Empty cells report the layer's `emptyCost`: `undefined` (default) passes through to lower layers; `Infinity` makes a blocking base. `TileType` (`scripts/TileType/`) holds `{ id, name, pathCost }` (`pathCost: null` → `Infinity`, default `1`).

**`TileEdit`** (`scripts/TileEdit/`, Core) is the genre-agnostic tile-editing service that keeps a layer's **derived data** (nav cost + solid colliders) in sync with edits, so the "edit a solid tile → resync nav + rebuild colliders" invariant lives in one place. `occupied(layer,gx,gy)` (truthy read — `Grid.get` returns `0`, not `undefined`, for an empty in-bounds cell), `set(level,layer,gx,gy,type)` / `clear(level,layer,gx,gy)` (write + `level.syncAt`), `meshSolid(world,level,layer,out)` (greedy-mesh the solid cells into the fewest kinematic-solid colliders — extend right for width, then down while the whole row is solid — so straight walls become single seamless colliders, avoiding the per-cell-seam snag bug; box size = `level.cellWidth/Height`, ids pushed onto `out`), and `remesh(world,level,layer,colliders)` (remove old + re-`meshSolid` after a solid-tile edit). Shared by `RpgLevel.build` (initial mesh) and `BuildMode` (per-edit set/clear/remesh); the seed for a future in-engine tile editor.

### Zones

**`Zone`** / **`ZoneMap`** / **`ZoneSystem`** add named, tagged spatial regions on top of the level grid — the substrate for build-mode buildable area, faction territory, in-game events, quest regions, weather areas, etc. (Separate from tile layers and from nav cost; a zone is metadata, not a tile.)

- **`Zone`** (`scripts/Zone/`) — a flat definition object `{ id, name, tags, data }`. `tags` is a **`string[]`** (`hasTag(t)` via `indexOf`), never a `Set` (Set iteration crashes GMRT); `data` is a flat scalar payload (`{ factionId, weather, questId, color, … }`) to stay JSON-safe.
- **`ZoneMap`** (`scripts/ZoneMap/`) — one zone **channel**: a `Grid` of zone-id ints (`0` = none) plus a registry of `Zone`s, exactly as `TileLayer` wraps `Grid<TileType>`. A cell belongs to **at most one zone within a map**, so lookup is O(1) and storage is one int per cell; purposes that can overlap (faction vs. weather vs. event) live in **separate maps**. API: `define(opt) → Zone` (auto-assigns id), `zone(id)`, `byTag(tag)`, `paint(id,gx,gy)`/`paintRect(id,x1,y1,x2,y2)`, `erase`/`eraseRect`, `idAt(gx,gy)`, `at(gx,gy) → Zone`, `contains(gx,gy,tag)`, `cells(id) → {x,y}[]`, `export`/`import`/`destroy`.
- **`ZoneSystem`** (`scripts/ZoneSystem/`) — the entity↔zone glue, a stateless system object with named methods (no World tick): `update(world, level, map, { tag?, onEnter?, onExit? })` fires enter/exit edges as entities cross borders (mark-and-sweep over `map._inside`, so leaving to an empty cell _or_ being removed both fire `onExit`); `zoneOf(world, level, map, id) → Zone`; `entitiesIn(world, level, map, id, { tag? }) → id[]`. Drive `update` from a scene's `step()` for events/weather/quests.

Zones live on the **`Level`** (they are level data): `level.addZoneMap(key, map?)` (sized to the grid by default), `level.zoneMap(key)`, and `level.zoneAt(key, wx, wy) → Zone` (world-space convenience). `Level.export`/`import` round-trip zone maps under a `zoneMaps` key, emitted only when non-empty so existing serialized levels are unaffected; `Level.destroy` tears them down.

To **visualize** a channel, add a `RenderZone` pass (see Renderer) to the scene's renderer: `renderer.insert(new RenderZone(level, "faction"))`; for the zone names add a `RenderZoneLabel` pass after it: `renderer.insert(new RenderZoneLabel(level, "faction", { font }))`.

The reference consumers are the RPG scene's **build mode** (`BuildMode`, see Genre UI managers) — a `"buildable"` channel whose region a Survey Post claims (`paintRect`), gating where tiles may be placed, drawn by a `RenderZone` pass — and its **`"climate"` channel** (see _Climate zones_ under Weather): regions that override the global `Weather` (forced condition + temperature offset) while the player is inside.

## Renderer

`Renderer` (`scripts/Renderer/Renderer.js`) is an ordered list of `RenderPass` objects (`{ draw(world), destroy() }`). `insert(pass, index?)` / `remove(pass)` manage the list; `draw(world)` runs every pass; `destroy()` tears them down. Each scene owns its renderer and calls `this.renderer.draw(this.world)` in `draw()`.

Built-in passes:

- **`RenderEntity`** — draws entities with `Visual` + `Position` via `draw_sprite_ext`. Interpolates between `PrevPosition` and `Position` by `world.alpha` when present (see `InterpolationSystem`); falls back to raw `Position` otherwise.
- **`RenderDebugBox`** — draws each entity as a filled `Visual.color` rectangle + black outline (GMRT can't render the SVG character sprites); interpolates via `InterpolationSystem.lerp`. **One concern — just the box.** The gameplay templates use it as the entity pass, pairing it with the single-concern overlays below inserted _after_ so each layer toggles independently (`enabled`): `RenderDebugName` (Name labels), `RenderDebugDirection` (facing dot), `RenderDebugAnimator` (animator state), `RenderDebugEntity` (lime bbox outline). For debug passes informativeness beats sharing a draw loop, so each cue is its own pass rather than baked into the box.
- **`RenderDebugName`** — `Name` labels (white) centered just above each entity's box top, for entities with `Name` + `Position`. Split out of `RenderDebugBox`; insert _after_ the box pass.
- **`RenderDebugDirection`** — a small facing dot offset from each entity's box center toward its `Direction` (skips zero-direction / invisible entities). Split out of `RenderDebugBox`; insert _after_ it. Only scenes whose entities carry `Direction` (platformer, Demo) add it.
- **`RenderDebugAnimator`** — each entity's current `Animator.state` as a yellow label below its box, so the sprite state machine is legible. `Animator` is in the Gameplay kit, so this pass lives in **`Gameplay/Animation`** (with `Animator`/`AnimationSystem`), **not** in `Core/Render` with the genre-agnostic Core passes. Split out of `RenderDebugBox`; insert _after_ it.
- **`RenderTileMap`** (`new RenderTileMap(layer, level, sprite, opt?)`) — hardware-accelerated tiles via `VertexBuffer`. `opt`: `{ autotile: 0|16|47|"dual"|"corner", alpha, color, softEdge }`. Call `.markDirty()` after tile changes to rebuild the VBO. Autotile: `0` = raw frame id, `16` = blob4, `47` = blob8, `"dual"` = dual-grid corner sampling, `"corner"` = quarter / sub-tile (13 half-cell pieces). Neighbor bits: `N=1, E=2, S=4, W=8` (blob8 adds `NE=16, SE=32, SW=64, NW=128`), so a blob4 tileset's frame index equals its cardinal-neighbor mask. `spr_tile16` is the project's 16-frame blob4 tileset and `spr_tile47` its 47-frame blob8 set — both consumed by the RPG levels (`RpgLevel`).
  - **`"dual"` (dual-grid)** — the blob modes draw one centered tile per _filled cell_ and cannot show two materials meeting (binary occupancy: a 2×2 filled block renders as a donut with blob4). Dual-grid instead renders a half-cell-**offset** grid where each display tile samples the 4 cells touching a grid _corner_; corner bits `TL=1, TR=2, BR=4, BL=8` → 16-frame index = mask (like blob4 but corner-keyed). Because a tile's empty corners stay transparent, **stacking several `"dual"` passes — one `TileLayer` per terrain, lowest priority first** — makes each upper terrain's border reveal the one beneath it, i.e. RPG-Maker-style A-over-B transitions with only a 16-frame corner tileset per terrain (no hand-drawn transition art). This is how the project supports _terrain-to-terrain_ blending; the priority stack is just ordered `Renderer` passes (no new class). `softEdge` is ignored in dual mode. `spr_tiledual` is the project's 16-frame corner tileset (frame N fills the corners of mask N); the **RPG overworld** is the reference composition — `TerrainStream` stacks per-material `"dual"` passes (water < sand < grass, `spr_tiledual` tinted per material).
  - **`"corner"` (quarter / sub-tile)** — the other corner-keyed mode: each _filled cell_ is drawn as **4 half-cell quadrants**, each quadrant's `cellWidth/2 × cellHeight/2` piece picked **independently** by the 3 neighbors touching that corner (both cardinals empty → outer corner; one cardinal → straight edge; both cardinals + diagonal empty → inner corner; all three → fill). The **13-piece** set — `0` fill · `1-4` outer TL/TR/BR/BL · `5-8` edge top/bottom/left/right · `9-12` inner TL/TR/BR/BL — reproduces the full blob8 look from 13 pieces and covers all 256 masks (no `_BLOB8` table; the per-corner selectors read bits inline off one neighbor int — no cached primitive-bool locals, which GMRT miscompiles). `spr_tilecorner`/`spr_tilecornerRough` are the project's 8×8 piece sets. Unlike `"dual"` (which keys per display-grid corner), `"corner"` keys per _cell_ but draws sub-tile pieces, so the material necessarily repeats every half-cell (pieces are position-shared) and borders read rounder. `softEdge` is per-cell-mode only — ignored for both `"dual"` and `"corner"`. (The kit's `tools/pixel-art-kit/common/tileset.py` synthesizes both the `"dual"` 16-frame and `"corner"` 13-piece sets from one material texture, seamless by construction.)
- **`RenderDebugEntity`** — `BBox` outlines (lime) for all entities with `Position` + `BBox`. Interpolates via `PrevPosition` + `world.alpha` like `RenderEntity`.
- **`RenderDebugPath`** (`new RenderDebugPath(level)`) — active `PathResponse` paths (yellow) + pending `PathRequest` goals (red cross).
- **`RenderZone`** (`new RenderZone(level, key, opt?)`) — world-space overlay for one **zone channel** (see Zones): fills each zone's cells by color and outlines region borders (only edges where the neighbor differs, so map edges outline too). `opt`: `{ alpha, border }`. Color is `zone.data.color` (`"#rrggbb"`) when set, else a stable hue from the zone id. Reads `level.zoneMap(key)` live each frame — a no-op until that channel exists, so it's safe to insert before zones are painted. Uses plain `draw_line` for borders (`draw_line_width_color` renders nothing on GMRT).
- **`RenderZoneLabel`** (`new RenderZoneLabel(level, key, opt?)`) — zone-name labels (white) at each zone's centroid for one channel. `opt`: `{ font }`. Split out of `RenderZone` so labels toggle independently; insert _after_ the zone pass.
- **`RenderGrid`** (`new RenderGrid(level, opt?)`) — cell boundary lines for a Level's grid. `opt`: `{ color, alpha, camera? }`. Split out of `RenderDebugTileMap` so the grid toggles independently; insert it wherever the grid is wanted (the RPG map + the level editor pair it with the debug tilemap pass). Plain `draw_line` (`draw_line_width_color` renders nothing on GMRT).
- **`RenderChunks`** (`new RenderChunks(chunkManager, opt?)`) — world-space pass for a `ChunkManager`'s streamed terrain (see Chunk Streaming & Sim-LOD below). Per active chunk: an opaque ground fill (a subtle checker by chunk parity, so chunk seams + streaming read at a glance; unloaded area stays the dark scene background = a visible "edge of the loaded world"), the chunk's wall rects, and — for LOAD-ring (frozen) chunks — each held entity **snapshot** as a dimmed box + name (matching `RenderDebugBox`/`Name`). SIM-ring entities are live in the World and drawn by the normal entity passes, so insert this **before** them (ground under everything). The active set is already tiny (bounded by `loadRadius`), so no per-chunk view cull. `opt`: `{ font, ground0, ground1, wallColor, frozenAlpha }`.
- **`RenderWeather`** (`new RenderWeather(opt?)`, Demo) — world-space weather pass driven by `Weather` (see _Weather_): a flat condition tint plus falling **rain** (`draw_line` streaks — `draw_line_width_color` renders nothing on GMRT) / drifting **snow** (`draw_rectangle` flakes), **cross-faded** by `Weather.blend()` (outgoing + incoming conditions both drawn during a change). Particles are screen-space over the view rect and animate on **`Time.raw`** (wall-clock — a visual effect, so they keep falling while the sim is paused); **no trig** (straight diagonal fall + a fixed per-particle base offset + uniform wind — `Math.sin`/`cos` are `undefined` on GMRT). Inserted **just before `RenderLighting`** so the night/light tint also darkens the rain. `opt`: `{ camera, maxParticles }`. Reads the view rect from the held `Camera`'s **own fields** (not `camera_get_view_*`; see CLAUDE.md); the scene assigns `pass.camera` after building the camera.
- **`RenderLighting`** (`Gameplay/Lighting`) — world-space 2D **light-map** pass: the RPG's lighting + day/night in one. Per frame it builds an off-screen surface cleared to its **injected `ambient` provider** (`() => { color, alpha }`; the demo wires `WorldClock.tint`) mapped to a **multiply** model (white in daylight → night hue when dark, scaled by `opt.darkness`, default 1.5), `bm_add`s a soft radial blob (`draw_circle_color`, hue→black) for every **`Light`** + `Position` entity, then composites it over the world **multiplicatively** (`gpu_set_blendmode_ext(bm_dest_colour, bm_zero)` → `scene × light`; no `bm_multiply` constant). So **day/night is "lighting with no lights"** and point lights (the player's lantern, torches) reveal the night. **Self-balancing:** in full daylight the ambient is white, so lights clamp to white and the multiply is a no-op — the pass early-outs (zero surface work). Lights are the **`Light`** component (`scripts/Light/`, `Gameplay/Lighting` — `{ radius, color, intensity?, flicker? }`); the player carries a lantern `Light` (`RpgPlayer.spawn`). **Falloff only — no shadows yet.** A **night vignette** multiplies the light map's corners down (a white-center→dark-edge radial reaching the corners, baked into the same surface), scaled by the cycle so it fades in at dusk and is gone in daylight with the early-out — multiplicative like the composite, so it deepens the scene toward the edges rather than alpha-blending a flat-black wash. `opt.vignette` is the corner-darkening fraction at full night (default 0.25; 0 disables). Inserted **last** in the RPG renderer (over tiles + entities + weather). `opt`: `{ camera, darkness, vignette }`; reads the view rect from the Camera's own fields (not `camera_get_view_*`), scene assigns `pass.camera`. The light surface is volatile (lost on resize/focus) — the pass guards `surface_exists` + recreates it on a size change.
- **`RenderDebugTileMap`** (`new RenderDebugTileMap(level, opt?)`) — overlay: cost shading, tile id/name + coordinate labels (grid lines are a separate `RenderGrid` pass). `opt`: `{ cost, tiles, coords, names, alpha, font, camera? }`. Call `level.syncAll()` first. Like `RenderGrid`, an optional **`camera`** (a `Camera` instance, settable later via `pass.camera`) culls iteration to the view rect (read from the Camera's `toX`/`toY`/`width`/`height` fields — `camera_get_view_*` returns 0 for the matrix-driven Camera; see CLAUDE.md), required for a large grid; omit for full-grid (small grids).

**`VertexBuffer`** (`scripts/VertexBuffer/`) wraps GameMaker vertex buffers with a fixed `position + texcoord + colour` format: `.begin()`, `.addQuad(x,y,w,h,u0,v0,u1,v1,color?,alpha?)`, `.addQuadV(...)` (per-corner alpha), `.end(freeze?)`, `.submit(texture)`, `.destroy()`.

## UI System

The GUI layer is a **fixed design resolution** (`UI.designW`×`UI.designH` = 1920×1080) divided by the `uiScale` Setting, set via `UI.applyScale()` in `obj_game` `Create_0` — **not** `display_set_gui_maximise`. So UI lays out the same on every monitor and GameMaker scales the GUI to the window; the SDF locale fonts keep text crisp at any GUI→window ratio. The `uiScale` slider applies **live**: it calls `UI.applyScale(v)`, which resizes the GUI layer and `markDirty`s every root so they reflow. For that reflow to be clean, full-screen chrome must fill via flex rather than snapshot `display_get_gui_height()` at build — the lobby and `SystemMenu` use `gemsTabs({ grow: true })` (root + content host flex-grow) over `gemsScroll({ grow: true })`, so they re-lay-out to the new GUI size with no rebuild (fixed-size windows like the RPG inventory keep `gemsTabs({ height })`). World cursor picking uses GameMaker's `mouse_x`/`mouse_y` (camera-space, GUI-independent); the one place mixing GUI-mouse with the application surface (`CameraPan`) scales GUI→surface explicitly.

- **`UIElement`** (`scripts/UIElement/`): tree node backed by `flexpanel` (GameMaker Flexbox). `insertChild`, `removeChild`, `addComponent(c)`, `getComponent(Class)`, `getComponents(Class)`, `removeComponent(c)`. `markDirty()` propagates to root; `refresh()` calls `flexpanel_calculate_layout`.
- **`UI`** (`scripts/UI/`): static root registry. `UI.insert(root, index?, enabled?)`, `UI.remove(root)`, `UI.setEnabled(root, bool)`. `update()` traverses in reverse (highest index blocks lower); `draw()` forward.
- **`UIComponent` interface**: `{ onUpdate?(element, block), onDraw?(element), onDestroy?(element) }`. Built-ins: `UIButton`; `UIText`; `UIRichText` (markup → colored spans `[c=#hex]…[/c]` + inline icons `[spr=name]`; self-sizes like `UIText`, host stacked lines in fixed-height rows); `UIImage`; `UIPanel`; `UITrigger`; `UISlider` (always-on value readout — `format`/`showValue`); `UISelect` (`< value >` cycler); `UIDropdown` (combobox field + chevron → popup list; the popup is an injected `onOpen(dropdown, field)` so Core stays theme-agnostic — `gemsDropdown` supplies a `UIModal` one, `UINav`-navigable + scrolling); `UIInput`; `UIRebind` (key-rebind row — click to arm "press a key…", next press rebinds); `UIProgress` (0–1 fill bar); `UICheckbox` (`style:"check"` box+tick or `"switch"` pill+knob); `UITooltip` (self-detecting hover tooltip, feeds the global `Tooltip`); `UIStepper` (`< n >` over min/max/step); `UISlots` (inventory-slot grid; `draggable` opts into `SlotDrag`; immediate-mode); `UITabs` (tab strip — one focus stop, swaps content by `enabled`, no reflow); `UIAccordion` (collapsible; confirm expands); `UIScroll` (vertical scroll for a `clip` viewport — draw-time `scrollY`, never flex mutation); `UIModal` (full-screen exclusive backdrop, blocks pointer + nav, Esc/backdrop close; built by `gemsModal`); `UIDrag` (window drag handle — accumulates into `target.dragX/dragY`, offset-not-mutation); `UIResize` (window resize grip — companion to `UIDrag`, lives on a bottom-right grip; captures the target's current laid-out size on grab then sets `target` width/height via flexpanel mutation (`setWidth`/`setHeight`), clamped to `[minWidth/minHeight, GUI]`. Unlike drag it genuinely changes layout, so it mutates style rather than offsetting — the reliable-on-0.20 path `UIText` self-sizes with); `UINineSlice` (sprite-skinned panel; source needs nine-slice in the IDE); `UIMinimap` (radar-blip view of a `World`, `rules` `[{ has, color }]` where `has` is a component token — an entity blips when it carries that component); `UIQuestTracker` (live list bound to an **injected quest source** — `opts.source`, the RPG passes its `QuestLog` — so this Core widget never references the RPG layer; immediate-mode, resolves `I18n.font(key)` at draw time); `UITable` (data table — declarative columns with text/color/icon accessors, a multi-key sort stack (click a header → primary key, re-click flips), external `setFilter`, `setColumns` (remaps the sort by each column's stable `key`), identity row-selection, sticky header, row-based scroll, zebra striping. Immediate-mode over ONE element so re-sort/filter never reflows; draw geometry recomputed each `onDraw` so it stays glued to a dragged window. **Browse mode**: `navActivate` enters it, then the table owns the arrows via a per-frame `UITable.active` claim that `UINav.consume()`s. Built by `gemsTable`; public reads are METHODS (`getView`/`getRows`/`getSelected`) — an external `table.view` faults on GMRT).
- **`Tooltip`**: standalone static class (not a `UIComponent`). `Tooltip.set(str)` from anywhere; renders once per frame at mouse position via `Tooltip.draw()` in `Draw_75`.
- **`Toast`**: standalone static class (not a `UIComponent`), same pattern as `Tooltip`. `Toast.push(str, opts)` from anywhere; `Toast.draw()` in `Draw_75` (after `Tooltip`) ages the stack by `Time.raw` and renders a bottom-center timed stack (newest at bottom). `opts`: `{ duration, type ("info"|"success"|"warn"|"error"), accent }` — `type` picks the left accent-stripe color; entries fade/slide in+out and are culled when expired (`Toast.maxItems` cap drops the oldest).
- **`UIPointer`**: standalone static class (not a `UIComponent`) — the UI's frame-latched pointer state. `UIPointer.poll()` runs in `Step_0` before `UI.update` and latches the left-button edges + level + wheel once per frame into `UIPointer.pressed`/`released`/`down`/`wheel`. Every UI widget + UI-layer reader (`SlotDrag`/`BuildMode`/`DebugInspector`/`Dialogue`) reads those static fields instead of calling `mouse_check_button*`/`mouse_wheel*` directly — those are realtime-sampled on GMRT, so re-reading the same query in a frame can diverge, and a per-widget `const pressed = …` is also the cached-bool clobber pattern (see GMRT-Safe Idioms). One query/frame, shared.
- **`SlotDrag`**: standalone static class (not a `UIComponent`) backing drag-and-drop between `UISlots` grids (built with `draggable: true`). Reads the latched pointer edges from `UIPointer` (never `mouse_check_button*` directly — see the realtime-sampling note in GMRT-Safe Idioms). A grid calls `SlotDrag.begin(grid, i)` on `pressed` over a filled slot (picks it up; source slot empties, floating icon drawn in `SlotDrag.draw()` in `Draw_75`), then `SlotDrag.hover(grid, j)` each frame the cursor is over one of its slots to **record** the drop target. `SlotDrag.update()` (`Step_0`, after `UI.update`) resolves on the release edge: drop onto the last-recorded slot (swaps occupants, works across grids), or — if none was ever hovered — restore to source. The recorded target is _persisted_ (not cleared when the cursor leaves a slot), so a small drift off the slot as the button comes up still drops. (Note: `UISlots.onUpdate` keeps the hit-test in instance fields `this._inside`/`this._hover`, not boolean local consts — those get clobbered mid-function on GMRT; that was the long drag-drop bug.)
- **`VirtualKeyboard`**: standalone static class (not a `UIComponent`) — on-screen keyboard for gamepad/mouse text entry into a `UIInput`. `VirtualKeyboard.open(input)` pops a `gemsModal` (exclusive backdrop, blocks background nav, Esc/backdrop cancels) whose body is a preview line + a grid of character keys; the keys are ordinary `gemsButton`s, so the whole keyboard is `UINav`-navigable for free (dpad/stick to move, A/Enter to type). Keys edit an in-memory buffer; **Done** commits to the field (`setValue` + `onConfirm`), Cancel/Esc/backdrop discard — the field is untouched until Done. Shift toggles letter case via live key labels (no relabel). `VirtualKeyboard.isOpen()` is a **method, not a `static get`** — a static getter with a comparison body miscompiles on GMRT 0.20 (verified; see CLAUDE.md), and yielded `undefined` outright on 0.19.
- **`UINav`**: standalone static class — keyboard/gamepad menu navigation, touching neither `UI` nor `UIElement`. An element is **focusable** by duck-typing: a component implements `navActivate(element)` (confirm) and/or `navAxis(element, dir)` (horizontal adjust, `dir` = ±1). `UINav.update()` (`Step_0`, after `UI.update`) walks the enabled roots, collects focusables with a valid on-screen rect, and routes input: arrows/dpad/stick move focus to the geometrically nearest focusable in that direction (edge-aware `_pick` — the perpendicular term is the gap between rects, ties broken by collection order, so Down lands on the leftmost item below); a horizontal press over a `navAxis` widget tweaks it; Enter/Space/`gp_face1` → `navActivate`; Esc/`gp_face2` disengages. `UINav.draw()` (`Draw_75`) draws a pulsing focus ring. Collection **stops at an exclusive root** (`navExclusive() → true`, e.g. an open `UIModal`), mirroring the modal's pointer block. Focusables scrolled out of a `UIScroll` stay collectable; when focus lands on one, `_scrollIntoView` nudges each `UIScroll` ancestor so it comes into view. Engagement: the first nav input only engages + focuses; moving the mouse disengages; while a field is typed (`UIInput.active`) or a `UITable` is in browse mode (`UITable.consume()`), nav is suspended so the caret keeps the keys. `obj_game` calls `UINav.reset()` on each scene swap and seeds `UINav.color` from the theme. Nav hooks live on `UIButton`/`UICheckbox`/`UISelect`/`UIDropdown`/`UIStepper`/`UISlider`/`UITabs`/`UIAccordion`/`UITable`/`UIInput`; any new widget becomes navigable by adding `navActivate`/`navAxis` (a blocking root by adding `navExclusive`). **Debug**: hold `UINav.debugKey` (Tab) to draw every focusable boxed + numbered with direction lines from the focused element.
- **`SceneTransition`**: standalone static singleton — full-screen fade between scenes, replacing `obj_game`'s hard cut on `openScene`. `start(applyFn)` fades OUT to a solid cover, swaps the scene at full cover (`applyFn` rebuilds the UI hidden under the cover), then fades back IN. Wiring: `SceneTransition.update()` in `Step_0` (drives the timer + fires the swap at mid-fade, gated by `isBusy()`); `SceneTransition.draw()` **last** in `Draw_75` so the cover veils the UI teardown/rebuild too. Timer uses `Time.raw`.
- **`Dialogue`**: standalone static singleton — RPG paged dialogue box with typewriter reveal. `Dialogue.start(pages, opts)` (a page is a string or `{ speaker, text }`); reveals at `opts.speed` chars/sec (`Time.raw`), advances on Enter/Space/`gp_face1`/click. `Dialogue.update()` in `Step_0`, `Dialogue.draw()` in `Draw_75` (over the UI). Static fields are initialized with literals, not `Dialogue.x` self-references (the static-initializer self-reference quirk in CLAUDE.md).
- **`FloatingText`**: standalone static singleton — **world-space** floating combat numbers (damage/heal) that rise + fade. `FloatingText.push(x, y, value, opts)`; drawn from a **scene's own `draw()`** (inside the camera view), _not_ `Draw_75`. `obj_game` calls `FloatingText.clear()` on each scene swap (a number must not survive into the next scene). Ages by `Time.delta` (sim time — slow-mo slows the numbers too), unlike the GUI singletons on `Time.raw`.
- Many `flexpanel_node_style_*` setters in `UIElement` stay commented to keep the class under the 50-method ceiling (#15065); enable one on demand (see the flexpanel GMRT-Safe Idiom).

## Input System

**`Input`** / **`InputAction`**: `Input.register(key, action)`, `Input.get(key)` → `InputAction`. Query: `.down()`, `.pressed()`, `.released()`, `.value()`. Bind: `.bindButton(source, button)` / `.bindAxis(mode, axis)`. Display: `action.label()` → the primary binding as UI text (e.g. `"W"`/`"Shift"`/`"LMB"`), delegating to `InputButton.label()` / `InputButton.keyName(code)` (the one keycode→string table). This is the single binding→text source shared by the rebind row (`UIRebind`) and the live hint bar (`gemsKeyHints`), so a remap renders the same string everywhere. Bulk: `Input.bindAll({ key: [source, button], … })` registers a whole keymap in one call; `Input.unbindAll([keys])` removes them — used by the genre controllers. **All four query methods return falsy while a text field owns the keyboard** (`UIInput.active !== null`, via `InputAction.captured()`): typing in a UI field (e.g. the RPG inventory search) must not also drive gameplay hotkeys/movement — pressing `i` while typing "Hi" can't toggle the inventory. This is the same `UIInput.active` signal that suspends `UINav`; `UIInput` clears it on blur **and on destroy** (so tearing a focused field down at a scene change can't strand the capture).

**`InputContext`** (`scripts/InputContext/`, Core) — a named-context **stack** over the Input layer that generalizes `captured()` from "a text field mutes everything" to "the active context decides which actions are live." The active context is the top of the stack (base is always `"default"`); `push(name)`/`pop()`/`set(name)` (replace top — auto-pushes if only the base remains, so a forgotten `push` can't clobber `"default"`)/`reset()` (back to `["default"]`)/`active()`/`is(name)`. An `InputAction` may declare the contexts it is live in via `action.inContext(["play","window"])` — or, declaratively, an **optional 3rd element** in a `bindAll` spec entry (`fire: [INPUT_SOURCE.MOUSE, mb_left, ["play"]]`). The query methods then add `_blocked()` (`contexts !== null && !InputContext.allows(contexts)`) to the existing `captured()` guard. An action with **no** declared contexts (the default, `contexts === null`) is live in every context, so all existing keymaps (platformer/UI) are unaffected — only opt-in tagged actions are gated. `captured()` still wins (a focused field mutes regardless of context). Contexts/tags are **not serialized** (`Input.export`/`import` ignore them) — a controller re-applies them in `create()` each scene, so a saved/rebound keymap never loses its tags.

The **RPG scene** is the reference consumer: `RpgController.create` tags its keymap — movement live in `["play","build","window"]` (the player keeps walking with a window open), `fire` `["play"]` only (so it **self-mutes** while building — LMB places tiles — or with a gameplay window open — clicks don't shoot — replacing the old `!BuildMode.active` reach-in), `interact` `["play","window"]` (open in play, close a station window in window; inert while building), `build`/`follow` `["play","build"]`. `sceneRpg` pushes `"play"` in `create()`, resets in `destroy()`, and each `step()` (before the tick loop, so the tick's movement/fire reads see it) calls `_resolveContext()` → `InputContext.set(...)` with **window > build > play** priority (`invOpen`/`_storeOpen`/`_craftOpen` → `window`; else `_buildActive` → `build`). A window thus **pauses** build mode (`BuildMode.update` gates `active` on `InputContext.is("build")`, so LMB/RMB on the window can't place/remove tiles) and resumes it on close. The single `E` press is arbitrated in one place — `sceneRpg._dispatchInteract()`: a station window open → `E` closes it; else pick station-vs-NPC by **cursor (`Interactable.isCursorOver`), then nearest to the player**, and call `Interactable.activate(scene)` or `scene._npcActivate()`. `Interactable.update`/`_updateNpc` only do proximity/prompt/dialogue text — no input reads.

## `EntityPreset`

`EntityPreset` (`scripts/EntityPreset/`) spawns entities from named presets:

```js
EntityPreset.register([
  {
    id: "enemy",
    components: { Velocity: { x: 0, y: 0, z: 0 }, Lifetime: { ticks: 120 } },
  },
]);
const id = EntityPreset.spawn("enemy", world, x, y, z);
EntityPreset.has("enemy");
EntityPreset.get("enemy"); // → boolean / preset or undefined
```

## `Query` — Spatial Entity Lookup

`Query` (`scripts/Query/`) searches entities with `Position`:

```js
Query.nearest(world, x, y, opts); // → id or -1
Query.farthest(world, x, y, opts); // → id or -1
Query.inRect(world, x1, y1, x2, y2, opts); // → id[]
Query.inRadius(world, x, y, radius, opts); // → id[]
```

`opts`: `{ has?, maxDist?, hasCollision? }`. `has` filters to entities carrying that component (its token) — presence, not a tag string (the `Tag` component was removed; markers like `NPC`/`Portal`/`Follower`/`Raider`/`Rat` are queried directly).

## Utility Modules

- **`Settings`**: persists to `settings.json` (`Settings.PATH`). `registerDefaults({...})` before `load()` at startup (calls merge additively). `get(key)` falls back to defaults; `set(key, val)` updates memory; `save()` writes only keys present in defaults.
- **`Color`**: `Color.rgb(r,g,b)`, `Color.hsv(h,s,v)`, `Color.merge(c1,c2,t)`, `Color.parse("#rrggbb")` → GameMaker color ints; `Color.alpha(color)` → alpha byte `[0,1]`.
- **`I18n`**: `I18n.load(manifestPath)` reads a `manifest.json` listing text-file masks (e.g. `text/*.json`), fonts, images, sounds; flat `{ key: value }` text JSON is merged into `I18n.texts`. `I18n.text(key, ...params)` or `I18n.textRef(...)` (a `() => string` for live-updating UI labels); fonts via `I18n.font(key)`. Ships `en-US` (default, loaded in `obj_game` `Create_0`) and `ko-KR`, each declaring its own Noto Sans in its `manifest.json` (en-US `Noto Sans`, Latin-1 range; ko-KR `Noto Sans KR`; both SIL OFL 1.1, SDF). Strings are split by genre under each locale's `text/`: `common`, `platformer`, `rpg`, `rts`, `map` (the `text/*.json` mask merges them all). Fonts are keyed by role, not size: `default` (Regular 12), `header` (Bold 16), `description` (Regular 10). Both locales declare all three, so `I18n.font(...)` resolves to the bundled Noto Sans (an undeclared key still falls back to `draw_get_font()`).
- **`Camera`** / **`CameraFollow`** / **`CameraPan`**: `Camera` wraps a `camera_*` handle (ORTHO, PERSPECTIVE, PERSPECTIVE*FOV). `CameraFollow` and `CameraPan` are namespace objects of factory methods (PascalCase, like `CameraFly`): `CameraFollow.create({ world, followTarget, followLerp?, followHeight?, ... })` — 3D perspective follow; `CameraFollow.create2d({ world, followTarget, followLerp?, width?, height?, ... })` — 2D orthographic (pixel-snapped); `CameraPan.create({ ... })` — drag-to-pan + wheel-zoom orthographic camera (the level editor). All read from `world` where relevant. Call `.update()` each step and `.assign(viewIndex)` to attach to a viewport. Note: `view_camera[]` is not exposed in GMRT — hold the `Camera` instance and read the view rect from its own fields (`toX`/`toY`/`width`/`height`), **not** `camera_get_view_*` (which returns 0 for the matrix-driven Camera; see GMRT-Safe Idioms).
- **`Audio`** (`scripts/Audio/`, Core): the project's **sound wrapper** — a thin static-singleton facade over GameMaker's `audio_*` API (one audio space, like `ParticleFx`), playing the **audio-kit**'s `GMSound` assets (`snd_*` SFX, `mus_*` BGM; see _Tools_ in CLAUDE.md). Three play paths: `play(name, opts)` non-positional 2D cue (UI/global), **`playAt(name, x, y, opts)` SPATIAL** (`audio_play_sound_at` — attenuated + panned relative to the listener), and `bgm(name, opts)` looping music cross-faded on `Time.raw` (re-requesting the playing track is a no-op; `update()` reaps the finished fade, `stopBgm()` ends it). Spatial needs a **listener + distance model**, both owned here: `setup()` (obj_game `Create_0`) selects `audio_falloff_linear_distance_clamped` (the default is `audio_falloff_none` = no attenuation), fixes the 2D listener **orientation** once (`audio_listener_orientation(0,0,1, 0,-1,0)` → only `x` drives L/R pan, y maps to front/back — right for a top-down view), **loads the `bgm`/`sfx` audio groups** (the `mus_*`/`snd_*` assets live in those non-default GMAudioGroups, which must be `audio_group_load`'d before playback), and applies the saved `Settings` `volMaster`/`volMusic`/`volSfx` — **category volume is the audio-GROUP gain** (`setMusicGain`/`setSfxGain` → `audio_group_set_gain(bgm/sfx)`, `setMasterGain` → `audio_master_gain`), so it scales every playing sound in the group live, including the BGM, with no per-sound bookkeeping; the **SystemMenu** volume sliders call these setters in their `onChange` (Settings-bound; the Save button persists). **`listener(x, y)`** (the RPG scene, each frame, from `camera.toX/toY`) moves the ears. Falloff window is the 16px world's (`REF`/`MAX`/`FACTOR` = full volume within 48px, silent past 400px; override per `playAt`). Wiring mirrors `ParticleFx`: `setup` in `Create_0`, `update` in `Step_0`, `reset` (stop BGM + all SFX) in `SceneManager._apply` only — **not** across a guest push or an RPG map change, so music carries over. State is read-write static fields + plain methods (no static getters — GMRT). **Wired into the Demo** at Demo-layer chokepoints (the genre-agnostic kit systems stay silent): the RPG plays `mus_overworld` (`sceneRpg` create + resume) with spatial SFX — `snd_shoot` (`RpgController._fireGun`), `snd_hit`/`snd_hurt` (impact, in `RpgScene._diffHp` beside the floating-number push — enemy "hit", ally "hurt", the death-blow deferred to the death pass), `snd_explosion` (`resolveHealth.onDespawn`), `snd_coin` (`collectDrops` callback), `snd_powerup` (`RpgInventoryUI` consumable use); the Platformer plays `mus_battle` with non-positional `snd_jump` (`PlatformerController.update`), `snd_hit` (stomp), `snd_hurt` (`PlatformerController.respawn` — covers touch/spike/void). **Core UI cues** (non-positional): `snd_ui_confirm` on activation — `UIButton`'s mouse click + `UINav`'s confirm dispatch (one place, covering every focusable widget on the gamepad/keyboard path) — and `snd_ui_move` on a `UINav` focus change (press-edged input, so one cue per move). All 9 SFX + 2 BGM are wired; the only gap is a mouse click on a non-button widget (covered for gamepad/keyboard via `UINav`).
- **`Tween`**: static easing + frame-rate-independent smoothing helper for UI motion (pure methods; callers keep their own state). Two families: `approach`/`approachColor` (exponential smoothing toward a _moving_ target, no fixed duration — UIButton's hover/press easing) and the easing _curves_ (`easeOutCubic`/`easeInOutQuad`/…) mapping `t∈[0,1]` for _timed_ 0→1 motion (Toast/modal enter, FloatingText pop).
- **`MotionPlanner`**: static A\* on `MotionPlanningGrid`. `MotionPlanner.plan(start, goal, algorithm?, opt?)` → `{x,y}[]`. Options: `allowDiag`, `cornerCutting`, `heuristicWeight`, `maxIter`.
- **`AABB`**: world-space box geometry that owns the non-uniform `BBox`-anchor convention (see Component Pattern note). `AABB.edges(pos, box)` / `AABB.of(world, id)` → `{ x1, y1, x2, y2, cx, cy }`; `AABB.overlap(a, b)` → strict overlap (touching edges don't count). Every collision/geometry system derives edges through this, never inline `pos.x + box.x` — consumers: `SolidSystem`, `SeparationSystem`, `TriggerSystem`, `BlockSystem`, `EnemySystem`, `Raycast`, `RenderDebugEntity`. (`Query` is _not_ a consumer — it does point-vs-rect tests on `Position` only.)
- **`Broadphase`** (`scripts/Broadphase/`): Uniform-grid broadphase for O(n) physics pair queries. `new Broadphase(worldWidth, worldHeight, cellSize)` — `cellSize` must exceed entity full diameter so center-based bucketing guarantees all overlapping pairs are in adjacent cells. `clear()`, `insert(id, cx, cy)`, `pairs(fn)` (calls `fn(a, b)` per candidate pair, no duplicates). Assign to `world.broadphase` to opt `SeparationSystem` and `TriggerSystem` into the broadphase path; scenes without it fall back to O(n²). Apply selectively — crowded scenes (many slimes/units) benefit; scenes with few interacting bodies (platformer) don't need it. Currently no scene sets it — the RPG's `SeparationSystem` runs O(n²) over its handful of dynamic bodies, which is cheap; wire a `Broadphase` onto `world.broadphase` if slime counts grow.
- **`Raycast`**: static segment-vs-AABB cast over all collider entities. `Raycast.cast(world, x0, y0, x1, y1, opts)` → nearest hit `{ id, x, y, nx, ny, t }` or `null`; `Raycast.castAll(...)` → **all** solid hits along the segment, ascending by `t` (the multi-hit form for hitscan pierce walks). `opts`: `{ ignore?, solidOnly? (default true), mask? }`. Shared by `ProjectileSystem` (bullets), `Combat.hitscan` (gun/turret shots), and line-of-sight queries.
- **`File`**: sync I/O. Text: `File.find(mask)` → `string[]`, `File.read(fname)` → `string|undefined` (NUL-terminates the loaded buffer so `buffer_text` can't over-read past EOF into uninitialized memory — that over-read corrupts `JSON.parse` non-deterministically, the bug that long looked like a runtime memory fault), `File.write(fname, data)` → `boolean`. Binary: `File.readBuffer(fname)` → buffer handle (caller owns it, must `buffer_delete`) or `undefined`, `File.writeBuffer(fname, buffer)` → `boolean` (saves only the _used_ bytes via `buffer_save_ext` + `buffer_get_used_size`, so a `buffer_grow` buffer's over-allocation doesn't pad the file). Use the binary path for tile grids / dense or large data — JSON text both hard-faults on nested values and has an O(n²) serialize cost for big inline arrays. Async binary: `File.saveAsync(fname, buffer, cb?)` / `File.loadAsync(fname, cb)` wrap `buffer_save_async`/`buffer_load_async` — they return a request id, register it, and the completion arrives in `obj_game`'s **Async Save/Load event** (`Other_72`), which calls `File._resolve(id, status)` to fire the callback on the main thread (`saveAsync` → `cb(ok)`; `loadAsync` → `cb(buffer)` on success, caller then owns it, or `cb(undefined)` on failure). For streaming a huge save without freezing the frame, and the form console vendors (Xbox/PS/Switch) **require** to pass cert. ⚠️ **GMRT 0.20**: a known open runtime bug — GMRT's `buffer_save`/`buffer_save_ext` (and these async variants) fail to create the destination directory ([#15223](https://github.com/YoYoGames/GameMaker-Bugs/issues/15223)) — trips on the forced `default/` subfolder, so on desktop GMRT the write silently no-ops while `buffer_save_async` still reports `status:true` (false positive). Use the sync `writeBuffer`/`readBuffer` on desktop (root-level files need no new directory, so they're unaffected); the async path is for console and should work once #15223 is fixed. The event-routing plumbing (event → `_resolve` → callback) is verified good. (Both `saveAsync`/`loadAsync` round-trip with **each other** — they share the `default/` prefix, unlike the sync readers.)
- **`Log`**: text-based behavior verification (there are no tests). `Log.info/warn/error/debug(msg)` buffer timestamped lines; `obj_game` calls `Log.clear()` at startup and `Log.flush()` once per frame (only rewrites `game.log` when dirty). Read `game.log` to confirm runtime behavior without watching the window. `Log.exception(ex)` is the unhandled-exception handler `obj_game` registers via `exception_unhandled_handler` in `Create_0` — an uncaught runtime fault is written to `game.log` (`UNHANDLED EXCEPTION: <message>`) and flushed before the runner closes the game (it returns a non-zero exit code). Without it a mid-frame crash just stops the log at its last flush with no reason recorded. GMRT populates only `ex.message` for JS runtime faults (`script`/`line`/`stacktrace` come through empty), so only the message is logged.
- **`Debug`** (`scripts/Debug/`, Core): the **back-end** of the debug system — a registry of named panels that does **not** render, so a human and an agent debug the same state through different front-ends. `Debug.panel(name, (p) => …)` populates a panel via emit closures: `p.watch(label, fn)` / `p.watch(label, obj, key)` / `p.slider` / `p.checkbox` / `p.dropdown` / `p.input` (editable scalar) / `p.button` / `p.text`. Each entry is a **live binding** — a getter fn (read-only) or an `(obj, key)` pair (read/write live); the discriminator is whether a `key` arg was passed, **not** `typeof` (a class like `Time` is itself a function, so `typeof`-routing would mis-bind and later call `Time()` — a crash). Two front-ends: (1) **text** — `Debug.update()` (in `Step_0`) periodically writes `Debug.snapshot()` to **`debug.txt`** (the agent-readable view); (2) **ImGui** — `DebugImGui` (Core), the human overlay (toggle **F3**) via `show_debug_overlay` + `dbg_view`/`dbg_*` + `ref_create`. Since `ref_create` needs a `(struct, "field")` pair but an entry is often a getter fn, each gets a plain **mirror** `{ v }`; `refresh()` syncs it each frame (pull for read-only, change-detected push for editable, so an external write like the pause `Time.scale=0` isn't clobbered by a stale slider). Agent control: `Debug.set(panel, label, value)` / `Debug.press(panel, label)` from a temp harness, then verify on the game surface. Built-in panels `Time`/`Perf`/`Log`/`Sim` (the relocated sim controls — Pause / Step Frame / Restart Scene) + **`DebugRender`**'s `Render` (per-pass overlay toggles, each finding the live scene's pass by `instanceof` and flipping `enabled`) register in `obj_game` `Create_0`; Core lists only Core passes — a genre layer contributes its own via `DebugRender.add(cls, label)` (the RPG registers `RenderDebugAnimator` from `RpgMap.build`, since that pass reads the Demo-layer `Animator`), keeping Core decoupled. `DebugImGui` rebuilds on a `Debug.version()` change into **two windows** kept independent so one's churn doesn't move the other: a stable **Debug** view (Time/Perf) and a live **Inspector** view (the `Entity` panel), the latter kept alive across picks (only its `dbg_section` is swapped — there's no `dbg_set_view` on GMRT). Each panel is an explicit `dbg_section` (else GM bleeds the first control onto an auto "Default" header).
- **`DebugInspector`** (`scripts/DebugInspector/`, Core): the ECS entity inspector over `Debug`. While the overlay is open, left-clicking a world entity (`Query.nearest` from a cursor→world unproject via the scene camera's `toX/toY/width/height`) selects it; `select(world, id)` reads `world.componentsOf(id)` and registers an **`Entity`** panel exposing every component's scalar fields — numbers/strings as editable `input`s, booleans as `checkbox`es — bound LIVE to the component data objects, so an edit (in the overlay, or `Debug.set("Entity", "Health.hp", …)`) mutates the real entity. `draw(game)` highlights the selection on the GUI layer (reprojecting its `Position`). The Entity panel stays **registered at all times** (a placeholder line when nothing is selected) so its Inspector window is present from the moment the overlay opens, like Time/Perf; Deselect or a stale selection (entity removed / scene swapped) empties it to the placeholder rather than removing it. Wired in `Step_0` (`update`) + `Draw_75` (`draw`). While the overlay is open, `InputAction._debugMuted` mutes gameplay **mouse** input (so a pick-click can't fire the weapon) and **keyboard** input only while `is_keyboard_used_debug_overlay()` (typing in a `dbg_text_input`), so WASD still roams while inspecting.
- **Utils** (`scripts/Utils/`): global helper grab-bag — `noop()`, `uuid()` → UUID v4, `rem(value)` → pixel size relative to current font size.
