# G.E.M.S. Architecture

Detailed architecture reference for **G.E.M.S.**, imported into context by [CLAUDE.md](CLAUDE.md) (via its `@ARCHITECTURE.md` line), so it is always loaded alongside it. See CLAUDE.md for the project overview, build & run, asset-creation workflow, code style, and the **GMRT-Safe Idioms** that always apply — those live there (kept always-in-context) and are referenced by name in code comments.

## Demo Layer — `obj_game`, `Level` & `LevelManager`

`obj_game` is the unified controller — it drives global system ticks each event and **delegates the scene lifecycle to `LevelManager`** (held as `this.scenes`, an alias of `World.levels`).

```
Create_0 → display/GPU setup; Log.clear/info; Settings defaults + load; I18n.load for `Settings.language`; this.scenes = World.levels (= new LevelManager()); scenes.start(SCENES.lobby) [the lobby is the boot scene + dev launcher; F2 returns to it] + SceneTransition.reveal()
Draw_0   → draw_clear(background), this.scenes.draw()
Step_0   → Time.update(), UIPointer.poll(), UI.update(), SlotDrag.update(), SystemMenu.update(this), UINav.update(), Dialogue.update(), this.scenes.update() [pending→SceneTransition.start + SceneTransition.update()], this.scenes.step() [skipped while SystemMenu open or Debug-paused, except a one-frame Step], Log.flush()
Draw_75  → UI.draw(), UINav.draw(), SlotDrag.draw(), Tooltip.draw(), Toast.draw(), Dialogue.draw(), SceneTransition.draw(), F5 screenshot
CleanUp  → Log.info("game end"); this.scenes.destroy() (before UI.destroy — it removes the scene's UI roots), UI/Input/I18n cleanup; Log.flush() last (Step_0's flush won't run again, so teardown logs would otherwise be lost)
Other_72 → Async - Save/Load (event-driven): completion of File.saveAsync/loadAsync — reads `async_load` `id` + `status` and calls File._resolve to fire the request's callback
Other_75 → Async - System (event-driven, not per-frame): gamepad connect/disconnect — reads `async_load` `event_type` ("gamepad discovered"/"gamepad lost") + `pad_index` and logs it
```

GameMaker's built-in per-instance events: **Create** (`Create_0`) runs once at boot; **Step** (`Step_0`) every frame (game logic); **Draw** (`Draw_0`) every frame to the `application_surface` (camera-transformed world view); **Draw GUI End** (`Draw_75`) every frame on the **GUI layer** (own resolution, not camera-transformed — so HUD / windows / overlays live here; it's the _End_ sub-event because `screen_save()` is only permitted there). **Clean Up** (`CleanUp_0`) fires at game end (single room, no transitions). The two **Async events** (`Other_72` Save/Load, `Other_75` System) are event-driven, not per-frame — the runtime triggers them on a callback and passes a `ds_map` in `async_load`, read via `ds_map_find_value` (the `[? ]` accessor is GML-only). `Other_75` (System) fires on a system-level callback (here, a gamepad being plugged in or removed) and only because the project already calls `gamepad_*` functions (`UINav`/`UITable`/`SystemMenu`/`Dialogue`) — the runner skips initialising the pad subsystem otherwise. `Other_72` (Save/Load) fires on a `File.saveAsync`/`loadAsync` completion (see _Utility Modules → File_).

**`LevelManager`** (`scripts/LevelManager/LevelManager.js`, Core — held as `World.levels`, aliased as `obj_game`'s `this.scenes`) owns the level lifecycle as a **flat collection with one active pointer** — there is **no scene stack**. **Only the active level is stepped + drawn**; **`switchTo(factory, opts)`** is the single transition: by default it **destroys every live level** and fades to the new one (plain navigation), while `keep: true` **freezes the current level as-is** (`suspend()` hides its UI; its world/state stay untouched in the collection) and **`back()`** later thaws it. `current` (an instance getter — GMRT-safe, unlike static computed ones) exposes the active level. `obj_game` delegates `update()`/`step()`/`draw()`/`destroy()` to its `this.scenes` instance; `SystemMenu` reads/restarts/quits the live level through the manager (`scenes.current`, `scenes.label()`, `scenes.restart()`, `scenes.switchTo(factory)`). A plain instance class, not a static singleton (GMRT static-getter quirk). It also carries the **resident-map registry** (`register`/`entryOf`/`ids`/`take`/`put`/`transfer`, the old Universe) — which **is the RPG's map pool**: a registry entry is opaque to Core beyond `{ world, level }`, and `RpgMap` parks its full map bundle there at each suspend. See _Map graph_.

- **Base navigation** — `switchTo(factory)` (the `openScene` callback handed to each `create()`) queues a faded swap that **destroys every live level** first (a quit from a guest also drops its frozen host); `_apply` resets the cross-scene singletons (`UINav`/`SystemMenu`/`Dialogue`/`FloatingText`/`ParticleFx`). The app **boots into the lobby** (`scenes.start(SCENES.lobby)`) — the dev launcher / scene catalogue, also reached via **F2** (gated by `DEV_MODE`); from it the RPG + other genres open.
- **Guest minigames** — `switchTo(factory, { keep: true, onResult })` freezes the host and runs a guest in front (no fade — an instant in-world switch); `back()` reads the guest's optional `result()`, destroys it, thaws the host, and fires `onResult(result)`. **One kept level at a time** (no nesting — a second keep-switch warns and refuses). The world-space singletons (`FloatingText`/`ParticleFx`/`Dialogue`) are cleared across both boundaries so a host's leftovers don't bleed into the guest. The reference consumer is the RPG **arcade cabinet** (an `Interaction` of kind `"arcade"` → `sceneRpg._openArcade` → a kept switch to `ScenePlatformer`, rewarding coins from the run's `result()` score). A guest is exited with **Esc / gamepad-B** — `SystemMenu` calls `back()` (returns false when nothing is kept), before falling through to the pause menu. The genre showcases (`scenePlatformer`, …) are thus reusable as embedded minigames unchanged; the host depends on a guest only via the factory it switches to.

**`Level`** (`scripts/Level/Level.js`) is **not a base class to extend** — it is (1) the **duck-typed screen contract** LevelManager drives, and (2) the **blank screen** menus instantiate bare (the lobby's `Object.assign(new Level(), { create, destroy })`, its no-op stubs covering the rest). The contract: `create(openScene)` / `step()` / `draw()` / `destroy()` are required (called unconditionally); `suspend()`/`resume()` (keep-switch freeze/thaw), `result()` (a guest's return value), `handleEscape()` (SystemMenu's Esc hook), and the `label`/`gameplay` fields are optional. The genre screens (`sceneRpg`/`scenePlatformer`/`sceneEditor`/`sceneUIKit`) are **standalone classes** satisfying it — composition, never `extends Level` (GMRT subclassing is broken: subclass field inits don't run, `super` faults). Screens are **factory functions** returning a fresh instance each time they open. `create(openScene)` receives the navigation callback (`LevelManager.switchTo`); the manager also sets `scene.manager` (the back-ref a host uses to open guests — `switchTo` with `keep: true`). **`suspend()`/`resume()`** freeze/thaw a screen while a guest runs in front — a host with extra state defines its own (the RPG re-binds its keymap on `resume`, since a guest controller's `destroy` unbinds shared action names like `moveLeft`/`moveRight`).

**Scene navigation**: call `openScene(factory)` to queue a base transition (applied after the current UI update completes). The only **built-in scene** (`scripts/sceneLobby/sceneLobby.js`) is `SCENES.lobby` — the merged **title + lobby**, the **boot scene** + dev launcher (also reached via **F2**): a G.E.M.S. header, a **tabbed** scene catalogue (registry categories grouped into RPG / Showcase tabs), and a footer of global actions (Settings → SystemMenu, Credits → SystemMenu's About tab, Quit). There is no separate title or credits scene; Settings/Pause are the **`SystemMenu`** overlay, not scenes (see Genre UI managers below).

**`SceneRegistry`** (`scripts/demo/demo.js`) is the lobby catalogue. Register at the top level of a scene's script:

```js
SceneRegistry.add(() => new MyScene(), {
  label: "My Scene",
  category: "SCENE_CAT_FOO",
});

// standalone — never `extends Level` (GMRT); declare the full required contract
class MyScene {
  label = "My Scene";
  create(openScene) {
    /* build UI; openScene(SCENES.lobby) to go back */
  }
  step() {}
  draw() {}
  destroy() {
    /* remove UI, clean up */
  }
}
```

`SceneRegistry.byCategory()` returns entries grouped by category string. To add a scene: create the script asset (see Asset Creation), define the class, then `SceneRegistry.add(...)`.

**GemsUI kit** (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`): a themed factory library so scenes build UI declaratively instead of hand-wiring `UIElement`/`UIPanel`/`UIText`. Factories are assigned via `globalThis.X = function X(…)` and split across small files (large-file global-hoisting fault). All visual constants live in **`GemsTheme`** (colors as hex, geometry as numbers); the `gems*` functions parse + compose them.

- **Containers**: `gemsRoot` (full-screen scene root), `gemsList` (vertical stack), `gemsGrid` (horizontal wrap row), `gemsPanel`/`gemsCard` (rounded panel; card adds gradient+border+shadow), `gemsHeader` (title bar), `gemsSection` (titled card with divider), `gemsRow(label, control)`, `gemsDivider`, `gemsCatBar(categories, opts?)` (a bar of category buttons; clicking one toggles a pop-up flyout of its items above the bar — one open at a time; selecting an item highlights it + fires `onSelect`. Driven by structural insert/remove, not flex mutation; `root.catbar` exposes `open/close/select`. Shared by the RPG build-mode HUD + level-editor palette), `gemsWindow(title, opts?)` (a centered, **draggable + resizable** floating window — title bar with `UIDrag` + optional close, a `body` callers fill. Resizable by default via a bottom-right `UIResize` grip clamped to `opts.minWidth`/`opts.minHeight` (opt out with `resizable:false`); the card + body flex-grow so content fills the resized frame. Pass `opts.height` for a fixed starting size when the content itself flex-grows (a grow `gemsTabs`/`gemsTable`), else the window opens content-sized and fixes its size on first resize. Size is within-session only — not persisted. Used by the RPG inventory + `StorageUI`).
- **Widgets**: `gemsLabel`, `gemsHint` (one-line help on a readable card, for overlays over a scene's render), `gemsKeyHints(entries, opts?)` (a **live, context-aware key-bind hint bar** — replaces a hardcoded "WASD: Move · …" string. Each entry `{ label, contexts?, actions? | text? }` shows an action's i18n name next to its CURRENT binding, read **live** from `Input.get(action).label()` each frame — so a future key remap updates the hint with zero wiring — or a literal `text` key for non-rebindable hints (raw build-mode `LMB`/`RMB`, `Esc`). `contexts` gates an entry to the matching `InputContext`, so the bar swaps its hints as the scene changes context (play / build / window). Multi-key `actions` join to "WASD" when single-glyph else "Up/Left/…". Built on `gemsLabel`), `gemsButton(label, onClick, opts?)` (`opts.primary` accent CTA; `opts.disabled` a bool **or live `() => bool`** evaluated each frame; `opts.selected` a live `() => bool` tints toward the accent for an active toggle/palette button — hover/press win on top), `gemsIconButton`, `gemsToggle` (renders `label: ON/OFF`), `gemsCheckbox` (`opts.style` `"check"`/`"switch"`), `gemsProgress` (non-interactive 0–1 bar), `gemsSlider`/`gemsSelect`/`gemsDropdown` (Settings-bound) + `gemsSelectCustom`/`gemsDropdownCustom` (caller-driven; the `*Dropdown*` pair opens a navigable popup list rather than cycling in place — the fit for many options like resolutions/locales, scrolls past `opts.maxVisible`), `gemsTable(columns, opts?)` (a sortable/filterable `UITable` sized to `opts.rows` whole rows, or `opts.grow` to flex-fill the parent's height — `UITable` then reflows its visible-row count to the live layout height, so a table in a resizable `gemsWindow` shows more/fewer rows as it resizes; reach the component via `el.getComponent(UITable)`).
- **Tooltips**: `gemsTooltip(element, label, opts?)` attaches a hover `UITooltip`; every interactive factory also takes `opts.tooltip` (string or `() => string`).

`label`/`onText`/`offText` accept a string or `() => string` (live `I18n.textRef`); color opts accept a `GemsTheme` key, hex string, or color int. Styling lives in `GemsTheme` + **`UIPanel`** options: `color2` (edge tint; `draw_roundrect`'s two colors run center→edge/radial), `border`/`borderColor`, soft multi-pass `shadow`/`shadowColor`/`shadowAlpha`, `highlight`/`highlightColor`/`highlightAlpha` (inner top-bevel sheen) — all default off. `UIButton` eases color/glow/shadow between hover/press on `Time.raw`; `UISlider`/`UISelect`/`UIProgress`/`UICheckbox` render directly in `onDraw` (`UISelect` shows `< value >` arrows, steps by click side). **`teardownScene(scene)`** releases the `world`/`renderer`/`camera`/`ui` a scene holds on `this`, in dependency order (missing fields skipped) — call from `destroy()` after releasing scene-specific resources (controllers, levels).

## ECS Core — `World`

`World` (`scripts/World/World.js`) is the instance-based ECS core, owning all component storage and the generational ID allocator. Each scene holds its own as `this.world` (there is no `WORLD` global). **`Entity` is deprecated** — its functionality moved to `World`.

```js
const world = new World(maxEntities, tickrate, opts); // opts: { gravity? } overrides GravitySystem.strength

// Entity lifecycle
const id = world.create(); // allocate generational ID
world.remove(id); // mark for removal (deferred)
world.flush(); // commit queued removals
world.isValid(id); // generational validity check

// Component storage
world.register(Position); // allocate storage (optional; add auto-registers)
world.add(id, Position, { x: 0, y: 0, z: 0 }); // set data
world.get(Position, id); // → data object or undefined
world.detach(id, Position); // remove one component

world.query(Position, Velocity); // → ids that have ALL listed components
world.forEach([Position, Velocity], fn); // calls fn(id) per match, no id array allocated

// Fixed-rate tick
const ticks = world.update(); // # ticks to run this frame; advances accumulator, computes alpha
world.alpha; // [0, 1) interpolation factor for rendering
world.maxTicks; // tick cap per frame (default 5) — spiral-of-death guard:
// under overload the sim slows instead of freezing

// Snapshot
world.export(); // plain object, components keyed by string token, sparse entries
world.import(s); // restores ids + registered components; unknown keys ignored
world.componentsOf(id); // { token: data } of every component this entity has
```

## `EntitySnapshot`

`EntitySnapshot` (`scripts/EntitySnapshot/`, Core) is the single-entity serialize/migrate primitive — the counterpart to `World.export` for one entity. `capture(world, id, components?)` → `{ components: { token: data } }` (a component-token subset, or all via `world.componentsOf`); `apply(world, id, snapshot)` adds those components onto an **existing** entity; `restore(world, snapshot, overrides?)` `world.create`s a fresh entity, applies the snapshot, then applies `overrides` (e.g. a new `Position`/zeroed `Velocity`). Data objects are **referenced, not deep-copied** — a captured component re-attaches by reference; when a source world is freed (chunk un/load) the objects survive its `world.destroy()` since only the storage map is dropped. It's the substrate for migrating an entity between Worlds — `World.levels.take`/`put`/`transfer` wrap it, and the RPG **squad** crosses a portal as whole-entity take/put (see `RpgMap.go`) — and the seed for disk saves + chunk streaming (a chunk un/load is the same capture/restore over a region's entities). Serialize the record yourself for disk (mind the `JSON` nested-value fault + `Set` fields).

## `IdPool`

`IdPool` (`scripts/IdPool/IdPool.js`) is the generational ID allocator owned by `World` as `world.ids`. IDs encode index (lower 20 bits) + generation (upper 12 bits). Static helpers: `IdPool.getIndex(id)`, `IdPool.makeId(index, gen)`, `IdPool.getGeneration(id)`. Instance methods (`world.ids.*`): `alloc()`, `free(id)`, `isValid(id)`, `reset()`, `export()`, `import()`.

## Component Pattern

Components are **string tokens** — a global name used as a `Map` key and for serialization. Data shape is defined at the call site; there are no static arrays, `defineComponent`, or static component classes (all deprecated).

```js
globalThis.Position = "Position";
/** @typedef {Object} Position @property {number} x @property {number} y @property {number} z */
// usage: world.add(id, Position, { x, y, z })
```

## System Pattern

Systems are **plain objects** with an `update(world)` method:

```js
globalThis.MovementSystem = {
  update(world) {
    for (const id of world.query(Position, Velocity)) {
      const pos = world.get(Position, id);
      const vel = world.get(Velocity, id);
      pos.x += vel.x * world.tickDuration;
      pos.y += vel.y * world.tickDuration;
    }
  },
};
```

On-demand utility systems (e.g. cursor methods on `PathfindingSystem`) expose named methods instead of `update(world)`.

## Fixed-Rate Simulation (ECS Scene Pattern)

Scenes running an ECS simulation dispatch systems explicitly inside `step()`:

```js
step() {
  const ticks = this.world.update();
  for (let t = 0; t < ticks; t++) {
    InterpolationSystem.snapshot(this.world); // first: record pre-move positions for render lerp
    GravitySystem.update(this.world);
    SolidSystem.update(this.world);       // integrates + resolves solid bodies
    SeparationSystem.update(this.world);  // pushes overlapping bodies apart
    StateSystem.update(this.world);
    LifetimeSystem.update(this.world);
    this.world.flush();
  }
}
draw() { this.renderer.draw(this.world); }
```

Genre scenes compose these into a **`Pipeline`** (`scripts/Pipeline/`): `this.physics = new Pipeline().add(SystemA).add(stepFn)`, then `this.physics.update(world)` each tick. A step is any `{ update(world) }` object or a bare function. Per genre: platformer `Gravity → clampFall → SolidSystem`; top-down/RPG `SolidSystem → SeparationSystem → ProjectileSystem` (separation unstacks crowding slimes/followers, equal-mass push-apart).

**Motion integrators are exclusive per body**: `MovementSystem` integrates _free_ movers (no collision response), `SolidSystem` is move-and-collide for solid bodies, `ProjectileSystem` is move-and-raycast for projectiles. A given mover is integrated by exactly one of them.

**`Time`** (`scripts/Time/Time.js`): `Time.delta` (scaled seconds), `Time.raw` (wall-clock), `Time.scale` (time dilation). Updated by `obj_game` in `Step_0` before `scene.step()` — always available in scene code.

## Genre Controllers & Template Gameplay Systems

The Core systems above are genre-agnostic. A playable genre scene layers a **player brain** plus **gameplay systems** on top — these live under the merged top-level **Demo** folder (the `Platformer` minigame in `Demo/Platformer`; the action-RPG in `Demo/Scene`/`Demo/System`/`Demo/Component` alongside the shared RPG layer) and are orchestrated by the scene's `step()` (directly, or via its `Pipeline`), not auto-run by `World`.

**The RPG player brain is an ECS system** — **`PlayerSystem`** (`scripts/PlayerSystem/`, Demo/System; the input counterpart of `CombatAI`) driving the **`Playable`** component (`scripts/Playable/`, Demo/Component). `Playable`'s presence marks THE input-driven entity — every consumer finds the player **live by query** (`PlayerSystem.id(world)`; `sceneRpg.step` re-latches it each frame as **`scene.playerId`**, also set on boot spawn + portal arrival, so there is no stored player handle to dangle) — and its flat data (`{ fireCd, attackCd, cursorX, cursorY }` — attack cooldowns + the scene-latched world cursor) is the brain's per-tick state, riding `EntitySnapshot`/map transfer with the rest of the player sheet. `PlayerSystem.update(world)` runs at the **head of the RPG physics `Pipeline`** (before `SolidSystem` integrates the `Velocity` it writes): movement + sprint (`StaminaSystem`), twin-stick or cursor aim, and the **item-driven attack** — it reads the equipped weapon's composed profile (or, unarmed, the shared fist fallback `PLAYER_FIST`, so unarmed never fires a free bullet) and runs whatever it describes; a gun fires via `RpgPlayer.fireBullet(world, shooterId, { damage, penetration?, pierce?, range, muzzleY?, nx?, ny? })` — an instant **hitscan** shot (`Combat.hitscan`, no projectile entity) returning the normalized aim `{ nx, ny }`. Input **lifecycle** stays scene-driven, not simulation: `PlayerSystem.bindKeys()` registers the keymap + `InputContext` tags (boot via `RpgMap._buildWorld`, re-applied on host `resume()`), `PlayerSystem.unbind()` drops it (scene `destroy`), and `PlayerSystem.spawn(world, spawn)` builds the player at this genre's tuning via **`RpgPlayer.spawn`** (`scripts/RpgPlayer/`, Demo — assembles the full sheet: transform + `Collision` + `Health`/`Stats`/`Inventory`/`Equipment`/`Encumbrance`/`Visual`/…, including `Playable` + `Animator`).

**The platformer keeps a genre controller** (`PlatformerController`) — player input + entity setup as a three-phase lifecycle over a plain `ctrl` state bag, not an `update(world)`. It is a movement showcase: it builds a plain player itself (transform + `Collision` + `Direction`/`Grounded`/`Visual`, **no** RPG components) and has no firing.

- `create(world, spawn)` — registers the keymap (`Input.bindAll`), spawns the player, returns the `ctrl` state bag (`{ id, facing, ... }`).
- `pollInput(ctrl)` — call **once per frame, before `world.update()`**, outside the tick loop. Samples _edge-triggered_ input (jump `pressed()`/`released()`) into buffers so presses aren't lost on 0-tick frames or double-counted on multi-tick frames. (The RPG brain reads no buffered edges, so `PlayerSystem` has no poll step.)
- `update(world, ctrl)` — call **once per physics tick**. Reads _continuous_ input (movement) and applies acceleration/jump to `Velocity` (before `SolidSystem` integrates it).
- `destroy()` — unregisters input. Plus genre verbs like `respawn`.

Read flags like `Grounded.isGrounded` live off the component each use (boolean-local clobber idiom).

**Template gameplay systems** are stateless `globalThis` objects like Core systems but expose _named query/resolve methods_ (not `update(world)`), called from `step()` after physics resolves: `EnemySystem` (`update` patrol + `resolveStomp` jump-kill + `resolveTouch` side-hit) and `CollectibleSystem` (`hitSpike`). They read `col.hits` (filled by `TriggerSystem`) or do their own overlap test, and return values the scene applies to player state. (Platformer-only; the RPG combat/loot systems live in the RPG layer.)

`scenePlatformer` (a movement showcase, no RPG) is a compact reference orchestration: per tick → `snapshot` → `controller.update` → `physics` Pipeline (`Gravity → clampFall → SolidSystem → TriggerSystem`) → `EnemySystem.update` → `resolveStomp` (bounce the player on a kill) else `resolveTouch`/`hitSpike` → respawn → void-fall respawn → `flush`. One open hand-built level.

**Lobby categories** are `SCENE_CAT_*` i18n keys: `ACTION`, `RPG`, `STRATEGY`, `EDITOR`, `UI`. `SceneRegistry.add(factory, { label, category })` slots a scene under one.

## Gameplay Kit

The **`Gameplay`** pillar is the reusable, genre-agnostic gameplay kit between `Core` and `Demo` — the systems a second genre reuses unchanged. The placement rule across the four pillars (`Core` / `Gameplay` / `GemsUI` / `Demo`): references only engine concepts → **Core**; imposes a gameplay model but names **no** specific content → **Gameplay**; names specific content/scenes/`Rpg*` → **Demo**. Every kit module depends only on `Core` + sibling kit modules — **never on `Demo`** (so the demo could be deleted and the kit still builds; this is exactly why `Downed` is in `Combat`, since `FollowerSystem` reads it, while `Portal` stays in `Demo`, since only `RpgMap`/`RpgSpawn` do).

Grouped by **feature module** (component + system colocated, unlike Core's type-split):

- **`Combat`** — the shared damage applier `Combat.applyDamage` (over an injectable `Combat.mitigate` hook), plus `Health`, `Stamina`(+`StaminaSystem`), `Faction`(+`FactionSystem`), `Mortal` + `Downed`, `Projectile`(+`ProjectileSystem`), `MeleeSystem`. Every path lands hp through `Combat.applyDamage`, which subtracts after `mitigate` (default identity — the kit stays stat-agnostic; a game injects its formula, the RPG a `Stats.defense` one). The attack side (weapon + attacker stat) is composed by the consumer. All paths only SUBTRACT hp; the reaction at ≤0 hp is the `Mortal` death pass (see _Death_).
- **`Items`** — the `Item` + `Rarity` + `Manufacturer` registries and the per-item capability components (`Weapon`, `Consumable`(+`ConsumableSystem`), `Container`). "Kinds of item" are a flat `Item` carrying a `components: []` queried by `instanceof` (composition over inheritance — GMRT can't `super`).
- **`Inventory`** — `Inventory`(+`InventorySystem`), `ItemDrop`, `Encumbrance`(+`EncumbranceSystem`).
- **`Equipment`** — `Equipment`(+`EquipmentSystem`), `Equippable`, `AppearanceSystem` (rebuilds the Core `Appearance` paper-doll layer stack from worn gear — see _Gameplay / RPG Layer → Paper-doll appearance_).
- **`Animation`** — `Animator`, `AnimationSystem` (a data-driven sprite state machine).
- **`Lighting`** — `Light` + `RenderLighting`. The day/night ambient is **injected**: `RenderLighting` takes `opt.ambient: () => { color, alpha }` (default full daylight = inert, early-outs), so the pass carries no day/night opinion; the demo wires `WorldClock.tint` in `RpgMap.build`.
- **`Quest`** — `QuestLog` (quest defs + progress; the Core `UIQuestTracker` widget binds to it via an injected source, so Core never references the kit).
- **`Crafting`** — `CraftSystem` + `Recipe`.
- **`Squad`** — `Squad` (membership: entities sharing a squad id travel together) + `Follower`(+`FollowerSystem`) (companion follow/wait behavior, hire/kick membership transitions, carry bonus).
- **`NPC`** — the `NPC` dialogue-character component (pairs with Core's `Dialogue` singleton).
- **`Status`** — the buff/debuff layer: `Status` (def registry) + `StatusEffects` (component) + `StatusSystem`. Stat-model-agnostic: a `mods`-bearing status folds into the derived sheet via an **injected** `StatusSystem.onStatsChanged` hook (the demo wires `StatModel.recompute`), mirroring `Combat.mitigate`. See _Gameplay / RPG Layer → Buffs & statuses_.
- **`Survival`** — the needs layer: `Thirst`/`Hunger`/`Drowsiness` components, their per-need systems (`ThirstSystem`/`HungerSystem`/`DrowsinessSystem`) over a shared `Survival` core. A need is a "rising meter" that, at its `critical` threshold, applies a debuff **`Status`** (depends on the `Status` sibling module); restored by drinking/eating/sleeping. See _Gameplay / RPG Layer → Survival needs_.
- **`Interaction`** — the "walk near + press E to do something" layer: the `Interaction` component (`{ kind, ...params }`, marks an entity interactable) + the **`InteractAction`** registry (`register([{ id, prompt, run(ctx) }])`, mirrors `Item`/`Status`/`Prefab`). The `kind` names a registered action; `run(ctx)` does anything — open a UI window, feed/hydrate/buff the player, claim a zone — so the mechanism is data, not a hardcoded switch. Genre-agnostic: the registry holds no concrete actions (the RPG registers its set in `RpgInteractions`), and the generic pick/prompt/dispatch **engine** is Demo/UI `Interactable` (it reads Demo windows, so it stays in Demo). Replaces the old Core `Station` component. See _Gameplay / RPG Layer → Interactions_.
- **`Trade`** — the merchant layer: `Merchant` (a trade-config component that pairs with the entity's own `Inventory` = its stock) + `TradeSystem` (price/buy/sell/restock). Currency-agnostic: the money is the `Merchant.currencyId` item (a fungible the buyer carries), so the kit names no specific currency. Two modes by a `Merchant.infinite` flag — **infinite** (bottomless stock + wallet; buying never depletes, selling discards) or **finite** (real stock + a `credits` wallet that gates buying your goods, with `TradeSystem.update` restocking toward a `template` every `restockSecs`). Prices: `marketValue = round(Rarity.modify(rarity, value))`, buy `= ceil(market·buyMargin)`, sell `= floor(market·sellMargin)`. The demo opens **`TradeUI`** (Demo) on a merchant NPC — the kit↔Demo split mirrors `Crafting`/`CraftingUI`. See _Gameplay / RPG Layer → Genre UI managers → TradeUI_.

The per-module **behavior** is documented in detail in _Gameplay / RPG Layer_ below (the RPG scene is the reference consumer); this section is the membership + the kit→Core dependency contract.

## Gameplay / RPG Layer

The **RPG** scene (`sceneRpg`) is the action-RPG (the platformer is a movement showcase with no RPG layer). The pieces below split across two pillars — the genre-agnostic modules in the **`Gameplay` kit** (`Combat`/`Items`/`Inventory`/`Equipment`/`Animation`/`Lighting`/`Quest`/`Crafting`/`Squad`/`NPC`/`Status`/`Survival`/`Trade`; see _Gameplay Kit_), and the content/model-specific glue in **`Demo`** (`Stats`, all `Rpg*`, `CombatAI`, the `WorldClock`/`Weather`/`Temperature` world-sim, build mode) — and are driven explicitly from the scene's `step()`, never auto-run by `World`. The design constraint throughout is **composition over inheritance** (GMRT can't do `super`/subclassing): "kinds of item" are a flat `Item` carrying a `components: []` array of standalone capability/marker classes queried by `instanceof` — exactly the `UIElement.getComponent` pattern.

**Items & registry.** `Item` (`scripts/Item/`) is a definition registry (`Item.register([...])`, `Item.get(id)`), like `Rarity`. A definition is identity + universal scalars (`name` i18n key, `sprite`, `stack`, `weight`, `value`, `rarity`) plus `components` — capability/marker instances attached via `addComponent` and read via `getComponent(Class)`/`hasComponent(Class)`. **Definition vs instance** (`item.isInstanced()` → has `Equippable`): a _fungible_ item (potions/materials/currency) is a shared definition with stacking `qty`; an _instance_ (all equippable gear) is unique — an `Inventory` slot of `{ itemId, qty:1, uid, mods }` (a gun instance also carries `ammo`/`rounds`) carrying **per-instance state inline** (a minted `uid` + a named-slot **attachment map** `mods` — plus, for a gun, the loaded `ammo` itemId + magazine `rounds`), so two `wood_sword`s can differ and `Equipment`/drops/etc. reference the specific one by `uid` (see _Inventory & equipment_):

- `Equippable` (`{ slot, mods, worn? }`) — wearable in an `Equipment` slot (`weapon`/`armor`/`trinket`/`backpack`); `mods` are flat `Stats` deltas folded onto the wearer's attribute-derived base by `StatModel.recompute` while worn. `worn` (a sprite NAME, default `""` = invisible) is the item's paper-doll overlay sheet, shown on the wearer while equipped (see _Paper-doll appearance_).
- `Weapon` (`{ slots, fireCd?, damage?, reach? }`) — the **universal** weapon profile that **fully drives the action** (the controller hardcodes no built-in attack): the named, typed attachment **`slots`** (`[{ id, accepts }]`, the unified slot model — `accepts` is an attachment category or `"*"`), the melee numbers (`damage`/`reach`), and the shared cadence `fireCd`. **Melee vs gun is decided by a sibling `Gun` component, NOT a flag** — an item that also carries `Gun` (`item.hasComponent(Gun)`) is ammo-driven ranged (`composeWeapon`'s gun branch); else it's melee (`MeleeSystem` swings a `reach`-px hitbox in the facing dir). The **`PlayerSystem`** reads the equipped profile (or, when unarmed, a weak melee **fist** fallback — the pre-composed shared profile `PLAYER_FIST`, so being unarmed never fires a free bullet) and runs whatever it describes. The player spawns with a `wood_sword` (melee; slots `edge`/`pommel`) equipped (`sceneRpg.create`).
- `Gun` (`{ caliber, magazine, ops }`) — presence ⇒ the weapon is an **ammo-driven gun**. It fires the **loaded `Ammo`'s base stats** run through an OPERATOR pipeline: ammo base → the gun-base `ops` layer → each installed attachment's `ops` (`EquipmentSystem.composeWeapon`/`_applyOps`: `final = (base + Σadd)·Πmul` per field). `caliber` gates which `Ammo` chambers; `magazine` is the base clip. The composed **power is kinetic** — `power = ammoPower + KIN_K·mass·(velocity/KIN_REF)²` (fast/heavy rounds hit harder) **+ the wielder's `Stats.attack`**; the round's **`penetration`** rides the shot and lowers target defense at the hit. Ammo is **consumed** per shot from the magazine; **R** (or auto-on-empty) reloads from the bag (`EquipmentSystem.reload`/`loadAmmo`, + the `*Slot` variants the panel uses) — a gun with **no ammo type chosen yet** (fresh from craft/purchase) auto-loads the first caliber-compatible ammo in the bag on R or on fire (`reloadSlot` → `_firstAmmo`), so firing a new gun never needs the Toolkit panel (deliberate type _switching_ stays there). The HUD shows `rounds/magazine`. (`KIN_K`/`KIN_REF` are tunable constants on `EquipmentSystem`.)
- `Ammo` (`{ caliber, mass, velocity, power, penetration }`) — a fungible round; its four stats are the BASE of a gun's firing pipeline (mass + velocity → kinetic power; `penetration` vs defense). `velocity` also scales the hitscan **reach** (the shot is instant — no travel time). Three demo rounds — `ammo_light` (fast/low-pen), `ammo_heavy` (slow/punchy), `ammo_ap` (armor-piercing), all `caliber:"standard"`.
- `WeaponMod` (`{ slot, ops, stat }`) — marks a (fungible) `Item` as an installable **attachment**. `slot` is the category it fits (matched vs a weapon slot's `accepts`); `ops` are per-field **operators** (`{ field: { add?, mul? } }`) over the composed profile (gun: velocity/mass/power/penetration/fireCd/magazine; melee: damage/reach/fireCd); `stat` deltas fold into the wearer's derived `Stats` (`StatModel._foldInstanceMods`). A weapon instance's `mods` is a **map** `{ slotId → attachmentItemId }`; installed/removed into a matching named slot at a **workbench with the Toolkit module slotted** (the `WeaponModUI` panel). The consumed item _is_ the definition (no parallel registry); an op on a field the weapon doesn't expose is inert. Demo set: gun attachments `mod_scope`/`mod_long_barrel`/`mod_extended_mag`/`mod_grip`/`mod_suppressor`, melee `mod_sharp` (edge) / `mod_heavy` (pommel).
- `WorkbenchModule` (`{ kind }`) — marks a (fungible) `Item` as a **workbench upgrade** slotted into a bench's single module slot (`Interaction.module`). Rather than a station per category, one bench is upgraded by swapping modules (removable freely). `kind:"recipes"` (default) unlocks the recipes that declare `requires: <this itemId>` (base recipes — no `requires` — are always available); `kind:"weaponmod"` (the **Toolkit**) switches the bench window into the weapon-mod panel. The four demo modules (`forge`/`alembic`/`hearth`/`toolkit`) are crafted at the **bare** bench, so the bench bootstraps its own upgrades. See _Genre UI managers → CraftingUI_.
- `Consumable` (`{ heal }`) — usable from the bag (one unit consumed for an instant effect).
- `Container` (`{ capacity }`) — while equipped, grows the wearer's `Inventory.capacity` (e.g. a backpack pairs `Equippable` + `Container`).

`Rarity` (`scripts/Rarity/`) is a parallel registry of tiers (`{ id, name, color, valueMod }`); rarity color drives loot/inventory tinting. **`Manufacturer`** (`scripts/Manufacturer/`, Gameplay/Items) is the parallel registry of in-world companies (`{ id, name, lore, color, ops? }`) an item references via the def field `maker` (default `""` = unbranded, like `rarity`): a maker's optional **`ops`** is its signature weapon layer (same operator shape as `WeaponMod.ops`), folded by `composeWeapon`'s `_modLayers` on top of the authored base for every weapon that maker makes — so brand identity is mechanical, not just cosmetic. Shown in the Settings-gated inventory **Maker** column (`invColMaker`, brand-colored) and as a brand-colored line in the `WeaponModUI` weapon detail. The demo companies (`RPG_MAKERS` in `RpgItems`, colony-era lore): **Aeon Dynamics** (fast/precise, softer hits), **Vekt Heavy Industries** (slow/punchy, small clips), **Helios Terraforming Authority** (survival gear, no ops) — with a curated branded set (`aeon_pistol`/`vekt_pistol`/`aeon_cutter`/`vekt_wrench`/`helios_vest`/`helios_trauma_kit`/`helios_ration`/`aeon_rounds`) sold by the hub merchants. **`RpgContent`** (`scripts/RpgContent/`, Demo) registers **all** shared RPG content — the rarity tiers, the **full item set** (consumables, weapons `wood_sword` (melee) + `blaster` (ammo-driven **gun**), the **`Ammo`** rounds (`ammo_light`/`ammo_heavy`/`ammo_ap`), armor/trinket/backpack, currency `coin`/`gem`/`key`, crafting materials, the `mod_*` **`WeaponMod`** attachment items, the `forge`/`alembic`/`hearth`/`toolkit` **`WorkbenchModule`** items), and the workbench recipes (base + per-module, gated by `Recipe.requires` — the Forge module crafts the gun, ammo, and attachments). The RPG scene's own content is **`RpgQuests`** (its quests) and **`RpgAchievements`** (its achievement defs + the trigger rules — see below). `sceneRpg` calls `RpgContent.register()` once from `create()` (via `RpgQuests.register()`, which calls it first; `RpgAchievements.register()` follows), **not** at top level, to dodge GMRT load-order issues.

**Achievements (push model).** The **`Achievement`** engine (`scripts/Achievement/`, Demo) is a registry (`{ id, name, desc }` — pure data, **no conditions**) + unlock persistence (comma-joined ids via `SaveData`). It never evaluates or sweeps: an outside **trigger** requests `Achievement.unlock(id)`, and the engine checks the request (registered? still locked?), persists, and returns whether it was newly unlocked. The demo's triggers live in **`RpgAchievements`** (Demo/Content): declarative threshold `RULES` per lifetime counter (`enemiesKilled`/`itemsCollected`/`questsCompleted`); a gameplay chokepoint that bumps a `Profile` counter calls `sceneRpg._reportAchievements(key)` → `RpgAchievements.report(key, value)` → unlock requests, and toasts the newly-unlocked. Debug: an RPG-scoped **`Achievements`** Debug-overlay panel (unlocked count + **Unlock All** / **Clear All** via `Achievement.unlockAll()`/`clear()`), registered in `sceneRpg.create()` and removed in `destroy()`.

**Inventory & equipment (pure systems over components).** Components are string tokens; their systems take the component (or `world` + entity id) directly, with no world tick:

- `Inventory` = `{ slots: [{ itemId, qty }], capacity, maxWeight? }` (an _instance_ slot adds `uid` + `mods`; see the definition-vs-instance split above) — every player, enemy (its loot table), and storage chest owns one. `InventorySystem` (`add`/`remove`/`has`/`weight`) stacks fungibles per `Item.stack`; an **instanced** item never stacks — `add` mints one slot per unit with a fresh `uid` + an empty `mods` **map** (a gun's `ammo`/`rounds` are added lazily by the firing path), `addSlot` re-inserts a pre-existing instance preserving its `uid`/`mods` (transfer/drop), and `findByUid`/`removeByUid` reach a specific one. `sort` keeps instance slots individual (only fungible stacks merge). `add` is gated first by `maxWeight` then by `capacity`, returning the amount that did **not** fit.
- `Equipment` = `{ slots: { weapon, armor, trinket, backpack } }` of **instance `uid` strings** (the equipped item is unique — two of one itemId may differ by mods, so an itemId can't say "which one"; flat → `world.export`-safe). `EquipmentSystem.equip(world,id,uid)` (or `equipFirst(...,itemId)` for the itemId-keyed entry points — the starting-gear seed + the hotbar) keeps the item in the `Inventory` (it still counts toward capacity/weight) and **re-derives the wearer's `Stats` from source** via `StatModel.recompute` (which folds every equipped instance's `Equippable.mods` **+ installed `WeaponMod.stat`** onto the attribute base — so there's no +/- delta to keep balanced; a re-derive can't drift). A `Container.capacity` bonus stays a direct `Inventory.capacity` delta. `EquipmentSystem.weaponSlot`/`weaponProfile` resolve the equipped weapon `uid` → instance slot and return a **fresh composed profile** via `composeWeapon` (a melee weapon's damage/reach numbers, or a gun's ammo-driven kinetic profile + clip), or `null` when unarmed → `PlayerSystem` falls back to `PLAYER_FIST`.
- `ConsumableSystem.use` applies a `Consumable`'s effect and removes one unit; it refuses to waste an item that would do nothing (e.g. healing at full HP). A `Consumable` carries three independent effects: `heal` (HP, clamped to `Stats.maxHp`), a **permanent attribute grant** `{ attr, amount }` (the `*_shard` items) applied through the **injected `ConsumableSystem.grantAttr` hook**, and a **status grant** `status` (a `Status` id, e.g. the Tonic→`regen` / Elixir→`fortify` items) applied via `StatusSystem.apply` — kit default no-ops, the Demo wires the `Attributes`+`StatModel.recompute` policy in `sceneRpg.create` (the same injection idiom as `Combat.mitigate`, keeping the `Gameplay/Items` kit free of the Demo stat model).
- `Encumbrance` (`{ threshold, minScale }`) + `EncumbranceSystem.scale(world, id)` → a speed multiplier from carried weight. The **penalty is delivered through the Buff/Status system**, not by the mover directly: `EncumbranceSystem.update` maintains an `"encumbered"` status (`StatusSystem.maintain`) whose live `{ speed }` mult is this gradient, and the mover reads `StatusSystem.scale(world, id, "speed")` — so encumbrance composes with any other speed status and shows in the HUD. This module still owns the weight→penalty mechanic (the gradient + the on/off decision); only how the slow reaches the entity moved to the status layer. See _Buffs & statuses_ below.

**Combat & stats.** `Health` = `{ hp }`; `Stats` = the session-scoped character sheet — `maxHp`/`attack`/`defense`/`speed`/`maxStamina`, all **derived from `Attributes`** (see _Attributes & derivation_ below). There is **no `level`/`xp`**: the RPG is deliberately **item- + skill-driven, not playtime-driven** — permanent power comes from equipment and attribute-granting consumables, never an XP grind. `MeleeSystem.swing(world, attackerId, dirX, dirY, reach, damage)` resolves a melee hit immediately (no projectile): an AABB hitbox extends `reach` in the facing **direction** (snapped to the dominant axis → 4-way) and damages every body with `Health` **except the attacker** and its faction allies (the slimes — player excluded; NPCs/furniture carry no `Health`), returning the struck ids. Ranged attacks (player guns + turrets) are **instant hitscan** via **`Combat.hitscan(world, x0, y0, x1, y1, { owner, damage, penetration?, pierce? })`** (`Gameplay/Combat`): it casts the shot with **`Raycast.castAll`** and walks every solid body along the ray in order — each hostile `Health` takes `damage` (with the round's `penetration`, default 0), the shot **passing through up to `pierce` of them** (default 1 = single target; a future sniper sets it higher) until a wall or a `FactionSystem`-allied body **blocks** it (an ally just eats the shot like a wall) — and returns the impact endpoint (for a tracer) + the struck ids. (The travel-time `Projectile`/`ProjectileSystem` path is **retained** in the kit for lobbed/grenade projectiles — it's simply no longer how guns fire; it despawned its bullet on first impact too, so hitscan with `pierce:1` is behaviorally identical.) All three paths land damage through the shared **`Combat.applyDamage(world, target, amount, penetration?)`** (`Gameplay/Combat`): the kit applier subtracts hp after an **injected `Combat.mitigate(world, target, amount, penetration)`** (default identity; `sceneRpg.create` sets it to `max(1, amount − max(0, defense − penetration))`), so defense, armor penetration, and a min-1 floor apply uniformly while the kit stays stat-agnostic — the _attack_ side (`weaponPower + attacker.Stats.attack`) is composed by the callers (`PlayerSystem` for the player, `CombatAI._attackPower` for a monster, whose weapon part is 0; melee/turret callers pass penetration 0). **Every combatant carries a `Stats` sheet** (slime/turret/follower, not just the player), so damage is genuinely stat-driven for all actors. The paths only **SUBTRACT** hp — the reaction at ≤ 0 hp is decided centrally by the `Mortal` death pass (see _Death_ below). `Combat.hitscan` lives in the `Gameplay/Combat` kit (not Core) because it needs `Health`/`Faction`; both `PlayerSystem` (the player) and `CombatAI` (turrets) call it (the retained `ProjectileSystem` lives there for the same reason). **`CombatAI`** (Demo) is the one AI for every non-player combatant — `CombatAI.register()` (called by `RpgContent.register`) registers the named states **`combat.idle`/`combat.chase`/`combat.attack`** into the `StateSystem` pool (separate entries transitioned by NAME, not a hardcoded bundle — the seam for preset-composed state sets), and `CombatAI.attach(world, id, level, opt?)` seeds `State { next: "combat.idle" }` plus a flat `Brain` whose `mobile` + `ranged` flags pick the behavior: a **slime** is `mobile` melee (the default) — a dynamic solid body `SolidSystem` integrates + collides for free; a **turret** is `{ mobile:false, ranged:true }` — an immovable, player-faction actor that stands and fires a hitscan shot, replacing the old per-kind `SlimeAI` + `Turret`/`TurretSystem`. The `Brain` holds `home`/`aggro`/`deAggro`/`attackRange`/`bulletSpeed` + a `pathCd` replan throttle (damage is the actor's `Stats.attack`, not on the `Brain`); targets are the nearest hostile by faction. **Chase is line-of-sight-first** — a clear shot is a straight seek; a wall between slime and player triggers an A\* detour over the `NavGrid` (see _Pathfinding Flow_).

**Attributes & derivation.** The derived combat `Stats` are computed from a data-driven primary-attribute layer (Demo, like `CombatAI` — the kit reads only the derived `Stats`, via `Combat`'s injected `mitigate`). **`Attributes`** (`scripts/Attributes/`) is a flat `{ key: number }` bag (opt-in: the player carries one, monsters author `Stats` directly); **`StatModel`** (`scripts/StatModel/`) is the swappable model — `ATTRS` (this RPG's lean set: `POW`→attack, `VIT`→maxHp (+ a little defense), `AGI`→speed, `END`→maxStamina, each with a default) + `derive(attrs)` (the rules, tuned so the defaults reproduce the legacy sheet `10/1/0/220/100`) + `recompute(world, id)`. **`recompute` is recompute-from-source**: derived `Stats` = `derive(attrs)` + Σ equipped `Equippable.mods` + Σ active status `mods` (`_foldStatuses` — buffs like `fortify`), rebuilt from scratch each call (so it can't drift); a no-op without `Attributes`, it clamps `Health`/`Stamina` to the new maxima. It runs on `RpgPlayer.spawn`, on equip/unequip (`EquipmentSystem`), and on an **attribute change** — which, with leveling removed, comes from **attribute-granting consumables** (the `*_shard` items: `power`/`vitality`/`agility`/`endurance`, one per `ATTRS` key, each `+1` forever via `Consumable { attr, amount }`). Using one runs the kit's `ConsumableSystem.use` → its **injected `grantAttr` hook** (set in `sceneRpg.create`, mirroring `Combat.mitigate` — the kit can't reach the Demo stat model) → raise the bag key + `recompute`. Shards are obtained by **crafting** (workbench recipes, gem + a material) and **quest reward** (the ruins quest), so growth is gated on gathering/exploring, not playtime. `Attributes` ride the carried sheet across a map change (`RpgMap.go`), so a re-derive on the new map uses the grown attributes (without this, shard gains would silently reset). **Swapping the model** (to D&D-6, SPECIAL, …) is a `StatModel`-only edit — rewrite `ATTRS` + `derive`; combat, equipment, and save/migration all read the derived `Stats`. The inventory **Stats** tab lists the attributes (data-driven from `ATTRS`).

**Buffs & statuses.** The **`Status`** module (`Gameplay/Status`) is the generic buff/debuff layer — a swap-in for poison/regen/slow/haste/fortify/encumbrance, stat-model-agnostic like the rest of the kit. Three pieces: **`Status`** (`scripts/Status/`) is the def registry (`Status.register([...])`/`get`/`all`, like `Item`/`Rarity`); **`StatusEffects`** (`scripts/StatusEffects/`) is the per-entity component holding the active list (`{ id, remaining, accum, mult? }` — flat, `world.export`/`EntitySnapshot`-safe); **`StatusSystem`** (`scripts/StatusSystem/`) runs them. A def carries up to **three effect kinds**, each routed the idiomatic way: **`dot`/`hot`** (HP per second, applied every `interval` by `StatusSystem.update` straight to `Health` — DoT bypasses `Combat.mitigate`, the `≤0` reaction stays the `Mortal` pass; floating numbers come free from `RpgScene.trackDamage`); **`mult`** (live multiplicative factors read at point of use via `StatusSystem.scale(world, id, key)` — the mover reads `"speed"`, so encumbrance/slow/haste compose by multiplication, never folded into the sheet); and **`mods`** (flat additive `Stats` deltas folded into the derived sheet by `StatModel._foldStatuses`, mirroring `_foldEquipment`). The `mods` path needs a re-derive on apply/expire, so it goes through the **injected `StatusSystem.onStatsChanged` hook** (kit default no-op; `sceneRpg.create` wires `StatModel.recompute`, exactly like `Combat.mitigate`/`ConsumableSystem.grantAttr`) — keeping the kit free of the Demo stat model. API: `apply(world, id, statusId, opts?)` (timed — `opts.duration` overrides the def; refresh keeps the longer remaining, no magnitude stacking yet), `remove`, `maintain(world, id, statusId, mult|null)` (a LIVE-driven permanent status whose per-instance `mult` a driver refreshes each tick — the encumbrance path; carries no `mods`, so no re-derive), `has`/`list` (the HUD reads `list`), `scale`, and the per-tick `update`. Content is **`RpgStatuses`** (Demo, registered by `RpgContent.register`): `encumbered` (maintained debuff, live speed mult from `EncumbranceSystem`), `regen` (HoT buff — the Tonic consumable), `fortify` (timed `mods` +attack/+defense buff — the Elixir consumable). `sceneRpg.step` ticks `StatusSystem.update` then `EncumbranceSystem.update` at the top of the tick loop (before the mover reads `scale`); the HUD card lists active statuses tinted by each def's `color` (rich-text `[c=#hex]` spans, read live). A DoT debuff (poison) is the symmetric counterpart of `regen` — one def + an applier away.

**Survival needs.** The **`Survival`** module (`Gameplay/Survival`) is the needs layer — `Thirst`, `Hunger`, `Drowsiness`, each a **"rising meter"** component `{ value, max, rate, critical, status }`: `value` climbs by `rate`/sec (0 = fine, `max` = critical). Each has its own thin system (`ThirstSystem`/`HungerSystem`/`DrowsinessSystem`) over a shared **`Survival`** core: `Survival.tick(world, token)` raises + clamps the meter and, at `value/max >= critical`, **applies the named debuff `Status`** (`StatusSystem.apply`/`remove` — reusing the Buff/Status kit, so the consequence shows in the HUD), while `Survival.restore(comp, amount)` lowers it (returning whether it changed, so a no-op drink/food is refused). Opt-in like `Stamina`/`Encumbrance` (only the player carries them — `RpgPlayer.spawn`), and — like `Stamina` — they ride the carried sheet across a map change (`RpgMap.go`'s capture list), so a need doesn't reset or diverge per map. Restores: a **`Consumable`** with `thirst`/`hunger` (the Water Bottle / Bread / Cooked Meat — `ConsumableSystem` routes them to `ThirstSystem`/`HungerSystem.restore`); Drowsiness is restored by **sleeping**. Demo content (`RpgStatuses`): `dehydrated`/`starving` (a `dot`) + `drowsy` (a speed `mult`). `sceneRpg.step` ticks the three systems in the tick loop (after `StatusSystem`/`EncumbranceSystem`). **Sleep (bed):** a built **`bed`** carries an `Interaction` kind `"bed"`; the `"bed"` `InteractAction` routes its E to `sceneRpg._sleep`, which sets `_sleeping` → `step()` **ramps** `Time.scale` multiplicatively on `Time.raw` (wall clock — `Time.delta` is itself scaled) up to the `RPG_SLEEP_SCALE_MAX` ceiling (reached in `ln(max)/RPG_SLEEP_ACCEL` wall-seconds; `WorldClock`/`Weather` run at the full scale while the tick-bound sim caps at `World.sim.maxTicks`) and drains `Drowsiness` each tick (`DrowsinessSystem.restore` instead of `update`); **hitting the ceiling is the `td_time_skip` achievement trigger** (once per sleep session — `_sleepPeaked` guards, `sleepFastForwards` counter → `RpgAchievements` rule); any key/click wakes (`_wakeInput`, checked before the tick loop) and restores `Time.scale = 1`. So sleeping skips time + restores rest but **costs water/food** (those needs keep rising while fast-forwarded). The HUD shows the three needs as **reserve bars** (`1 - value/max`).

**Death (`Mortal` / `Downed`).** What happens when an entity's `Health` hits 0 is **configured per spawn preset** by an opt-in **`Mortal`** component (`scripts/Mortal/`, `Gameplay/Combat`), resolved in one place — `RpgScene.resolveHealth` (the instant reaction) + `RpgScene.updateDowned` (the down-timer) — so the damage systems just subtract hp and a body with `Health` but **no** `Mortal` (e.g. a built turret, removed by `BuildMode.reapDestroyed`) is left alone. Kinds: **`corpse`** (the mobs — raiders/rats) leaves a **lootable body**: `RpgScene._toCorpse` strips the combatant **in place** (detaches `Health`/`Stats`/`Brain`/`State`/`Velocity`/`PrevPosition`/`Faction`/`Animator`, makes the collider non-solid, dims + flattens the `Visual`) and tags it **`Interaction { kind: "corpse" }`**, so E opens the standard `StorageUI` transfer window over the body's own `Inventory` — takes report pickup credit (quest/achievement `collect`) via the per-open **`scene._storeOnTake`** hook the `"corpse"` `InteractAction` sets (a plain chest never sets it, so withdrawing can't farm collect quests; `StorageUI.close` clears it). `RpgScene.reapCorpses` (tick loop) removes a corpse once its `Inventory` empties — a lootless kill reaps the same tick, i.e. the old despawn; because the corpse is the **same entity**, chunk demote/unload snapshots it like any resident, and the scene's `onKill` detaches the `Raider`/`Rat` species marker so the radar stops blipping the body. **`despawn`** spills the entity's `Inventory` as ground drops then removes it (no live preset uses it now; the kit path remains); **`respawn`** (player) refills to `Stats.maxHp` and repositions; **`down`** (companions) incapacitates — it **detaches `Health`** (so `FactionSystem.nearestHostile` stops targeting it and the death scan skips it), zeroes velocity, dims the sprite, and attaches **`Downed { timer }`** (`scripts/Downed/`); after `Mortal.recoverSecs` of sim time `updateDowned` re-adds `Health` (`reviveHp`), un-dims, and teleports it to the recovery spot — `sceneRpg._recoverSpot()` = the claimed build zone centroid, else the map spawn. The scene injects the side effects as handlers (`onKill` (fired for `despawn` + `corpse`, before the body transform)/`onRespawn`/`onDown`/`downSpot`/`onRecover` — quest/profile counters, the player respawn reset, down/recover toasts). `FollowerSystem` holds a `Downed` companion still; the inventory Squad tab shows its **Down (recovering)** status and disables Kick; the carry bonus is untouched (it tracks `Follower.state`, which a down→recover cycle doesn't change). A downed companion round-trips a map change via `EntitySnapshot` (it carries `Downed`, not `Health`) and recovers in the new map.

**Loot, progression & dialogue.** `ItemDrop` = `{ itemId, qty }` on a non-solid sensor entity the player collects on overlap; enemy deaths leave a **lootable corpse** over their `Inventory` (the `corpse` `Mortal` kind — see _Death_; the `despawn` kind's drop-spill path remains for kit consumers). `QuestLog` (`scripts/QuestLog/`) holds quest defs + active progress (objectives `{ kind: "kill"|"collect"|"reach", target, count }`, **item-only rewards** `{ items? }` — there's no XP, so a quest grants items, e.g. the ruins quest gives a `vitality_shard`); `RpgProgression.applyReward` is the single apply path (adds the items to the bag). The scene calls `QuestLog.report(kind, target)` after gameplay events and turns in on NPC interaction. `NPC` = `{ name, lines, questId? }` — the scene proximity-checks the player and opens a dialogue panel that can offer/turn in the linked quest. `Animator`/`AnimationSystem` are a data-driven sprite state machine: `Animator` holds a `graph` of named `AnimState`s (`{ sprite, start?, frames, fps, loop }`); the controller picks `state`, `AnimationSystem.update` advances playback into the entity's `Visual` (clamps `frames ≥ 1` for the SVG-sprite quirk). `start` offsets the state into a **shared strip** (`vis.subimg = start + frame`) — how the unified humanoid sheet packs walk + attack into one sprite (see _Paper-doll appearance_).

**Paper-doll appearance (`Appearance` / `AppearanceSystem`).** Humanoids are one **unified, tintable body sprite** with worn gear drawn as **overlay layers**, not a baked sprite per outfit. Three pieces: **`spr_human`** is the canonical humanoid strip — since 2026-07-11 a **hand-drawn Aseprite sheet** (source `tools/pixel-art-kit/templates/human/sheet.png` + `sheet.json` — edit/re-export THOSE and re-run the importer; the sprite folder is importer-owned): 11 foot-anchored **32×32** frames of a white Rayman-style figure in **2-color art** (white fill + dark outline), tagged **idle 0 / walk 1–2 / fist 3–5 / kick 6–10**, with head/torso/hands/feet kept as **disconnected floating blobs** — no longer because animation is generated (it's hand-animated now), but because `human_sprites.py` **segments each frame's parts to cut the worn/held overlays from them** (two big blobs = head above torso; the four limbs split into hand/foot pairs by blob SIZE, learned from the neutral frame — so a kicking foot swung above a hand can't be misread; the importer fails fast if a redraw breaks the 6-blob contract). The white fill is **tinted per entity via `Visual.color` = the skin tone** (`RpgPlayer.SKIN`, a literal GM color int — a top-level `Color.parse` would race script load order); the outline stays dark under the multiply. The graph is defined once in `RpgPlayer.animGraph()` (offset-based `AnimState.start` over the one strip, mirroring the Aseprite tags — `attack` = the fist frames, plus a `kick` state the player's **unarmed** fist-fallback swing alternates with the punch (`PlayerSystem` latches `Playable.attackAnim` per swing; armed melee and gun-fire always play the punch thrust, so a held weapon rides the hand)). **`Appearance`** (`scripts/Appearance/`, Core/Component — Core because `RenderBillboard` reads it) is the layer stack `{ back: [{sprite,color}], front: [...] }`: `RenderBillboard` draws `back` layers, the body (`Visual`), then `front` layers, all at the **same subimg** — but **coplanar depth equality cannot be relied on**: GameMaker auto-trims sprites on the texture page, so each sheet's quad has different vertices and the interpolated depth diverges by float rounding under the depth-writing billboard pass — a later layer _randomly_ loses `cmpfunc_lessequal` (raiders bald under their bandanas; repacking the texture page reshuffles who loses). So each layer is **Y-biased** by draw order (`BB_LAYER_DY` = 0.05 world px per step — front layers toward the south-side camera at +y, back layers away at −y), which is decisive in the depth buffer yet invisible on screen; `sh_meshlit`'s texel cutout (`u_alphaRef`) keeps transparent texels from writing depth. (It must be **Y, not Z**: an upright sprite's quad is a constant-y vertical plane, so a z offset slides the layer _within_ the plane with zero depth separation — the original z-bias worked only for the pre-2026-07-05 reclined billboards, and the bald-raider z-fight returned the day sprites went upright.) Overlay layers keep their **own** color — the body's `Visual.color` is the skin tint and must not bleed into outfit colors; whole-doll effects (the downed dim) ride `Visual.alpha`, which layers share. **`AppearanceSystem`** (`scripts/AppearanceSystem/`, Gameplay/Equipment) rebuilds the stack **derived-from-source** like `StatModel.recompute`: it walks `Equipment` slots (order policy: `backpack` → back; `armor`/`trinket`/`weapon` → front) and pushes each worn item's `Equippable.worn` sprite (resolved via `asset_get_index` + `sprite_exists`). Rebuild runs at the same chokepoints as the stat re-derive — `EquipmentSystem.equip`/`unequip`, plus after the carried sheet lands via `EntitySnapshot.apply` in `RpgMap.go`/`resume` (Equipment arrives there outside `equip()`); `Appearance` itself is never serialized. **The invariant: every overlay sheet mirrors `spr_human`'s strip layout** (frame count/order, cell, foot anchor) — so overlays are **derived by `human_sprites.py` from the hand-drawn frames themselves** (each frame segmented, garments cut from the parts in place — never freehand) and can't desync. Reference overlay: the armored vest (`worn: "spr_wear_vest"` — the torso recolored below a 1-row neckline, outline preserved). **Held weapons are NOT sheets** (the generated `spr_held_pipe`/`spr_held_blaster` were deregistered 2026-07-11): a weapon `Equippable` with no `worn` falls back to the item's **own icon drawn ANCHORED at the right hand** — the importer emits each part's per-frame centroid into the manifest as `anchors` (origin-relative offsets), `AppearanceSystem` pushes an anchored front layer `{ sprite: item.sprite, anchor: "handR", scale: HELD_SCALE }`, and `RenderBillboard._drawLayer`'s anchored branch draws the icon (subimg 0, half scale, signed-xscale mirrored) at that frame's hand point — so **every weapon gets a held visual with zero dedicated art**, and the hand's own motion carries the thrust/kick. A weapon wanting bespoke posed art can still set `worn` (the `weapon` slot stays last in `FRONT_SLOTS`). Item **icons** auto-wire by the `spr_item_<id>` naming convention with a legacy-name fallback (`RpgItems.ICONS` alias table, `sprite_exists`-guarded) — an unmatched id keeps the UI's colored-box fallback. **The raider is a doll too**: its spawn uses `spr_human` with a deterministic skin pick (`RpgSpawn.SKINS`, hashed from the spawn cell so a regenerated chunk keeps the same face) plus an **authored** bandit outfit (`spr_wear_redBandana`/`blackShirt`/`blackSneakers` — an `Appearance` with **no** `Equipment`, which `AppearanceSystem.rebuild` deliberately leaves alone: only equipment-carrying dolls are derived/cleared) and the shared graph. **`CombatAI` drives the doll**: `_animate` picks idle/walk/attack per state (a short punch window after each swing) and flips facing by velocity **sign** (magnitude-preserving), and the aggro cue is a **flush** — `Color.merge` from `Brain.baseColor` (captured at attach; the skin tint) toward the state color, `k = 0` restoring the base exactly — instead of the old from-white wash that would have wiped the skin. **Every humanoid is now a doll** — NPCs (elder/merchants/the traveling peddler, all via the `npc` preset) and companions (`spawnFollower`) get a hashed skin + the **tintable civilian outfit** (`RpgSpawn._outfit` — the near-WHITE `spr_wear_shirt`/`spr_wear_shoes` sheets colored per entity via the Appearance layer color; the npc descriptor's `color` sets the shirt, so the elder/Trader/Quartermaster read distinct in `overworld.json`, and a companion's `opt.color` ally-green became its shirt, not a whole-body wash). Static NPCs just hold the idle pose; `FollowerSystem` drives a companion's idle/walk + magnitude-preserving facing flip (same pattern as `CombatAI._animate`). Non-humanoids split: creatures (rat) and the fence keep the plain single-`Visual` path, while boxy props with a vox model (crate/chest/survey sign/survival stations/portal/workbench/bed/cot/barrel/torch/lantern/turret) and the wilderness rocks carry a **`Mesh`** instead of a `Visual` (see Renderer → `RenderMesh`); the legacy `spr_hero`/`spr_heroAttack`/`spr_raider` assets were deleted in the 2026-07 media overhaul. **Entity size is a baked per-preset DESIGN scale, art density divides the draw scale — with `size` the separate per-spawn scalar**: each `EntityPreset` def's `scale` is the archetype's BASIC factor (raider 1.7 / rat 1.4 / npc 1.6 / follower 1.5 at the 32px cell; a spawn descriptor's **`size?`** scalar multiplies on top — the dedicated knob for special mobs like an Alpha Rat/boss, baking BBox + Visual + **Mesh** uniformly so a sized entity's look never diverges from its collider) and `RPG_PLAYER_SCALE` (via `RpgPlayer.spawn`'s `opts.scale`) are the **design size**, baked at spawn into `Visual.scale` **and** the `BBox` — so the foot shadow (`RenderEntityShadow`, BBox-driven) and the paper-doll layers (drawn at the body's `xscale/yscale`) follow with no extra plumbing, and per-preset size variety is a per-def tune. The **draw scale** (`Visual.xscale/yscale`) is `scale / SpriteMeta.density(sprite)` (see _Utility Modules → SpriteMeta_): a sheet authored denser for detail declares its density (default 1 = today's baseline) and lands at the **same world size**, so swapping art of a different resolution changes nothing in-world and never touches the BBox. Bake sites are `EntityPreset.spawn` / `RpgPlayer.spawn`; `AnimationSystem` refits when a graph state swaps to a different sheet (so mixed-density graphs are legal — a `Visual` without `scale` is legacy raw and never refitted). Overlay sheets inherit the body's draw scale, which is correct because the strip-layout invariant above forces them to share the body's cell/density. Because `|xscale|` carries size, the facing flip must preserve magnitude (`vis.xscale = ±Math.abs(vis.xscale)` — `PlayerSystem`), never assign bare `±1`.

**Interactions (`Interaction` / `InteractAction`).** "Walk near an entity + press E to do something" is a two-piece, data-driven system (`Gameplay/Interaction` kit — see _Gameplay Kit → `Interaction`_). An entity carries an **`Interaction`** component `{ kind, ...params }` (`kind` names a registered action; the flat params are per-instance data an action reads, e.g. `{ kind: "buff", status: "regen" }`). The **`InteractAction`** registry holds the behaviors — `register([{ id, prompt, run(ctx) }])`, mirroring `Item`/`Status`/`Prefab`; `run(ctx)` (with `ctx = { scene, world, id, comp, playerId }`) does anything, so adding an interaction is a data entry, not an engine edit. The RPG registers its set in **`RpgInteractions`** (Demo, called by `RpgContent.register`): **window** actions open a UI + set `scene._interOpenId` so the engine range-closes/refreshes them (`storage`→`StorageUI`, `workbench`→`CraftingUI`); **instant** actions act once per E press (`claim`→`BuildMode.claim`, `arcade`→`_openArcade`, `bed`→`_sleep`, and the survival trio `hydrate`/`feed`/`buff` that act on the **player** — `ThirstSystem`/`HungerSystem.restore`, `StatusSystem.apply`). The generic pick/prompt/dispatch **engine** is `Interactable` (Demo/UI): each frame `_pick` chooses one target `Interaction` (cursor-in-range, else nearest-in-range), the prompt pill reads the def's `prompt`, and E → `_open` looks up `InteractAction.get(comp.kind).run(ctx)` (no per-kind switch). E is arbitrated once by `sceneRpg._dispatchInteract` (station vs NPC). The survival trio is buildable (`BuildMode.CATALOG` **Survival** — vox-mesh props: tub/bin/alter) and authorable in the level editor (`RpgCatalog`'s Interaction field). Replaces the old Core `Station` component + hardcoded `_open`/`_promptText` switches.

- `RpgWorldOverlay` — the RPG scene's **world-space** overlay (`drawWorld(scene)`, called from `sceneRpg.draw()` inside the camera view, **after `renderer.draw()`** — the chunked overworld's `RenderChunks` pass paints an opaque ground fill that would hide overlay content drawn first): item-drop rarity squares, projectile dots (lobbed/grenade `Projectile` entities) + fading **hitscan tracers** (`pushTracer`, the muzzle→impact streak the firers push), and (when the scene exposes `reachZone`) the reach-quest zone. `_rarityColor` is shared with the inventory rows. The HUD, dialogue, and inventory window are real UI panels drawn on the GUI layer (`Draw_75`). **The RPG scene's walls are a real tilemap** (`RpgLevel` keeps a wall + floor `TileLayer` on the `Level`), drawn as lit boxes by the `RenderWalls` mesh pass (the other resident layers render as real `RenderTileMap` tilemaps per `RpgLevel.LAYERS`; the sprite-free `RenderDebugTileMap` cost fill remains as an off-by-default Debug → Render → Tiles overlay) with the buildable region by a `RenderZone` pass — world-space passes under/among the entity passes.

**World time & day/night.** **`WorldClock`** (`scripts/WorldClock/`, Demo) is the in-game clock — a static class like `Time` (one world clock), holding `hour` (0–24 float) + `day` (1-based), advanced once per frame from `sceneRpg.step()` by `Time.delta` (sim time — pauses with the game, dilates with `Time.scale`). `dayLength` (real seconds per in-game day, default 240) sets the pace. The scene `reset()`s it once in `create()` — **not** per map — so a portal trip keeps the hour. API: `reset()`, `update(dt)`, `clockText()` (`"HH:MM"`), `phase()` (`night`/`dawn`/`day`/`dusk`), `tint()` → `{ color, alpha }` interpolated from a keyframe table (deep blue at night → clear by morning, warm at dawn/dusk; alpha 0 in full daylight). The HUD shows `Day N HH:MM` (read live), and the **`RenderLighting`** pass (now in the `Gameplay/Lighting` kit) consumes `tint()` as its **injected ambient term** (`RpgMap.build` passes `ambient: () => WorldClock.tint()`; day/night is the light map with no lights).

**Seasons & temperature.** `WorldClock` also derives the **season** purely from `day` (no stored state, like `phase()` from `hour`): `daysPerSeason` (default 7) days each, the four cycling forever over a `_SEASONS` literal (`{ id, name }`). API: `season()`, `seasonDay()` (1-based day-within-season). The HUD time row reads `Season · Day N  HH:MM`. Season biases the `Weather` transition + the `Temperature` baseline. **`Temperature`** (`scripts/Temperature/`, Demo) is the ambient temperature in **Kelvin** (`toCelsius`/`toFahrenheit` convert) — a **pure derivation, not a stored sim**: `now()` = `ZERO_C` (273.15) + season baseline (`_BASE`, authored in °C, keyed by `season().id`) + a time-of-day swing (`diurnal()`, a cosine of the hour peaking mid-afternoon) + the live `Weather.tempMod()` (which already folds in the active climate zone's offset). The Kelvin/Celsius scales share one increment, so all the deltas are scale-agnostic — only the baseline is offset. Kept **off** `WorldClock` so the clock stays the pure temporal authority. The HUD shows the weather condition + temperature via **`Temperature.display()`**, which formats `now()` in the `tempUnit` Setting (`"K"`|`"C"`|`"F"`, default `"K"`; toggled in the inventory **Settings** tab); the bundled locale fonts carry the `°` glyph, so `°C`/`°F` render.

**Weather.** **`Weather`** (`scripts/Weather/`, Demo) is the global sky — a static singleton like `WorldClock` (one sky), holding the current condition + a **season-biased transition**. Conditions are a fixed built-in literal table (`_COND` — `clear`/`cloudy`/`rain`/`storm`/`snow`), each carrying its render look (`{ c, a }` tint + `particle`/`density` + `cloud` shadow coverage) and a **Kelvin `temp` delta** (scale-agnostic, folded into `Temperature.now()`). `update(dt)` (driven from `sceneRpg.step()` by `Time.delta`, so weather **freezes when the game pauses** and dilates with `Time.scale`, like the clock; it also accumulates **`Weather.time()`**, the cumulative sim-second clock the weather **visuals** — rain/snow fall, cloud drift — scroll on, so they pause/dilate too) counts down a 25–70 s hold then re-rolls the next condition by `_WEIGHTS[season]` (winter favors snow + bans rain, summer favors clear + the odd storm, …), **excluding** the current one so a change always changes the weather. A change **cross-fades** over `_fadeTime` (2.5 s): `previous()`/`current()`/`blend()` let the render pass + `tempMod()` lerp the outgoing→incoming conditions so weather eases in/out instead of snapping. `reset()` (scene `create()` once, like `WorldClock.reset()`) settles a clear sky and survives map changes. The **`RenderWeather`** pass (see Renderer) draws it; the HUD reads `current().name`.

**Climate zones (regional weather).** A **climate `ZoneMap` channel** lets a region **override** the open sky. `Weather.enterRegion(zone)`/`exitRegion()` read the zone's flat `data` — `weather` (a forced condition id) + `tempMod` (a Kelvin offset) — into an `_override`/`_regionTemp` slot; the _displayed_ condition is the effective one (`override ?? ambient`), so the season-rolled ambient keeps running underneath and resumes on exit (the cross-fade handles both edges). Climate zones are **data-driven** from a level file's optional `meta.climate` array (`[{ name, rect: [gx1,gy1,gx2,gy2], weather?, tempMod?, color? }]`), painted into the `"climate"` channel by `RpgMap.build` (once, right after the buildable channel — a map builds only on its first visit). `sceneRpg._updateClimate()` tracks the **player's** climate cell directly each frame (a single-entity `ZoneMap.idAt` lookup — cheaper than `ZoneSystem`'s all-entity sweep) and fires enter/exit on a border cross; `RpgMap.suspend` calls `exitRegion()` so a portal trip clears it (the resumed/built map re-detects on its first step). The reference is `overworld.json`'s **Frostlands** (`weather: "snow"`, `tempMod: -15`) — walking in turns the sky to snow and drops the temperature ~23 K. **Indoor maps** (`meta.indoor`, e.g. `interior_01`) skip the `RenderWeather` pass entirely — no open sky inside a cave (the global `Weather` keeps running; only its visual is suppressed).

The combat/loot plumbing the RPG scene (`sceneRpg`) uses lives in **`RpgScene`** (`scripts/RpgScene/`, Demo) — free functions taking the scene (composition; no class inheritance on GMRT): `trackDamage(scene, yOffset)` (also pops ally numbers for every `Follower` entity, by live query), the `Mortal`-driven death pair `resolveHealth(scene, handlers)` + `updateDowned(scene, handlers)` (see _Death_ above — these replace the old `resolveDeaths`/`checkPlayerDeath`), `spillLoot`/`spawnDrop`, `collectDrops(scene, onCollect?)`. Scene-specific side effects (quest/profile counters, the player respawn reset, the companion recovery spot, down/recover toasts) are the handlers; the scene supplies the contract fields `world`/`playerId`/`_hpTrack`/`_invDirty` (the enemy set is derived live by **`Faction`** — Health-bearing bodies hostile to the player — not stored, and not a marker/tag).

The **character window** is centralized in **`RpgInventoryUI`** (`scripts/RpgInventoryUI/`, Demo) — a **near-fullscreen, fixed** (non-draggable, non-resizable) **`gemsTabs`-based** overlay modeled on the `SystemMenu` panel: an absolute full-screen host with a dim backdrop (shown/hidden via `scene._invWin.enabled`, **not** a `UIModal`) centering a full-height card whose tab host flex-grows, built once in `build(scene)` on `scene._invWin`, with seven tabs: **Items** (the bag `UITable` over a usage line + a category-filter `gemsSelectCustom` + a free-text name-search `gemsInput` composing into one `table.setFilter` via `_applyFilter` — search lowercases via an ASCII char-code map, since `toLowerCase()` is broken on GMRT — plus a select/action row: click selects, double-click / the context **Use/Equip/Unequip** button / a gamepad confirm acts on the row), **Equipment** (worn-slot rows, click to unequip — `scene._invEquipHost`), **Squad** (the companion roster — one `gemsCard` per squad member (live `FollowerSystem.members` query, player excluded) into `scene._invFollowerHost`, with the follower's name + a **live** follow/wait status & carry-bonus line + a **Kick from squad** button (`scene._kickFollower`, live-disabled once out or while down) + a binding-aware rehire hint; the host is repopulated per `rebuild` since membership changes, but each row's text/disabled-state reads the live components so an F-toggle/kick updates with no rebuild), **Stats** (the live sheet + the genre's extra records — `scene._invExtraHost`), **Quests** (a live `gemsQuestTracker` bound to `QuestLog`), **Achievements** (one `gemsCard` per registered `Achievement` def — built once, since the set is static after registration; the Unlocked/Locked status is a live `gemsRichText`, so an unlock or the Debug panel's Unlock/Clear All shows with no rebuild), **Settings** (per-column toggles). The Items columns are gated by the **Settings** toggles (`gemsCheckbox` → `Settings.set`/`save`, persisted across launches): worn-marker / Name / Qty always; **Rarity** / Type / Weight / Value optional. A toggle calls `_applyColumns` → `UITable.setColumns`, which remaps the active sort by each column's stable `key` (the sort stack stores indices, which shift when columns change). `rebuild(scene, { equipSlots, extraRows? })` only refreshes live data: `table.setRows` (re-applies the current sort/filter, so view + scroll + active tab survive every equip/use), re-maps the selection by `itemId`, repopulates the equipment + extra sections. `equipSlots` is the rows to show (RPG adds `backpack`); `extraRows(scene, host)` appends genre lines (RPG Profile records). The scene keeps only `invOpen` (toggled on the `inventory` key) and calls `build` in `create()` + `rebuild` when `_invDirty`. (The HUD stays per-scene — `sceneRpg._buildHud` = HP + quest tracker.)

`sceneRpg.step()` is the reference RPG orchestration: edge-toggle the inventory window → per tick: `snapshot` → `physics` Pipeline (headed by `PlayerSystem`, the player brain) → `RpgScene.trackDamage` → `RpgScene.resolveHealth` (despawn/respawn/down by `Mortal`) → `RpgScene.updateDowned` (revive timer) → `RpgScene.collectDrops` → reach/quest/achievement checks → `flush`; then once per frame: `AnimationSystem.update`, NPC proximity + dialogue, `Interactable.update`, `BuildMode.update`, `camera.update`, an inventory rebuild when `_invDirty`, and finally `_checkPortals()` **last** (a door swaps the world out from under everything). (No pause gate in `step()` — `obj_game` skips `scene.step()` entirely while the `SystemMenu` overlay is open.)

**Map graph (overworld / sub-levels / side-islands).** Maps are discrete level files connected by portals, not one streamed world (the deliberate fit for the `JSON.parse`-on-large-files limit and the one-`World`-per-scene model). The world graph is the seed registry **`RpgLevel.MAPS`** (`{ mapId → "levels/x.json" }`) + `RpgLevel.START`; extract to a `maps.json` manifest if it grows. A level file gains two things over the base format: `meta.entries` (a named-point map, e.g. `{ default, from_interior }` — the matching side of a door; `RpgLevel.build(world, data, entryId)` resolves the spawn from it, falling back to `entries.default` then legacy `meta.playerSpawn`) and a **`portal`** spawn preset (`{ toMap, toEntry, label?, color? }` → a non-solid sensor entity, returned in `RpgLevel.spawn`'s `portals[]`). `sceneRpg.create()` builds the **persistent** UI once (HUD/dialogue/inventory/Interactable/BuildMode — they read `world`/`playerId` live, so they survive a map swap), then calls **`RpgMap.go(scene, mapId, entryId)`** — the portal-travel orchestrator. Rather than destroy + rebuild on every door, `go` keeps each visited map's `World` **alive and suspended** in the **`World.levels` registry** (the map pool — the registry entry IS the park bundle; there is no scene-side pool): it **parks** the current map (`suspend` → stash its `world`/`level`/`renderer`/`camera`/`pipeline` references into the registry entry, no teardown) and then either **resumes** the target's parked bundle (`World.levels.entryOf` — a revisit: no file reload, no rebuild) or **builds** it from file (`RpgMap.build` — a first visit only, registering a minimal `{ world, level }` entry that the next suspend overwrites). Only the **squad** crosses worlds: `go` collects every entity sharing the player's `Squad` id (player first — there is **no per-map player** and no carried component subset), forces any `"wait"` member back to `"follow"` (+carry bonus — waiting is map-local, never a way to stay behind), and moves each one as a **whole entity** through **`World.levels.take`/`put`** (the same registry transfer the wandering trader uses), landing them at the target's named entry with Position/Velocity overrides; `scene.playerId` re-latches to the transferred player's new id (and is re-derived from the live `Playable` query each frame anyway — there is no stored player handle to dangle). Everything else (kicked/unhired companions, built tiles/entities, the buildable zone, dead enemies) just stays resident in its parked world, so nothing has to be hand-marked for persistence. A resume re-binds the map-context statics (`MotionPlanner` grid + `CombatAI.bind`). The player-centered radar (`RadarArrows`) reads `world`/`playerId` live, so it needs no per-map rebuild. `RpgMap.checkPortals` (step's last line) travels through the first portal the player overlaps. The editor's Test Play still works: a `playtestFile` is registered under a synthetic `_playtest` map id and booted as a single portal-less map. `_updateNpc`/`_checkReach` guard the no-NPC / no-reach-marker maps (interiors). The reference graph is `overworld` ⇄ `interior_01` (a cave door).

**Map persistence (everything, always — for the session).** A map builds from file exactly **once** (its first visit) and thereafter only freezes/thaws **as-is**: the map's `World`/`Level` are **kept alive** in the `World.levels` registry (the map pool) for the whole session — there is **no eviction, no cold serialize, and no respawn-from-file reconcile** (the old `Persistent`/gone-ledger machinery is deleted). So _everything_ persists across a door trip by construction — player edits (claimed buildable zone, built tiles, placed entities), kicked/unhired resident companions, dead enemies (a killed unique is simply absent from the live world), moved/hurt bodies, and file spawns (which run once, ever — nothing re-spawns on a revisit). The pool is session-scoped: `Quit to Lobby` / scene destroy parks the active map, frees every registry entry (`sceneRpg.destroy` → `RpgMap.suspend` + a `World.levels.ids()` walk of `RpgMap._free`), and resets the registry (a fresh RPG open is a new world). Memory pressure is bounded by the map-graph size (currently 2); a disk save is the follow-up seam (serialize the registry bundles next to the carried character sheet — mind the `JSON` nested-value fault).

**The squad (dynamic-world entities).** The party concept is a **component, not scene data**: **`Squad`** (`scripts/Squad/`, Gameplay/Squad, `{ id }`) marks membership — the player mints a unique id at spawn (`RpgPlayer.spawn`, `uuid()`), and every hired companion carries the same id. There is **no roster list anywhere**; every consumer (travel, the F toggle, the Squad tab, ally damage numbers) resolves membership by live query (`FollowerSystem.members(world, squadId, playerId)` — player first). `Follower` (`scripts/Follower/`, `{ state: "follow"|"wait", speed, range, bonusCapacity, bonusWeight }`) is the **behavior** component; `FollowerSystem.update(world, playerId)` drives every `Follower` entity per tick (a `"follow"` member steers toward the player, easing to a stop within `range`; `"wait"` and non-members hold still). The player id is **passed in, never stored**, so a transferred companion needs no re-link. It's a dynamic solid body; `RpgSpawn.spawnFollower(world, x, y, opt)` builds it via the `follower` `EntityPreset` def — spawning **unhired**: a map resident with an `Interaction { kind: "rehire" }` (talk to recruit). **Hire/kick own the membership transitions** (`FollowerSystem.hire`/`kick`): hire = `Squad` + follow + carry bonus + drop the rehire prompt; kick = the reverse, **permanently and in place** — a kicked companion stays a resident of that map until re-hired by talking. `sceneRpg` seeds the starting companion programmatically once in `create()` (spawn + `hire`); the `F` key flips the nearest **member** between follow and wait — but waiting is **map-local only**: a portal forces every member back to `"follow"` (+bonus) and takes the whole squad (see _Map graph_). A companion carries `Health` + a `down`-kind `Mortal`, so it's an **attackable combatant**; at 0 hp it goes **Down** and later revives at the recovery spot (see _Death_).

A member also **helps carry**: while following it grants the player **`bonusCapacity`/`bonusWeight`** (extra `Inventory` slots + weight cap) via `FollowerSystem.applyBenefit` — a balanced +/- delta exactly like `EquipmentSystem`'s `Container` bonus, paired with the state flip in **one place** (`FollowerSystem.setState`) so it can't half-apply; hire/kick and the portal's forced-follow all route through it. Because the bonus is baked into the player's live `Inventory` and the player transfers **whole**, it rides across maps with no re-apply. Only the programmatic seed grants a bonus; the `follower` preset leaves it 0, so file-authored followers stay benefit-free. Kicking happens from the inventory **Squad** tab (`scene._kickFollower`) or not at all — there is no dismiss-and-recall; re-hiring is the `rehire` interaction (walk up + E).

**Chunk streaming & sim-LOD (scalable overworld).** A **chunked map** (`meta.chunked: true` in the level file) streams its terrain + entities around the player so the `World` only ever holds what's nearby — entity count + per-tick cost stay bounded no matter how far the player roams (the overworld; interiors keep the plain build-everything path). The engine is the Core **`ChunkManager`** (`scripts/ChunkManager/`, a plain instance class owned by the scene as `this.chunks`, like `LevelManager`); content comes from the **generator** it's handed (the RPG's pass-composed `OverworldGen.create` `ChunkGenerator`) plus the injected `opts.spawn` adapter. Built on `EntitySnapshot` (the capture/restore foundation) + `Portal` (`scripts/Portal/`, `{ toMap, toEntry }` on the doorway entity, so a streamed door resolves via a live `world.query(Portal)`).

- **Two-ring sim-LOD** (Chebyshev chunk distance from the player's chunk): `d ≤ simRadius` → **SIM ring** (entities live in the World, walls have colliders, full simulate + render); `simRadius < d ≤ loadRadius` → **LOAD ring** (entities held as snapshots, **not** in the World / not simulated, drawn statically by `RenderChunks`; walls drawn, no colliders); `d > loadRadius` → **UNLOADED** (the whole record parked in an in-session cache keyed by chunk, restored on return so hurt/killed/moved entities persist). `ChunkManager.update(centerX, centerY)` (called once per frame from `step()`, outside the tick loop) diffs the rings on a chunk-border crossing and **promotes** (restore → World + mesh colliders) / **demotes** (capture → snapshot + drop colliders) / loads / unloads, then `world.flush()`es its own removals. **The world is pregenerated** ("generate the level once, then only load/unload"): `RpgMap.build` calls **`ChunkManager.pregenerate()`** once (the finite 8×8 = 64 chunks, ~130 ms, behind the scene fade), generating every in-bounds chunk's record into that cache up front — mid-game streaming is pure load/unload (`generate()` never runs during play; entity _spawning_ still LODs — descriptors stay dormant until a chunk first enters the SIM ring), and the manager's **store-backed samplers** (`materialAt`/`costAt`, falling back to the generator's pure sampler outside the store) feed `TerrainStream`'s seam apron, `NavGrid`'s weights, and `PathFollow`'s pricing from stored terrain instead of re-sampling noise (`RpgMap._terrainCost` wires `chunks.costAt`). Pregeneration runs **once per session** (a map is never rebuilt); determinism (same seed → same world) still holds per build. (A non-pregenerated chunk still generates lazily on first load; the old amortizing load queue is gone — moot once loads became cache moves.) The **squad (player + hired companions) is never chunk-managed** — the scene keeps it in the World always.
- **Resident grid vs streamed terrain.** A chunked map's `Level` is a large **resident** grid (`meta.worldCols/worldRows`, built by `RpgLevel.buildChunked`) whose `wallLayer`/`floorLayer` hold **player builds only** (build mode + `TileEdit` colliders, unchanged) — the streamed terrain (authored hub + procedural wilderness) is owned by the `ChunkManager` with its own colliders + `RenderChunks` pass, never written into those layers, so the two never conflict. The world is a **finite `worldCols × worldRows` rectangle** (the resident-grid extent, anchored at cell 0): `ChunkManager` clamps streaming to chunks inside it (`opts.worldCols/worldRows` → it skips out-of-bounds chunks, so the active set shrinks near an edge — e.g. 9 at a corner vs the usual 25), and `RpgLevel.buildWorldBorder` rings it with 4 always-present kinematic-solid edge colliders so the player/slimes can't leave (procedural fills the rectangle out to the border; building is gated to the claimed origin zone). `IdPool` reuses freed indices, so streaming churn keeps the high-water mark bounded.
- **`OverworldGen` (composition) over `ChunkGenerator` (frame) + `AuthoredStamp`/`PrefabStamp` (passes) + `TerrainField`/`Rand`/`Prefab` (Core machinery), with `RpgBiomes` (data) + `RpgPrefabs` (templates).** Generation is **not fixed** — it's split so a different world is a swap, not a rewrite:
  - **`AuthoredStamp`** (`scripts/AuthoredStamp/`, Core/Level) is the authored-overlay **pass** (it replaced the old `ChunkSource` router layer): the level file's walls + spawns are indexed per chunk at construction, and any chunk inside the authored **bounding box** takes exactly that content — the pass runs first and sets `ctx.authored`, which the procedural passes (`PrefabStamp`, the scatters) respect by early-outing, so the hand-built hub (Elder, cave portal, chest, workbench, survey post) stays procedural-free even where sparse. With the router gone, `ChunkManager` holds the **generator directly** and takes an injected **`opts.spawn`** adapter (`(world, level, desc) → id`; the RPG wraps **`RpgSpawn.spawnEntity`** — the descriptor adapter over the `EntityPreset` defs — so streamed + up-front spawns build through one code path; fail-fast if a chunk carries spawns with no adapter). `TerrainStream` reads the material table off `chunks.generator.palette` (the generator instance's field, never a class static, so a swapped-in generator brings its own tilesets).
  - **`ChunkGenerator`** (`scripts/ChunkGenerator/`, Core/Level) is the generation **frame** — `Renderer`:`RenderPass` :: `ChunkGenerator`:gen pass: an ordered list of **passes** (each `{ salt?, apply(ctx) }` or a bare `fn(ctx)`, wrapped on `insert` like a `Pipeline` step; `insert(pass, index?)`/`remove(pass)` mirror `Renderer`) builds a chunk's `walls`/`spawns` into a shared ctx (`{ gen, field, cx, cy, gx0, gy0, cols, rows, rng, out }`), while the terrain base comes from the composed **`field`** (a `TerrainField`-like sampler, required) — so the frame satisfies the whole generator surface `ChunkSource` routes (`generate(cx,cy) → { terrain, solid, walls, spawns }` + `palette` + the four samplers). **Each pass draws from its own rng stream**, seeded from `(cx, cy, seed, pass salt)`: a chunk regenerates identically every visit (the streaming contract), **and** inserting/removing a pass never reshuffles the other passes' output — declare a unique small-int `salt` per pass (an undeclared salt falls back to list index, which re-couples streams to order). All randomness through **`Rand`** (Core/Util; MINSTD, not xorshift — the GMRT-Safe Idiom).
  - **`PrefabStamp`** (`scripts/PrefabStamp/`, Core/Level) is the generic prefab-stamp **pass**: chance roll → weighted pick from `Prefab.byTag(tag)` (resolved at construction — register prefabs first) → `Prefab.stamp` at a random interior offset (`margin` cells off the chunk border so stamped walls can't merge across a seam), deep-copying `loot`/`items` per stamp. Policy enters via two hooks so the pass stays content-free: `spawnFilter(s, field)` (keep a stamped spawn?) and `defaultLoot(s, rng)` (loot for a spawn that authored none — drawn **before** the filter verdict so a skipped spawn consumes the same rng draws). Warns at construction if an eligible prefab carries `tiles`/`zones` (chunk output has no channel for them).
  - **`OverworldGen`** (`scripts/OverworldGen/`, Demo/System) is now the RPG **composition**: `OverworldGen.create(opts) → ChunkGenerator`, wiring the RPG `TerrainField` (data in `RpgBiomes`) + three passes — a `PrefabStamp` carrying the RPG spawn policy (`spawnFilter` default keeps mobile combatants (raider) off water — nothing spawns swimming; `defaultLoot` default rolls the wilderness raider loot table, `OverworldGen.rollLoot`), a **rocks** scatter, and a **rats** scatter (wildlife kept off water) — the scatter passes are plain pass objects defined here (content, not machinery). A different world (cave/desert/…) is a different composition of the same Core pieces; a variant overworld overrides the policy hooks via `opts` (`seed`/`chunkCols`/`chunkRows`/`prefabChance`/`prefabTag`/`spawnFilter`/`defaultLoot`). The terrain machinery is **`TerrainField`** (`scripts/TerrainField/`, Core/Level — held as `gen.field`, a palette-driven pure-coordinate sampler; a cave generator composes the same class with its own palette), and the RPG's DATA is **`RpgBiomes`** (`scripts/RpgBiomes/`, Demo/Content — the `TERRAIN` palette, the design-reference `PALETTE`, and the noise tuning `LATTICE`/`GROUND_LATTICE`/`GROUND_SALT`; a plain top-level data literal, no registration step): per cell it picks a material from **two value-noise channels** (`materialAt`) — an **elevation** gradient (`threshold` entries — deep water → water → sand; past the last one the cell is land) plus an independent **ground-detail** channel (`ground` entries — mud/soil/rich soil/grass/gravel/rocky, grass dominant with wet depressions and gravel-ringed rock outcrops as patchy features — one shared gradient would instead ring every shoreline with fixed contour bands). Each palette entry carries a **weighted `pathCost`** (TileType convention: `null` → impassable) that prices both routes (`NavGrid` samples it via `costAt`, `MotionPlanner` multiplies it into step distance) and movement-point consumption (`PathFollow.speedScale` — a mover's speed × `1/cost`): easy ground 1, sand/gravel 1.5, mud/rocky 2, shallow water **wadeable** at 3 (A* only wades when it beats walking around) but **`spawnable: false`** (`TerrainField.spawnable` — travel yes, homes no); only **deep water** is `null` → `solidTerrain(cx,cy)` greedy-meshes those cells into `solid` rects in `generate()`'s output, which `ChunkManager` turns into **collide-only** colliders (not rendered — `TerrainStream` already draws the water) that physically block bodies **and** feed `NavGrid`.
  - **`Prefab`** (`scripts/Prefab/`, **Core/Level**) is a registry of reusable mini-layouts, mirroring `Item`/`Rarity`: a `cols/rows` footprint + scope `tags`/`weight` + up to four **prefab-local** content channels (all optional) — `walls` (bare collide-only rects `[[lx,ly,w,h]]`), `tiles` (writes into a **named** `TileLayer`: `{ layer, type, rects }`), `zones` (a region painted into a `ZoneMap` channel: `{ channel, name?, tags?, data?, rects }`), and `spawns` (**opaque** consumer-shaped descriptors `{ lx, ly, ... }` — Core never reads their fields). `register()` **fail-fast validates** every channel against the footprint (an out-of-footprint rect would silently break a generator's seam margin). Two consumption modes: **`stamp(ox, oy)`** translates all channels local→absolute (pure data — the chunk path), and **`apply(opts)`** writes the Core-expressible channels into a level (`tiles` via `TileEdit.set` — the caller remeshes a solid layer's colliders once after its stamps; `zones` defined + painted, channel created on demand; `walls` as kinematic colliders in the passed entity store) and returns the translated `spawns` for the caller's own adapter (e.g. `RpgSpawn.spawnEntity`). The chunk pipeline consumes only `walls` + `spawns` — the **`PrefabStamp`** pass (see above) does the picking/stamping and warns when an eligible prefab carries `tiles`/`zones` (an `apply()`-based generator is the consumer for those). The RPG's defs (`boulder_cluster`/`raider_camp`/`ruin` — walls + spawns only) live in **`RpgPrefabs`** (Demo/Content), registered by `RpgContent.register()` alongside items/recipes.
  - Slimes survive capture/restore because state callbacks receive `(world, id)` from `StateSystem` (no world static), `State` holds pool-id **strings**, and `Brain` carries no self-id; the one per-map static left is `CombatAI._level` (pathfinding), refreshed on each `attach` and re-pointed by `CombatAI.bind` when a parked map is _resumed_ without re-attaching — see _Map graph_.
- **Scene wiring** (`sceneRpg`): `RpgMap.build` branches on `meta.chunked` — chunked builds the resident grid + creates `this.chunks`/`this.generator` + pregenerates + an initial `chunks.update(spawn)` + inserts `RenderChunks`; plain is unchanged. The scene reads NPC / portal / enemy handles **live by tag** (`Query.nearest({tag:"npc"})`, `world.query(Portal)`, `RpgScene._enemies`) rather than stored id lists, so chunk churn never dangles a handle. A map switch **parks** the manager with its world (a suspended chunked map just stops streaming; `resume` re-centers it on the entry), and `RpgMap._free` drops it only at scene end. Verified flat (~74 ents / 25 chunks at `simRadius 1`/`loadRadius 2`) across a ~15-chunk traverse, clamping near a world edge. **Now retained by the pool:** the chunked overworld's chunk cache survives a portal trip (its world is parked, not torn down). **Deferred:** per-chunk _build_ persistence + on-disk chunk saves, throttled distant ticks.

## Pathfinding Flow

1. `world.add(id, PathRequest, { startX, startY, goalX, goalY })` — request in grid coords.
2. `PathfindingSystem.update(world)` resolves → writes `PathResponse: { path, index }` (`index` = cursor).
3. `PathfindingSystem.current(world, id)` → current waypoint `{x, y}` or `undefined`.
4. `PathfindingSystem.advance(world, id)` → `true` if more waypoints remain; `false` (and detaches `PathResponse`) when complete.
5. After any grid change: `PathfindingSystem.invalidate(world)` — detaches all `PathResponse`.

**Path consumption (`PathFollow`).** **`PathFollow`** (`scripts/PathFollow/`, Core) is the consumer side of the flow — extracted from `CombatAI` so any steering system shares one path walker and one terrain-cost rule. `target(world, level, id, state, sp, tx, ty)` returns the mover's proper **movement point** this tick: it replans on `state`'s `pathCd`/`pathRate` throttle (any bag carrying those fields — `CombatAI`'s `Brain`), advances the waypoint cursor on arrival (within 0.4 cell), and falls back to `(tx, ty)` while no `PathResponse` exists (the request resolves later the same tick). `clear(world, id)` drops both path components (LOS cleared / leaving the behavior). It also owns **terrain movement-point pricing**: an injected per-map `costProvider` (`bind(fn)`, rebound each map activate like `CombatAI.bind`, `(wx, wy) → cost`) feeds `costAt`/`speedScale` — a mover multiplies its speed by `1/cost` at its feet (clamped at `maxCost` 4 so a blocked sliver can't strand it). Consumers: `CombatAI._seek`, `FollowerSystem`, `PlayerSystem` (the player wades/slogs like everyone).

**Pathfinding grid (`NavGrid`) — the ONE live nav source.** `MotionPlanner` plans over one `MotionPlanningGrid`; the obstacles aren't tile data — terrain/walls/border exist as kinematic-solid collider _entities_ (owned by `ChunkManager` on the chunked overworld, where the world is large and only nearby chunks are loaded). **`NavGrid`** (`scripts/NavGrid/`, Core) is the adapter: a small fixed window (default 32×32) re-centered on the player each frame (`rebuild(world, gx, gy)` from `sceneRpg.step`, before the tick loop) by rasterizing every kinematic-solid collider's `AABB.of` footprint into blocked cells **over a terrain-cost base** — an optional constructor `costAt(wx, wy)` sampler (the same provider `PathFollow` binds; `RpgMap._terrainCost` wires `chunks.costAt`) fills each cell with its weighted movement cost (cached per window, resampled only when the origin moves), which `MotionPlanner` multiplies into step distance — so A* prefers cheap ground and only wades water when it beats walking around. Exposes the `MotionPlanningGrid` interface in **absolute level-cell coords** so paths return level cells. `size()` is constant, so `MotionPlanner.setGrid(scene.nav)` is called **once per map**; only occupancy/origin change per frame. One cheap grid unifies streamed terrain + border + player builds + interior walls. The consumer is **`CombatAI.CHASE`**: line-of-sight-first — a clear shot (`Raycast`) is a straight seek; only a wall triggers a throttled `PathRequest` → `PathfindingSystem` → `PathResponse`, walked via `PathFollow.target`. `RpgMap` inserts a default-off `RenderDebugPath` pass for the Debug **paths** toggle.

## Level & Map Layers

`LevelGrid` (`scripts/LevelGrid/`) manages the tile grid + zone channels, **separate from the ECS store** (scenes hold one as `.level`). It carries **no pathfinding grid** — live nav is `NavGrid` (colliders + streamed-terrain costs, see Pathfinding Flow); the layers' tile costs are read on demand via `costAt` only for debug inspection.

```js
const grid = new LevelGrid({ cellWidth: 32, cellHeight: 32 }); // cols/rows derived from room size
const terrain = new TileLayer(grid.cols, grid.rows, { emptyCost: Infinity }); // blocking base
grid.insert(terrain); // append a LevelLayer (grid.remove to detach)
grid.costAt(x, y); // on-demand tile cost — topmost layer wins (debug shading; NOT live nav)
grid.worldToGrid(wx, wy);
grid.gridToWorld(gx, gy); // ↔ { x, y } (gridToWorld returns cell center)
```

**`LevelLayer` interface**: `get(x,y)`, `set(x,y,v)`, `getNavData(x,y) → { cost }`, `export()`, `import()`, `destroy()`. The one built-in is **`TileLayer`** (`scripts/TileLayer/`), wrapping a `Grid` of **`TileType`** values. Later-added layers have higher cost priority in `costAt`. Empty cells report the layer's `emptyCost`: `undefined` (default) passes through to lower layers; `Infinity` makes a blocking base. `TileType` (`scripts/TileType/`) holds `{ id, name, pathCost }` (`pathCost: null` → `Infinity`, default `1`).

**`TileEdit`** (`scripts/TileEdit/`, Core) is the genre-agnostic tile-editing service that keeps a solid layer's **colliders** in sync with edits, so the "edit a solid tile → rebuild colliders" invariant lives in one place (there is no nav resync — live pathfinding reads `NavGrid`, and the colliders it meshes ARE how a wall reaches nav). `occupied(layer,gx,gy)` (truthy read — `Grid.get` returns `0`, not `undefined`, for an empty in-bounds cell), `set(layer,gx,gy,type)` / `clear(layer,gx,gy)`, `meshSolid(world,level,layer,out)` (greedy-mesh the solid cells into the fewest kinematic-solid colliders — extend right for width, then down while the whole row is solid — so straight walls become single seamless colliders, avoiding the per-cell-seam snag bug; box size = `level.cellWidth/Height`, ids pushed onto `out`), and `remesh(world,level,layer,colliders)` (remove old + re-`meshSolid` after a solid-tile edit). Shared by `RpgLevel.build` (initial mesh) and `BuildMode` (per-edit set/clear/remesh); the seed for a future in-engine tile editor.

### Zones

**`Zone`** / **`ZoneMap`** / **`ZoneSystem`** add named, tagged spatial regions on top of the level grid — the substrate for build-mode buildable area, faction territory, in-game events, quest regions, weather areas, etc. (Separate from tile layers and from nav cost; a zone is metadata, not a tile.)

- **`Zone`** (`scripts/Zone/`) — a flat definition object `{ id, name, tags, data }`. `tags` is a **`string[]`** (`hasTag(t)` via `indexOf`), never a `Set` (Set iteration crashes GMRT); `data` is a flat scalar payload (`{ factionId, weather, questId, color, … }`) to stay JSON-safe.
- **`ZoneMap`** (`scripts/ZoneMap/`) — one zone **channel**: a `Grid` of zone-id ints (`0` = none) plus a registry of `Zone`s, exactly as `TileLayer` wraps `Grid<TileType>`. A cell belongs to **at most one zone within a map**, so lookup is O(1) and storage is one int per cell; purposes that can overlap (faction vs. weather vs. event) live in **separate maps**. API: `define(opt) → Zone` (auto-assigns id), `zone(id)`, `byTag(tag)`, `paint(id,gx,gy)`/`paintRect(id,x1,y1,x2,y2)`, `erase`/`eraseRect`, `idAt(gx,gy)`, `at(gx,gy) → Zone`, `contains(gx,gy,tag)`, `cells(id) → {x,y}[]`, `export`/`import`/`destroy`.
- **`ZoneSystem`** (`scripts/ZoneSystem/`) — the entity↔zone glue, a stateless system object with named methods (no World tick): `update(world, level, map, { tag?, onEnter?, onExit? })` fires enter/exit edges as entities cross borders (mark-and-sweep over `map._inside`, so leaving to an empty cell _or_ being removed both fire `onExit`); `zoneOf(world, level, map, id) → Zone`; `entitiesIn(world, level, map, id, { tag? }) → id[]`. Drive `update` from a scene's `step()` for events/weather/quests.

Zones live on the **`Level`** (they are level data): `level.addZoneMap(key, map?)` (sized to the grid by default), `level.zoneMap(key)`, and `level.zoneAt(key, wx, wy) → Zone` (world-space convenience). `Level.export`/`import` round-trip zone maps under a `zoneMaps` key, emitted only when non-empty so existing serialized levels are unaffected; `Level.destroy` tears them down.

To **visualize** a channel, add a `RenderZone` pass (see Renderer) to the scene's renderer: `renderer.insert(new RenderZone(level, "faction"))`; for the zone names add a `RenderZoneLabel` pass after it: `renderer.insert(new RenderZoneLabel(level, "faction", { font }))`.

The reference consumers are the RPG scene's **build mode** (`BuildMode`, see Genre UI managers) — a `"buildable"` channel whose region a Survey Post claims (`paintRect`), gating where tiles may be placed, drawn by a `RenderZone` pass — and its **`"climate"` channel** (see _Climate zones_ under Weather): regions that override the global `Weather` (forced condition + temperature offset) while the player is inside.

## Renderer

`Renderer` (`scripts/Renderer/Renderer.js`) is an ordered list of `RenderPass` objects (`{ draw(world), destroy() }`). `insert(pass, index?)` / `remove(pass)` manage the list; `draw(world)` runs every pass; `destroy()` tears them down. Each scene owns its renderer and calls `this.renderer.draw(this.world)` in `draw()`.

Built-in passes:

- **`RenderEntity`** — draws entities with `Visual` + `Position` via `draw_sprite_ext`. Interpolates between `PrevPosition` and `Position` by `world.alpha` when present (see `InterpolationSystem`); falls back to raw `Position` otherwise. An invalid `Visual.sprite` — or an SVG one, which exists but reports 0 frames on GMRT — draws as the **`spr_missing`** placeholder (subimg re-wrapped to the placeholder's frame range); `RenderBillboard` shares the same fallback on the body sprite. This fallback is what retired the colored-box entity stand-in (`RenderDebugBox`) and its label companions (`RenderDebugName`/`RenderDebugDirection`/`RenderDebugAnimator`) — per-entity scalar data (name, facing, animator state) is inspected by clicking the entity in the Debug overlay (`DebugInspector`) instead of world-space label passes.
- **`RenderBillboard`** (`new RenderBillboard(opt?)`, Core) — the **STANDING pass** of the art projection contract (ROADMAP → Art Rework): on pitched 2.5D maps it replaces `RenderEntity`, drawing each `Visual` + `Position` sprite **upright** (constant −90 tilt off the ground — deliberately _not_ camera-facing; a perpendicular billboard reclines ~cos(pitch) along the ground and buried into wall meshes at contact) as **depth-writing** geometry (z-write on around its loop only), so bodies sort per-pixel against walls/furniture. Sprites submit through **`sh_meshlit`** (the one world shader) in textured + cutout mode: the `u_alphaRef` texel discard keeps transparent pixels from writing depth (hard-alpha sprites required), and the **sprite sun response** runs **per-pixel in-shader at a fixed bent normal** riding `u_normal` ((0, 0.5, −0.866), 30° south of straight-up): nearly 1 at noon (authored colors, clamped), dimming + warming toward dawn/dusk, torch-side sprites brightening directionally at night (the shader's `POINT_FILL` wrap behind) — a tall sprite half inside a torch pool lights half-and-half. With `opt.lights` = the host `RenderMesh` pass (wired by `RpgMap` on pitched maps) it shares that pass's sun + view-culled point gather, so a sprite and the mesh beside it can't diverge; unset (flat maps, kit default) the pass sets neutral uniforms — full-bright albedo with the cutout only. Draws the `Appearance` paper-doll stack per entity, each layer Y-biased for deterministic depth (see _Paper-doll appearance_); composes **under** `RenderLighting`'s multiply exactly like the meshes — the light map still owns absolute darkness.
- **`RenderMesh`** (`new RenderMesh(opt?)`, Core) — the **VOLUME pass** of the art projection contract (ROADMAP → Art Rework): draws every **`Mesh`** + `Position` entity (`scripts/Mesh/`, Core/Component — the 3D counterpart of `Visual`) as real **depth-writing** geometry, so bodies sort against deep furniture per-pixel with no manual layering. Two paths: `Mesh.model` submits a baked vox-kit vertex buffer (`meshes/<name>.vbuf` via `buffer_load` → `vertex_create_buffer_from_buffer`, frozen + cached; visual-only `scale` or per-axis `xscale/yscale/zscale`, negative xscale mirrors, plus **rotation** — `yaw` turns about the footprint center (vbufs bake top + all FOUR side faces, so any facing is solid; the shader rotates the packed normals by `mat3(world)`, so lighting follows), `pitch`/`roll` tilt about world x/y (no bottom faces — a >90° tip shows a hollow underside) — the BBox stays authored and axis-aligned) **lit by `sh_meshlit`**: the buffer carries UNSHADED albedo + a packed per-face normal (in the texcoord slot — see CLAUDE.md → Capabilities), and the shader computes N·L from an **injected directional sun** (`opt.sun` provider, wired to `WorldClock.sunDir()` by `RpgMap` — strength 0 at night, warm at dawn/dusk; the default is a fixed neutral sun so a kit consumer gets shading with zero wiring) plus the **nearest `Light` entities as point lights** (up to 8, same flicker formula as `RenderLighting`, nearest-to-view-center when over budget via the assigned `pass.camera`) — so a torch lights the furniture faces that FACE it while the light map supplies the visible glow pool (the shader differentiates by direction; `RenderLighting`'s screen-space multiply keeps owning absolute darkness; no-shader fallback = flat albedo). The other path: an analytic two-quad box (plan-view TOP at `-height` + vertical FRONT at the south edge, sprite-or-color faces — drawn OUTSIDE the lit shader, its texcoords being real UVs). Inserted by `RpgMap.build` on pitched maps, between the shadow and entity passes. **A mesh entity carries `Mesh` INSTEAD of `Visual`** — the billboard/shadow passes query `Visual` and so skip it for free (`CombatAI`'s `Visual` reads are all guarded, so the mesh turret is a legal combatant). Consumers: the furniture presets/`prop` kinds with a model (workbench/bed/cot/barrel/crate/survey sign/survival tub·bin·alter), `chest`/`portal`/`torch`/`lantern`/`turret`, and the wilderness `rock` boulders (`RpgSpawn`); model sources are committed `.vox` files in `tools/vox-kit/templates/` (the 2026-07 media set — `wooden_*`/`military_*`/`prison_bed`/`lantern_floor`/`portal`, plus spares like the tables/dressers/stools not yet spawned by any preset), baked by `vox2vbuf.py` (see CLAUDE.md → Capabilities for the 24 B/vertex lockstep contract).
- **`RenderWalls`** (`new RenderWalls(level, layer, opt?)`, Core) — the **WALLS pass** of the art projection contract (ROADMAP → Art Rework): draws a solid `TileLayer` as **lit boxes** — per wall cell a plan-view TOP quad at `-height` plus a vertical SOUTH face only where the south neighbor is empty (the two orientations the fixed-yaw pitched camera can see; hidden-face removal happens at **build time**, so nothing emitted can backface and GPU cull modes are moot). Vertices are the vox-kit 24 B format in one of two `sh_meshlit` modes: **textured** (`opt.sprite` + `opt.frame`) puts real frame UVs in the texcoord and the material tint in the COLOUR channel (`texture × tint × light` — a grayscale-ish pattern texture serves every material color by tint), with the face normal riding the **`u_normal` uniform** (constant per orientation — tops and souths live in separate VBOs, submitted under `u_useTex = 1` with the normal swapped between; uniforms are **fsh-declared only**, the GMRT vsh-uniform trap in CLAUDE.md); **flat tint** (no sprite, and the sprite-missing fallback) packs the face normal in the texcoord like the vox models. Either way `opt.lights` is the host `RenderMesh` pass, whose `_setupLights` supplies the frame's sun + view-culled point lights (and pins `u_useTex = 0` for the vox models); walls join the same depth pool as furniture and billboards (no shader → unlit texture/tint fallback). VBO-cached like `RenderTileMap`: `markDirty()` after tile edits — `BuildMode._markTileDirty` reaches it via `scene._tilePasses.wall`. `opt`: `{ height (default 32 — one cell), color, sprite, frame, lights }`. The RPG wires `spr_tex_brick` frame 0 (the dedicated near-white wall texture from the 2026-07 media set; its siblings `spr_tex_tile`/`carpet`/`mosaic` are unwired spares, `spr_tex_plaid` is the floor layer's). The `layer` only needs `get(gx, gy)` truthiness, so any occupancy view satisfies it. Inserted by `RpgMap._buildRenderer` on pitched maps **twice**: for the **resident** wall layer (interior maps + player builds, keyed into `scene._tilePasses.wall` for edits) and — on the chunked overworld — a second instance over **`ChunkManager.wallLayer()`**, the whole-store wall-occupancy view (after `pregenerate()` the records are the immutable world, so the cell set rasterizes once on first draw with no streaming coupling; the camera's `viewCap` already keeps beyond-ring walls off-screen), which converts the AUTHORED hub/prefab walls to the same lit boxes (`RenderChunks`' flat rects are disabled via its `walls` opt on pitched maps).
- **`RenderTileMap`** (`new RenderTileMap(layer, level, sprite, opt?)`) — hardware-accelerated tiles via `VertexBuffer`. `opt`: `{ autotile: 0|16|47|"dual"|"corner", alpha, color, softEdge }`. Call `.markDirty()` after tile changes to rebuild the VBO. Autotile: `0` = raw frame id, `16` = blob4, `47` = blob8, `"dual"` = dual-grid corner sampling, `"corner"` = quarter / sub-tile (13 half-cell pieces). Neighbor bits: `N=1, E=2, S=4, W=8` (blob8 adds `NE=16, SE=32, SW=64, NW=128`), so a blob4 tileset's frame index equals its cardinal-neighbor mask. `spr_tile16` is the project's 16-frame blob4 tileset and `spr_tile47` its 47-frame blob8 set — both consumed by the RPG levels (`RpgLevel`).
  - **`"dual"` (dual-grid)** — the blob modes draw one centered tile per _filled cell_ and cannot show two materials meeting (binary occupancy: a 2×2 filled block renders as a donut with blob4). Dual-grid instead renders a half-cell-**offset** grid where each display tile samples the 4 cells touching a grid _corner_; corner bits `TL=1, TR=2, BR=4, BL=8` → 16-frame index = mask (like blob4 but corner-keyed). Because a tile's empty corners stay transparent, **stacking several `"dual"` passes — one `TileLayer` per terrain, lowest priority first** — makes each upper terrain's border reveal the one beneath it, i.e. RPG-Maker-style A-over-B transitions with only a 16-frame corner tileset per terrain (no hand-drawn transition art). This is how the project supports _terrain-to-terrain_ blending; the priority stack is just ordered `Renderer` passes (no new class). `softEdge` is ignored in dual mode. `spr_tiledual` is the project's 16-frame corner tileset (frame N fills the corners of mask N); the **RPG overworld** is the reference composition — `TerrainStream` stacks per-material `"dual"` layers (deep water < water < sand < mud < soil < rich soil < grass < gravel < rocky, each drawing its own untinted `spr_terrain*` set generated by the pixel-art-kit's terrain pipeline). A full cell (mask 15) picks a **weighted full-tile variant** from the sheet's `SpriteMeta` def (`variants["15"]` = `[[frame, weight], …]` over frames 15+, emitted by `terrain_sprites.py` — plain texture re-rolls heavy, **decorated** frames (grass flowers/pebbles, sand stones) light, so decorations are occasional accents by probability) via a deterministic MINSTD position hash — stable across chunk reloads; an undeclared sheet falls back to uniform weights over its frames past 15. `RenderTileMap`'s own dual path draws `frame = mask` with no variants (add the same pick when a variant-bearing sheet gets a `RenderTileMap` consumer).
  - **`"corner"` (quarter / sub-tile)** — the other corner-keyed mode: each _filled cell_ is drawn as **4 half-cell quadrants**, each quadrant's `cellWidth/2 × cellHeight/2` piece picked **independently** by the 3 neighbors touching that corner (both cardinals empty → outer corner; one cardinal → straight edge; both cardinals + diagonal empty → inner corner; all three → fill). The **13-piece** set — `0` fill · `1-4` outer TL/TR/BR/BL · `5-8` edge top/bottom/left/right · `9-12` inner TL/TR/BR/BL — reproduces the full blob8 look from 13 pieces and covers all 256 masks (no `_BLOB8` table; the per-corner selectors read bits inline off one neighbor int — no cached primitive-bool locals, which GMRT miscompiles). `spr_tilecorner`/`spr_tilecornerRough` are the project's 8×8 piece sets. Unlike `"dual"` (which keys per display-grid corner), `"corner"` keys per _cell_ but draws sub-tile pieces, so the material necessarily repeats every half-cell (pieces are position-shared) and borders read rounder. `softEdge` is per-cell-mode only — ignored for both `"dual"` and `"corner"`. (The kit's `tools/pixel-art-kit/common/tileset.py` synthesizes both the `"dual"` 16-frame and `"corner"` 13-piece sets from one material texture, seamless by construction.)
- **`RenderDebugEntity`** — `BBox` outlines (lime) for all entities with `Position` + `BBox`. Interpolates via `PrevPosition` + `world.alpha` like `RenderEntity`.
- **`RenderDebugPath`** (`new RenderDebugPath(level)`) — active `PathResponse` paths (yellow) + pending `PathRequest` goals (red cross).
- **`RenderZone`** (`new RenderZone(level, key, opt?)`) — world-space overlay for one **zone channel** (see Zones): fills each zone's cells by color and outlines region borders (only edges where the neighbor differs, so map edges outline too). `opt`: `{ alpha, border }`. Color is `zone.data.color` (`"#rrggbb"`) when set, else a stable hue from the zone id. Reads `level.zoneMap(key)` live each frame — a no-op until that channel exists, so it's safe to insert before zones are painted. Uses plain `draw_line` for borders (`draw_line_width_color` renders nothing on GMRT).
- **`RenderZoneLabel`** (`new RenderZoneLabel(level, key, opt?)`) — zone-name labels (white) at each zone's centroid for one channel. `opt`: `{ font }`. Split out of `RenderZone` so labels toggle independently; insert _after_ the zone pass.
- **`RenderGrid`** (`new RenderGrid(level, opt?)`) — cell boundary lines for a Level's grid. `opt`: `{ color, alpha, camera? }`. Split out of `RenderDebugTileMap` so the grid toggles independently; insert it wherever the grid is wanted (the RPG map + the level editor pair it with the debug tilemap pass). Plain `draw_line` (`draw_line_width_color` renders nothing on GMRT).
- **`RenderChunks`** (`new RenderChunks(chunkManager, opt?)`) — world-space pass for a `ChunkManager`'s streamed terrain (see Chunk Streaming & Sim-LOD below). Per active chunk: an opaque ground fill (a subtle checker by chunk parity, so chunk seams + streaming read at a glance; unloaded area stays the dark scene background = a visible "edge of the loaded world"), the chunk's flat wall rects (`opt.walls: false` disables them — the RPG's pitched maps draw streamed walls as lit boxes via `RenderWalls` over `ChunkManager.wallLayer()` instead), and — for LOAD-ring (frozen) chunks — each held entity **snapshot** as a dimmed box + name. SIM-ring entities are live in the World and drawn by the normal entity passes, so insert this **before** them (ground under everything). The active set is already tiny (bounded by `loadRadius`), so no per-chunk view cull. `opt`: `{ font, ground0, ground1, wallColor, frozenAlpha, ground, walls }`.
- **`RenderCloudShadow`** (`new RenderCloudShadow(opt?)`, Demo) — screen-space **cloud-shadow** pass: drifting cumulus **clusters** (3–5 overlapping lobes strung along a wind-ish axis, hashed per cloud-grid cell with MINSTD integer-float math) **multiplied** over the scene (`gpu_set_blendmode_ext(bm_dest_colour, bm_zero)`, gray-center→white-edge `draw_circle_color` lobes projected via `Camera.project` — lobe overlap deliberately compounds toward each cloud's core, per-lobe darkness halved in multiplier space to compensate). Coverage is the condition's **`cloud`** fraction (cross-faded by `Weather.blend()`, per-cell fade ramp) scaled by daylight (`WorldClock.tint` alpha — gone by nightfall, so the night tint never double-darkens); drift scrolls on **`Weather.time()`**. Inserted just **before `RenderWeather`**, outdoor maps only (`meta.indoor` skips both). `opt`: `{ camera, cell, darkness, windX, windY, seed }`.
- **`RenderWeather`** (`new RenderWeather(opt?)`, Demo) — world-space weather pass driven by `Weather` (see _Weather_): a flat condition tint plus falling **rain** (`draw_line` streaks — `draw_line_width_color` renders nothing on GMRT) / drifting **snow** (`draw_rectangle` flakes, per-flake `Math.sin` sway), **cross-faded** by `Weather.blend()` (outgoing + incoming conditions both drawn during a change). Particles are screen-space over the view rect and scroll on **`Weather.time()`** (the cumulative SIM-second clock advanced by `Weather.update` on `Time.delta` — so the fall **freezes when the game pauses** and dilates with `Time.scale`, e.g. the bed fast-forward; a cumulative clock, never a per-frame delta, which would freeze every particle). Inserted **just before `RenderLighting`** so the night/light tint also darkens the rain. `opt`: `{ camera, maxParticles }`. Reads the view rect from the held `Camera`'s **own fields** (not `camera_get_view_*`; see CLAUDE.md); the scene assigns `pass.camera` after building the camera.
- **`RenderLighting`** (`Gameplay/Lighting`) — world-space 2D **light-map** pass: the RPG's lighting + day/night in one. Per frame it builds an off-screen surface cleared to its **injected `ambient` provider** (`() => { color, alpha }`; the demo wires `WorldClock.tint`) mapped to a **multiply** model (white in daylight → night hue when dark, scaled by `opt.darkness`, default 1.5), `bm_add`s a soft radial blob (`draw_circle_color`, hue→black) for every **`Light`** + `Position` entity, then composites it over the world **multiplicatively** (`gpu_set_blendmode_ext(bm_dest_colour, bm_zero)` → `scene × light`; no `bm_multiply` constant). So **day/night is "lighting with no lights"** and point lights (the player's lantern, torches) reveal the night. **Self-balancing:** in full daylight the ambient is white, so lights clamp to white and the multiply is a no-op — the pass early-outs (zero surface work). Lights are the **`Light`** component (`scripts/Light/`, `Gameplay/Lighting` — `{ radius, color, intensity?, flicker? }`); the player carries a lantern `Light` (`RpgPlayer.spawn`). **Falloff only — no shadows yet.** A **night vignette** multiplies the light map's corners down (a white-center→dark-edge radial reaching the corners, baked into the same surface), scaled by the cycle so it fades in at dusk and is gone in daylight with the early-out — multiplicative like the composite, so it deepens the scene toward the edges rather than alpha-blending a flat-black wash. `opt.vignette` is the corner-darkening fraction at full night (default 0.25; 0 disables). Inserted **last** in the RPG renderer (over tiles + entities + weather). `opt`: `{ camera, darkness, vignette }`; reads the view rect from the Camera's own fields (not `camera_get_view_*`), scene assigns `pass.camera`. The light surface is volatile (lost on resize/focus) — the pass guards `surface_exists` + recreates it on a size change.
- **`RenderDebugTileMap`** (`new RenderDebugTileMap(level, opt?)`) — overlay: cost shading (reads `level.costAt(x, y)` live — computed from the layers on demand, no sync step), tile id/name + coordinate labels (grid lines are a separate `RenderGrid` pass). `opt`: `{ cost, tiles, coords, names, alpha, font, camera? }`. Like `RenderGrid`, an optional **`camera`** (a `Camera` instance, settable later via `pass.camera`) culls iteration to the view rect (read from the Camera's `toX`/`toY`/`width`/`height` fields — `camera_get_view_*` returns 0 for the matrix-driven Camera; see CLAUDE.md), required for a large grid; omit for full-grid (small grids).

**`VertexBuffer`** (`scripts/VertexBuffer/`) wraps GameMaker vertex buffers with a fixed `position_3d + texcoord + colour` format (quads at z = 0, so a ground VBO can submit under `sh_meshlit`, which reads a 3-component position; ground passes stay z-write-off painter order): `.begin()`, `.addQuad(x,y,w,h,u0,v0,u1,v1,color?,alpha?)`, `.addQuadV(...)` (per-corner alpha), `.end(freeze?)`, `.submit(texture)`, `.destroy()`.

**Ground lighting**: `RenderTileMap` + `TerrainStream` take a `lights` field (the host `RenderMesh` pass — `RpgMap` assigns `scene._meshPass` on pitched maps) and submit under `sh_meshlit` textured mode with the straight-up normal, so the ground joins the same sun/point-light model as walls/meshes/billboards (torch pools shade the ground per-pixel under the light map); unset (kit default, flat maps, the editor) they submit fixed-function unlit exactly as before.

## UI System

The GUI layer is a **fixed design resolution** (`UI.designW`×`UI.designH` = 1920×1080) divided by the `uiScale` Setting, set via `UI.applyScale()` in `obj_game` `Create_0` — **not** `display_set_gui_maximise`. So UI lays out the same on every monitor and GameMaker scales the GUI to the window; the SDF locale fonts keep text crisp at any GUI→window ratio. The `uiScale` slider applies **live**: it calls `UI.applyScale(v)`, which resizes the GUI layer and `markDirty`s every root so they reflow. For that reflow to be clean, full-screen chrome must fill via flex rather than snapshot `display_get_gui_height()` at build — the lobby and `SystemMenu` use `gemsTabs({ grow: true })` (root + content host flex-grow) over `gemsScroll({ grow: true })`, so they re-lay-out to the new GUI size with no rebuild (fixed-size windows like the RPG inventory keep `gemsTabs({ height })`). World cursor picking under a **flat** matrix camera can use GameMaker's `mouse_x`/`mouse_y` (the level editor's `CameraPan` does), but under the RPG's **pitched** 2.5D camera they are wrong — the world cursor there is **`Camera.cursorWorld()`** (GUI mouse → surface px → `Camera.unproject`, the pitch-aware ground-plane inverse of `Camera.project`), latched once per frame by `sceneRpg.step` into `scene.mouseWorld` (+ the player's `Playable.cursorX/Y`) for `PlayerSystem` aim, `BuildMode`, and `Interactable` (see the GMRT-Safe Idioms camera bullet). The one place mixing GUI-mouse with the application surface (`CameraPan`) scales GUI→surface explicitly.

- **`UIElement`** (`scripts/UIElement/`): tree node backed by `flexpanel` (GameMaker Flexbox). `insertChild`, `removeChild`, `addComponent(c)`, `getComponent(Class)`, `getComponents(Class)`, `removeComponent(c)`. `markDirty()` propagates to root; `refresh()` calls `flexpanel_calculate_layout`.
- **`UI`** (`scripts/UI/`): static root registry. `UI.insert(root, index?, enabled?)`, `UI.remove(root)`, `UI.setEnabled(root, bool)`. `update()` traverses in reverse (highest index blocks lower); `draw()` forward.
- **`UIComponent` interface**: `{ onUpdate?(element, block), onDraw?(element), onDestroy?(element) }`. Built-ins: `UIButton`; `UIText`; `UIRichText` (markup → colored spans `[c=#hex]…[/c]` + inline icons `[spr=name]`; self-sizes like `UIText`, host stacked lines in fixed-height rows); `UIImage`; `UIPanel`; `UITrigger`; `UISlider` (always-on value readout — `format`/`showValue`); `UISelect` (`< value >` cycler); `UIDropdown` (combobox field + chevron → popup list; the popup is an injected `onOpen(dropdown, field)` so Core stays theme-agnostic — `gemsDropdown` supplies a `UIModal` one, `UINav`-navigable + scrolling); `UIInput`; `UIRebind` (key-rebind row — click to arm "press a key…", next press rebinds); `UIProgress` (0–1 fill bar); `UICheckbox` (`style:"check"` box+tick or `"switch"` pill+knob); `UITooltip` (self-detecting hover tooltip, feeds the global `Tooltip`); `UIStepper` (`< n >` over min/max/step); `UISlots` (inventory-slot grid; `draggable` opts into `SlotDrag`; immediate-mode); `UITabs` (tab strip — one focus stop, swaps content by `enabled`, no reflow); `UIAccordion` (collapsible; confirm expands); `UIScroll` (vertical scroll for a `clip` viewport — draw-time `scrollY`, never flex mutation); `UIModal` (full-screen exclusive backdrop, blocks pointer + nav, Esc/backdrop close; built by `gemsModal`); `UIDrag` (window drag handle — accumulates into `target.dragX/dragY`, offset-not-mutation); `UIResize` (window resize grip — companion to `UIDrag`, lives on a bottom-right grip; captures the target's current laid-out size on grab then sets `target` width/height via flexpanel mutation (`setWidth`/`setHeight`), clamped to `[minWidth/minHeight, GUI]`. Unlike drag it genuinely changes layout, so it mutates style rather than offsetting — the reliable-on-0.20 path `UIText` self-sizes with); `UINineSlice` (sprite-skinned panel; source needs nine-slice in the IDE); `UIMinimap` (radar-blip view of a `World`, `rules` `[{ has, color }]` where `has` is a component token — an entity blips when it carries that component); `UIQuestTracker` (live list bound to an **injected quest source** — `opts.source`, the RPG passes its `QuestLog` — so this Core widget never references the RPG layer; immediate-mode, resolves `I18n.font(key)` at draw time); `UITable` (data table — declarative columns with text/color/icon accessors, a multi-key sort stack (click a header → primary key, re-click flips), external `setFilter`, `setColumns` (remaps the sort by each column's stable `key`), identity row-selection, sticky header, row-based scroll, zebra striping. Immediate-mode over ONE element so re-sort/filter never reflows; draw geometry recomputed each `onDraw` so it stays glued to a dragged window. **Browse mode**: `navActivate` enters it, then the table owns the arrows via a per-frame `UITable.active` claim that `UINav.consume()`s. Built by `gemsTable`; public reads are METHODS (`getView`/`getRows`/`getSelected`) — an external `table.view` faults on GMRT).
- **`Tooltip`**: standalone static class (not a `UIComponent`). `Tooltip.set(str)` from anywhere; renders once per frame at mouse position via `Tooltip.draw()` in `Draw_75`.
- **`Toast`**: standalone static class (not a `UIComponent`), same pattern as `Tooltip`. `Toast.push(str, opts)` from anywhere; `Toast.draw()` in `Draw_75` (after `Tooltip`) ages the stack by `Time.raw` and renders a bottom-center timed stack (newest at bottom). `opts`: `{ duration, type ("info"|"success"|"warn"|"error"), accent }` — `type` picks the left accent-stripe color; entries fade/slide in+out and are culled when expired (`Toast.maxItems` cap drops the oldest).
- **`UIPointer`**: standalone static class (not a `UIComponent`) — the UI's frame-latched pointer state. `UIPointer.poll()` runs in `Step_0` before `UI.update` and latches the left-button edges + level + wheel once per frame into `UIPointer.pressed`/`released`/`down`/`wheel`. Every UI widget + UI-layer reader (`SlotDrag`/`BuildMode`/`DebugInspector`/`Dialogue`) reads those static fields instead of calling `mouse_check_button*`/`mouse_wheel*` directly — those are realtime-sampled on GMRT, so re-reading the same query in a frame can diverge, and a per-widget `const pressed = …` is also the cached-bool clobber pattern (see GMRT-Safe Idioms). One query/frame, shared.
- **`SlotDrag`**: standalone static class (not a `UIComponent`) backing drag-and-drop between `UISlots` grids (built with `draggable: true`). Reads the latched pointer edges from `UIPointer` (never `mouse_check_button*` directly — see the realtime-sampling note in GMRT-Safe Idioms). A grid calls `SlotDrag.begin(grid, i)` on `pressed` over a filled slot (picks it up; source slot empties, floating icon drawn in `SlotDrag.draw()` in `Draw_75`), then `SlotDrag.hover(grid, j)` each frame the cursor is over one of its slots to **record** the drop target. `SlotDrag.update()` (`Step_0`, after `UI.update`) resolves on the release edge: drop onto the last-recorded slot (swaps occupants, works across grids), or — if none was ever hovered — restore to source. The recorded target is _persisted_ (not cleared when the cursor leaves a slot), so a small drift off the slot as the button comes up still drops. (Note: `UISlots.onUpdate` keeps the hit-test in instance fields `this._inside`/`this._hover`, not boolean local consts — those get clobbered mid-function on GMRT; that was the long drag-drop bug.)
- **`VirtualKeyboard`**: standalone static class (not a `UIComponent`) — on-screen keyboard for gamepad/mouse text entry into a `UIInput`. `VirtualKeyboard.open(input)` pops a `gemsModal` (exclusive backdrop, blocks background nav, Esc/backdrop cancels) whose body is a preview line + a grid of character keys; the keys are ordinary `gemsButton`s, so the whole keyboard is `UINav`-navigable for free (dpad/stick to move, A/Enter to type). Keys edit an in-memory buffer; **Done** commits to the field (`setValue` + `onConfirm`), Cancel/Esc/backdrop discard — the field is untouched until Done. Shift toggles letter case via live key labels (no relabel). `VirtualKeyboard.isOpen()` is a **method, not a `static get`** — a static getter with a comparison body miscompiles on GMRT 0.20 (verified; see CLAUDE.md), and yielded `undefined` outright on 0.19.
- **`UINav`**: standalone static class — keyboard/gamepad menu navigation, touching neither `UI` nor `UIElement`. An element is **focusable** by duck-typing: a component implements `navActivate(element)` (confirm) and/or `navAxis(element, dir)` (horizontal adjust, `dir` = ±1). `UINav.update()` (`Step_0`, after `UI.update`) walks the enabled roots, collects focusables with a valid on-screen rect, and routes input: arrows/dpad/stick move focus to the geometrically nearest focusable in that direction (edge-aware `_pick` — the perpendicular term is the gap between rects, ties broken by collection order, so Down lands on the leftmost item below); a horizontal press over a `navAxis` widget tweaks it; Enter/Space/`gp_face1` → `navActivate`; Esc/`gp_face2` disengages. `UINav.draw()` (`Draw_75`) draws a pulsing focus ring. Collection **stops at an exclusive root** (`navExclusive() → true`, e.g. an open `UIModal`), mirroring the modal's pointer block. Focusables scrolled out of a `UIScroll` stay collectable; when focus lands on one, `_scrollIntoView` nudges each `UIScroll` ancestor so it comes into view. Engagement: the first nav input only engages + focuses; moving the mouse disengages; while a field is typed (`UIInput.active`) or a `UITable` is in browse mode (`UITable.consume()`), nav is suspended so the caret keeps the keys. `obj_game` calls `UINav.reset()` on each scene swap and seeds `UINav.color` from the theme. Nav hooks live on `UIButton`/`UICheckbox`/`UISelect`/`UIDropdown`/`UIStepper`/`UISlider`/`UITabs`/`UIAccordion`/`UITable`/`UIInput`; any new widget becomes navigable by adding `navActivate`/`navAxis` (a blocking root by adding `navExclusive`). **Debug**: hold `UINav.debugKey` (Tab) to draw every focusable boxed + numbered with direction lines from the focused element.
- **`SceneTransition`**: standalone static singleton — full-screen fade between scenes, replacing `obj_game`'s hard cut on `openScene`. `start(applyFn)` fades OUT to a solid cover, swaps the scene at full cover (`applyFn` rebuilds the UI hidden under the cover), then fades back IN. Wiring: `SceneTransition.update()` in `Step_0` (drives the timer + fires the swap at mid-fade, gated by `isBusy()`); `SceneTransition.draw()` **last** in `Draw_75` so the cover veils the UI teardown/rebuild too. Timer uses `Time.raw`.
- **`Dialogue`**: standalone static singleton — RPG paged dialogue box with typewriter reveal. `Dialogue.start(pages, opts)` (a page is a string or `{ speaker, text }`); reveals at `opts.speed` chars/sec (`Time.raw`), advances on Enter/Space/`gp_face1`/click. `Dialogue.update()` in `Step_0`, `Dialogue.draw()` in `Draw_75` (over the UI). Static fields are initialized with literals, not `Dialogue.x` self-references (the static-initializer self-reference quirk in CLAUDE.md).
- **`FloatingText`**: standalone static singleton — **world-space** floating combat numbers (damage/heal) that rise + fade. `FloatingText.push(x, y, value, opts)`; drawn from a **scene's own `draw()`** (inside the camera view), _not_ `Draw_75`. `obj_game` calls `FloatingText.clear()` on each scene swap (a number must not survive into the next scene). Ages by `Time.delta` (sim time — slow-mo slows the numbers too), unlike the GUI singletons on `Time.raw`.
- Many `flexpanel_node_style_*` setters in `UIElement` stay commented to keep the class under the 50-method ceiling (#15065); enable one on demand (see the flexpanel GMRT-Safe Idiom).

## Input System

**`Input`** / **`InputAction`**: `Input.register(key, action)`, `Input.get(key)` → `InputAction`. Query: `.down()`, `.pressed()`, `.released()`, `.value()`. Bind: `.bindButton(source, button)` / `.bindAxis(mode, axis)`. Display: `action.label()` → the primary binding as UI text (e.g. `"W"`/`"Shift"`/`"LMB"`), delegating to `InputButton.label()` / `InputButton.keyName(code)` (the one keycode→string table). This is the single binding→text source shared by the rebind row (`UIRebind`) and the live hint bar (`gemsKeyHints`), so a remap renders the same string everywhere. Bulk: `Input.bindAll({ key: [source, button], … })` registers a whole keymap in one call; `Input.unbindAll([keys])` removes them — used by the genre controllers. **All four query methods return falsy while a text field owns the keyboard** (`UIInput.active !== null`, via `InputAction.captured()`): typing in a UI field (e.g. the RPG inventory search) must not also drive gameplay hotkeys/movement — pressing `i` while typing "Hi" can't toggle the inventory. This is the same `UIInput.active` signal that suspends `UINav`; `UIInput` clears it on blur **and on destroy** (so tearing a focused field down at a scene change can't strand the capture).

**`InputContext`** (`scripts/InputContext/`, Core) — a named-context **stack** over the Input layer that generalizes `captured()` from "a text field mutes everything" to "the active context decides which actions are live." The active context is the top of the stack (base is always `"default"`); `push(name)`/`pop()`/`set(name)` (replace top — auto-pushes if only the base remains, so a forgotten `push` can't clobber `"default"`)/`reset()` (back to `["default"]`)/`active()`/`is(name)`. An `InputAction` may declare the contexts it is live in via `action.inContext(["play","window"])` — or, declaratively, an **optional 3rd element** in a `bindAll` spec entry (`fire: [INPUT_SOURCE.MOUSE, mb_left, ["play"]]`). The query methods then add `_blocked()` (`contexts !== null && !InputContext.allows(contexts)`) to the existing `captured()` guard. An action with **no** declared contexts (the default, `contexts === null`) is live in every context, so all existing keymaps (platformer/UI) are unaffected — only opt-in tagged actions are gated. `captured()` still wins (a focused field mutes regardless of context). Contexts/tags are **not serialized** (`Input.export`/`import` ignore them) — a controller re-applies them in `create()` each scene, so a saved/rebound keymap never loses its tags.

The **RPG scene** is the reference consumer: `PlayerSystem.bindKeys` tags its keymap — movement live in `["play","build","window"]` (the player keeps walking with a window open), `fire` `["play"]` only (so it **self-mutes** while building — LMB places tiles — or with a gameplay window open — clicks don't shoot — replacing the old `!BuildMode.active` reach-in), `interact` `["play","window"]` (open in play, close a station window in window; inert while building), `build`/`follow` `["play","build"]`. `sceneRpg` pushes `"play"` in `create()`, resets in `destroy()`, and each `step()` (before the tick loop, so the tick's movement/fire reads see it) calls `_resolveContext()` → `InputContext.set(...)` with **window > build > play** priority (`invOpen`/`_storeOpen`/`_craftOpen` → `window`; else `_buildActive` → `build`). A window thus **pauses** build mode (`BuildMode.update` gates `active` on `InputContext.is("build")`, so LMB/RMB on the window can't place/remove tiles) and resumes it on close. The single `E` press is arbitrated in one place — `sceneRpg._dispatchInteract()`: a station window open → `E` closes it; else pick station-vs-NPC by **cursor (`Interactable.isCursorOver`), then nearest to the player**, and call `Interactable.activate(scene)` or `scene._npcActivate()`. `Interactable.update`/`_updateNpc` only do proximity/prompt/dialogue text — no input reads.

## `EntityPreset`

`EntityPreset` (`scripts/EntityPreset/`) spawns entities from named presets — the **declarative side of entity construction** (component data + size + a `post` hook for the wiring data can't express), with **variant inheritance**:

```js
EntityPreset.register([
  {
    id: "raider",
    scale: 1.7, // BASIC design factor — scales the BBox, Visual, and Mesh (see below)
    components: {
      BBox: { x: -8, y: -8, width: 16, height: 16 }, // world units at scale 1
      Visual: { sprite: spr_human, color: c_white }, // xscale/yscale are DERIVED, never authored
      Health: { hp: 3 },
      Inventory: { slots: [], capacity: 8 },
    },
    post(world, id, ctx) { CombatAI.attach(world, id, ctx.opts.level); }, // irreducible code
  },
  { id: "boss_raider", extends: "raider", components: { Health: { hp: 12 } } },
]);
// `size` is the dedicated per-spawn SCALAR for special entities (bosses/alpha mobs)
const id = EntityPreset.spawn("boss_raider", world, x, y, z, { size: 1.5 }); // opts: { size?, components? }
EntityPreset.has("raider"); EntityPreset.get("raider");
```

- **`scale` vs `size`** — two separate knobs: the def's `scale` is the archetype's **basic factor** (per-preset tuning; a `Mesh`'s own `scale`/`xscale`/`yscale`/`zscale` stay the authored per-axis base), while `opts.size` (a spawn descriptor's `size?`) is the **per-spawn scalar** for special entities — an Alpha Rat or boss. Both fold into one factor `k = scale × size` that bakes **BBox + Visual + Mesh uniformly** (`_bakeMesh` multiplies the mesh's scale fields + analytic-box dims), so a sized entity's look never diverges from its collider.
- **`extends`** resolves at **register time** (base must register first; unknown base throws): per-component **field** merge, the variant's fields win, new components add; `scale`/`post` inherit unless overridden. Per-spawn `opts.components` merges the same way (e.g. a descriptor's `{ Health: { hp } }`).
- **Every spawn deep-copies its component data** (instances never share nested arrays/objects like `Inventory.slots`) via a GMRT-safe clone: a GM **asset ref** also reports `typeof "object"` but its `constructor !== Object` (probed on 0.20), so refs/scalars/functions pass through **by reference** — a stored sprite handle survives.
- **The size/art bake**: `Visual` is authored lean (`sprite`/`color` + optional overrides) and spawn normalizes it — `Visual.scale` = design size (`scale × size`), `xscale/yscale = scale / SpriteMeta.density(sprite)` (see _Utility Modules → SpriteMeta_), and the `BBox` multiplies by the same factor. Art resolution never touches the collision footprint.

## `Query` — Spatial Entity Lookup

`Query` (`scripts/Query/`) searches entities with `Position`:

```js
Query.nearest(world, x, y, opts); // → id or -1
Query.farthest(world, x, y, opts); // → id or -1
Query.inRect(world, x1, y1, x2, y2, opts); // → id[]
Query.inRadius(world, x, y, radius, opts); // → id[]
```

`opts`: `{ has?, maxDist?, hasCollision? }`. `has` filters to entities carrying that component (its token) — presence, not a tag string (the `Tag` component was removed; markers like `NPC`/`Portal`/`Follower`/`Raider`/`Rat` are queried directly).

## Utility Modules

- **`Settings`**: persists to `settings.json` (`Settings.PATH`). `registerDefaults({...})` before `load()` at startup (calls merge additively). `get(key)` falls back to defaults; `set(key, val)` updates memory; `save()` writes only keys present in defaults.
- **`Color`**: `Color.rgb(r,g,b)`, `Color.hsv(h,s,v)`, `Color.merge(c1,c2,t)`, `Color.parse("#rrggbb")` → GameMaker color ints; `Color.alpha(color)` → alpha byte `[0,1]`.
- **`Rand`** (`scripts/Rand/`, Core/Util): deterministic hashing + PRNG over Park–Miller MINSTD integer-float math — the **one home** for the idiom (GMRT miscompiles xorshift chains; see GMRT-Safe Idioms → PRNG). Two families: **position hashes**, pure in `(x, y, seed)` — `int2`/`hash2` (int / `[0,1)` float), `seed2` (→ LCG seed), `noise2(x, y, seed, lattice)` (smoothstep value noise; fold a salt into `seed` for an independent channel) — the substrate for anything that must regenerate identically; and **streams** — `lcg(seed)` → `() => [0,1)` closure, or `step`/`norm` for a hot loop keeping state in a field instead of allocating a closure per reseed (`RenderCloudShadow` reseeds per cloud cell per frame). Consumers: `TerrainField` (noise), `OverworldGen` (per-chunk stream), `TerrainStream` (tile-variant pick), `RenderCloudShadow`. The GML `random_*` built-ins are no substitute: one global stream, and `random_get_seed()` doesn't track it on 0.20 (see CLAUDE.md).
- **`SpriteMeta`** (`scripts/SpriteMeta/`, Core/Util): per-sprite **metadata** registry — the semantic layer a `GMSprite` doesn't carry (frames/trim/origin only). A def is JSON-manifest-safe data `{ sprite: "spr_name", kind, density?, cell?, variants?, anchors? }`: `kind` (`"entity"`/`"overlay"`/`"tileset"`/`"atlas"` — descriptive; consumers read specific **fields**, never switch on kind), `density` (source px per world px, default 1 — **declared, never inferred**: a 32px cell can mean a denser subject OR a taller one, only the art's author knows; divides the **draw scale** only, never the BBox), `cell` (`[w, h]` frame size, doc/validation), `variants` (tilesets: per-mask weighted frame tables `{ "15": [[frame, weight], …] }` — `TerrainStream` picks per cell by deterministic hash, see Renderer → `"dual"`), `anchors` (`{ name: [[dx, dy], …] }` — named per-frame **attachment points** as origin-relative source-px offsets, emitted by `human_sprites.py` from the segmented parts; read via `anchor(sprite, name, frame)` — the substrate for anchored `Appearance` layers, i.e. the held-weapon icon at `handR`). Declarations are **emitted by the pixel-art-kit importers** as `datafiles/spritemeta/*.json` manifests (generated alongside the art, so they can't drift from it — `human_sprites.py` emits `human.json`, `terrain_sprites.py` `terrain.json`; each included file is registered in `gems.yyp` once, re-runs only rewrite content), loaded at boot by `SpriteMeta.load()` (obj_game `Create_0`); hand-authored sprites get hand entries via `register(defs)`. API: `of(refOrName)` → def or undefined; `density(sprite)` → declared or 1; `fit(scale, sprite)` → `scale / density`, the final draw scale for a **design** scale — the split of the two meanings `Visual.xscale` used to conflate (design size `Visual.scale` also scales the `BBox`; density never touches it), so a hi-detail sheet lands at the same world size. Defs are keyed by **name** (string Map — safe) and resolved to refs at registration; the ref lookup is **parallel arrays + `===` identity scan** — a `Map` keyed by a sprite ref crashes GMRT natively at `.get` (see CLAUDE.md GMRT-Safe Idioms). Consumers: `EntityPreset.spawn` (the bake), `RpgPlayer.spawn`, `AnimationSystem` (refit on sheet swap). Supersedes `ArtDensity` (density is one field of the def). See _Gameplay / RPG Layer → Paper-doll appearance_ for the sizing model.
- **`I18n`**: `I18n.load(manifestPath)` reads a `manifest.json` listing text-file masks (e.g. `text/*.json`), fonts, images, sounds; flat `{ key: value }` text JSON is merged into `I18n.texts`. `I18n.text(key, ...params)` or `I18n.textRef(...)` (a `() => string` for live-updating UI labels); fonts via `I18n.font(key)`. Ships `en-US` (default, loaded in `obj_game` `Create_0`) and `ko-KR`, each declaring its own Noto Sans in its `manifest.json` (en-US `Noto Sans`, Latin-1 range; ko-KR `Noto Sans KR`; both SIL OFL 1.1, SDF). Strings are split by genre under each locale's `text/`: `common`, `platformer`, `rpg`, `rts`, `map` (the `text/*.json` mask merges them all). Fonts are keyed by role, not size: `default` (Regular 12), `header` (Bold 16), `description` (Regular 10). Both locales declare all three, so `I18n.font(...)` resolves to the bundled Noto Sans (an undeclared key still falls back to `draw_get_font()`).
- **`Camera`** / **`CameraFollow`** / **`CameraPan`**: `Camera` wraps a `camera_*` handle (ORTHO, PERSPECTIVE, PERSPECTIVE*FOV). `CameraFollow` and `CameraPan` are namespace objects of factory methods (PascalCase, like `CameraFly`): `CameraFollow.create({ world, followTarget, followLerp?, followHeight?, ... })` — 3D perspective follow; `CameraFollow.create2d({ world, followTarget, followLerp?, width?, height?, pitch?, pitchCurve?, ... })` — 2D orthographic (pixel-snapped; `pitch` tilts for 2.5D, and the optional **`pitchCurve`** `(zoom) => pitch°` re-derives it from the live zoom each update — the RPG's upright-sprite camera wires `RpgMap._pitchCurve`, 42° zoomed out → 58° in; the curve overwrites `pitchDeg`, so the Debug pitch slider hand-tunes only when the Camera panel's "Pitch by zoom" is unchecked); `CameraPan.create({ ... })` — drag-to-pan + wheel-zoom orthographic camera (the level editor). All read from `world` where relevant. Call `.update()` each step and `.assign(viewIndex)` to attach to a viewport. **The follow target resolves by LIVE query**: an entity carrying the Core **`CameraFocus`** marker component (`scripts/CameraFocus/` — flat `{}`, presence is the signal; `RpgPlayer.spawn` attaches it) wins over the raw `followTarget` id each update, so the camera never dangles a stored entity id — a portal transfer re-mints the player's id, but the marker rides the `EntitySnapshot` into the new world and the resumed map's camera just finds it again (`followTarget` remains the raw-id fallback for worlds without the marker — the platformer). Note: `view_camera[]` is not exposed in GMRT — hold the `Camera` instance and read the view rect from its own fields (`toX`/`toY`/`width`/`height`), **not** `camera_get_view_*` (which returns 0 for the matrix-driven Camera; see GMRT-Safe Idioms).
- **`Audio`** (`scripts/Audio/`, Core): the project's **sound wrapper** — a thin static-singleton facade over GameMaker's `audio_*` API (one audio space, like `ParticleFx`), playing the hand-authored 2026-07 media `GMSound` set (`snd_*`; the `snd_ambient_*` loops sit in the `bgm` audio group despite the prefix — see _Tools_ in CLAUDE.md). Three play paths: `play(name, opts)` non-positional 2D cue (UI/global), **`playAt(name, x, y, opts)` SPATIAL** (`audio_play_sound_at` — attenuated + panned relative to the listener), and `bgm(name, opts)` looping music cross-faded on `Time.raw` (re-requesting the playing track is a no-op; `update()` reaps the finished fade, `stopBgm()` ends it). Spatial needs a **listener + distance model**, both owned here: `setup()` (obj_game `Create_0`) selects `audio_falloff_linear_distance_clamped` (the default is `audio_falloff_none` = no attenuation), fixes the 2D listener **orientation** once (`audio_listener_orientation(0,0,1, 0,-1,0)` → only `x` drives L/R pan, y maps to front/back — right for a top-down view), **loads the `bgm`/`sfx` audio groups** (the `mus_*`/`snd_*` assets live in those non-default GMAudioGroups, which must be `audio_group_load`'d before playback), and applies the saved `Settings` `volMaster`/`volMusic`/`volSfx` — **category volume is the audio-GROUP gain** (`setMusicGain`/`setSfxGain` → `audio_group_set_gain(bgm/sfx)`, `setMasterGain` → `audio_master_gain`), so it scales every playing sound in the group live, including the BGM, with no per-sound bookkeeping; the **SystemMenu** volume sliders call these setters in their `onChange` (Settings-bound; the Save button persists). **`listener(x, y)`** (the RPG scene, each frame, from `camera.toX/toY`) moves the ears. Falloff window is the 32px world's (`REF`/`MAX`/`FACTOR` = full volume within 96px, silent past 800px; override per `playAt`). Wiring mirrors `ParticleFx`: `setup` in `Create_0`, `update` in `Step_0`, `reset` (stop BGM + all SFX) in `LevelManager._apply`'s destroying path only — **not** across a guest keep-switch or an RPG map change, so music carries over. State is read-write static fields + plain methods (no static getters — GMRT). **Wired into the Demo** at Demo-layer chokepoints (the genre-agnostic kit systems stay silent): the RPG plays `snd_ambient_tense` (`sceneRpg` create + resume) with spatial SFX — `snd_gun_fire` (`PlayerSystem._fireGun`; `snd_gun_uncocked` dry-click, edge-gated on the fire press since fire is held-polled), `snd_hitsound_flesh`/`snd_hitsound_armor` (impact, in `RpgScene._diffHp` beside the floating-number push — enemy "flesh", ally "armor", the death-blow deferred to the death pass), `snd_small_explosion` (`resolveHealth.onKill`), `snd_coin` (`sceneRpg._onCollect` — ground pickups AND corpse-loot takes), and the per-consumable cue in `RpgInventoryUI` (`snd_drink` thirst/hunger, `snd_bandage` heal, `snd_magic` buffs/attr grants); the Platformer plays `snd_ambient_danger` with non-positional `snd_jump` (`PlatformerController.update`), `snd_hitsound_flesh` (stomp), `snd_hitsound_armor` (`PlatformerController.respawn` — covers touch/spike/void). **Core UI cues** (non-positional): `snd_button_click` on activation — `UIButton`'s mouse click + `UINav`'s confirm dispatch (one place, covering every focusable widget on the gamepad/keyboard path) — and `snd_button_muted` on a `UINav` focus change (press-edged input, so one cue per move). Unwired spares: `snd_hitsound_metal`, `snd_large_explosion`, `snd_ambient_cozy`/`snd_ambient_emergency`; the old gap remains — a mouse click on a non-button widget is silent (covered for gamepad/keyboard via `UINav`).
- **`Tween`**: static easing + frame-rate-independent smoothing helper for UI motion (pure methods; callers keep their own state). Two families: `approach`/`approachColor` (exponential smoothing toward a _moving_ target, no fixed duration — UIButton's hover/press easing) and the easing _curves_ (`easeOutCubic`/`easeInOutQuad`/…) mapping `t∈[0,1]` for _timed_ 0→1 motion (Toast/modal enter, FloatingText pop).
- **`MotionPlanner`**: static A\* on `MotionPlanningGrid`. `MotionPlanner.plan(start, goal, algorithm?, opt?)` → `{x,y}[]`. Options: `allowDiag`, `cornerCutting`, `heuristicWeight`, `maxIter`.
- **`AABB`**: world-space box geometry that owns the non-uniform `BBox`-anchor convention (see Component Pattern note). `AABB.edges(pos, box)` / `AABB.of(world, id)` → `{ x1, y1, x2, y2, cx, cy }`; `AABB.overlap(a, b)` → strict overlap (touching edges don't count). Every collision/geometry system derives edges through this, never inline `pos.x + box.x` — consumers: `SolidSystem`, `SeparationSystem`, `TriggerSystem`, `BlockSystem`, `EnemySystem`, `Raycast`, `RenderDebugEntity`. (`Query` is _not_ a consumer — it does point-vs-rect tests on `Position` only.)
- **`Broadphase`** (`scripts/Broadphase/`): Uniform-grid broadphase for O(n) physics pair queries. `new Broadphase(worldWidth, worldHeight, cellSize)` — `cellSize` must exceed entity full diameter so center-based bucketing guarantees all overlapping pairs are in adjacent cells. `clear()`, `insert(id, cx, cy)`, `pairs(fn)` (calls `fn(a, b)` per candidate pair, no duplicates). Assign to `world.broadphase` to opt `SeparationSystem` and `TriggerSystem` into the broadphase path; scenes without it fall back to O(n²). Apply selectively — crowded scenes (many slimes/units) benefit; scenes with few interacting bodies (platformer) don't need it. Currently no scene sets it — the RPG's `SeparationSystem` runs O(n²) over its handful of dynamic bodies, which is cheap; wire a `Broadphase` onto `world.broadphase` if slime counts grow.
- **`Raycast`**: static segment-vs-AABB cast over all collider entities. `Raycast.cast(world, x0, y0, x1, y1, opts)` → nearest hit `{ id, x, y, nx, ny, t }` or `null`; `Raycast.castAll(...)` → **all** solid hits along the segment, ascending by `t` (the multi-hit form for hitscan pierce walks). `opts`: `{ ignore?, solidOnly? (default true), mask? }`. Shared by `ProjectileSystem` (bullets), `Combat.hitscan` (gun/turret shots), and line-of-sight queries.
- **`File`**: sync I/O. Text: `File.find(mask)` → `string[]`, `File.read(fname)` → `string|undefined` (NUL-terminates the loaded buffer so `buffer_text` can't over-read past EOF into uninitialized memory — that over-read corrupts `JSON.parse` non-deterministically, the bug that long looked like a runtime memory fault), `File.write(fname, data)` → `boolean`. Binary: `File.readBuffer(fname)` → buffer handle (caller owns it, must `buffer_delete`) or `undefined`, `File.writeBuffer(fname, buffer)` → `boolean` (saves only the _used_ bytes via `buffer_save_ext` + `buffer_get_used_size`, so a `buffer_grow` buffer's over-allocation doesn't pad the file). Use the binary path for tile grids / dense or large data — JSON text both hard-faults on nested values and has an O(n²) serialize cost for big inline arrays. Async binary: `File.saveAsync(fname, buffer, cb?)` / `File.loadAsync(fname, cb)` wrap `buffer_save_async`/`buffer_load_async` — they return a request id, register it, and the completion arrives in `obj_game`'s **Async Save/Load event** (`Other_72`), which calls `File._resolve(id, status)` to fire the callback on the main thread (`saveAsync` → `cb(ok)`; `loadAsync` → `cb(buffer)` on success, caller then owns it, or `cb(undefined)` on failure). For streaming a huge save without freezing the frame, and the form console vendors (Xbox/PS/Switch) **require** to pass cert. ⚠️ **GMRT 0.20**: a known open runtime bug — GMRT's `buffer_save`/`buffer_save_ext` (and these async variants) fail to create the destination directory ([#15223](https://github.com/YoYoGames/GameMaker-Bugs/issues/15223)) — trips on the forced `default/` subfolder, so on desktop GMRT the write silently no-ops while `buffer_save_async` still reports `status:true` (false positive). Use the sync `writeBuffer`/`readBuffer` on desktop (root-level files need no new directory, so they're unaffected); the async path is for console and should work once #15223 is fixed. The event-routing plumbing (event → `_resolve` → callback) is verified good. (Both `saveAsync`/`loadAsync` round-trip with **each other** — they share the `default/` prefix, unlike the sync readers.)
- **`Log`**: text-based behavior verification (there are no tests). `Log.info/warn/error/debug(msg)` buffer timestamped lines; `obj_game` calls `Log.clear()` at startup and `Log.flush()` once per frame (only rewrites `game.log` when dirty). Read `game.log` to confirm runtime behavior without watching the window. `Log.exception(ex)` is the unhandled-exception handler `obj_game` registers via `exception_unhandled_handler` in `Create_0` — an uncaught runtime fault is written to `game.log` (`UNHANDLED EXCEPTION: <message>`) and flushed before the runner closes the game (it returns a non-zero exit code). Without it a mid-frame crash just stops the log at its last flush with no reason recorded. GMRT populates only `ex.message` for JS runtime faults (`script`/`line`/`stacktrace` come through empty), so only the message is logged.
- **`Debug`** (`scripts/Debug/`, Core): the **back-end** of the debug system — a registry of named panels that does **not** render, so a human and an agent debug the same state through different front-ends. `Debug.panel(name, (p) => …)` populates a panel via emit closures: `p.watch(label, fn)` / `p.watch(label, obj, key)` / `p.slider` / `p.checkbox` / `p.dropdown` / `p.input` (editable scalar) / `p.button` / `p.text`. Each entry is a **live binding** — a getter fn (read-only) or an `(obj, key)` pair (read/write live); the discriminator is whether a `key` arg was passed, **not** `typeof` (a class like `Time` is itself a function, so `typeof`-routing would mis-bind and later call `Time()` — a crash). Two front-ends: (1) **text** — `Debug.update()` (in `Step_0`) periodically writes `Debug.snapshot()` to **`debug.txt`** (the agent-readable view); (2) **ImGui** — `DebugImGui` (Core), the human overlay (toggle **F3**) via `show_debug_overlay` + `dbg_view`/`dbg_*` + `ref_create`. Since `ref_create` needs a `(struct, "field")` pair but an entry is often a getter fn, each gets a plain **mirror** `{ v }`; `refresh()` syncs it each frame (pull for read-only, change-detected push for editable, so an external write like the pause `Time.scale=0` isn't clobbered by a stale slider). Agent control: `Debug.set(panel, label, value)` / `Debug.press(panel, label)` from a temp harness, then verify on the game surface. Built-in panels `Time`/`Perf`/`Log`/`Sim` (the relocated sim controls — Pause / Step Frame / Restart Scene) + **`DebugRender`**'s `Render` (per-pass overlay toggles, each finding the live scene's pass by `instanceof` and flipping `enabled`) register in `obj_game` `Create_0`; Core lists only Core passes — a genre layer contributes its own via `DebugRender.add(cls, label)` (deduped by class, so repeated scene builds are no-ops), keeping Core decoupled. `DebugImGui` rebuilds on a `Debug.version()` change into **two windows** kept independent so one's churn doesn't move the other: a stable **Debug** view (Time/Perf) and a live **Inspector** view (the `Entity` panel), the latter kept alive across picks (only its `dbg_section` is swapped — there's no `dbg_set_view` on GMRT). Each panel is an explicit `dbg_section` (else GM bleeds the first control onto an auto "Default" header).
- **`DebugInspector`** (`scripts/DebugInspector/`, Core): the ECS entity inspector over `Debug`. While the overlay is open, left-clicking a world entity (`Query.nearest` from a cursor→world unproject via the scene camera's `toX/toY/width/height`) selects it; `select(world, id)` reads `world.componentsOf(id)` and registers an **`Entity`** panel exposing every component's scalar fields — numbers/strings as editable `input`s, booleans as `checkbox`es — bound LIVE to the component data objects, so an edit (in the overlay, or `Debug.set("Entity", "Health.hp", …)`) mutates the real entity. `draw(game)` highlights the selection on the GUI layer (reprojecting its `Position`). The Entity panel stays **registered at all times** (a placeholder line when nothing is selected) so its Inspector window is present from the moment the overlay opens, like Time/Perf; Deselect or a stale selection (entity removed / scene swapped) empties it to the placeholder rather than removing it. Wired in `Step_0` (`update`) + `Draw_75` (`draw`). While the overlay is open, `InputAction._debugMuted` mutes gameplay **mouse** input (so a pick-click can't fire the weapon) and **keyboard** input only while `is_keyboard_used_debug_overlay()` (typing in a `dbg_text_input`), so WASD still roams while inspecting.
- **Utils** (`scripts/Utils/`): global helper grab-bag — `noop()`, `uuid()` → UUID v4, `rem(value)` → pixel size relative to current font size.
