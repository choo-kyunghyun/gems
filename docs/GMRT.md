# GMRT

## Overview

G.E.M.S. targets GMRT — GameMaker's next-generation runtime — and nothing else: all game logic is JavaScript, which only GMRT executes (the legacy GMS2 runtime silently drops it). The toolchain is pinned to GMRT 0.21 by `gm-options.json` (the runner's `Startup: GMRT` banner prints 0.20.0 on it — the build cache's `runtimes-gmrt/0.21.0` is the truth).

The JS↔GML boundary is direct: GML built-ins are in scope from JS, and a JS object/array IS a GML struct/array — pass them straight to built-ins (`json_stringify`, `variable_struct_get_names`/`_get`/`_exists`, `is_array`/`array_length` all operate on JS data directly, nested included).

This file is the deny-list for that target: the standard JS forms GMRT miscompiles or chokes on, and the built-ins that diverge from the manual's contract. Every entry is live on 0.21 (Node as the ES2020 oracle; a divergence is A/B-run against GMS2 or the prior GMRT) — re-audit on a runtime upgrade. A deny-list only: a built-in absent from it is simply usable, and "it works now" is history, which git owns. Area-scoped rules live at their area's owner (its JSDoc — `UI.insert`, `Camera.cursorWorld`, `shMeshlit`); the Spine cluster is `SPINE.md`; this file keeps what can bite in any script.

Entry form: [#00000] carries the ticket, [unreported] marks a verified divergence with no ticket of its own — its closer is "Worth filing" or a why-not, a decision rather than an omission. Never a ticket's state (open, in QA, "fixed in 0.22"): state is the tracker's and rots the moment upstream moves, and a stale "fixed" reads as permission on the pinned runtime. Read it from the tracker when an upgrade plan needs it: `gh issue view <n> --repo YoYoGames/GameMaker-Bugs`.

Working rules: avoid the quirks, don't "clean up" code back into them, and leave a one-line comment citing this file where a quirk forces an unusual idiom. Codegen is name-sensitive ([#15597], the per-unit budgets), so verify an identifier rename by running the game, never by compiling alone.

## Recording a Quirk

Prove it first: `gm-cli manual read <fn>` (it may be documented behaviour), then `gh search issues --repo YoYoGames/GameMaker-Bugs` (it may be ticketed — thumbs-up, don't duplicate). An entry states the rule, its ticket, and the safe idiom — no discovery narration, no measurements. A divergence that reproduces on both runtimes is GameMaker behaviour, not a GMRT bug: if it needs a rule, record it closing with its why-not-filing. An agent NEVER files an issue — only the IDE's reporter can attach the reproduction project; "Worth filing" hands the entry to the user.

## Runtime and Build Issues

What fails loudly, by phase: at runtime, a built-in diverging from its manual contract or JS that hangs, corrupts a value, or returns garbage; at build, JS the compiler refuses or a compilation unit it corrupts.

### Runtime

- [#15546] `merge_colour` FLOORS its channel math where GMS2 rounds — re-merging a packed color into itself every frame drifts it to black, and a packed-int lerp freezes on sub-1 steps. One-shot merges are fine (`Color.merge`); animate a color as float r/g/b channels, rounding only the final `make_colour_rgb` (`UIButton._easeColor`).
- [#14737] the fixed-function alpha test (`gpu_set_alphatestenable`/`_ref`) is INERT — a transparent fragment still writes depth, so a sprite's empty pixels occlude what's behind. `discard` in the fragment shader instead (`shMeshlit`'s `u_alphaRef`, cutting on the TEXEL alpha; `RenderBillboard` sets it, `RenderMesh.setupLights` pins it 0). The commented-out `gpu_set_alphatestenable(true)` in `Game` Create_0 records the dead end — leave it.
- `gpu_set_scissor` quirk cluster — it is the UI clip mechanism (`UIElement._drawClipped`). The rules:
  1. Coords are render-target PIXELS, not GUI units — convert by `k = target/gui`. ([#11377] — intended behaviour.)
  2. [#15476] `window_get_width/height()` and the application surface lag the back buffer on a resize — a scissor sized from a raw query can overflow the target (fatal error). Size clips from `Display.clipW/clipH`.
  3. The scissor is not cleared between frames — `UI.draw()` re-anchors it to the full target at the start of each frame.
  4. `gpu_get_scissor()` returns `{0,0,0,0}` when unset — treat it as a nesting parent only when `w`/`h` are positive, and never restore a saved `{0,0,0,0}`; reset to the full target instead.
  5. [#6523] setting the scissor does NOT flush the pending vertex batch: `draw_flush()` at the END of `_drawClipped` (a start-of-clip flush corrupts the clip), and the preceding drawer must end with a flushed primitive (`UITabs.onDraw`'s trailing re-stroke — leave it). `draw_flush` is manual-flagged debug-only but is the only flush primitive — once per clip per frame is fine; a text-only clip can compute the visible substring itself (`UIInput.onDraw`). The draw right AFTER the flush must be untextured: a text run there is encoded with no pipeline, Dawn drops the whole command buffer up to the next submit, and `No pipeline set` logs every frame — `_drawClipped` re-arms with a zero-alpha untextured rect after its flush, so nothing outside it needs to care.
- [#15095] a `Map` iterator's internal pointer never advances — `next()` yields the first entry with `done: false` forever, so `for...of` (or any `next()`-driven loop) hangs the game: no exception, `game.log` just stops. Keep parallel arrays and index-loop (`World._keys`/`_storages`). `Map.forEach` bypasses the iterator and is safe; `Set` iteration, array/string `for...of`, and `for...in` over a plain object are also fine.
- [#15549] short-circuit `&&`/`||` corrupts its LEFT operand — codegen writes the operator's result back into the operand's local (`let b = true; const r = b && false;` → `b === false`); only `?:` is safe. Never reuse a variable after it has been a `&&`/`||` left operand — cache the object and read the property live (`Raycast.cast`).
- [#15563] `toUpperCase()` returns garbage Unicode and `toLowerCase()` an empty string, even for ASCII; GML `string_upper`/`string_lower` are correct. Map case via char codes (`VirtualKeyboard._upper`, `InvTable.lower`).
- [unreported] `working_directory` is the BUILD asset dir (lost on a rebuild), not the manual's save dir — root persistent paths on `game_save_id` (`%LOCALAPPDATA%\gems\`). A RELATIVE path lands beside `Runner.exe`; a bare filename through the `File` APIs still resolves to the save dir. Worth filing — distinct from the sandbox refusals [#15395]/[#15397].
- [unreported] `screen_save` auto-creates a subdir path's directories, but a BARE filename logs a bogus `Failed to create directories for ''` — the PNG is still written. Don't chase it, don't "fix" a subdir path back to bare. Worth filing — not [#11067].
- [unreported] `audio_play_sound_ext` IGNORES its `position` sub-struct — the cue plays plain 2D, no error. The spatial pipeline itself (falloff, listener, emitters, `audio_play_sound_at`) is correct per the manual: play a spatial cue with `audio_play_sound_at` (`Audio.play`'s position path) — same falloff triple plus every tail option, no emitter to reap. Worth filing — #2057 is unrelated.
- [unreported] `audio_sound_get_audibility` is MISSING (`typeof` → `undefined`; a call is a ReferenceError) — there is no in-engine read of a voice's computed gain. Worth filing.
- [unreported] `display_set_timing_method` is INERT (the getter always reports `tm_countvsyncs`), so the manual's `tm_systemtiming` uncap TIP is a dead end — uncap with a large `game_set_speed`, honored in both directions (`Display.UNCAPPED_FPS`). Worth filing — #14499/#13918 are different failures.
- [unreported] `console.log` prints only its FIRST argument (concatenate into one string), and `console.log` and `show_debug_message` are separate output streams — their relative order in a captured log is NOT execution order. Stay on ONE API when order matters, or use `Log` (file-backed, strictly ordered). Low-severity tooling.
- [unreported] a runtime-built struct's NESTED arrays reach JS opaque — `sprite_get_info(spr).animation_names`/`.bones`/`.slots` read `typeof` `[[unknown]]`, no `length`, no index (a top-level array RETURN like `sprite_get_uvs` converts fine; `Object.keys`/`json_stringify` on the struct still work). Read them through `array_length`/`array_get` (struct elements come out usable, their own nested arrays opaque again), or round-trip the struct through `json_stringify` → `JSON.parse` into plain data (`SkeletonSystem.info`). Worth filing.
- [unreported] the AREA collision queries are INERT: `collision_rectangle`, `collision_circle` and `collision_line` never report a hit, at any `prec`/`notme`, with an object or an instance as the target. `collision_point`, `instance_position`, `instance_nearest` and instance-scoped `place_meeting` are correct — build a spatial query from those, or stay in JS (`Broadphase`). Test any result with `instance_exists`, NEVER against `noone` (Differences from ES2020). Worth filing — #11395/#10946 are different failures.
- [unreported] `keyboard_clear(key)` drops the key's HELD state but NOT its same-step PRESSED edge — `keyboard_check_pressed` still reads true after the clear, so it cannot consume a press for a later reader in the same step. Consume through a frame-scoped record instead (`Input.consumeKey`/`Input.keyPressed`). The manual promises only the held-state drop — worth filing only if GMS2 clears the edge too (not A/B-run).
- [unreported] `keyboard_key_press(key)`/`_release` land their edge one to two steps AFTER the calling step, never in it — a debug driver polls for the edge across the following steps. Not filing — the manual states no timing.
- [unreported] the `keyboard_virtual_*` Windows/IME surface (#5524's) is broken: `keyboard_virtual_set_position` is MISSING (ReferenceError), `keyboard_virtual_status()`/`_height()` return `undefined` (the desktop contract since #6549 is a boolean / `0`), the manual's pass-`undefined` show idiom faults argument validation (only real `kbv_*` constants pass), and show/hide fire no "virtual keyboard status" System event. Avoid the family on 0.21, and typeof-guard `keyboard_virtual_set_position` in cross-runtime code. Worth filing — no GMRT ticket exists; `virtual_key_*` being desktop no-ops is documented, not part of this.
- [unreported] the ASYNC buffer family is inert on desktop: `buffer_save_async` reports `status` true and writes nothing, a grouped save (`buffer_async_group_end`) reports false, `buffer_load_async` reports false for a file that is there — so `File` is sync only (`buffer_save_ext`/`buffer_load`, which create and read every subfolder). Two rules for the day it lands: a group name is ONE path component (a slash is a fatal error), and inside a group the per-file calls return -1 — key a completion on `buffer_async_group_end`'s id. Worth filing — #15223 is the SYNC family.
- [#15733] `file_exists`/`directory_exists` answer false for EVERY save-area path (a `Not allowing file operation` line per call) — the file is there and `buffer_load` finds it. Verify a write by reading it back; there is no cheap existence check (`File` offers none).
- [unreported] the Async Save/Load event fires once at boot with a two-key `async_load` carrying no `"id"` (at the "gamepad discovered" System event) — a Save/Load handler tests `ds_map_exists(async_load, "id")` first. Not filing — harmless once guarded.

### Build

- [#15079] no optional chaining (`?.`) — any `a?.b` crashes the compiler with no file/line. Write the guard explicitly. Nullish `??`/`??=` are fine.
- [#15566] no empty `for` initializer — `for (; c<n; c++)` fails the BUILD. Add an initializer or use `while`.
- [#15065] a class with ~50 methods corrupts its compilation unit — the symptom varies with the exact count, and the enclosing unit's own body counts against the budget. Split into collaborators, free functions, or composition (`UIElement`/`Item`). Same per-unit budget defect as #15564 at class scale; when the ceiling lifts, `UIElement`'s commented-out flexpanel setters can return.
- [#15067] class inheritance is broken: `super.method()` is a compile error, and a subclass silently skips its BASE class's field initializers/constructor. Use composition (a flat class + `components: []` queried by `instanceof`); assign anything a base would have initialized in a method that runs (`create()`).
- [#15564] a file with roughly 200+ top-level `function` declarations corrupts its compilation unit — the game faults at startup. Assign explicitly (`globalThis.X = function X(…)`) and keep files small (why the Facet kit is split). Same per-unit budget defect as #15065 at file scale.
- [unreported] `get`/`set` as an object-literal SHORTHAND property (`{ get, set }` off same-named locals) fails the BUILD with `SyntaxError_InvalidArgs` — the parser reads them as ES5 accessor syntax. Plain shorthand and an explicit `get: get` key are fine; rename the field instead (`read`/`write`). Worth filing.
- The Sprite compile cache and Spine json: `SPINE.md` → Drawing and Playback.

## Differences from ES2020

The spec boundary rather than broken features: a feature GMRT doesn't implement — using it throws or faults — or one that behaves like a GameMaker built-in rather than ES2020 (Node as the oracle).

- [#15567] a `Map`/`Set` keyed by an OBJECT (asset ref, array, or plain object) crashes natively — an unhandled `Bad optional access` kills the run (minimal: `new Set().add({})`); string/number keys are fine. For object-identity membership use parallel arrays + an `===` scan (`SpriteMeta`, `Json._onPath`). (Distinct from #15095, the iterator hang.)
- [#15194] no array destructuring in a `for...of` header (`ReferenceError` at runtime) — destructure inside the loop body. (Object destructuring and a `.forEach(([a,b]) => …)` param are fine.)
- [#15565] `JSON.stringify` faults natively on any nested object/array (flat is fine, though `1` prints `1.0`). Serialize with GML `json_stringify()` — a JS object IS a GML struct (Overview) — and read back with native `JSON.parse` (only stringify faults); the `Json` codec adds ref-tagging + cycle-safety for save-game bundles.
- [#15593] `Array.prototype.sort` truncates the comparator's return toward zero AND is not stable — ties are actively reordered, so a fractional difference comparator shuffles near-equal items. Return a SIGN (`a < b ? -1 : a > b ? 1 : 0`, `Raycast.castAll`) and break ties explicitly when their order matters. (GML `array_sort` truncates too — there it's documented.)
- [unreported] `Set.prototype.forEach(fn)` THROWS when `thisArg` is omitted or `null`/`undefined` (`cannot coerce undefined or null value into object`), where ES2020 makes it optional; `Map.prototype.forEach(fn)` is fine without one. Pass any object (`s.forEach(fn, {})`) or iterate the Set with `for...of`/spread/`Array.from`, all sound on a `Set`. Worth filing.
- [unreported] A `Set`/`Map` crosses the boundary EMPTY: `json_stringify` writes it as `{"[[SetData]]":null}` / `{"[[MapData]]":null}`, and reflection sees one key `[[SetData]]` with `is_struct` true — a serialized or deep-copied collection silently loses every member. A persisted field holds plain arrays/objects only (ARCHITECTURE.md → Serialization-safe data); spread a `Set` into an array before it is stored. Not filing — a `Set` is not a struct, so the interop rule has nothing to carry.
- [unreported] `TypedArray.prototype.fill(v)` is a silent NO-OP when the range is omitted — `new Int32Array(8).fill(-1)` stays all-zero; `fill(v, 0, n)` writes correctly and plain `Array.prototype.fill(v)` is fine. Always pass the range on a typed array (`EntityID.reset`). Worth filing.
- [#15597] a top-level/event-body `var` named after a GML built-in resolves to the BUILT-IN (built-ins are in scope from JS — Overview) — the `var` binding never exists, so every read yields the function or constant. `let`, `const`, parameters, and `var` inside a function body all shadow correctly. The project uses `let`/`const` exclusively — never introduce `var`, and prefer non-colliding names regardless.
- [unreported] Top-level bare `const` isn't visible to other scripts — scoping is module-like per file, and a `.js` GMScript's top-level code auto-runs at startup; share via `globalThis.Name`. Not filing — coherent module semantics (the hoisting FAILURE past ~200 top-level functions is the bug — [#15564]).
- [unreported] Scripts' top-level code runs in the project's RESOURCE order — the `gems.yyp` list, which gm-cli keeps sorted by name case-INSENSITIVELY (`sceneColony` before `SceneTransition`) — so a top-level cross-script reference throws `ReferenceError: X is not defined` at startup unless the script it names sorts earlier. Register from top level only into a global whose script name is a PREFIX of every registrant's (`Scene.register` from the `scene*` scripts); anything else registers from `create()`. Not filing — the order is the project's.
- [unreported] READING an undeclared identifier KILLS the runner natively — no exception, no stack, no `UNHANDLED EXCEPTION` line, where ES2020 mandates a catchable `ReferenceError`; CALLING one throws correctly, so only the bare read is fatal. What makes it bite: the GML keywords `noone` and `all` are NOT in JS scope (`typeof` → `"undefined"`; `other`, `global`, and ordinary constants like `c_white`/`vk_f5` resolve), so the idiomatic `r === noone` test is a process death. Test such a result with `instance_exists(r)`, and probe anything uncertain through `typeof`, which is always safe. Worth filing — #10904 is a different failure.
- [unreported] No TDZ for `const` — a read above the declaration yields `undefined` where ES2020 mandates a `ReferenceError` (`let` throws correctly; the hoisted `const` does still shadow a same-named built-in). Keep declarations above first use; `checkJs` flags straight-line use-before-declare.
- [unreported] Bitwise ops don't apply ES2020 ToInt32: an operand or result outside Int32 range computes silently WRONG values (`0x9E3779B9 | 0` → -2147483648; `0x80000001 << 1` → 0), and some out-of-range chains still coincide with ES2020 — a passing probe proves nothing. In-range ops (`EntityID`'s packing) are exact; anything that can overflow (a PRNG, hash, or accumulator) uses float math: `hash2` (sine position hash) or a Park–Miller LCG (`s = (s*48271) % 2147483647`). Not filing — a consequence of GMRT's number model, themed at [#15060]/[#11835]; comment there.
- [unreported] `Math.random()` draws from GML's global generator stream — `random_set_seed(k)` fixes its output, and every call shifts each following `irandom`/`random` draw; `uuid()`'s unpredictability rests on the boot `randomize()` in `Game` Create_0. Keep reproducible data on `hash2` (no shared stream) and never pin the global seed while other consumers draw. (Adjacent trap: `randomize(k)` silently discards `k` — the seeding call is `random_set_seed(k)`.) Not filing — ES2020 leaves the algorithm implementation-defined.
- [unreported] the `GM_*` build constants — `GM_runtime_version`, `GM_version`, `GM_build_date`, `GM_build_type` — are not in JS scope (`typeof` → `"undefined"`; a bare read is the fatal kind, above), so a run cannot self-report its runtime and the build cache's `runtimes-gmrt/<version>` stays the truth (Overview). Not filing — unlisted in the JS surface rather than broken; probe through `typeof` if a later runtime lands them.
- [unreported] JS `Date` is UTC-pinned and second-granular — `getTimezoneOffset()` is `0`, the local getters read UTC, and `Date.now()`/`getTime()` zero the milliseconds; `toISOString()` is well-formed. Local wall clock lives on the GML side (`current_*`, `date_current_datetime()` + `date_get_*`), sub-second stamps on `current_time` — `Screenshot._autoname` composes both. (`date_datetime_string` is unusable regardless — mojibake on a non-ASCII locale.) Worth filing.
- [unreported] An asset ref reflects as an empty object (`typeof` `"object"`, `is_struct` true, `Object.keys` `[]`) — a generic deep copy silently turns a stored handle into `{}`, and JS reflection cannot identify one. Discriminate plain data by `v.constructor === Object`, pass refs through by reference (`EntityPreset._clone`), and asset-validate with GM functions (`sprite_exists`/`asset_get_type`). Likewise documented: `asset_get_index` returns a handle, not a number. Not filing — documented handle behaviour, shared by both runtimes.
- [unreported] A GML pointer value is NEVER `===`-equal in JS, not even to itself (`h === h` → `false`) — an identity scan over stored pointers, sound for asset refs and JS objects ([#15567]), silently matches nothing; an emptiness check (`h !== undefined`) still discriminates (`Display._pendingResize`). Test a pointer only through its owning API predicate (`dbg_view_exists`, `surface_exists`, …).
- [unreported] A `static` field initializer can't reference its own class — `static x = ClassName.y` throws at load and `static x = this.y` silently reads `undefined`; only a literal is safe. Use a static method, or assign `Foo.x = …` after the class body; referencing another already-loaded class is fine. Not filing — static class fields are ES2022, outside GMRT's ES2020 target.

## On a Runtime Upgrade

Part of what the code works around is GMRT's youth rather than physics, and a workaround does not BREAK when its defect is fixed — it silently becomes dead weight, and nothing surfaces it but this list. So on an upgrade: re-audit every entry above (and `SPINE.md`), re-run `sceneTest` (`GEMS_TEST=1 gm-cli run gems.yyp`) and read its `[BENCH]` lines against these triggers.

| when this changes | revisit |
| --- | --- |
| a TYPED array element read reaches plain-array cost (`read.typed` vs `read.array`, ~20x today) | the `EntityID.packed` mirror stops paying for itself |
| a BUILT-IN instance variable reaches user-defined cost (3-4.5x today) | the rule that an instance holds no data, only scope (`Instance`) |
| `Math.*` reaches its GML twins (`js.abs` vs `native.abs`, loses by ~1.5x today) | drop the native detours; `Array.sort` over `array_sort` |
| the boundary falls below ~10 ns (`native.clamp` vs `js.clamp`) | re-test natives at scalar sites, and `tilemap_*` against `RenderTileMap`'s vertex buffers |
| GMRT gains a JIT (~40–110x V8 today) | the hot-path idioms (ARCHITECTURE.md) become advisory — re-rank them by clarity, since the constant would no longer decide the frame |

Two results are NOT on this list and will not move: the instance-scoped built-ins are an API contract, not a gap, and the selectivity argument for columns (`perf.layout`) is a property of the data layout.
