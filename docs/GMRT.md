# GMRT

## Overview

G.E.M.S. runs on GMRT only: the game logic is JavaScript, which the legacy runtime silently drops. `gm-options.json` pins GMRT 0.21 (the runner's banner prints 0.20.0; the build cache's `runtimes-gmrt/0.21.0` is the truth). The JS↔GML boundary is direct — built-ins are in scope from JS, and a JS object/array IS a GML struct/array, nested included.

This file is the deny-list for that runtime: the JS forms it miscompiles or misruns and the built-ins off their manual contract, filed by what diverged — GMRT (a built-in at runtime, the compiler at build) or JavaScript (Bug, a clear departure from ES2020 with Node as the oracle; Env Diff, host-defined behaviour). Every entry is live on 0.21 and re-audited on a runtime upgrade (TODO.md → Planned); anything absent is simply usable, and "it works now" is history, which git owns. An area's own quirks live at its owner's JSDoc and the Spine cluster in `SPINE.md`; this file keeps what can bite in any script.

An entry is the rule, its ticket as [#00000], and the safe idiom — no narration, no measurements, and never a ticket's state, which is the tracker's and rots (`gh issue view <n> --repo YoYoGames/GameMaker-Bugs` when an upgrade plan needs it). Without a ticket it closes with "Worth filing" or a why-not. A project member is named only when it IS the safe idiom; examples live in the code, whose comments cite this file.

Working with it: avoid the quirks, never "clean up" code back into them, and cite this file in a one-line comment where a quirk forces an unusual idiom. Codegen is name-sensitive ([#15597], the per-unit budgets), so an identifier rename is verified by running the game, never by compiling alone. Recording a new one: `gm-cli manual read <fn>` first (it may be documented), then `gh search issues --repo YoYoGames/GameMaker-Bugs` (it may be ticketed — thumbs-up, don't duplicate); a divergence that reproduces on both runtimes is GameMaker behaviour, recorded with its why-not-filing. An agent never files an issue — only the IDE's reporter attaches the reproduction project — so "Worth filing" hands the entry to the user.

## GMRT

What GameMaker itself gets wrong under GMRT: the gaps its changelog declares, a built-in off its manual contract at runtime, and JS the compiler refuses or a compilation unit it corrupts at build. The manual is the contract; the rules for reading the tracker are Overview's.

### Known Incompatibilities

The gaps GMRT's changelog itself declares — upstream-known, listed so nobody re-probes them.

- Prefabs
- Video playback (other platforms)
- SVG Assets
- flexpanel_node_get_measure() / flexpanel_node_set_measure()
- vertex_buffer_exists() / vertex_format_exists()
- application_surface_is_draw_enabled()
- Lots of error spam from SDL

### Runtime

A built-in diverging from its manual contract — inert, missing, or returning garbage — and the boundary a built-in's value crosses.

- [#15546] `merge_colour` FLOORS its channel math where GMS2 rounds — re-merging a packed color into itself every frame drifts it to black, and a packed-int lerp freezes on sub-1 steps. One-shot merges are fine; animate a color as float r/g/b channels, rounding only the final `make_colour_rgb`.
- [#14737] the fixed-function alpha test (`gpu_set_alphatestenable`/`_ref`) is INERT — a transparent fragment still writes depth, so a sprite's empty pixels occlude what's behind. `discard` in the fragment shader instead (`shMeshlit`'s `u_alphaRef`, cutting on the TEXEL alpha so a dimmed entity stays visible).
- [#6553] a `draw_primitive_begin` batch draws at most 1000 vertices — every vertex past the 1000th is dropped silently, so a long run ends mid-list with no error (the manual documents no limit). Re-open the batch on that boundary, keeping one shape whole (`RenderDebugEntity`'s box walk), or bake a `VertexBuffer` where the geometry outlives the frame.
- `gpu_set_scissor` quirk cluster — it is the UI clip mechanism (`UIElement._drawClipped`). The rules:
  1. Coords are render-target PIXELS, not GUI units — convert by `k = target/gui`. ([#11377] — intended behaviour.)
  2. [#15476] `window_get_width/height()` and the application surface lag the back buffer on a resize — a scissor sized from a raw query can overflow the target (fatal error). Size clips from `Display.clipW/clipH`.
  3. The scissor is not cleared between frames — `UI.draw()` re-anchors it to the full target at the start of each frame.
  4. `gpu_get_scissor()` returns `{0,0,0,0}` when unset — treat it as a nesting parent only when `w`/`h` are positive, and never restore a saved `{0,0,0,0}`; reset to the full target instead.
  5. [#6523] setting the scissor does NOT flush the pending vertex batch: `draw_flush()` at the END of the clip (a start-of-clip flush corrupts the clip), and the preceding drawer must end with a flushed primitive. `draw_flush` is manual-flagged debug-only but is the only flush primitive — once per clip per frame is fine; a text-only clip can compute the visible substring itself. The draw right AFTER the flush must be untextured: a text run there is encoded with no pipeline, Dawn drops the whole command buffer up to the next submit, and `No pipeline set` logs every frame — `_drawClipped` re-arms with a zero-alpha untextured rect after its flush, so nothing outside it needs to care.
- `working_directory` is the BUILD asset dir (lost on a rebuild), not the manual's save dir — root persistent paths on `game_save_id` (`%LOCALAPPDATA%\gems\`). A RELATIVE path lands beside `Runner.exe`; a bare filename through the `File` APIs still resolves to the save dir. Worth filing — distinct from the sandbox refusals [#15395]/[#15397].
- `screen_save` auto-creates a subdir path's directories, but a BARE filename logs a bogus `Failed to create directories for ''` — the PNG is still written. Don't chase it, don't "fix" a subdir path back to bare. Worth filing — not [#11067].
- [#16014] `audio_play_sound_ext` IGNORES its `position` sub-struct — the cue plays plain 2D, no error. The spatial pipeline itself (falloff, listener, emitters, `audio_play_sound_at`) is correct per the manual: play a spatial cue with `audio_play_sound_at` (`Audio.play`'s position path) — same falloff triple plus every tail option, no emitter to reap.
- `display_set_timing_method` is INERT (the getter always reports `tm_countvsyncs`), so the manual's `tm_systemtiming` uncap TIP is a dead end — uncap with a large `game_set_speed`, honored in both directions. Worth filing — #14499/#13918 are different failures.
- a GML array reaches JS as a boundary value, not an `Array`: a top-level RETURN like `sprite_get_uvs` indexes fine (`uv[6]`) and passes `Array.isArray`, but `.length`, spread, `for...of` and every prototype method (`slice`/`map`/`forEach`/`join`/`indexOf`) throw `unhandled type (13) for JS_ToObject`; a runtime-built struct's NESTED arrays — `sprite_get_info(spr).frames`/`.animation_names`/`.bones`/`.slots` — reach opaque (`typeof` `[[unknown]]`, no index either; `Object.keys`/`json_stringify` on the struct still work). Read either through `array_length`/`array_get` (struct elements come out usable, their own nested arrays opaque again), or round-trip through `json_stringify` → `JSON.parse` into plain data. Worth filing.
- the AREA collision queries are INERT: `collision_rectangle`, `collision_circle` and `collision_line` never report a hit, at any `prec`/`notme`, with an object or an instance as the target. `collision_point`, `instance_position`, `instance_nearest` and instance-scoped `place_meeting` are correct — build a spatial query from those, or stay in JS (`Broadphase`). Test any result with `instance_exists`, NEVER against `noone` (JavaScript → Bug). Worth filing — #11395/#10946 are different failures.
- `keyboard_clear(key)` drops the key's HELD state but NOT its same-step PRESSED edge — `keyboard_check_pressed` still reads true after the clear, so it cannot consume a press for a later reader in the same step. Consume through a frame-scoped record instead (`Input.consumeKey`/`Input.keyPressed`). The manual promises only the held-state drop — worth filing only if GMS2 clears the edge too (not A/B-run).
- `keyboard_key_press(key)`/`_release` land their edge one to two steps AFTER the calling step, never in it — a debug driver polls for the edge across the following steps. Not filing — the manual states no timing.
- the `keyboard_virtual_*` Windows/IME surface (#5524's) is broken: `keyboard_virtual_set_position` is MISSING (ReferenceError), `keyboard_virtual_status()`/`_height()` return `undefined` (the desktop contract since #6549 is a boolean / `0`), the manual's pass-`undefined` show idiom faults argument validation (only real `kbv_*` constants pass), and show/hide fire no "virtual keyboard status" System event. Avoid the family on 0.21, and typeof-guard `keyboard_virtual_set_position` in cross-runtime code. Worth filing — no GMRT ticket exists; `virtual_key_*` being desktop no-ops is documented, not part of this.
- the ASYNC buffer family is inert on desktop: `buffer_save_async` reports `status` true and writes nothing, a grouped save (`buffer_async_group_end`) reports false, `buffer_load_async` reports false for a file that is there — so `File` is sync only (`buffer_save_ext`/`buffer_load`, which create and read every subfolder). Two rules for the day it lands: a group name is ONE path component (a slash is a fatal error), and inside a group the per-file calls return -1 — key a completion on `buffer_async_group_end`'s id. Worth filing — #15223 is the SYNC family.
- `buffer_read(buf, buffer_text)` scans for a NUL past the END of the buffer — `buffer_load` gives an exact-size buffer with no terminator, so the read returns the file plus whatever memory follows it, and a `JSON.parse` of that fails at random. Terminate it yourself: grow the buffer by one byte and poke a 0 before the read (`File.read`). Worth filing.
- `buffer_save`/`buffer_save_ext` of a ZERO-size buffer or range writes one byte of uninitialized memory, never an empty file — a cleared text file reads back as one garbage char. Save one zeroed byte in its place (`File.write`), which `buffer_text` reads as an empty string. Worth filing.
- [#15733] `file_exists`/`directory_exists` answer false for EVERY save-area path (a `Not allowing file operation` line per call) — the file is there and `buffer_load` finds it. Verify a write by reading it back; there is no cheap existence check (`File` offers none).
- the Async Save/Load event fires once at boot with a two-key `async_load` carrying no `"id"` (at the "gamepad discovered" System event) — a Save/Load handler tests `ds_map_exists(async_load, "id")` first. Not filing — harmless once guarded.

### Build

JS the compiler refuses outright or compiles into a corrupt unit; the error names no file or line, or none comes.

- [#15079] no optional chaining (`?.`) — any `a?.b` crashes the compiler with no file/line. Write the guard explicitly. Nullish `??`/`??=` are fine.
- [#15566] no empty `for` initializer — `for (; c<n; c++)` fails the BUILD. Add an initializer or use `while`.
- [#15065] a class with ~50 methods corrupts its compilation unit — the symptom varies with the exact count, and the enclosing unit's own body counts against the budget. Split into collaborators, free functions, or composition. Same per-unit budget defect as #15564 at class scale; when the ceiling lifts, `UIElement`'s commented-out flexpanel setters can return.
- [#15067] class inheritance is broken: `super.method()` is a compile error, and a subclass silently skips its BASE class's field initializers/constructor. Use composition (a flat class + `components: []` queried by `instanceof`); assign anything a base would have initialized in a method that runs (`create()`).
- [#15564] a file with roughly 200+ top-level `function` declarations corrupts its compilation unit — the game faults at startup. Assign explicitly (`globalThis.X = function X(…)`) and keep files small. Same per-unit budget defect as #15065 at file scale.
- `get`/`set` as an object-literal SHORTHAND property (`{ get, set }` off same-named locals) fails the BUILD with `SyntaxError_InvalidArgs` — the parser reads them as ES5 accessor syntax. Plain shorthand and an explicit `get: get` key are fine; rename the field instead (`read`/`write`). Worth filing.
- The Sprite compile cache and Spine json: `SPINE.md` → Drawing and Playback.

## JavaScript

The language as GMRT executes it, Node as the ES2020 oracle.

### Bug

A clear departure from ES2020: a standard form that hangs, crashes the runner, or computes a wrong value.

- [#15095] a `Map` iterator's internal pointer never advances — `next()` yields the first entry with `done: false` forever, so `for...of` (or any `next()`-driven loop) hangs the game: no exception, `game.log` just stops. Keep parallel arrays and index-loop. `Map.forEach` bypasses the iterator and is safe; `Set` iteration, array/string `for...of`, and `for...in` over a plain object are also fine.
- [#15549] short-circuit `&&`/`||` corrupts its LEFT operand — codegen writes the operator's result back into the operand's local (`let b = true; const r = b && false;` → `b === false`); only `?:` is safe. Never reuse a variable after it has been a `&&`/`||` left operand — cache the object and read the property live. It reaches the LEFTMOST operand of a long chain too, so a flag tested first in a guard (`if (flag && … && …)`) is false for every later reader — a whole loop's worth. A comparison as the operand is safe (there is no named local to write back), which is why `inBounds`' chain is fine; a bare flag is not.
- [#15563] `toUpperCase()` returns garbage Unicode and `toLowerCase()` an empty string, even for ASCII; GML `string_upper`/`string_lower` are correct. Map case via char codes.
- [#15567] a `Map`/`Set` keyed by an OBJECT (asset ref, array, or plain object) crashes natively — an unhandled `Bad optional access` kills the run (minimal: `new Set().add({})`); string/number keys are fine. For object-identity membership use parallel arrays + an `===` scan. (Distinct from #15095, the iterator hang.)
- [#15194] no array destructuring in a `for...of` header (`ReferenceError` at runtime) — destructure inside the loop body. (Object destructuring and a `.forEach(([a,b]) => …)` param are fine.)
- [#15565] `JSON.stringify` faults natively on any nested object/array (flat is fine, though `1` prints `1.0`). Serialize with GML `json_stringify()` — a JS object IS a GML struct (Overview) — and read back with native `JSON.parse` (only stringify faults); the `Json` codec adds ref-tagging + cycle-safety for save-game bundles.
- [#15593] `Array.prototype.sort` truncates the comparator's return toward zero AND is not stable — ties are actively reordered, so a fractional difference comparator shuffles near-equal items. Return a SIGN (`a < b ? -1 : a > b ? 1 : 0`) and break ties explicitly when their order matters. (GML `array_sort` truncates too — there it's documented.)
- `Set.prototype.forEach(fn)` THROWS when `thisArg` is omitted or `null`/`undefined` (`cannot coerce undefined or null value into object`), where ES2020 makes it optional; `Map.prototype.forEach(fn)` is fine without one. Pass any object (`s.forEach(fn, {})`) or iterate the Set with `for...of`/spread/`Array.from`, all sound on a `Set`. Worth filing.
- `TypedArray.prototype.fill(v)` is a silent NO-OP when the range is omitted — `new Int32Array(8).fill(-1)` stays all-zero; `fill(v, 0, n)` writes correctly and plain `Array.prototype.fill(v)` is fine. Always pass the range on a typed array. Worth filing.
- [#15597] a top-level/event-body `var` named after a GML built-in resolves to the BUILT-IN (built-ins are in scope from JS — Overview) — the `var` binding never exists, so every read yields the function or constant. `let`, `const`, parameters, and `var` inside a function body all shadow correctly. The project uses `let`/`const` exclusively — never introduce `var`, and prefer non-colliding names regardless.
- READING an undeclared identifier KILLS the runner natively — no exception, no stack, no `UNHANDLED EXCEPTION` line, where ES2020 mandates a catchable `ReferenceError`; CALLING one throws correctly, so only the bare read is fatal. What makes it bite: the GML keywords `noone` and `all` are NOT in JS scope (`typeof` → `"undefined"`; `other`, `global`, and ordinary constants like `c_white`/`vk_f5` resolve), so the idiomatic `r === noone` test is a process death. Test such a result with `instance_exists(r)`, and probe anything uncertain through `typeof`, which is always safe. Worth filing — #10904 is a different failure.
- No TDZ for `const` — a read above the declaration yields `undefined` where ES2020 mandates a `ReferenceError` (`let` throws correctly; the hoisted `const` does still shadow a same-named built-in). Keep declarations above first use; `checkJs` flags straight-line use-before-declare.
- Bitwise ops don't apply ES2020 ToInt32: an operand or result outside Int32 range computes silently WRONG values (`0x9E3779B9 | 0` → -2147483648; `0x80000001 << 1` → 0), and some out-of-range chains still coincide with ES2020 — a passing probe proves nothing. In-range ops are exact; anything that can overflow (a PRNG, hash, or accumulator) uses float math: `hash2` (sine position hash) or a Park–Miller LCG (`s = (s*48271) % 2147483647`). Not filing — a consequence of GMRT's number model, themed at [#15060]/[#11835]; comment there.

### Env Diff

Not off the standard, or outside it: host-defined behaviour — scope, load order, clocks, host values, the console — that differs from Node and bites when Node's is assumed.

- `console.log` prints only its FIRST argument (concatenate into one string), and `console.log` and `show_debug_message` are separate output streams — their relative order in a captured log is NOT execution order. Stay on ONE API when order matters, or use `Log` (file-backed, strictly ordered). Low-severity tooling.
- A `Set`/`Map` crosses the boundary EMPTY: `json_stringify` writes it as `{"[[SetData]]":null}` / `{"[[MapData]]":null}`, and reflection sees one key `[[SetData]]` with `is_struct` true — a serialized or deep-copied collection silently loses every member. A persisted field holds plain arrays/objects only (ARCHITECTURE.md → Serialization-safe data); spread a `Set` into an array before it is stored. Not filing — a `Set` is not a struct, so the interop rule has nothing to carry.
- Top-level bare `const` isn't visible to other scripts — scoping is module-like per file, and a `.js` GMScript's top-level code auto-runs at startup; share via `globalThis.Name`. Not filing — coherent module semantics (the hoisting FAILURE past ~200 top-level functions is the bug — [#15564]).
- Scripts' top-level code runs in the project's RESOURCE order — the `gems.yyp` list, which gm-cli keeps sorted by name case-INSENSITIVELY (`sceneColony` before `SceneTransition`) — so a top-level cross-script reference throws `ReferenceError: X is not defined` at startup unless the script it names sorts earlier. Register from top level only into a global whose script name is a PREFIX of every registrant's (`Scene.register` from the `scene*` scripts); anything else registers from `create()`. Not filing — the order is the project's.
- `Math.random()` draws from GML's global generator stream — `random_set_seed(k)` fixes its output, and every call shifts each following `irandom`/`random` draw; `uuid()`'s unpredictability rests on the boot `randomize()`. Keep reproducible data on `hash2` (no shared stream) and never pin the global seed while other consumers draw. (Adjacent trap: `randomize(k)` silently discards `k` — the seeding call is `random_set_seed(k)`.) Not filing — ES2020 leaves the algorithm implementation-defined.
- the `GM_*` build constants — `GM_runtime_version`, `GM_version`, `GM_build_date`, `GM_build_type` — are not in JS scope (`typeof` → `"undefined"`; a bare read is the fatal kind, above), so a run cannot self-report its runtime and the build cache's `runtimes-gmrt/<version>` stays the truth (Overview). Not filing — unlisted in the JS surface rather than broken; probe through `typeof` if a later runtime lands them.
- JS `Date` is UTC-pinned and second-granular — `getTimezoneOffset()` is `0`, the local getters read UTC, and `Date.now()`/`getTime()` zero the milliseconds; `toISOString()` is well-formed. Local wall clock lives on the GML side (`current_*`, `date_current_datetime()` + `date_get_*`), sub-second stamps on `current_time`. (`date_datetime_string` is unusable regardless — mojibake on a non-ASCII locale.) Worth filing.
- An asset ref reflects as an empty object (`typeof` `"object"`, `is_struct` true, `Object.keys` `[]`) — a generic deep copy silently turns a stored handle into `{}`, and JS reflection cannot identify one. Discriminate plain data by `v.constructor === Object`, pass refs through by reference, and asset-validate with GM functions (`sprite_exists`/`asset_get_type`). Likewise documented: `asset_get_index` returns a handle, not a number. Not filing — documented handle behaviour, shared by both runtimes.
- A GML pointer value is NEVER `===`-equal in JS, not even to itself (`h === h` → `false`) — an identity scan over stored pointers, sound for asset refs and JS objects ([#15567]), silently matches nothing; an emptiness check (`h !== undefined`) still discriminates. Test a pointer only through its owning API predicate (`dbg_view_exists`, `surface_exists`, …).
- A `static` field initializer can't reference its own class — `static x = ClassName.y` throws at load and `static x = this.y` silently reads `undefined`; only a literal is safe. Use a static method, or assign `Foo.x = …` after the class body; referencing another already-loaded class is fine. Not filing — static class fields are ES2022, outside GMRT's ES2020 target.
