# GMRT

## Overview

G.E.M.S. runs on GMRT only: the game logic is JavaScript, which the legacy runtime silently drops. `gm-options.json` names the toolchain `GMRT` with no version, so the newest installed runtime builds — 0.21 (the runner's banner and GML's `GM_runtime_version` print 0.20.0; the build cache's `runtimes-gmrt/0.21.0` is the truth). The JS↔GML boundary is direct — built-ins are in scope from JS, and a JS object/array IS a GML struct/array, nested included.

This file is the deny-list for that runtime: the JS forms it miscompiles or misruns and the built-ins off their manual contract, filed by what diverged — GMRT (a built-in at runtime, the compiler at build) or JavaScript (Bug, a clear departure from ES2020 with Node as the oracle; Env Diff, host-defined behaviour). Every entry is live on 0.21 and re-audited on a runtime upgrade (TODO.md → Planned); anything absent is simply usable, and "it works now" is history, which git owns. An area's own quirks live at its owner's JSDoc and the Spine cluster in `SPINE.md`; this file keeps what can bite in any script.

An entry is the rule, its ticket as [#00000], and the safe idiom — no narration, no measurements, and never a ticket's state, which is the tracker's and rots (`gh issue view <n> --repo YoYoGames/GameMaker-Bugs` when an upgrade plan needs it). Without a ticket it closes with "Worth filing" or a why-not. A project member is named only when it IS the safe idiom; examples live in the code, whose comments cite this file.

Working with it: avoid the quirks, never "clean up" code back into them, and cite this file in a one-line comment where a quirk forces an unusual idiom. Codegen is name-sensitive ([#15597], the per-unit budgets), so an identifier rename is verified by running the game, never by compiling alone. Recording a new one: `gm-cli manual read <fn>` first (it may be documented), then `gh search issues --repo YoYoGames/GameMaker-Bugs` (it may be ticketed — thumbs-up, don't duplicate); a divergence that reproduces on both runtimes is GameMaker behaviour, recorded with its why-not-filing. An agent never files an issue — only the IDE's reporter attaches the reproduction project — so "Worth filing" hands the entry to the user.

## GMRT

### Runtime

A built-in diverging from its manual contract — inert, missing, or returning garbage — and the boundary a built-in's value crosses.

- [#15546] `merge_colour` FLOORS its channel math where GMS2 rounds — re-merging a packed color into itself every frame drifts it to black, and a packed-int lerp freezes on sub-1 steps. One-shot merges are fine; animate a color as float r/g/b channels, rounding only the final `make_colour_rgb`.
- [#14737] the fixed-function alpha test (`gpu_set_alphatestenable`/`_ref`) is INERT — a transparent fragment still writes depth, so a sprite's empty pixels occlude what's behind. `discard` in the fragment shader instead (`shMeshlit`'s `u_alphaRef`, cutting on the TEXEL alpha so a dimmed entity stays visible).
- [#6553] a `draw_primitive_begin` batch draws at most 1000 vertices — every vertex past the 1000th is dropped silently, so a long run ends mid-list with no error (the manual documents no limit). Re-open the batch on that boundary, keeping one shape whole (`RenderDebugEntity`'s box walk), or bake a `VertexBuffer` where the geometry outlives the frame.
- `gpu_set_scissor` quirk cluster — it is the UI clip mechanism (`UIElement._drawClipped`). The rules:
  1. Coords are render-target PIXELS, not GUI units — convert by `k = target/gui`. ([#11377] — intended behaviour.)
  2. [#15476] `window_get_width/height()` and the application surface lag the back buffer on a resize — a scissor sized from a raw query can overflow the target (fatal error). Size clips from `Display.clipW/clipH`.
  3. `gpu_get_scissor()` is not the live clip: unset it returns `{0,0,0,0}` (GMS2: the full target), and it keeps returning the last rect set across events and frames while the clip itself resets with each frame's target — so the manual's save/restore idiom replays a stale or empty rect. `UI.draw()` re-anchors to the full target at the start of each frame; a read rect is a nesting parent only when `w`/`h` are positive, and a `{0,0,0,0}` is never restored — reset to the full target instead. Worth filing.
  4. [#6523] setting the scissor does NOT flush the pending vertex batch: `draw_flush()` at the END of the clip (a start-of-clip flush corrupts the clip), and the preceding drawer must end with a flushed primitive. `draw_flush` is manual-flagged debug-only but is the only flush primitive — once per clip per frame is fine; a text-only clip can compute the visible substring itself. The draw right AFTER the flush must be untextured: a text run there is encoded with no pipeline, Dawn drops the whole command buffer up to the next submit, and `No pipeline set` logs every frame — `_drawClipped` re-arms with a zero-alpha untextured rect after its flush, so nothing outside it needs to care.
- [#15933] the save dir (`game_save_id`, `%LOCALAPPDATA%\gems\`) takes only some paths. `working_directory` is the BUILD asset dir (lost on a rebuild): a write through it is remapped to `<save>\assets\`, where a read through the same path misses; an ABSOLUTE `game_save_id` path is refused by `buffer_save` (`Not allowing file operation`), as is `file_text_open_write` through `working_directory`; a RELATIVE path, bare or with subfolders, saves into the save dir and loads back. Keep file I/O on relative names (`File`). `screen_save` is the reverse — a relative name lands in the build asset dir (a bare one also logs a bogus `Failed to create directories for ''`) while an absolute `game_save_id` path lands in the save dir, so root a screenshot there. Distinct from the sandbox refusals [#15395]/[#15397].
- [#16014] `audio_play_sound_ext` IGNORES its `position` sub-struct — the cue plays plain 2D, no error. The spatial pipeline itself (falloff, listener, emitters, `audio_play_sound_at`) is correct per the manual: play a spatial cue with `audio_play_sound_at` (`Audio.play`'s position path) — same falloff triple plus every tail option, no emitter to reap.
- `display_set_timing_method(tm_systemtiming)` is IGNORED — the getter keeps the previous method and the frame rate stays capped (GMS2 uncaps; `tm_sleep`/`tm_countvsyncs` do set), so the manual's uncap is a dead end — uncap with a large `game_set_speed`, honored in both directions. Worth filing — #14499/#13918 are different failures.
- a GML array reaches JS as a boundary value, not an `Array`: a top-level RETURN like `sprite_get_uvs` indexes fine (`uv[6]`) and passes `Array.isArray`, but `.length`, spread, `for...of` and every prototype method (`slice`/`map`/`forEach`/`join`/`indexOf`) throw `unhandled type (13) for JS_ToObject`, and a truthiness test (`arr ? a : b`, `if (arr)`) throws `unhandled type (13) for JS_ToBoolean` — inside a `try/catch` it can kill the runner natively instead (`Bad optional access`), so a returned array such as `move_and_collide`'s is read through `array_length` and never tested; a runtime-built struct's NESTED arrays — `sprite_get_info(spr).frames`/`.animation_names`/`.bones`/`.slots` — reach opaque (`typeof` `[[unknown]]`, no index either; `Object.keys`/`json_stringify` on the struct still work). Read either through `array_length`/`array_get` (struct elements come out usable, their own nested arrays opaque again), or round-trip through `json_stringify` → `JSON.parse` into plain data. Worth filing.
- the AREA collision queries (`collision_rectangle`, `collision_circle`, `collision_line`) never report an instance whose OBJECT has no editor sprite — a `sprite_index`/`mask_index` assigned at runtime (`Puppet`'s idiom) never registers it: not after a step, a move or a scale write, at any `prec`/`notme`, with an object or an instance as the target, from GML and JS alike, while its bbox reads correctly and `collision_point`, `instance_position`, `instance_nearest` and instance-scoped `place_meeting` find it. An object with an editor sprite is found, a runtime sprite swap included. Give the object a placeholder editor sprite (`Puppet` carries `pixMaskUnit`, guarded by testGame puppet.area), or build the query from the point forms. Test any result with `instance_exists`, NEVER against `noone` (JavaScript → Env Diff). Worth filing — GMS2 passes the same project; #11395/#10946 are different failures.
- an instance's `bbox_left`/`_top`/`_right`/`_bottom` keep the FRACTION of a sub-pixel position (`x = 500.5` → `bbox_left` 500.5) where the manual promises an integer; `collision_point` tests those exact edges, but the instance and rectangle tests ROUND each edge to a whole pixel, so an overlap under half a pixel goes unreported — a body moved by `move_and_collide` can rest up to 0.5 px inside a face, and a float audit against it allows that half pixel (`_stressOverlaps`, system.solid); at whole-pixel positions a float AABB and the mask agree exactly (testCollision perf.builtin). Not filing — GMS2 behaves identically.
- `sprite_collision_mask` is INERT on a runtime sprite (`sprite_duplicate`): the manual bbox never lands — `sprite_get_bbox_*`, `bbox_*` and every collision keep the source sprite's full box, whatever the object (GMS2 applies the box image-relative). No per-shape mask at runtime: size a mask with `image_xscale`/`image_yscale` over a unit mask sprite (`pixMaskUnit`), and for an EMPTY mask author a sprite whose manual bbox is one pixel parked far off the image (`pixMaskNone`, -32768) — a zero box is one inclusive pixel a rectangle query still hits, and an inverted one (left > right), which the rectangle and point tests honour as empty, the circle test normalizes back into that pixel. Worth filing.
- [#15365] `sprite_set_offset` drops its X offset — Y lands, X stays at the old origin, and the mask follows. Author the origin in the editor.
- [#15364] a DEACTIVATED instance (`instance_deactivate_object`) is skipped by every `collision_*` query, `instance_exists` reads false and `instance_destroy` on it is a silent no-op, as documented — but `instance_activate_object` is INERT, given the instance, its id or its object, even past the calling event the manual defers activation to (the instance stays deactivated, so nothing per-instance can ever destroy it), while `instance_activate_all()` brings everything back: thaw with the latter, re-park what should stay parked and destroy what was released meanwhile (`PuppetSystem.thaw`).
- `keyboard_clear(key)` drops the key's HELD state but NOT its same-step PRESSED edge — `keyboard_check_pressed` still reads true after the clear, so it cannot consume a press for a later reader in the same step. Consume through a frame-scoped record instead (`Input.consumeKey`/`Input.keyPressed`). The manual promises only the held-state drop — worth filing only if GMS2 clears the edge too, which a run cannot show (a simulated press never reaches GMS2's `keyboard_check`).
- `keyboard_key_press(key)`/`_release` land their edge one to two steps AFTER the calling step, never in it — a debug driver polls for the edge across the following steps. Not filing — the manual states no timing.
- the `keyboard_virtual_*` Windows/IME surface (#5524's) is broken: `keyboard_virtual_set_position` is MISSING (ReferenceError), `keyboard_virtual_status()`/`_height()` return `undefined` (the desktop contract since #6549 is a boolean / `0`), and the manual's pass-`undefined` show idiom faults argument validation with a TypeError no `try/catch` stops, ending the run (only real `kbv_*` constants pass). Avoid the family on 0.21, and typeof-guard `keyboard_virtual_set_position` in cross-runtime code. Worth filing — `virtual_key_*` being desktop no-ops is documented, not part of this.
- the ASYNC buffer family is inert on desktop, each call logging `Not allowing file operation`: `buffer_save_async` reports `status` true and writes nothing, a grouped save (`buffer_async_group_end`) reports false, `buffer_load_async` reports false for a file that is there — so `File` is sync only (`buffer_save_ext`/`buffer_load`, which create and read every subfolder). Two rules for the day it lands: a group name is ONE path component (a slash is a fatal error), and inside a group the per-file calls return -1, as on GMS2 — key a completion on `buffer_async_group_end`'s id. Worth filing — [#15933] is the sync family, #15553 the load's bundle fallback.
- `buffer_read(buf, buffer_text)` scans for a NUL past the END of the buffer — `buffer_load` gives an exact-size buffer with no terminator, so the read returns the file plus whatever memory follows it, and a `JSON.parse` of that fails at random. Terminate it yourself: grow the buffer by one byte and poke a 0 before the read (`File.read`). Worth filing.
- `buffer_save`/`buffer_save_ext` of a ZERO-SIZE buffer writes one byte of uninitialized memory where GMS2 writes one zero byte — a cleared text file reads back as one garbage char; a zero RANGE of a non-empty buffer saves an empty file on both. Save one zeroed byte in its place (`File.write`), which `buffer_text` reads as an empty string. Worth filing.
- [#15733] `file_exists`/`directory_exists` answer false for EVERY save-area path (a `Not allowing file operation` line per call) — the file is there and `buffer_load` finds it. Verify a write by reading it back; there is no cheap existence check (`File` offers none).

### Build

JS the compiler refuses outright or compiles into a corrupt unit; the error names no file or line, or none comes.

- [#15079] no optional chaining (`?.`) — any `a?.b` crashes the compiler with no file/line. Write the guard explicitly. Nullish `??`/`??=` are fine.
- [#15566] no empty `for` initializer — `for (; c<n; c++)` fails the BUILD. Add an initializer or use `while`.
- [#15065] a class with ~50 methods corrupts its compilation unit — the symptom varies with the exact count, and the enclosing unit's own body counts against the budget. Split into collaborators, free functions, or composition. Same per-unit budget defect as #15564 at class scale; when the ceiling lifts, `UIElement`'s commented-out flexpanel setters can return.
- [#15067] class inheritance is broken: `super.method()` is a compile error, and a subclass silently skips its BASE class's field initializers/constructor. Use composition (a flat class + `components: []` queried by `instanceof`); assign anything a base would have initialized in a method that runs (`create()`).
- [#15564] a file with roughly 200+ top-level `function` declarations corrupts its compilation unit — the game faults at startup. Assign explicitly (`globalThis.X = function X(…)`) and keep files small. Same per-unit budget defect as #15065 at file scale.
- `get`/`set` as an object-literal SHORTHAND property (`{ get, set }` off same-named locals) fails the BUILD with `SyntaxError_InvalidArgs` — the parser reads them as ES5 accessor syntax. Plain shorthand and an explicit `get: get` key are fine; rename the field instead (`read`/`write`). Worth filing.
- [#15024] a template literal processes NO escape sequence — `` `a\\b` `` keeps both backslashes, and `\n`, `\t`, a hex or Unicode escape, `` \` `` and `\$` all stay backslash text — while a quoted string escapes exactly. Write any escape in a quoted string and concatenate. Separately, a `\0` escape in any literal fails the BUILD (`SyntaxError_ExceptionParsing`) — build a NUL as `String.fromCharCode(0)`; that part is worth filing.
- The Sprite compile cache and Spine json: `SPINE.md` → Drawing and Playback.

## JavaScript

The language as GMRT executes it, Node as the ES2020 oracle.

### Bug

A clear departure from ES2020: a standard form that hangs, crashes the runner, or computes a wrong value.

- [#15095] a `Map` iterator's internal pointer never advances — `next()` yields the first entry with `done: false` forever, so `for...of` (or any `next()`-driven loop) hangs the game: no exception, `game.log` just stops. Keep parallel arrays and index-loop. `Map.forEach` bypasses the iterator and is safe; `Set` iteration, array/string `for...of`, and `for...in` over a plain object are also fine.
- [#15549] short-circuit `&&`/`||` corrupts its LEFT operand — codegen writes the operator's result back into the operand's local (`let b = true; const r = b && false;` → `b === false`); only `?:` is safe. Never reuse a variable after it has been a `&&`/`||` left operand — cache the object and read the property live. It reaches the LEFTMOST operand of a long chain too, so a flag tested first in a guard (`if (flag && … && …)`) is false for every later reader — a whole loop's worth. A comparison as the operand is safe (there is no named local to write back), which is why `inBounds`' chain is fine; a bare flag is not.
- [#15563] `toUpperCase()` returns garbage Unicode and `toLowerCase()` an empty string, even for ASCII; GML `string_upper`/`string_lower` are correct. Map case via char codes.
- [#15567] a `Map`/`Set` keyed by an OBJECT (asset ref, array, or plain object) crashes natively — an unhandled `Bad optional access` kills the run (minimal: `new Set().add({})`) — and so does an `undefined` key (`set.has(undefined)`, `set.add(undefined)`), which is how a missing instance variable read off a query's hit (`inst.eid` on a puppet that mirrors nothing) reaches one; string/number keys are fine, so test a key for `undefined` first. For object-identity membership use parallel arrays + an `===` scan. (Distinct from #15095, the iterator hang.)
- [#15194] no array destructuring in a `for...of` header (`ReferenceError` at runtime) — destructure inside the loop body. (Object destructuring and a `.forEach(([a,b]) => …)` param are fine.)
- [#15565] `JSON.stringify` faults natively on any nested object/array (flat is fine, though `1` prints `1.0`). Serialize with GML `json_stringify()` — a JS object IS a GML struct (Overview) — and read back with native `JSON.parse` (only stringify faults). `JSON.parse` leaves `json_stringify`'s manual-documented tags as strings — a keycode or colour constant as `@i64@…$i64$`, a sprite as `@ref GMSprite(name)` — so a blob carrying either goes through the `Json` codec, which writes the constant as its number and revives the sprite.
- [#15593] `Array.prototype.sort` truncates the comparator's return toward zero AND is not stable — ties are actively reordered, so a fractional difference comparator shuffles near-equal items. Return a SIGN (`a < b ? -1 : a > b ? 1 : 0`) and break ties explicitly when their order matters. (GML `array_sort` truncates too — there it's documented.)
- `JSON.parse` never throws — invalid text (garbage, empty, truncated, trailing junk) returns `null` where ES2020 mandates a `SyntaxError`, so a `try/catch` around it is dead and an `=== undefined` check passes the failure through; GML's `json_parse` does the same on GMRT, where GMS2 throws as its manual states. Test the result for `null` (`Json.decode` maps it to undefined). Worth filing.
- `json_parse` misreads an integer past 2^52 — `8000000000000001` comes back `8000000000000002`, `2^53 - 1` as `…990` — while `json_stringify` writes it exactly and `JSON.parse` reads it back exactly. A number that must survive whole above 2^52 is read through `JSON.parse` (`Json.decode`), never `json_parse`. Worth filing.
- global `isFinite` rejects only `±Infinity` — `NaN`, a non-numeric string and `undefined` all pass (`Number.isFinite`, `Number.isNaN` and `isNaN` are correct) — and `JSON.stringify` has no `null` for a non-finite number: `JSON.stringify(NaN)`/`(Infinity)` return `undefined`, and as an object value it is dropped, leaving an invalid `"a": `. Guard a number with `Number.isFinite`. Worth filing — [#15565] is the nested fault and the pretty-print.
- `Set.prototype.forEach(fn)` THROWS when `thisArg` is omitted or `null`/`undefined`, where ES2020 makes it optional — and the throw is a bare string (`… cannot coerce undefined or null value into object`), not an `Error`, so `e.message` reads `undefined`; `Map.prototype.forEach(fn)` is fine without one. Pass any object (`s.forEach(fn, {})`) or iterate the Set with `for...of`/spread/`Array.from`, all sound on a `Set`. Worth filing.
- A CLASS `get`/`set` accessor is unreliable — in a getter-only class the first getter throws `cannot coerce undefined or null value into object` while a later one may run another accessor's body (a `return this.grid.rows` getter answering another class's constant), and in a get+set pair a read after the first set can throw the same. An object-literal getter reads correctly. Write no class accessor: a plain field, or a method; `Level`'s `grid` pair is the one kept, held by its testLevel `level.self` case. Worth filing.
- `TypedArray.prototype.fill` is a silent NO-OP unless `end` is passed — `new Int32Array(8).fill(-1)` and `.fill(-1, 1)` stay all-zero; `fill(v, start, end)` writes correctly and plain `Array.prototype.fill(v)` is fine. Always pass the full range on a typed array. Worth filing.
- `Array.prototype.splice` with `deleteCount` omitted — `splice(start)` or a bare `splice()` — KILLS the runner natively (no exception, `game.log` just stops) where ES2020 removes every element from `start` (or nothing); `splice(start, n)` and `arr.length = n` are fine — truncate with the latter. Worth filing.
- [#15597] a top-level/event-body `var` named after a GML built-in resolves to the BUILT-IN (built-ins are in scope from JS — Overview) — the `var` binding never exists, so every read yields the function or constant. `let`, `const`, parameters, and `var` inside a function body all shadow correctly. The project uses `let`/`const` exclusively — never introduce `var`, and prefer non-colliding names regardless.
- No TDZ for `const` — a read above the declaration yields `undefined`, and `typeof` of it `"undefined"`, where ES2020 mandates a `ReferenceError` (`let` throws correctly; the hoisted `const` does still shadow a same-named built-in). Keep declarations above first use; `checkJs` flags straight-line use-before-declare. Worth filing.
- An unparenthesised chain of one bitwise operator over non-constant operands — `a | b | c`, `a & b & c`, `a ^ b ^ c`, and so `a | (b << 1) | (c << 2)` — KILLS the runner natively (a stack trace on stderr, nothing in `game.log`); two operands are fine, a literal chain folds and survives, and grouping each step (`(a | b) | c`) or accumulating (`m |= c`) is sound. Build a mask one `|=` at a time. Worth filing.
- Bitwise ops don't apply ES2020 ToInt32: an operand outside Int32 range collapses to -2147483648 instead of wrapping (`0x9E3779B9 | 0` → -2147483648; `0xFFFFFFFF & 0xFF` → 0), `>>>` of one yields 2147483648, and `Math.imul` returns the unwrapped product — while some out-of-range forms still coincide with ES2020 (`~0x80000000`), so a passing probe proves nothing. In-range ops are exact; anything that can overflow (a PRNG, hash, or accumulator) uses float math: `hash2` (sine position hash) or a Park–Miller LCG (`s = (s*48271) % 2147483647`). Worth filing — #15060 is GML's int64 promotion, not this.

### Env Diff

Not off the standard, or outside it: host-defined behaviour — scope, load order, clocks, host values, the console — that differs from Node and bites when Node's is assumed.

- `console.log` prints only its FIRST argument (concatenate into one string), and `console.log` and `show_debug_message` are separate output streams — their relative order in a captured log is NOT execution order. Stay on ONE API when order matters, or use `Log` (file-backed, strictly ordered). Low-severity tooling.
- A `Set`/`Map` crosses the boundary EMPTY: `json_stringify` writes it as `{"[[SetData]]":null}` / `{"[[MapData]]":null}`, and reflection sees one key `[[SetData]]` with `is_struct` true — a serialized or deep-copied collection silently loses every member. A persisted field holds plain arrays/objects only (ARCHITECTURE.md → Serialization-safe data); spread a `Set` into an array before it is stored. Not filing — a `Set` is not a struct, so the interop rule has nothing to carry.
- [#13263] a top-level `const`, `let` or `class` isn't visible to other scripts — only top-level `function` declarations and `globalThis` properties are shared, where ES2020 scripts share one global lexical scope — and a `.js` GMScript's top-level code auto-runs at startup; share via `globalThis.Name`. (The hoisting FAILURE past ~200 top-level functions is [#15564].)
- Scripts' top-level code runs in the project's RESOURCE order — the `gems.yyp` list, which gm-cli keeps sorted by name case-INSENSITIVELY (`sceneColony` before `SceneTransition`) — so a top-level cross-script reference throws `ReferenceError: X is not defined` at startup unless the script it names sorts earlier. Register from top level only into a global whose script name is a PREFIX of every registrant's (`Scene.register` from the `scene*` scripts); anything else registers from `create()`. Not filing — the order is the project's, and upstream calls it undefined by design (#7852).
- `Math.random()` draws from GML's global generator stream — `random_set_seed(k)` fixes its output, and every call shifts each following `irandom`/`random` draw; `uuid()`'s unpredictability rests on the boot `randomize()`. Keep reproducible data on `hash2` (no shared stream) and never pin the global seed while other consumers draw. (Adjacent trap: `randomize(k)` silently discards `k` — the seeding call is `random_set_seed(k)`.) Not filing — ES2020 leaves the algorithm implementation-defined.
- the GML keywords `noone`, `all` and `self` are NOT in JS scope (`typeof` → `"undefined"`; `other`, `global` and ordinary constants like `c_white`/`vk_f5` resolve, and GML reads all of them), so the idiomatic `r === noone` throws `ReferenceError: noone is not defined`. A missing instance comes back as the number `-4`: test such a result with `instance_exists(r)`, and probe anything uncertain through `typeof`. Worth filing — #15254 shows the same error from an unreduced sample; #10904 is a different failure.
- the `GM_*` build constants — `GM_runtime_version`, `GM_version`, `GM_build_date`, `GM_build_type` — are not in JS scope (`typeof` → `"undefined"`, a bare read throws `ReferenceError`), so a run cannot self-report its runtime and the build cache's `runtimes-gmrt/<version>` stays the truth (Overview). Not filing — unlisted in the JS surface rather than broken; probe through `typeof` if a later runtime lands them.
- JS `Date` is UTC-pinned and second-granular — `getTimezoneOffset()` is `0`, the local getters read UTC, and `Date.now()`/`getTime()` zero the milliseconds; `toISOString()` is well-formed, but the other string forms drop a digit (`01:46:4 GMT+000`) and `toLocaleString` misdates, so format from `toISOString` or the GML side. Local wall clock lives on the GML side (`current_*`, `date_current_datetime()` + `date_get_*`), sub-second stamps on `current_time`. (`date_datetime_string` is unusable regardless — mojibake on a non-ASCII locale, the GMS2 defect #10785 fixed that never reached GMRT.) Worth filing.
- [#15296] an asset ref reflects as an empty object (`typeof` `"object"`, `is_struct` true, `Object.keys` `[]`) — a generic deep copy silently turns a stored handle into `{}` — and GML's own reflection on GMRT agrees (`typeof` `"struct"`, `is_handle` false) where GMS2 and the manual answer `"ref"`/true. Discriminate plain data by `v.constructor === Object` (a ref's is `undefined`), pass refs through by reference, and asset-validate with GM functions (`sprite_exists`/`asset_get_type`), never `is_handle`. Likewise documented: `asset_get_index` returns a handle, not a number.
- A layer-element handle — a tile map's id from `layer_tilemap_create` — reaches JS opaque: `typeof` `[[unknown]]`, never `===`-equal even to itself, a field read (`h.eid`) throws `unhandled type (14) for JS_ToObject` and string concatenation `… for JS_ToPrimitive`, while every built-in takes it back intact (`tilemap_set`, a `move_and_collide` target array). A collision list that may carry a tile map is told apart with `instance_exists` before any field is read, and a handle prints through GML `string()`. Worth filing.
- A GML pointer value is NEVER `===`-equal in JS, not even to itself (`h === h` → `false`) — an identity scan over stored pointers, sound for asset refs and JS objects ([#15567]), silently matches nothing; an emptiness check (`h !== undefined`) still discriminates. Test a pointer only through its owning API predicate (`dbg_view_exists`, `surface_exists`, …). Worth filing — GML's `==` on the same values is true.
- A `static` field initializer can't reference its own class — `static x = ClassName.y` throws (at load, for a top-level class) and `static x = this.y` silently reads a wrong value (`undefined`, or `0` inside a function); only a literal is safe. Use a static method, or assign `Foo.x = …` after the class body; referencing another already-loaded class is fine. Not filing — static class fields are ES2022, outside GMRT's ES2020 target.
