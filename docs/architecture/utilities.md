## `EntityPreset`

`EntityPreset` spawns entities from named presets — the **declarative side of entity construction** (component data + size + a `post` hook for the wiring data can't express), with variant inheritance. `register([defs])`, `spawn(id, world, x, y, z, opts)` (`opts: { size?, components? }`), `has`/`get`. The contracts:

- A def is `{ id, extends?, scale?, components, post? }` — `components` authored at scale 1 (`Visual.xscale/yscale` are DERIVED, never authored); `post(world, id, ctx)` is the irreducible code hook (e.g. `CombatAI.attach`).
- **`scale` vs `size` — two separate knobs**: the def's `scale` is the archetype's basic factor (per-preset tuning), `opts.size` (a spawn descriptor's `size?`) is the per-spawn scalar for special entities (boss/alpha variants). Both fold into one factor `k = scale × size` that bakes **BBox + Visual + Mesh uniformly** (`_bakeMesh` multiplies the mesh's scale fields + analytic-box dims), so a sized entity's look never diverges from its collider.
- **`extends`** resolves at **register time** (base must register first; unknown base throws): per-component **field** merge — the variant's fields win, new components add; `scale`/`post` inherit unless overridden. Per-spawn `opts.components` merges the same way.
- **Every spawn deep-copies its component data** (instances never share nested arrays/objects like `Inventory.slots`) via a GMRT-safe clone: a GM asset ref also reports `typeof "object"` but its `constructor !== Object`, so refs/scalars/functions pass through **by reference** — a stored sprite handle survives (the asset-ref reflection idiom, GMRT.md §4).
- **The size/art bake**: spawn normalizes a lean authored `Visual` — `Visual.scale` = design size (`scale × size`), `xscale/yscale = scale / SpriteMeta.density(sprite)`, and the `BBox` multiplies by the same design factor. Art resolution never touches the collision footprint.

## `Query` — Spatial Entity Lookup

`Query` searches entities with `Position`: `nearest`/`farthest` (→ id or -1), `inRect`/`inRadius` (→ id[]), with `opts: { has?, maxDist?, hasCollision? }`. `has` filters by **component-token presence**, not a tag string — markers like `NPC`/`Portal`/`Raider` are components queried directly.

## Utility Modules

- **`Settings`**: persists to `settings.json`. `registerDefaults({...})` before `load()` at startup (calls merge additively); `get(key)` falls back to defaults; `save()` writes only keys present in defaults.
- **`Rand`** (Core/Util): deterministic hashing + PRNG over Park–Miller MINSTD integer-float math — the **one home** for the idiom (GMRT miscompiles xorshift chains, GMRT.md §2). Two families: **position hashes**, pure in `(x, y, seed)` — `int2`/`hash2`, `seed2`, `noise2(x, y, seed, lattice)` (smoothstep value noise; fold a salt into `seed` for an independent channel) — the substrate for anything that must regenerate identically; and **streams** — `lcg(seed)` → closure, or `step`/`norm` for a hot loop keeping state in a field (no per-reseed allocation). The GML `random_*` built-ins are no substitute for worldgen (all documented behaviour): one global stream, `random_get_seed()` returns the last seed SET (not the advanced position), and time-seeded `randomize()` can return the same seed twice in one frame — fine for one-shot gameplay randomness only.
- **`SpriteMeta`** (Core/Util): the per-sprite **metadata** registry — the semantic layer a `GMSprite` doesn't carry. A def is JSON-safe `{ sprite: "spr_name", kind, density?, cell?, variants?, anchors? }`: `kind` is descriptive only (consumers read specific **fields**, never switch on kind); **`density`** (source px per world px, default 1) is **declared, never inferred** — a 32px cell can mean a denser subject OR a taller one, only the art's author knows — and divides the **draw scale** only, never the BBox; `variants` are the tilesets' per-mask weighted frame tables (`RenderTileMap` dual mode); `anchors` are named per-frame attachment points as origin-relative source-px offsets (read via `anchor(sprite, name, frame)` — the substrate for anchored `Appearance` layers, i.e. the held-weapon icon at `handR`). Declarations are **emitted by the pixel-art-kit importers** as `datafiles/spritemeta/*.json` manifests (generated alongside the art, so they can't drift from it), loaded at boot by `SpriteMeta.load()`; hand-authored sprites get hand entries via `register(defs)`. `fit(scale, sprite)` → `scale / density`, the final draw scale for a design scale — the split of the two meanings `Visual.xscale` used to conflate. Defs are keyed by **name** (string Map — safe); the ref lookup is **parallel arrays + `===` identity scan** — a Map keyed by a sprite ref crashes GMRT natively (GMRT.md #15567). Consumers: `EntityPreset.spawn`, `RpgPlayer.spawn`, `AnimationSystem` (refit on sheet swap); the sizing model is rpg.md → _Paper-doll appearance_.
- **`I18n`**: `I18n.load(manifestPath)` reads a locale's `manifest.json` (text-file masks, fonts, images, sounds); flat `{ key: value }` text JSON merges into `I18n.texts`. `I18n.text(key, ...params)`, `I18n.textRef(...)` (a `() => string` for live-updating labels), `I18n.font(key)`. Fonts are keyed by **role**, not size (`default`/`header`/`description`); an undeclared key falls back to `draw_get_font()`. A locale switch `font_delete()`s every old handle — **never cache a font handle across frames**; widgets resolve `I18n.font(key)` at draw time (`resolveUIFont`). Bundled locales: `en-US` (default) + `ko-KR`, each declaring its own SDF Noto Sans.
- **`Camera`** / **`CameraFollow`** / **`CameraPan`**: `Camera` wraps a `camera_*` handle; the namespace objects are factories — `CameraFollow.create` (3D perspective follow), `CameraFollow.create2d` (2D orthographic, pixel-snapped; `pitch` tilts for 2.5D, and the optional **`pitchCurve`** `(zoom) => pitch°` re-derives it from the live zoom each update — it overwrites `pitchDeg`, so the Debug pitch slider hand-tunes only while the panel's "Pitch by zoom" is unchecked), `CameraPan.create` (drag-to-pan + wheel-zoom — the editor). Call `.update()` each step and `.assign(viewIndex)`. **The follow target resolves by LIVE query**: an entity carrying the **`CameraFocus`** marker component (flat `{}`, presence is the signal) wins over the raw `followTarget` id each update — the camera never dangles a stored id; a portal transfer re-mints the player's id, but the marker rides the `EntitySnapshot` and the resumed map's camera finds it again (`followTarget` stays the raw-id fallback for worlds without the marker — the platformer). **Read the view rect from the instance's own fields** (`toX`/`toY`/`width`/`height`), not `camera_get_view_*` — the project drives the view by matrix, so those return 0; an ORTHO `create2d` camera is centered on `(toX,toY)` spanning `width×height` world px (why the view-culling passes read the fields).
- **`Tween`**: static easing + frame-rate-independent smoothing for UI motion (pure methods; callers keep their own state). Two families: `approach`/`approachColor` (exponential smoothing toward a **moving** target, no fixed duration — hover/press easing) and the easing curves (`easeOutCubic`/…) mapping `t∈[0,1]` for **timed** motion.
- **`MotionPlanner`**: static A\* on `MotionPlanningGrid`. `plan(start, goal, algorithm?, opt?)` → `{x,y}[]`; options `allowDiag`, `cornerCutting`, `heuristicWeight`, `maxIter`.
- **`Raycast`**: static segment-vs-AABB cast over collider entities. `cast(...)` → nearest hit `{ id, x, y, nx, ny, t }` or `null`; `castAll(...)` → **all** solid hits ascending by `t` (the multi-hit form hitscan pierce walks). `opts: { ignore?, solidOnly? (default true), mask? }`. Shared by `ProjectileSystem`, `Combat.hitscan`, and line-of-sight queries.
- **`File`**: sync I/O. Text: `find(mask)`, `read(fname)` (NUL-terminates the loaded buffer so `buffer_text` can't over-read past EOF into uninitialized memory — an over-read corrupts `JSON.parse` non-deterministically), `write(fname, data)`. Binary: `readBuffer` (caller owns the buffer, must `buffer_delete`) / `writeBuffer` (saves only the _used_ bytes, so a `buffer_grow` over-allocation doesn't pad the file). **Use the binary path for tile grids / dense data** — JSON text both hard-faults on nested values and serializes big inline arrays at O(n²). Async binary: `saveAsync`/`loadAsync` wrap `buffer_*_async` — the completion arrives in `obj_game`'s Async Save/Load event, which calls `File._resolve(id, status)` to fire the callback on the main thread. ⚠️ On GMRT 0.20 the async path silently no-ops on desktop (`buffer_save*` fails to create the forced `default/` subdirectory yet still reports `status:true` — [#15223](https://github.com/YoYoGames/GameMaker-Bugs/issues/15223)); use sync `writeBuffer`/`readBuffer` on desktop, keep async for console (vendors require it for cert; the event-routing plumbing is verified good, and the two async calls round-trip with each other since they share the `default/` prefix).
- **`Json`** (Core/Util): ref-safe, nesting-safe, CYCLE-safe JSON codec — the disk-serialization substrate. Native JSON can't round-trip live game data on GMRT: `JSON.stringify` faults on nested values (so `encode` hand-walks containers, calling native stringify only on scalar leaves) and an asset ref serializes to `{}` (so a sprite handle is tagged `{"$spr": name}` and revived via `asset_get_index`). `encode` does DFS cycle detection via a path-array `===` scan (an object-keyed Set/Map crashes GMRT) plus a step cap, so a cyclic export can never OOM the runner; `decode` is native `JSON.parse` (only stringify faults) + tag revival. Consumers: `SaveGame` + any structured blob outgrowing `SaveData`'s flat model.
- **`Snapshot`** (Core/Util): the save/load FRAME — the persistence analogue of `Renderer`:`RenderPass`. An ordered list of `{ id, capture(ctx), restore(ctx) }` passes, each owning one slice of world state; **the same pass captures AND restores**, so the two directions can't drift. The bundle is hybrid by design — structured/variable data into a JSON `manifest` (`ctx.manifest`), dense data into named binary blobs (`ctx.putBlob`/`getBlob`). Engine-generic; the RPG's concrete passes + slot layout live in `SaveGame` (rpg.md → _Save/Load_).
- **`Log`**: text-based behavior verification (there are no tests). `Log.info/warn/error/debug` buffer timestamped lines; `obj_game` flushes once per frame (rewrites `game.log` only when dirty) — read `game.log` to confirm runtime behavior. `Log.exception` is the registered unhandled-exception handler: an uncaught fault is written as `UNHANDLED EXCEPTION: <message>` and flushed before the runner closes. GMRT populates only `ex.message` for JS faults (`script`/`line`/`stacktrace` come through empty).
- **`Utils`**: global helper grab-bag — `noop()`, `uuid()` → UUID v4, `rem(value)` → pixel size relative to current font size.
