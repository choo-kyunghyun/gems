# G.E.M.S. Architecture — EntityPreset, Query & Utility Modules

Area reference split out of the always-loaded core ([ARCHITECTURE.md](../ARCHITECTURE.md) — the layer map, cross-cutting invariants, and reference index). Loaded on demand: **Read this file before designing or modifying anything in this area.** Cross-references to sections of other areas resolve via the core index; runtime quirks live in [GMRT.md](../GMRT.md).

## `EntityPreset`

`EntityPreset` (`scripts/EntityPreset/`) spawns entities from named presets — the **declarative side of entity construction** (component data + size + a `post` hook for the wiring data can't express), with **variant inheritance**:

```js
EntityPreset.register([
  {
    id: "raider",
    scale: 1.7, // BASIC design factor — scales the BBox, Visual, and Mesh (see below)
    components: {
      BBox: { x: -8, y: -8, width: 16, height: 16 }, // world units at scale 1
      Visual: { sprite: spr_human, color: c_white }, // xscale/yscale are DERIVED, never authored
      Health: { hp: 3 },
      Inventory: { slots: [], capacity: 8 },
    },
    post(world, id, ctx) {
      CombatAI.attach(world, id, ctx.opts.level);
    }, // irreducible code
  },
  { id: "boss_raider", extends: "raider", components: { Health: { hp: 12 } } },
]);
// `size` is the dedicated per-spawn SCALAR for special entities (bosses/alpha mobs)
const id = EntityPreset.spawn("boss_raider", world, x, y, z, { size: 1.5 }); // opts: { size?, components? }
EntityPreset.has("raider");
EntityPreset.get("raider");
```

- **`scale` vs `size`** — two separate knobs: the def's `scale` is the archetype's **basic factor** (per-preset tuning; a `Mesh`'s own `scale`/`xscale`/`yscale`/`zscale` stay the authored per-axis base), while `opts.size` (a spawn descriptor's `size?`) is the **per-spawn scalar** for special entities — an Alpha Rat or boss. Both fold into one factor `k = scale × size` that bakes **BBox + Visual + Mesh uniformly** (`_bakeMesh` multiplies the mesh's scale fields + analytic-box dims), so a sized entity's look never diverges from its collider.
- **`extends`** resolves at **register time** (base must register first; unknown base throws): per-component **field** merge, the variant's fields win, new components add; `scale`/`post` inherit unless overridden. Per-spawn `opts.components` merges the same way (e.g. a descriptor's `{ Health: { hp } }`).
- **Every spawn deep-copies its component data** (instances never share nested arrays/objects like `Inventory.slots`) via a GMRT-safe clone: a GM **asset ref** also reports `typeof "object"` but its `constructor !== Object` (probed on 0.20), so refs/scalars/functions pass through **by reference** — a stored sprite handle survives.
- **The size/art bake**: `Visual` is authored lean (`sprite`/`color` + optional overrides) and spawn normalizes it — `Visual.scale` = design size (`scale × size`), `xscale/yscale = scale / SpriteMeta.density(sprite)` (see _Utility Modules → SpriteMeta_), and the `BBox` multiplies by the same factor. Art resolution never touches the collision footprint.

## `Query` — Spatial Entity Lookup

`Query` (`scripts/Query/`) searches entities with `Position`:

```js
Query.nearest(world, x, y, opts); // → id or -1
Query.farthest(world, x, y, opts); // → id or -1
Query.inRect(world, x1, y1, x2, y2, opts); // → id[]
Query.inRadius(world, x, y, radius, opts); // → id[]
```

`opts`: `{ has?, maxDist?, hasCollision? }`. `has` filters to entities carrying that component (its token) — presence, not a tag string (the `Tag` component was removed; markers like `NPC`/`Portal`/`Follower`/`Raider`/`Rat` are queried directly).

## Utility Modules

- **`Settings`**: persists to `settings.json` (`Settings.PATH`). `registerDefaults({...})` before `load()` at startup (calls merge additively). `get(key)` falls back to defaults; `set(key, val)` updates memory; `save()` writes only keys present in defaults.
- **`Color`**: `Color.rgb(r,g,b)`, `Color.hsv(h,s,v)`, `Color.merge(c1,c2,t)`, `Color.parse("#rrggbb")` → GameMaker color ints; `Color.alpha(color)` → alpha byte `[0,1]`.
- **`Rand`** (`scripts/Rand/`, Core/Util): deterministic hashing + PRNG over Park–Miller MINSTD integer-float math — the **one home** for the idiom (GMRT miscompiles xorshift chains; see GMRT-Safe Idioms → PRNG). Two families: **position hashes**, pure in `(x, y, seed)` — `int2`/`hash2` (int / `[0,1)` float), `seed2` (→ LCG seed), `noise2(x, y, seed, lattice)` (smoothstep value noise; fold a salt into `seed` for an independent channel) — the substrate for anything that must regenerate identically; and **streams** — `lcg(seed)` → `() => [0,1)` closure, or `step`/`norm` for a hot loop keeping state in a field instead of allocating a closure per reseed (`RenderCloudShadow` reseeds per cloud cell per frame). Consumers: `TerrainField` (noise), `OverworldGen` (per-chunk stream), `TerrainStream` (tile-variant pick), `RenderCloudShadow`. The GML `random_*` built-ins work but are no substitute here: one global stream, `random_get_seed()` returns the last seed SET — not the advanced stream position (the manual's workflow is capture-at-area-START; mid-stream capture/restore was never promised) — and time-seeded `randomize()` can return the same seed twice in one frame (both documented GameMaker behaviour, identical on GMS2 — don't file). Fine for one-shot gameplay randomness; worldgen needs `Rand`'s pure position hashing + per-chunk streams.
- **`SpriteMeta`** (`scripts/SpriteMeta/`, Core/Util): per-sprite **metadata** registry — the semantic layer a `GMSprite` doesn't carry (frames/trim/origin only). A def is JSON-manifest-safe data `{ sprite: "spr_name", kind, density?, cell?, variants?, anchors? }`: `kind` (`"entity"`/`"overlay"`/`"tileset"`/`"atlas"` — descriptive; consumers read specific **fields**, never switch on kind), `density` (source px per world px, default 1 — **declared, never inferred**: a 32px cell can mean a denser subject OR a taller one, only the art's author knows; divides the **draw scale** only, never the BBox), `cell` (`[w, h]` frame size, doc/validation), `variants` (tilesets: per-mask weighted frame tables `{ "15": [[frame, weight], …] }` — `TerrainStream` picks per cell by deterministic hash, see Renderer → `"dual"`), `anchors` (`{ name: [[dx, dy], …] }` — named per-frame **attachment points** as origin-relative source-px offsets, emitted by `human_sprites.py` from the segmented parts; read via `anchor(sprite, name, frame)` — the substrate for anchored `Appearance` layers, i.e. the held-weapon icon at `handR`). Declarations are **emitted by the pixel-art-kit importers** as `datafiles/spritemeta/*.json` manifests (generated alongside the art, so they can't drift from it — `human_sprites.py` emits `human.json`, `terrain_sprites.py` `terrain.json`; each included file is registered in `gems.yyp` once, re-runs only rewrite content), loaded at boot by `SpriteMeta.load()` (obj_game `Create_0`); hand-authored sprites get hand entries via `register(defs)`. API: `of(refOrName)` → def or undefined; `density(sprite)` → declared or 1; `fit(scale, sprite)` → `scale / density`, the final draw scale for a **design** scale — the split of the two meanings `Visual.xscale` used to conflate (design size `Visual.scale` also scales the `BBox`; density never touches it), so a hi-detail sheet lands at the same world size. Defs are keyed by **name** (string Map — safe) and resolved to refs at registration; the ref lookup is **parallel arrays + `===` identity scan** — a `Map` keyed by a sprite ref crashes GMRT natively at `.get` (see GMRT.md). Consumers: `EntityPreset.spawn` (the bake), `RpgPlayer.spawn`, `AnimationSystem` (refit on sheet swap). Supersedes `ArtDensity` (density is one field of the def). See _Gameplay / RPG Layer → Paper-doll appearance_ for the sizing model.
- **`I18n`**: `I18n.load(manifestPath)` reads a `manifest.json` listing text-file masks (e.g. `text/*.json`), fonts, images, sounds; flat `{ key: value }` text JSON is merged into `I18n.texts`. `I18n.text(key, ...params)` or `I18n.textRef(...)` (a `() => string` for live-updating UI labels); fonts via `I18n.font(key)`. Ships `en-US` (default, loaded in `obj_game` `Create_0`) and `ko-KR`, each declaring its own Noto Sans in its `manifest.json` (en-US `Noto Sans`, Latin-1 range; ko-KR `Noto Sans KR`; both SIL OFL 1.1, SDF). Strings are split by genre under each locale's `text/`: `common`, `platformer`, `rpg`, `rts`, `map` (the `text/*.json` mask merges them all). Fonts are keyed by role, not size: `default` (Regular 12), `header` (Bold 16), `description` (Regular 10). Both locales declare all three, so `I18n.font(...)` resolves to the bundled Noto Sans (an undeclared key still falls back to `draw_get_font()`). A locale switch (`I18n.load`) `font_delete()`s every old handle — never cache a font handle across frames; UI widgets resolve `I18n.font(key)` at draw time (see ui.md).
- **`Camera`** / **`CameraFollow`** / **`CameraPan`**: `Camera` wraps a `camera_*` handle (ORTHO, PERSPECTIVE, PERSPECTIVE*FOV). `CameraFollow` and `CameraPan` are namespace objects of factory methods (PascalCase, like `CameraFly`): `CameraFollow.create({ world, followTarget, followLerp?, followHeight?, ... })` — 3D perspective follow; `CameraFollow.create2d({ world, followTarget, followLerp?, width?, height?, pitch?, pitchCurve?, ... })` — 2D orthographic (pixel-snapped; `pitch` tilts for 2.5D, and the optional **`pitchCurve`** `(zoom) => pitch°` re-derives it from the live zoom each update — the RPG's upright-sprite camera wires `RpgMap._pitchCurve`, 42° zoomed out → 58° in; the curve overwrites `pitchDeg`, so the Debug pitch slider hand-tunes only when the Camera panel's "Pitch by zoom" is unchecked); `CameraPan.create({ ... })` — drag-to-pan + wheel-zoom orthographic camera (the level editor). All read from `world` where relevant. Call `.update()` each step and `.assign(viewIndex)` to attach to a viewport. **The follow target resolves by LIVE query**: an entity carrying the Core **`CameraFocus`** marker component (`scripts/CameraFocus/` — flat `{}`, presence is the signal; `RpgPlayer.spawn` attaches it) wins over the raw `followTarget` id each update, so the camera never dangles a stored entity id — a portal transfer re-mints the player's id, but the marker rides the `EntitySnapshot` into the new world and the resumed map's camera just finds it again (`followTarget` remains the raw-id fallback for worlds without the marker — the platformer). Note: hold the `Camera` instance and read the view rect from its own fields (`toX`/`toY`/`width`/`height`), **not** `camera_get_view_*` — the project drives the view by matrix, so those return 0 (`view_camera[]` indexing itself works fine on both runtimes — 2026-07 re-audit). An ORTHO `create2d` camera is centered on `(toX,toY)` spanning `width×height` world px; the view-culling passes (`RenderLighting`/`RenderWeather`/`RenderDebugTileMap`/`RenderGrid`) read the fields for this reason.
- **`Audio`** (`scripts/Audio/`, Core): the project's **sound wrapper** — a thin static-singleton facade over GameMaker's `audio_*` API (one audio space, like `ParticleFx`), playing the hand-authored 2026-07 media `GMSound` set (`snd_*`; the `mus_ambient_*` loops live in the `bgm` audio group — see `tools/audio-kit/GEMS.md`). Three play paths: `play(name, opts)` non-positional 2D cue (UI/global), **`playAt(name, x, y, opts)` SPATIAL** (`audio_play_sound_at` — attenuated + panned relative to the listener), and `bgm(name, opts)` looping music cross-faded on `Time.raw` (re-requesting the playing track is a no-op; `update()` reaps the finished fade, `stopBgm()` ends it). Spatial needs a **listener + distance model**, both owned here: `setup()` (obj_game `Create_0`) selects `audio_falloff_linear_distance_clamped` (the default is `audio_falloff_none` = no attenuation), fixes the 2D listener **orientation** once (`audio_listener_orientation(0,0,1, 0,-1,0)` → only `x` drives L/R pan, y maps to front/back — right for a top-down view), **loads the `bgm`/`sfx` audio groups** (the `mus_*`/`snd_*` assets live in those non-default GMAudioGroups, which must be `audio_group_load`'d before playback), and applies the saved `Settings` `volMaster`/`volMusic`/`volSfx` — **category volume is the audio-GROUP gain** (`setMusicGain`/`setSfxGain` → `audio_group_set_gain(bgm/sfx)`, `setMasterGain` → `audio_master_gain`), so it scales every playing sound in the group live, including the BGM, with no per-sound bookkeeping; the **SystemMenu** volume sliders call these setters in their `onChange` (Settings-bound; the Save button persists). **`listener(x, y)`** (the RPG scene, each frame, from `camera.toX/toY`) moves the ears. Falloff window is the 32px world's (`REF`/`MAX`/`FACTOR` = full volume within 96px, silent past 800px; override per `playAt`). Wiring mirrors `ParticleFx`: `setup` in `Create_0`, `update` in `Step_0`, `reset` (stop BGM + all SFX) in `LevelManager._apply`'s destroying path only — **not** across a guest keep-switch or an RPG map change, so music carries over. State is read-write static fields + plain methods (house style — the old GMRT static-getter bug was dismissed). **Wired into the Demo** at Demo-layer chokepoints (the genre-agnostic kit systems stay silent): the RPG plays a **per-map ambient** — `mus_ambient_tense` open world / `mus_ambient_cozy` on `meta.indoor` maps, requested by `RpgMap._applyBgm` on every arrival (build + resume + guest-return via `sceneRpg.resume`; a same-track re-request is a no-op, `scene._indoor` rides the park bundle) — with spatial SFX — `snd_gun_fire` (`PlayerSystem._fireGun`; `snd_gun_uncocked` dry-click, edge-gated on the fire press since fire is held-polled), `snd_hitsound_metal`/`snd_hitsound_flesh`/`snd_hitsound_armor` (impact, in `RpgScene._diffHp` beside the floating-number push — a mesh-bodied target (turret) rings metal (`trackDamage` adds a `Health`+`Mesh` query so built structures are tracked), else ally "armor" / enemy "flesh", the death-blow deferred to the death pass), `snd_explosion_small` (`resolveHealth.onKill`), `snd_coin` (`sceneRpg._onCollect` — ground pickups AND corpse-loot takes), and the per-consumable cue in `RpgInventoryUI` (`snd_drink` thirst/hunger, `snd_bandage` heal, `snd_magic` buffs/attr grants); the Platformer plays `mus_ambient_danger` with non-positional `snd_jump` (`PlatformerController.update`), `snd_hitsound_flesh` (stomp), `snd_hitsound_armor` (`PlatformerController.respawn` — covers touch/spike/void). **Core UI cues** (non-positional): `snd_button_click` on activation — `UIButton`'s mouse click + `UINav`'s confirm dispatch (one place, covering every focusable widget on the gamepad/keyboard path) — and `snd_button_muted` on a `UINav` focus change (press-edged input, so one cue per move). Reserved spares: `snd_explosion_large` (grenade/mine) + `mus_ambient_emergency` (raid event) — see ROADMAP; the old gap remains — a mouse click on a non-button widget is silent (covered for gamepad/keyboard via `UINav`).
- **`Tween`**: static easing + frame-rate-independent smoothing helper for UI motion (pure methods; callers keep their own state). Two families: `approach`/`approachColor` (exponential smoothing toward a _moving_ target, no fixed duration — UIButton's hover/press easing) and the easing _curves_ (`easeOutCubic`/`easeInOutQuad`/…) mapping `t∈[0,1]` for _timed_ 0→1 motion (Toast/modal enter, FloatingText pop).
- **`MotionPlanner`**: static A\* on `MotionPlanningGrid`. `MotionPlanner.plan(start, goal, algorithm?, opt?)` → `{x,y}[]`. Options: `allowDiag`, `cornerCutting`, `heuristicWeight`, `maxIter`.
- **`AABB`**: world-space box geometry that owns the non-uniform `BBox`-anchor convention (see Component Pattern note). `AABB.edges(pos, box)` / `AABB.of(world, id)` → `{ x1, y1, x2, y2, cx, cy }`; `AABB.overlap(a, b)` → strict overlap (touching edges don't count). Every collision/geometry system derives edges through this, never inline `pos.x + box.x` — consumers: `SolidSystem`, `SeparationSystem`, `TriggerSystem`, `BlockSystem`, `EnemySystem`, `Raycast`, `RenderDebugEntity`. (`Query` is _not_ a consumer — it does point-vs-rect tests on `Position` only.)
- **`Broadphase`** (`scripts/Broadphase/`): Uniform-grid broadphase for O(n) physics pair queries. `new Broadphase(worldWidth, worldHeight, cellSize)` — `cellSize` must exceed entity full diameter so center-based bucketing guarantees all overlapping pairs are in adjacent cells. `clear()`, `insert(id, cx, cy)`, `pairs(fn)` (calls `fn(a, b)` per candidate pair, no duplicates). Assign to `world.broadphase` to opt `SeparationSystem` and `TriggerSystem` into the broadphase path; scenes without it fall back to O(n²). Apply selectively — crowded scenes (many slimes/units) benefit; scenes with few interacting bodies (platformer) don't need it. Currently no scene sets it — the RPG's `SeparationSystem` runs O(n²) over its handful of dynamic bodies, which is cheap; wire a `Broadphase` onto `world.broadphase` if slime counts grow.
- **`Raycast`**: static segment-vs-AABB cast over all collider entities. `Raycast.cast(world, x0, y0, x1, y1, opts)` → nearest hit `{ id, x, y, nx, ny, t }` or `null`; `Raycast.castAll(...)` → **all** solid hits along the segment, ascending by `t` (the multi-hit form for hitscan pierce walks). `opts`: `{ ignore?, solidOnly? (default true), mask? }`. Shared by `ProjectileSystem` (bullets), `Combat.hitscan` (gun/turret shots), and line-of-sight queries.
- **`File`**: sync I/O. Text: `File.find(mask)` → `string[]`, `File.read(fname)` → `string|undefined` (NUL-terminates the loaded buffer so `buffer_text` can't over-read past EOF into uninitialized memory — that over-read corrupts `JSON.parse` non-deterministically, the bug that long looked like a runtime memory fault), `File.write(fname, data)` → `boolean`. Binary: `File.readBuffer(fname)` → buffer handle (caller owns it, must `buffer_delete`) or `undefined`, `File.writeBuffer(fname, buffer)` → `boolean` (saves only the _used_ bytes via `buffer_save_ext` + `buffer_get_used_size`, so a `buffer_grow` buffer's over-allocation doesn't pad the file). Use the binary path for tile grids / dense or large data — JSON text both hard-faults on nested values and has an O(n²) serialize cost for big inline arrays. Async binary: `File.saveAsync(fname, buffer, cb?)` / `File.loadAsync(fname, cb)` wrap `buffer_save_async`/`buffer_load_async` — they return a request id, register it, and the completion arrives in `obj_game`'s **Async Save/Load event** (`Other_72`), which calls `File._resolve(id, status)` to fire the callback on the main thread (`saveAsync` → `cb(ok)`; `loadAsync` → `cb(buffer)` on success, caller then owns it, or `cb(undefined)` on failure). For streaming a huge save without freezing the frame, and the form console vendors (Xbox/PS/Switch) **require** to pass cert. ⚠️ **GMRT 0.20**: a known open runtime bug — GMRT's `buffer_save`/`buffer_save_ext` (and these async variants) fail to create the destination directory ([#15223](https://github.com/YoYoGames/GameMaker-Bugs/issues/15223)) — trips on the forced `default/` subfolder, so on desktop GMRT the write silently no-ops while `buffer_save_async` still reports `status:true` (false positive). Use the sync `writeBuffer`/`readBuffer` on desktop (root-level files need no new directory, so they're unaffected); the async path is for console and should work once #15223 is fixed. The event-routing plumbing (event → `_resolve` → callback) is verified good. (Both `saveAsync`/`loadAsync` round-trip with **each other** — they share the `default/` prefix, unlike the sync readers.)
- **`Json`** (`scripts/Json/`, Core/Util): ref-safe, nesting-safe, CYCLE-safe JSON codec — the disk-serialization substrate for save games. Native JSON can't round-trip live game data on GMRT: `JSON.stringify` faults on a nested value (so `encode` hand-walks containers, calling native stringify only on scalar leaves) and an asset ref serializes to `{}` (so a sprite handle is tagged `{"$spr": name}` and revived via `asset_get_index`). `encode` does DFS cycle detection via a path-array `===` scan (an object-keyed Set/Map crashes GMRT — see GMRT.md) plus a step cap, so a cyclic `ecs.export()` can never OOM the runner. `decode` uses native `JSON.parse` (parse handles nesting; only stringify faults) then revives the tags. `Json.encode`/`Json.decode`; consumers: `SaveGame` + any structured blob outgrowing `SaveData`'s flat model.
- **`Snapshot`** (`scripts/Snapshot/`, Core/Util): the save/load FRAME — the persistence analogue of `Renderer`:`RenderPass` / `ChunkGenerator`:gen-pass. An ordered list of `{ id, capture(ctx), restore(ctx) }` PASSES, each owning one slice of world state; the same pass captures AND restores it, so the two directions can't drift. The bundle is HYBRID by design — passes write structured/variable data (the per-map component set differs by level) into a JSON `manifest` (`ctx.manifest`), and dense data into named binary blobs (`ctx.putBlob`/`getBlob`). Engine-generic (no game specifics); `insert`/`remove` mirror `Renderer`. The RPG's concrete passes + slot/disk layout live in `SaveGame` (Demo, see rpg.md → _Save/Load_).
- **`Log`**: text-based behavior verification (there are no tests). `Log.info/warn/error/debug(msg)` buffer timestamped lines; `obj_game` calls `Log.clear()` at startup and `Log.flush()` once per frame (only rewrites `game.log` when dirty). Read `game.log` to confirm runtime behavior without watching the window. `Log.exception(ex)` is the unhandled-exception handler `obj_game` registers via `exception_unhandled_handler` in `Create_0` — an uncaught runtime fault is written to `game.log` (`UNHANDLED EXCEPTION: <message>`) and flushed before the runner closes the game (it returns a non-zero exit code). Without it a mid-frame crash just stops the log at its last flush with no reason recorded. GMRT populates only `ex.message` for JS runtime faults (`script`/`line`/`stacktrace` come through empty), so only the message is logged.
- **`Debug`** (`scripts/Debug/`, Core): the **back-end** of the debug system — a registry of named panels that does **not** render, so a human and an agent debug the same state through different front-ends. `Debug.panel(name, (p) => …)` populates a panel via emit closures: `p.watch(label, fn)` / `p.watch(label, obj, key)` / `p.slider` / `p.checkbox` / `p.dropdown` / `p.input` (editable scalar) / `p.button` / `p.text`. Each entry is a **live binding** — a getter fn (read-only) or an `(obj, key)` pair (read/write live); the discriminator is whether a `key` arg was passed, **not** `typeof` (a class like `Time` is itself a function, so `typeof`-routing would mis-bind and later call `Time()` — a crash). Two front-ends: (1) **text** — `Debug.update()` (in `Step_0`) periodically writes `Debug.snapshot()` to **`debug.txt`** (the agent-readable view); (2) **ImGui** — `DebugImGui` (Core), the human overlay (toggle **F3**) via `show_debug_overlay` + `dbg_view`/`dbg_*` + `ref_create`. Since `ref_create` needs a `(struct, "field")` pair but an entry is often a getter fn, each gets a plain **mirror** `{ v }`; `refresh()` syncs it each frame (pull for read-only, change-detected push for editable, so an external write like the pause `Time.scale=0` isn't clobbered by a stale slider). Agent control: `Debug.set(panel, label, value)` / `Debug.press(panel, label)` from a temp harness, then verify on the game surface. Built-in panels `Time`/`Perf`/`Log`/`Sim` (the relocated sim controls — Pause / Step Frame / Restart Scene) + **`DebugRender`**'s `Render` (per-pass overlay toggles, each finding the live scene's pass by `instanceof` and flipping `enabled`) register in `obj_game` `Create_0`; Core lists only Core passes — a genre layer contributes its own via `DebugRender.add(cls, label)` (deduped by class, so repeated scene builds are no-ops), keeping Core decoupled. `DebugImGui` rebuilds on a `Debug.version()` change into **two windows** kept independent so one's churn doesn't move the other: a stable **Debug** view (Time/Perf) and a live **Inspector** view (the `Entity` panel), the latter kept alive across picks (only its `dbg_section` is swapped — there's no `dbg_set_view` on GMRT). Each panel is an explicit `dbg_section` (else GM bleeds the first control onto an auto "Default" header).
- **`DebugInspector`** (`scripts/DebugInspector/`, Core): the ECS entity inspector over `Debug`. While the overlay is open, left-clicking a world entity (`Query.nearest` from a cursor→world unproject via the scene camera's `toX/toY/width/height`) selects it; `select(world, id)` reads `world.componentsOf(id)` and registers an **`Entity`** panel exposing every component's scalar fields — numbers/strings as editable `input`s, booleans as `checkbox`es — bound LIVE to the component data objects, so an edit (in the overlay, or `Debug.set("Entity", "Health.hp", …)`) mutates the real entity. `draw(game)` highlights the selection on the GUI layer (reprojecting its `Position`). The Entity panel stays **registered at all times** (a placeholder line when nothing is selected) so its Inspector window is present from the moment the overlay opens, like Time/Perf; Deselect or a stale selection (entity removed / scene swapped) empties it to the placeholder rather than removing it. Wired in `Step_0` (`update`) + `Draw_75` (`draw`). While the overlay is open, `InputAction._debugMuted` mutes gameplay **mouse** input (so a pick-click can't fire the weapon) and **keyboard** input only while `is_keyboard_used_debug_overlay()` (typing in a `dbg_text_input`), so WASD still roams while inspecting.
- **Utils** (`scripts/Utils/`): global helper grab-bag — `noop()`, `uuid()` → UUID v4, `rem(value)` → pixel size relative to current font size.
