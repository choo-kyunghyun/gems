## Gameplay / RPG Layer

The **RPG** scene (`sceneRpg`) is the action-RPG (the platformer is a movement showcase with no RPG layer). The pieces below split across two pillars — the genre-agnostic modules in the **`Gameplay` kit** (`Combat`/`Items`/`Inventory`/`Equipment`/`Animation`/`Lighting`/`Quest`/`Crafting`/`Squad`/`NPC`/`Status`/`Survival`/`Trade`; see _Gameplay Kit_), and the content/model-specific glue in **`Demo`** (`Stats`, all `Rpg*`, `CombatAI`, the `WorldClock`/`Weather`/`Temperature` world-sim, build mode) — and are driven explicitly from the scene's `step()`, never auto-run by `World`. The design constraint throughout is **composition over inheritance** (GMRT can't do `super`/subclassing): "kinds of item" are a flat `Item` carrying a `components: []` array of standalone capability/marker classes queried by `instanceof` — exactly the `UIElement.getComponent` pattern.

**Items & registry.** `Item` (`scripts/Item/`) is a definition registry (`Item.register([...])`, `Item.get(id)`), like `Rarity`. A definition is identity + universal scalars (`name` i18n key, `sprite`, `stack`, `weight`, `value`, `rarity`) plus `components` — capability/marker instances attached via `addComponent` and read via `getComponent(Class)`/`hasComponent(Class)`. **Definition vs instance** (`item.isInstanced()` → has `Equippable`): a _fungible_ item (potions/materials/currency) is a shared definition with stacking `qty`; an _instance_ (all equippable gear) is unique — an `Inventory` slot of `{ itemId, qty:1, uid, mods }` (a gun instance also carries `ammo`/`rounds`) carrying **per-instance state inline** (a minted `uid` + a named-slot **attachment map** `mods` — plus, for a gun, the loaded `ammo` itemId + magazine `rounds`), so two `wood_sword`s can differ and `Equipment`/drops/etc. reference the specific one by `uid` (see _Inventory & equipment_):

- `Equippable` (`{ slot, mods, worn? }`) — wearable in an `Equipment` slot (`weapon`/`armor`/`trinket`/`backpack`); `mods` are flat `Stats` deltas folded onto the wearer's attribute-derived base by `StatModel.recompute` while worn. `worn` (a sprite NAME, default `""` = invisible) is the item's paper-doll overlay sheet, shown on the wearer while equipped (see _Paper-doll appearance_).
- `Weapon` (`{ slots, fireCd?, damage?, reach? }`) — the **universal** weapon profile that **fully drives the action** (the controller hardcodes no built-in attack): the named, typed attachment **`slots`** (`[{ id, accepts }]`, the unified slot model — `accepts` is an attachment category or `"*"`), the melee numbers (`damage`/`reach`), and the shared cadence `fireCd`. **Melee vs gun is decided by a sibling `Gun` component, NOT a flag** — an item that also carries `Gun` (`item.hasComponent(Gun)`) is ammo-driven ranged (`composeWeapon`'s gun branch); else it's melee (`MeleeSystem` swings a `reach`-px hitbox in the facing dir). The **`PlayerSystem`** reads the equipped profile (or, when unarmed, a weak melee **fist** fallback — the pre-composed shared profile `PLAYER_FIST`, so being unarmed never fires a free bullet) and runs whatever it describes. The player spawns with a `wood_sword` (melee; slots `edge`/`pommel`) equipped (`sceneRpg.create`).
- `Gun` (`{ caliber, magazine, ops }`) — presence ⇒ the weapon is an **ammo-driven gun**. It fires the **loaded `Ammo`'s base stats** run through an OPERATOR pipeline: ammo base → the gun-base `ops` layer → each installed attachment's `ops` (`EquipmentSystem.composeWeapon`/`_applyOps`: `final = (base + Σadd)·Πmul` per field). `caliber` gates which `Ammo` chambers; `magazine` is the base clip. The composed **power is kinetic** — `power = ammoPower + KIN_K·mass·(velocity/KIN_REF)²` (fast/heavy rounds hit harder) **+ the wielder's `Stats.attack`**; the round's **`penetration`** rides the shot and lowers target defense at the hit. Ammo is **consumed** per shot from the magazine; **R** (or auto-on-empty) reloads from the bag (`EquipmentSystem.reload`/`loadAmmo`, + the `*Slot` variants the panel uses) — a gun with **no ammo type chosen yet** (fresh from craft/purchase) auto-loads the first caliber-compatible ammo in the bag on R or on fire (`reloadSlot` → `_firstAmmo`), so firing a new gun never needs the Toolkit panel (deliberate type _switching_ stays there). The HUD shows `rounds/magazine`. (`KIN_K`/`KIN_REF` are tunable constants on `EquipmentSystem`.)
- `Ammo` (`{ caliber, mass, velocity, power, penetration }`) — a fungible round; its four stats are the BASE of a gun's firing pipeline (mass + velocity → kinetic power; `penetration` vs defense). `velocity` also scales the hitscan **reach** (the shot is instant — no travel time). Three demo rounds — `ammo_light` (fast/low-pen), `ammo_heavy` (slow/punchy), `ammo_ap` (armor-piercing), all `caliber:"standard"`.
- `WeaponMod` (`{ slot, ops, stat }`) — marks a (fungible) `Item` as an installable **attachment**. `slot` is the category it fits (matched vs a weapon slot's `accepts`); `ops` are per-field **operators** (`{ field: { add?, mul? } }`) over the composed profile (gun: velocity/mass/power/penetration/fireCd/magazine; melee: damage/reach/fireCd); `stat` deltas fold into the wearer's derived `Stats` (`StatModel._foldInstanceMods`). A weapon instance's `mods` is a **map** `{ slotId → attachmentItemId }`; installed/removed into a matching named slot at a **workbench with the Toolkit module slotted** (the `WeaponModUI` panel). The consumed item _is_ the definition (no parallel registry); an op on a field the weapon doesn't expose is inert. Demo set: gun attachments `mod_scope`/`mod_long_barrel`/`mod_extended_mag`/`mod_grip`/`mod_suppressor`, melee `mod_sharp` (edge) / `mod_heavy` (pommel).
- `WorkbenchModule` (`{ kind }`) — marks a (fungible) `Item` as a **workbench upgrade** slotted into a bench's single module slot (`Interaction.module`). Rather than a station per category, one bench is upgraded by swapping modules (removable freely). `kind:"recipes"` (default) unlocks the recipes that declare `requires: <this itemId>` (base recipes — no `requires` — are always available); `kind:"weaponmod"` (the **Toolkit**) switches the bench window into the weapon-mod panel. The four demo modules (`forge`/`alembic`/`hearth`/`toolkit`) are crafted at the **bare** bench, so the bench bootstraps its own upgrades. See _Genre UI managers → CraftingUI_.
- `Consumable` (`{ heal }`) — usable from the bag (one unit consumed for an instant effect).
- `Container` (`{ capacity }`) — while equipped, grows the wearer's `Inventory.capacity` (e.g. a backpack pairs `Equippable` + `Container`).

`Rarity` (`scripts/Rarity/`) is a parallel registry of tiers (`{ id, name, color, valueMod }`); rarity color drives loot/inventory tinting. **`Manufacturer`** (`scripts/Manufacturer/`, Gameplay/Items) is the parallel registry of in-world companies (`{ id, name, lore, color, ops? }`) an item references via the def field `maker` (default `""` = unbranded, like `rarity`): a maker's optional **`ops`** is its signature weapon layer (same operator shape as `WeaponMod.ops`), folded by `composeWeapon`'s `_modLayers` on top of the authored base for every weapon that maker makes — so brand identity is mechanical, not just cosmetic. Shown in the Settings-gated inventory **Maker** column (`invColMaker`, brand-colored) and as a brand-colored line in the `WeaponModUI` weapon detail. The demo companies (`RPG_MAKERS` in `RpgItems`, colony-era lore): **Aeon Dynamics** (fast/precise, softer hits), **Vekt Heavy Industries** (slow/punchy, small clips), **Helios Terraforming Authority** (survival gear, no ops) — with a curated branded set (`aeon_pistol`/`vekt_pistol`/`aeon_cutter`/`vekt_wrench`/`helios_vest`/`helios_trauma_kit`/`helios_ration`/`aeon_rounds`) sold by the hub merchants. **`RpgContent`** (`scripts/RpgContent/`, Demo) registers **all** shared RPG content — the rarity tiers, the **full item set** (consumables, weapons `wood_sword` (melee) + `blaster` (ammo-driven **gun**), the **`Ammo`** rounds (`ammo_light`/`ammo_heavy`/`ammo_ap`), armor/trinket/backpack, currency `coin`/`gem`/`key`, crafting materials, the `mod_*` **`WeaponMod`** attachment items, the `forge`/`alembic`/`hearth`/`toolkit` **`WorkbenchModule`** items), and the workbench recipes (base + per-module, gated by `Recipe.requires` — the Forge module crafts the gun, ammo, and attachments). The RPG scene's own content is **`RpgQuests`** (its quests) and **`RpgAchievements`** (its achievement defs + the trigger rules — see below). `sceneRpg` calls `RpgContent.register()` once from `create()` (via `RpgQuests.register()`, which calls it first; `RpgAchievements.register()` follows), **not** at top level, to dodge GMRT load-order issues.

**Achievements (push model).** The **`Achievement`** engine (`scripts/Achievement/`, Demo) is a registry (`{ id, name, desc }` — pure data, **no conditions**) + unlock persistence (comma-joined ids via `SaveData`). It never evaluates or sweeps: an outside **trigger** requests `Achievement.unlock(id)`, and the engine checks the request (registered? still locked?), persists, and returns whether it was newly unlocked. The demo's triggers live in **`RpgAchievements`** (Demo/Content): declarative threshold `RULES` per lifetime counter (`enemiesKilled`/`itemsCollected`/`questsCompleted`); a gameplay chokepoint that bumps a `Profile` counter calls `sceneRpg._reportAchievements(key)` → `RpgAchievements.report(key, value)` → unlock requests, and toasts the newly-unlocked. Debug: an RPG-scoped **`Achievements`** Debug-overlay panel (unlocked count + **Unlock All** / **Clear All** via `Achievement.unlockAll()`/`clear()`), registered in `sceneRpg.create()` and removed in `destroy()`.

**Inventory & equipment (pure systems over components).** Components are string tokens; their systems take the component (or `world` + entity id) directly, with no world tick:

- `Inventory` = `{ slots: [{ itemId, qty }], capacity, maxWeight? }` (an _instance_ slot adds `uid` + `mods`; see the definition-vs-instance split above) — every player, enemy (its loot table), and storage chest owns one. `InventorySystem` (`add`/`remove`/`has`/`weight`) stacks fungibles per `Item.stack`; an **instanced** item never stacks — `add` mints one slot per unit with a fresh `uid` + an empty `mods` **map** (a gun's `ammo`/`rounds` are added lazily by the firing path), `addSlot` re-inserts a pre-existing instance preserving its `uid`/`mods` (transfer/drop), and `findByUid`/`removeByUid` reach a specific one. `sort` keeps instance slots individual (only fungible stacks merge). `add` is gated first by `maxWeight` then by `capacity`, returning the amount that did **not** fit.
- `Equipment` = `{ slots: { weapon, armor, trinket, backpack } }` of **instance `uid` strings** (the equipped item is unique — two of one itemId may differ by mods, so an itemId can't say "which one"; flat → `world.export`-safe). `EquipmentSystem.equip(world,id,uid)` (or `equipFirst(...,itemId)` for the itemId-keyed entry points — the starting-gear seed + the hotbar) keeps the item in the `Inventory` (it still counts toward capacity/weight) and **re-derives the wearer's `Stats` from source** via `StatModel.recompute` (which folds every equipped instance's `Equippable.mods` **+ installed `WeaponMod.stat`** onto the attribute base — so there's no +/- delta to keep balanced; a re-derive can't drift). A `Container.capacity` bonus stays a direct `Inventory.capacity` delta. `EquipmentSystem.weaponSlot`/`weaponProfile` resolve the equipped weapon `uid` → instance slot and return a **fresh composed profile** via `composeWeapon` (a melee weapon's damage/reach numbers, or a gun's ammo-driven kinetic profile + clip), or `null` when unarmed → `PlayerSystem` falls back to `PLAYER_FIST`.
- `ConsumableSystem.use` applies a `Consumable`'s effect and removes one unit; it refuses to waste an item that would do nothing (e.g. healing at full HP). A `Consumable` carries three independent effects: `heal` (HP, clamped to `Stats.maxHp`), a **permanent attribute grant** `{ attr, amount }` (the `*_shard` items) applied through the **injected `ConsumableSystem.grantAttr` hook**, and a **status grant** `status` (a `Status` id, e.g. the Tonic→`regen` / Elixir→`fortify` items) applied via `StatusSystem.apply` — kit default no-ops, the Demo wires the `Attributes`+`StatModel.recompute` policy in `sceneRpg.create` (the same injection idiom as `Combat.mitigate`, keeping the `Gameplay/Items` kit free of the Demo stat model). An optional **`yields`** item id is left behind after use (best-effort add — the soda's empty can).
- `Encumbrance` (`{ threshold, minScale }`) + `EncumbranceSystem.scale(world, id)` → a speed multiplier from carried weight. The **penalty is delivered through the Buff/Status system**, not by the mover directly: `EncumbranceSystem.update` maintains an `"encumbered"` status (`StatusSystem.maintain`) whose live `{ speed }` mult is this gradient, and the mover reads `StatusSystem.scale(world, id, "speed")` — so encumbrance composes with any other speed status and shows in the HUD. This module still owns the weight→penalty mechanic (the gradient + the on/off decision); only how the slow reaches the entity moved to the status layer. See _Buffs & statuses_ below.

**Combat & stats.** `Health` = `{ hp }`; `Stats` = the session-scoped character sheet — `maxHp`/`attack`/`defense`/`speed`/`maxStamina`, all **derived from `Attributes`** (see _Attributes & derivation_ below). There is **no `level`/`xp`**: the RPG is deliberately **item- + skill-driven, not playtime-driven** — permanent power comes from equipment and attribute-granting consumables, never an XP grind. `MeleeSystem.swing(world, attackerId, dirX, dirY, reach, damage)` resolves a melee hit immediately (no projectile): an AABB hitbox extends `reach` in the facing **direction** (snapped to the dominant axis → 4-way) and damages every body with `Health` **except the attacker** and its faction allies (the slimes — player excluded; NPCs/furniture carry no `Health`), returning the struck ids. Ranged attacks (player guns + turrets) are **instant hitscan** via **`Combat.hitscan(world, x0, y0, x1, y1, { owner, damage, penetration?, pierce? })`** (`Gameplay/Combat`): it casts the shot with **`Raycast.castAll`** and walks every solid body along the ray in order — each hostile `Health` takes `damage` (with the round's `penetration`, default 0), the shot **passing through up to `pierce` of them** (default 1 = single target; a future sniper sets it higher) until a wall or a `FactionSystem`-allied body **blocks** it (an ally just eats the shot like a wall) — and returns the impact endpoint (for a tracer) + the struck ids. (The travel-time `Projectile`/`ProjectileSystem` path is **retained** in the kit for lobbed/grenade projectiles — it's simply no longer how guns fire; it despawned its bullet on first impact too, so hitscan with `pierce:1` is behaviorally identical.) All three paths land damage through the shared **`Combat.applyDamage(world, target, amount, penetration?)`** (`Gameplay/Combat`): the kit applier subtracts hp after an **injected `Combat.mitigate(world, target, amount, penetration)`** (default identity; `sceneRpg.create` sets it to `max(1, amount − max(0, defense − penetration))`), so defense, armor penetration, and a min-1 floor apply uniformly while the kit stays stat-agnostic — the _attack_ side (`weaponPower + attacker.Stats.attack`) is composed by the callers (`PlayerSystem` for the player, `CombatAI._attackPower` for a monster, whose weapon part is 0; melee/turret callers pass penetration 0). **Every combatant carries a `Stats` sheet** (slime/turret/follower, not just the player), so damage is genuinely stat-driven for all actors. The paths only **SUBTRACT** hp — the reaction at ≤ 0 hp is decided centrally by the `Mortal` death pass (see _Death_ below). `Combat.hitscan` lives in the `Gameplay/Combat` kit (not Core) because it needs `Health`/`Faction`; both `PlayerSystem` (the player) and `CombatAI` (turrets) call it (the retained `ProjectileSystem` lives there for the same reason). **`CombatAI`** (Demo) is the one AI for every non-player combatant — `CombatAI.register()` (called by `RpgContent.register`) registers the named states **`combat.idle`/`combat.chase`/`combat.attack`** into the `StateSystem` pool (separate entries transitioned by NAME, not a hardcoded bundle — the seam for preset-composed state sets), and `CombatAI.attach(world, id, level, opt?)` seeds `State { next: "combat.idle" }` plus a flat `Brain` whose `mobile` + `ranged` flags pick the behavior: a **slime** is `mobile` melee (the default) — a dynamic solid body `SolidSystem` integrates + collides for free; a **turret** is `{ mobile:false, ranged:true }` — an immovable, player-faction actor that stands and fires a hitscan shot, replacing the old per-kind `SlimeAI` + `Turret`/`TurretSystem`. The `Brain` holds `home`/`aggro`/`deAggro`/`attackRange`/`bulletSpeed` + a `pathCd` replan throttle (damage is the actor's `Stats.attack`, not on the `Brain`); targets are the nearest hostile by faction. **Chase is line-of-sight-first** — a clear shot is a straight seek; a wall between slime and player triggers an A\* detour over the `NavGrid` (see _Pathfinding Flow_).

**Attributes & derivation.** The derived combat `Stats` are computed from a data-driven primary-attribute layer (Demo, like `CombatAI` — the kit reads only the derived `Stats`, via `Combat`'s injected `mitigate`). **`Attributes`** (`scripts/Attributes/`) is a flat `{ key: number }` bag (opt-in: the player carries one, monsters author `Stats` directly); **`StatModel`** (`scripts/StatModel/`) is the swappable model — `ATTRS` (this RPG's lean set: `POW`→attack, `VIT`→maxHp (+ a little defense), `AGI`→speed, `END`→maxStamina, each with a default) + `derive(attrs)` (the rules, tuned so the defaults reproduce the legacy sheet `10/1/0/220/100`) + `recompute(world, id)`. **`recompute` is recompute-from-source**: derived `Stats` = `derive(attrs)` + Σ equipped `Equippable.mods` + Σ active status `mods` (`_foldStatuses` — buffs like `fortify`), rebuilt from scratch each call (so it can't drift); a no-op without `Attributes`, it clamps `Health`/`Stamina` to the new maxima. It runs on `RpgPlayer.spawn`, on equip/unequip (`EquipmentSystem`), and on an **attribute change** — which, with leveling removed, comes from **attribute-granting consumables** (the `*_shard` items: `power`/`vitality`/`agility`/`endurance`, one per `ATTRS` key, each `+1` forever via `Consumable { attr, amount }`). Using one runs the kit's `ConsumableSystem.use` → its **injected `grantAttr` hook** (set in `sceneRpg.create`, mirroring `Combat.mitigate` — the kit can't reach the Demo stat model) → raise the bag key + `recompute`. Shards are obtained by **crafting** (workbench recipes, gem + a material) and **quest reward** (the ruins quest), so growth is gated on gathering/exploring, not playtime. `Attributes` ride the carried sheet across a map change (`RpgMap.go`), so a re-derive on the new map uses the grown attributes (without this, shard gains would silently reset). **Swapping the model** (to D&D-6, SPECIAL, …) is a `StatModel`-only edit — rewrite `ATTRS` + `derive`; combat, equipment, and save/migration all read the derived `Stats`. The inventory **Stats** tab lists the attributes (data-driven from `ATTRS`).

**Buffs & statuses.** The **`Status`** module (`Gameplay/Status`) is the generic buff/debuff layer — a swap-in for poison/regen/slow/haste/fortify/encumbrance, stat-model-agnostic like the rest of the kit. Three pieces: **`Status`** (`scripts/Status/`) is the def registry (`Status.register([...])`/`get`/`all`, like `Item`/`Rarity`); **`StatusEffects`** (`scripts/StatusEffects/`) is the per-entity component holding the active list (`{ id, remaining, accum, mult? }` — flat, `world.export`/`EntitySnapshot`-safe); **`StatusSystem`** (`scripts/StatusSystem/`) runs them. A def carries up to **three effect kinds**, each routed the idiomatic way: **`dot`/`hot`** (HP per second, applied every `interval` by `StatusSystem.update` straight to `Health` — DoT bypasses `Combat.mitigate`, the `≤0` reaction stays the `Mortal` pass; floating numbers come free from `RpgScene.trackDamage`); **`mult`** (live multiplicative factors read at point of use via `StatusSystem.scale(world, id, key)` — the mover reads `"speed"`, so encumbrance/slow/haste compose by multiplication, never folded into the sheet); and **`mods`** (flat additive `Stats` deltas folded into the derived sheet by `StatModel._foldStatuses`, mirroring `_foldEquipment`). The `mods` path needs a re-derive on apply/expire, so it goes through the **injected `StatusSystem.onStatsChanged` hook** (kit default no-op; `sceneRpg.create` wires `StatModel.recompute`, exactly like `Combat.mitigate`/`ConsumableSystem.grantAttr`) — keeping the kit free of the Demo stat model. API: `apply(world, id, statusId, opts?)` (timed — `opts.duration` overrides the def; refresh keeps the longer remaining, no magnitude stacking yet), `remove`, `maintain(world, id, statusId, mult|null)` (a LIVE-driven permanent status whose per-instance `mult` a driver refreshes each tick — the encumbrance path; carries no `mods`, so no re-derive), `has`/`list` (the HUD reads `list`), `scale`, and the per-tick `update`. Content is **`RpgStatuses`** (Demo, registered by `RpgContent.register`): `encumbered` (maintained debuff, live speed mult from `EncumbranceSystem`), `regen` (HoT buff — the Tonic consumable), `fortify` (timed `mods` +attack/+defense buff — the Elixir consumable). `sceneRpg.step` ticks `StatusSystem.update` then `EncumbranceSystem.update` at the top of the tick loop (before the mover reads `scale`); the HUD card lists active statuses tinted by each def's `color` (rich-text `[c=#hex]` spans, read live). A DoT debuff (poison) is the symmetric counterpart of `regen` — one def + an applier away.

**Survival needs.** The **`Survival`** module (`Gameplay/Survival`) is the needs layer — `Thirst`, `Hunger`, `Drowsiness`, each a **"rising meter"** component `{ value, max, rate, critical, status }`: `value` climbs by `rate`/sec (0 = fine, `max` = critical). Each has its own thin system (`ThirstSystem`/`HungerSystem`/`DrowsinessSystem`) over a shared **`Survival`** core: `Survival.tick(world, token)` raises + clamps the meter and, at `value/max >= critical`, **applies the named debuff `Status`** (`StatusSystem.apply`/`remove` — reusing the Buff/Status kit, so the consequence shows in the HUD), while `Survival.restore(comp, amount)` lowers it (returning whether it changed, so a no-op drink/food is refused). Opt-in like `Stamina`/`Encumbrance` (only the player carries them — `RpgPlayer.spawn`), and — like `Stamina` — they ride the carried sheet across a map change (`RpgMap.go`'s capture list), so a need doesn't reset or diverge per map. Restores: a **`Consumable`** with `thirst`/`hunger` (the Water Bottle / Bread / Cooked Meat — `ConsumableSystem` routes them to `ThirstSystem`/`HungerSystem.restore`); Drowsiness is restored by **sleeping**. Demo content (`RpgStatuses`): `dehydrated`/`starving` (a `dot`) + `drowsy` (a speed `mult`). `sceneRpg.step` ticks the three systems in the tick loop (after `StatusSystem`/`EncumbranceSystem`). **Sleep (bed):** a built **`bed`** carries an `Interaction` kind `"bed"`; the `"bed"` `InteractAction` routes its E to `sceneRpg._sleep`, which sets `_sleeping` → `step()` **ramps** `Time.scale` multiplicatively on `Time.raw` (wall clock — `Time.delta` is itself scaled) up to the `RPG_SLEEP_SCALE_MAX` ceiling (reached in `ln(max)/RPG_SLEEP_ACCEL` wall-seconds; `WorldClock`/`Weather` run at the full scale while the tick-bound sim caps at `World.sim.maxTicks`) and drains `Drowsiness` each tick (`DrowsinessSystem.restore` instead of `update`); **hitting the ceiling is the `td_time_skip` achievement trigger** (once per sleep session — `_sleepPeaked` guards, `sleepFastForwards` counter → `RpgAchievements` rule); any key/click wakes (`_wakeInput`, checked before the tick loop) and restores `Time.scale = 1`. So sleeping skips time + restores rest but **costs water/food** (those needs keep rising while fast-forwarded). The HUD shows the three needs as **reserve bars** (`1 - value/max`).

**Death (`Mortal` / `Downed`).** What happens when an entity's `Health` hits 0 is **configured per spawn preset** by an opt-in **`Mortal`** component (`scripts/Mortal/`, `Gameplay/Combat`), resolved in one place — `RpgScene.resolveHealth` (the instant reaction) + `RpgScene.updateDowned` (the down-timer) — so the damage systems just subtract hp and a body with `Health` but **no** `Mortal` (e.g. a built turret, removed by `BuildMode.reapDestroyed`) is left alone. Kinds: **`corpse`** (the mobs — raiders/rats) leaves a **lootable body**: `RpgScene._toCorpse` strips the combatant **in place** (detaches `Health`/`Stats`/`Brain`/`State`/`Velocity`/`PrevPosition`/`Faction`/`Animator`, makes the collider non-solid, dims + flattens the `Visual`) and tags it **`Interaction { kind: "corpse" }`**, so E opens the standard `StorageUI` transfer window over the body's own `Inventory` — takes report pickup credit (quest/achievement `collect`) via the per-open **`scene._storeOnTake`** hook the `"corpse"` `InteractAction` sets (a plain chest never sets it, so withdrawing can't farm collect quests; `StorageUI.close` clears it). `RpgScene.reapCorpses` (tick loop) removes a corpse once its `Inventory` empties — a lootless kill reaps the same tick, i.e. the old despawn; because the corpse is the **same entity**, chunk demote/unload snapshots it like any resident, and the scene's `onKill` detaches the `Raider`/`Rat` species marker so the radar stops blipping the body. **`despawn`** spills the entity's `Inventory` as ground drops then removes it (no live preset uses it now; the kit path remains); **`respawn`** (player) refills to `Stats.maxHp` and repositions; **`down`** (companions) incapacitates — it **detaches `Health`** (so `FactionSystem.nearestHostile` stops targeting it and the death scan skips it), zeroes velocity, dims the sprite, and attaches **`Downed { timer }`** (`scripts/Downed/`); after `Mortal.recoverSecs` of sim time `updateDowned` re-adds `Health` (`reviveHp`), un-dims, and teleports it to the recovery spot — `sceneRpg._recoverSpot()` = the claimed build zone centroid, else the map spawn. The scene injects the side effects as handlers (`onKill` (fired for `despawn` + `corpse`, before the body transform)/`onRespawn`/`onDown`/`downSpot`/`onRecover` — quest/profile counters, the player respawn reset, down/recover toasts). `FollowerSystem` holds a `Downed` companion still; the inventory Squad tab shows its **Down (recovering)** status and disables Kick; the carry bonus is untouched (it tracks `Follower.state`, which a down→recover cycle doesn't change). A downed companion round-trips a map change via `EntitySnapshot` (it carries `Downed`, not `Health`) and recovers in the new map.

**Loot, progression & dialogue.** `ItemDrop` = `{ itemId, qty }` on a non-solid sensor entity the player collects on overlap; enemy deaths leave a **lootable corpse** over their `Inventory` (the `corpse` `Mortal` kind — see _Death_; the `despawn` kind's drop-spill path remains for kit consumers). `QuestLog` (`scripts/QuestLog/`) holds quest defs + active progress (objectives `{ kind: "kill"|"collect"|"reach", target, count }`, **item-only rewards** `{ items? }` — there's no XP, so a quest grants items, e.g. the ruins quest gives a `vitality_shard`); `RpgProgression.applyReward` is the single apply path (adds the items to the bag). The scene calls `QuestLog.report(kind, target)` after gameplay events and turns in on NPC interaction. `NPC` = `{ name, lines, questId? }` — the scene proximity-checks the player and opens a dialogue panel that can offer/turn in the linked quest. `Animator`/`AnimationSystem` are a data-driven sprite state machine: `Animator` holds a `graph` of named `AnimState`s (`{ sprite, start?, frames, fps, loop }`); the controller picks `state`, `AnimationSystem.update` advances playback into the entity's `Visual` (clamps `frames ≥ 1` for the SVG-sprite quirk). `start` offsets the state into a **shared strip** (`vis.subimg = start + frame`) — how the unified humanoid sheet packs walk + attack into one sprite (see _Paper-doll appearance_).

**Paper-doll appearance (`Appearance` / `AppearanceSystem`).** Humanoids are one **unified, tintable body sprite** with worn gear drawn as **overlay layers**, not a baked sprite per outfit. Three pieces: **`spr_human`** is the canonical humanoid strip — since 2026-07-11 a **hand-drawn Aseprite sheet** (source `tools/pixel-art-kit/templates/human/sheet.png` + `sheet.json` — edit/re-export THOSE and re-run the importer; the sprite folder is importer-owned): 11 foot-anchored **32×32** frames of a white Rayman-style figure in **2-color art** (white fill + dark outline), tagged **idle 0 / walk 1–2 / fist 3–5 / kick 6–10**, with head/torso/hands/feet kept as **disconnected floating blobs** — no longer because animation is generated (it's hand-animated now), but because `human_sprites.py` **segments each frame's parts to cut the worn/held overlays from them** (two big blobs = head above torso; the four limbs split into hand/foot pairs by blob SIZE, learned from the neutral frame — so a kicking foot swung above a hand can't be misread; the importer fails fast if a redraw breaks the 6-blob contract). The white fill is **tinted per entity via `Visual.color` = the skin tone** (`RpgPlayer.SKIN`, a literal GM color int — a top-level `Color.parse` would race script load order); the outline stays dark under the multiply. The graph is defined once in `RpgPlayer.animGraph()` (offset-based `AnimState.start` over the one strip, mirroring the Aseprite tags — `attack` = the fist frames, plus a `kick` state the player's **unarmed** fist-fallback swing alternates with the punch (`PlayerSystem` latches `Playable.attackAnim` per swing; armed melee and gun-fire always play the punch thrust, so a held weapon rides the hand)). **`Appearance`** (`scripts/Appearance/`, Core/Component — Core because `RenderBillboard` reads it) is the layer stack `{ back: [{sprite,color}], front: [...] }`: `RenderBillboard` draws `back` layers, the body (`Visual`), then `front` layers, all at the **same subimg** — but **coplanar depth equality cannot be relied on**: GameMaker auto-trims sprites on the texture page, so each sheet's quad has different vertices and the interpolated depth diverges by float rounding under the depth-writing billboard pass — a later layer _randomly_ loses `cmpfunc_lessequal` (raiders bald under their bandanas; repacking the texture page reshuffles who loses). So each layer is **Y-biased** by draw order (`BB_LAYER_DY` = 0.05 world px per step — front layers toward the south-side camera at +y, back layers away at −y), which is decisive in the depth buffer yet invisible on screen; `sh_meshlit`'s texel cutout (`u_alphaRef`) keeps transparent texels from writing depth. (It must be **Y, not Z**: an upright sprite's quad is a constant-y vertical plane, so a z offset slides the layer _within_ the plane with zero depth separation — the original z-bias worked only for the pre-2026-07-05 reclined billboards, and the bald-raider z-fight returned the day sprites went upright.) Overlay layers keep their **own** color — the body's `Visual.color` is the skin tint and must not bleed into outfit colors; whole-doll effects (the downed dim) ride `Visual.alpha`, which layers share. **`AppearanceSystem`** (`scripts/AppearanceSystem/`, Gameplay/Equipment) rebuilds the stack **derived-from-source** like `StatModel.recompute`: it walks `Equipment` slots (order policy: `backpack` → back; `armor`/`trinket`/`weapon` → front) and pushes each worn item's `Equippable.worn` sprite (resolved via `asset_get_index` + `sprite_exists`). Rebuild runs at the same chokepoints as the stat re-derive — `EquipmentSystem.equip`/`unequip`, plus after the carried sheet lands via `EntitySnapshot.apply` in `RpgMap.go`/`resume` (Equipment arrives there outside `equip()`); `Appearance` itself is never serialized. **The invariant: every overlay sheet mirrors `spr_human`'s strip layout** (frame count/order, cell, foot anchor) — so overlays are **derived by `human_sprites.py` from the hand-drawn frames themselves** (each frame segmented, garments cut from the parts in place — never freehand) and can't desync. Reference overlay: the armored vest (`worn: "spr_wear_vest"` — the torso recolored below a 1-row neckline, outline preserved). **Held weapons are NOT sheets** (the generated `spr_held_pipe`/`spr_held_blaster` were deregistered 2026-07-11): a weapon `Equippable` with no `worn` falls back to the item's **own icon drawn ANCHORED at the right hand** — the importer emits each part's per-frame centroid into the manifest as `anchors` (origin-relative offsets), `AppearanceSystem` pushes an anchored front layer `{ sprite: item.sprite, anchor: "handR", scale: HELD_SCALE }`, and `RenderBillboard._drawLayer`'s anchored branch draws the icon (subimg 0, half scale, signed-xscale mirrored) at that frame's hand point — so **every weapon gets a held visual with zero dedicated art**, and the hand's own motion carries the thrust/kick. A weapon wanting bespoke posed art can still set `worn` (the `weapon` slot stays last in `FRONT_SLOTS`). Item **icons** auto-wire by the `spr_item_<id>` naming convention with a shared-icon fallback (`RpgItems.ICONS` alias table — many-to-one entries only, e.g. one serum icon for all four shards; `sprite_exists`-guarded) — an unmatched id keeps the UI's colored-box fallback. **The raider is a doll too**: its spawn uses `spr_human` with a deterministic skin pick (`RpgSpawn.SKINS`, hashed from the spawn cell so a regenerated chunk keeps the same face) plus an **authored** bandit outfit (`spr_wear_red_bandana`/`black_shirt`/`black_sneakers` — an `Appearance` with **no** `Equipment`, which `AppearanceSystem.rebuild` deliberately leaves alone: only equipment-carrying dolls are derived/cleared) and the shared graph. **`CombatAI` drives the doll**: `_animate` picks idle/walk/attack per state (a short punch window after each swing) and flips facing by velocity **sign** (magnitude-preserving), and the aggro cue is a **flush** — `Color.merge` from `Brain.baseColor` (captured at attach; the skin tint) toward the state color, `k = 0` restoring the base exactly — instead of the old from-white wash that would have wiped the skin. **Every humanoid is now a doll** — NPCs (elder/merchants/the traveling peddler, all via the `npc` preset) and companions (`spawnFollower`) get a hashed skin + the **tintable civilian outfit** (`RpgSpawn._outfit` — the near-WHITE `spr_wear_shirt`/`spr_wear_shoes` sheets colored per entity via the Appearance layer color; the npc descriptor's `color` sets the shirt, so the elder/Trader/Quartermaster read distinct in `overworld.json`, and a companion's `opt.color` ally-green became its shirt, not a whole-body wash). Static NPCs just hold the idle pose; `FollowerSystem` drives a companion's idle/walk + magnitude-preserving facing flip (same pattern as `CombatAI._animate`). Non-humanoids split: creatures (rat) and the fence keep the plain single-`Visual` path, while boxy props with a vox model (crate/chest/survey sign/survival stations/portal/workbench/bed/cot/barrel/torch/lantern/turret) and the wilderness rocks carry a **`Mesh`** instead of a `Visual` (see Renderer → `RenderMesh`); the legacy `spr_hero`/`spr_heroAttack`/`spr_raider` assets were deleted in the 2026-07 media overhaul. **Entity size is a baked per-preset DESIGN scale, art density divides the draw scale — with `size` the separate per-spawn scalar**: each `EntityPreset` def's `scale` is the archetype's BASIC factor (raider 1.7 / rat 1.4 / npc 1.6 / follower 1.5 at the 32px cell; a spawn descriptor's **`size?`** scalar multiplies on top — the dedicated knob for special mobs like an Alpha Rat/boss, baking BBox + Visual + **Mesh** uniformly so a sized entity's look never diverges from its collider) and `RPG_PLAYER_SCALE` (via `RpgPlayer.spawn`'s `opts.scale`) are the **design size**, baked at spawn into `Visual.scale` **and** the `BBox` — so the foot shadow (`RenderEntityShadow`, BBox-driven) and the paper-doll layers (drawn at the body's `xscale/yscale`) follow with no extra plumbing, and per-preset size variety is a per-def tune. The **draw scale** (`Visual.xscale/yscale`) is `scale / SpriteMeta.density(sprite)` (see _Utility Modules → SpriteMeta_): a sheet authored denser for detail declares its density (default 1 = today's baseline) and lands at the **same world size**, so swapping art of a different resolution changes nothing in-world and never touches the BBox. Bake sites are `EntityPreset.spawn` / `RpgPlayer.spawn`; `AnimationSystem` refits when a graph state swaps to a different sheet (so mixed-density graphs are legal — a `Visual` without `scale` is legacy raw and never refitted). Overlay sheets inherit the body's draw scale, which is correct because the strip-layout invariant above forces them to share the body's cell/density. Because `|xscale|` carries size, the facing flip must preserve magnitude (`vis.xscale = ±Math.abs(vis.xscale)` — `PlayerSystem`), never assign bare `±1`.

**Interactions (`Interaction` / `InteractAction`).** "Walk near an entity + press E to do something" is a two-piece, data-driven system (`Gameplay/Interaction` kit — see _Gameplay Kit → `Interaction`_). An entity carries an **`Interaction`** component `{ kind, ...params }` (`kind` names a registered action; the flat params are per-instance data an action reads, e.g. `{ kind: "buff", status: "regen" }`). The **`InteractAction`** registry holds the behaviors — `register([{ id, prompt, run(ctx) }])`, mirroring `Item`/`Status`/`Prefab`; `run(ctx)` (with `ctx = { scene, world, id, comp, playerId }`) does anything, so adding an interaction is a data entry, not an engine edit. The RPG registers its set in **`RpgInteractions`** (Demo, called by `RpgContent.register`): **window** actions open a UI + set `scene._interOpenId` so the engine range-closes/refreshes them (`storage`→`StorageUI`, `workbench`→`CraftingUI`); **instant** actions act once per E press (`claim`→`BuildMode.claim`, `arcade`→`_openArcade`, `bed`→`_sleep`, `door` — toggles the built door's `Collision.solid` + swings its slab, refusing to close over a standing body — and the survival trio `hydrate`/`feed`/`buff` that act on the **player** — `ThirstSystem`/`HungerSystem.restore`, `StatusSystem.apply`). The generic pick/prompt/dispatch **engine** is `Interactable` (Demo/UI): each frame `_pick` chooses one target `Interaction` (cursor-in-range, else nearest-in-range), the prompt pill reads the def's `prompt`, and E → `_open` looks up `InteractAction.get(comp.kind).run(ctx)` (no per-kind switch). E is arbitrated once by `sceneRpg._dispatchInteract` (station vs NPC). The survival trio is buildable (`BuildMode.CATALOG` **Survival** — vox-mesh props: tub/bin/alter) and authorable in the level editor (`RpgCatalog`'s Interaction field). Replaces the old Core `Station` component + hardcoded `_open`/`_promptText` switches.

**Genre UI managers** (in Core and Demo) — gameplay overlays that are not the GemsUI scene panels:

- `SystemMenu` — the app's **one menu**: a global, open-anytime, near-fullscreen multi-tabbed overlay. Built on a `UIModal` root sized from `display_get_gui_height()` at open (flexpanel can't resize after layout). It **pauses all game + behind-UI logic** while open: `LevelManager.step()` skips `scene.step()` whenever `SystemMenu.isOpen()`, the menu forces `Time.scale=0`/`Time.delta=0` each frame (UI runs on `Time.raw`), and the `UIModal` blocks pointer + nav beneath it. Tabs: **System** (just `Resume`/`Quit to Lobby` — the latter destroys every live level, including a guest's frozen host), **Settings** (the `Settings`-bound form with explicit Save), **About** (project/engine info, reuses `CREDITS_*`). API: `open(tabIndex=0)` (lobby Credits passes `2` → About) / `close()` / `isOpen()` (a method, not a `static get` — GMRT) / `scale()` / `reset()`. `obj_game` drives `SystemMenu.update(this)` in `Step_0` before `UINav.update` (receives the controller so the System tab reads/restarts/quits the live scene via the `LevelManager` interface — `game.scenes.current`/`.label()`/`.restart()`/`.switchTo()`); `LevelManager.step()` skips `scene.step()` while `isOpen()` (and, independently, while `scenes.paused` — the Debug pause — running one frame on `requestStep()`), and `LevelManager._apply` calls `SystemMenu.reset()` on each destroying scene swap. Entry points: lobby footer (Settings + Credits), `F1`, gameplay Start, gameplay Esc.
- `StorageUI` — storage-chest transfer window for the RPG scene. Any entity tagged `"storage"` with an `Inventory` is a chest; walk near + press `interact` (E) to open a two-column Bag↔Chest transfer window (a **near-fullscreen** fixed overlay on `TradeUI`/`RpgInventoryUI`'s shell — absolute host + dim backdrop + centered card, shown/hidden via `.enabled`, built once — whose columns/tables flex-grow to fill the card height). Each side: a header (title + bulk button), a live **Slots/Weight usage line**, then a **`UITable`** whose columns mirror the inventory's Settings-driven set (the `invCol*` toggles; `_applyColumns` re-applies on open, and `RpgInventoryUI._applyColumns` pokes both tables live when a toggle flips). **Double-click** a row (or a gamepad/keyboard confirm in browse mode) transfers it to the other side (single click selects): a **fungible stack of >1 opens an amount picker** (`_promptAmount` — a `gemsModal` with a `gemsStepper` defaulting to the full stack + `1`/`Half`/`All` quick-set buttons, so the player can split it), while a single unit or an **instance** (unique gear — nothing to split) moves whole immediately; the per-column **Store All / Take All** button bulk-moves everything that fits (greedy, halting at the destination's cap) and disables itself live when its side is empty. The picker is a top-of-stack modal (handle on `scene._storeQtyModal`, nulled on close): `StorageUI.close` dismisses it if the window closes under it (walked out of range), and the scene's `handleEscape` cancels the picker first (so one Esc backs out the dialog, a second closes the chest). `_transfer(scene, src, dst, idx, amount)` bounds a fungible move by `amount` (instances always move whole, by reference, preserving uid/mods); favorited-protection + the last-copy hotbar unbind live in `_move`/`_doMove`. Both tables are built once; a transfer only swaps rows via `setRows`, so the column sort survives every move (a row sort is view-only — never reorders the `Inventory`). Per-open state lives on the scene (`_store*`), cleaned up by `teardownScene`. Contract: `build(scene)` once after player + ui exist, `refresh(scene)` when dirty (driven by `Interactable.update`), set `scene._storeDirty` when the bag changes elsewhere.
- `TradeUI` — the **merchant** shop window — the buy/sell counterpart to `StorageUI`, on a **merchant NPC** (an NPC tagged `"npc"` carrying a `Merchant` + a stock `Inventory`; `RpgSpawn` attaches both from a `merchant` descriptor on the level-file NPC spawn). Walk near + press `interact` (E): `sceneRpg._npcActivate` opens it (instead of the quest dialogue) when the NPC has a `Merchant`. A **near-fullscreen** fixed overlay modeled on `RpgInventoryUI`'s shell (absolute host + dim backdrop + centered card, shown/hidden via `.enabled`, built once) with `StorageUI`'s two-column content: **LEFT = BUY** (the merchant's stock), **RIGHT = SELL** (the player's bag, minus the currency item), each a sortable `UITable` with icon+Name / **Price** / Qty columns; the title bar reads the merchant name + the player's live balance (the currency item's own display name), and a finite merchant shows its **till**. **Double-click** buys/sells a row — a fungible stack > 1 opens the same amount picker `StorageUI` uses (`scene._tradeQtyModal`), an instance/single transacts at once; worn or favorited bag items are refused with a toast. All mechanics are **`TradeSystem`** (`Gameplay/Trade`); this file is presentation + the gesture. Per-open state on the scene (`_trade*`); built once in `create()` (`TradeUI.build`), refreshed on `_tradeDirty`, and **auto-closed if the player walks beyond `RPG_TRADE_RANGE`** of the merchant (an NPC window has no station range-close). `sceneRpg` ticks `TradeSystem.update` each frame (finite restock) and threads the window through `handleEscape`/`_resolveContext`/`_dispatchInteract` like the other windows. Demo merchants: **Trader** (infinite, general goods) + **Quartermaster** (finite, gear + restock) in the overworld hub. See _Gameplay Kit → `Trade`_.
- `CraftingUI` — the **workbench** window (`Interaction` kind `"workbench"`) — a **near-fullscreen** fixed overlay on `TradeUI`/`RpgInventoryUI`'s shell (absolute host + dim backdrop + centered card, shown/hidden via `.enabled`, built once; the content body flex-grows to fill it). The four modules are crafted at the **bare** bench, so it bootstraps its own upgrades; `BuildMode` deconstruct returns a slotted module to the bag so it can't be lost. Per-open state on the scene (`_craft*`/`_mod*`); built once by `Interactable.build`, refreshed via `Interactable.update` on `_craftDirty`.

The panel stacks within the near-fullscreen workbench card (ample room for a fully-stuffed gun). See _Items & registry → `Gun`/`Ammo`/`WeaponMod`_.
- `BuildMode` — **RPG grid build mode** (stateless singleton, like `Interactable`). `build(scene)` once in `create()`, `update(scene)` each frame after `Interactable.update` (outside the tick loop), `drawWorld(scene)` in `draw()`. `B` toggles. Tile edits go through the Core **`TileEdit`** service (`set`/`clear` + `remesh` for seam-free walls; floor edits touch no collider; `occupied` tests). Per-scene state: `_built` (`"gx,gy" → tile item id`), `_builtEnts` (`"gx,gy" → { ent, itemId }`, scene-tracked — **not** chunk-managed, so `ChunkManager` leaves them alone like the squad), `_buildItem`, `_buildActive`, plus a static `BuildMode.active` mirror (set only while the `"build"` input context owns input) that `drawWorld` reads to gate the cursor highlight. **Built tiles + entities persist across map changes**: a revisited map's World is **resumed from the live pool**, so `_built`/`_builtEnts` + the buildable zone are simply still there (no capture/restore on a door trip — maps are never evicted). - `RpgWorldOverlay` — the RPG scene's **world-space** overlay (`drawWorld(scene)`, called from `sceneRpg.draw()` inside the camera view, **after `renderer.draw()`** — the chunked overworld's `RenderChunks` pass paints an opaque ground fill that would hide overlay content drawn first): item-drop rarity squares, projectile dots (lobbed/grenade `Projectile` entities) + fading **hitscan tracers** (`pushTracer`, the muzzle→impact streak the firers push), and (when the scene exposes `reachZone`) the reach-quest zone. `_rarityColor` is shared with the inventory rows. The HUD, dialogue, and inventory window are real UI panels drawn on the GUI layer (`Draw_75`). **The RPG scene's walls are a real tilemap** (`RpgLevel` keeps a wall + floor `TileLayer` on the `Level`), drawn as lit boxes by the `RenderWalls` mesh pass (the other resident layers render as real `RenderTileMap` tilemaps per `RpgLevel.LAYERS`; the sprite-free `RenderDebugTileMap` cost fill remains as an off-by-default Debug → Render → Tiles overlay) with the buildable region by a `RenderZone` pass — world-space passes under/among the entity passes.

**World time & day/night.** **`WorldClock`** (`scripts/WorldClock/`, Demo) is the in-game clock — a static class like `Time` (one world clock), holding `hour` (0–24 float) + `day` (1-based), advanced once per frame from `sceneRpg.step()` by `Time.delta` (sim time — pauses with the game, dilates with `Time.scale`). `dayLength` (real seconds per in-game day, default 240) sets the pace. The scene `reset()`s it once in `create()` — **not** per map — so a portal trip keeps the hour. API: `reset()`, `update(dt)`, `clockText()` (`"HH:MM"`), `phase()` (`night`/`dawn`/`day`/`dusk`), `tint()` → `{ color, alpha }` interpolated from a keyframe table (deep blue at night → clear by morning, warm at dawn/dusk; alpha 0 in full daylight). The HUD shows `Day N HH:MM` (read live), and the **`RenderLighting`** pass (now in the `Gameplay/Lighting` kit) consumes `tint()` as its **injected ambient term** (`RpgMap.build` passes `ambient: () => WorldClock.tint()`; day/night is the light map with no lights).

**Seasons & temperature.** `WorldClock` also derives the **season** purely from `day` (no stored state, like `phase()` from `hour`): `daysPerSeason` (default 7) days each, the four cycling forever over a `_SEASONS` literal (`{ id, name }`). API: `season()`, `seasonDay()` (1-based day-within-season). The HUD time row reads `Season · Day N  HH:MM`. Season biases the `Weather` transition + the `Temperature` baseline. **`Temperature`** (`scripts/Temperature/`, Demo) is the ambient temperature in **Kelvin** (`toCelsius`/`toFahrenheit` convert) — a **pure derivation, not a stored sim**: `now()` = `ZERO_C` (273.15) + season baseline (`_BASE`, authored in °C, keyed by `season().id`) + a time-of-day swing (`diurnal()`, a cosine of the hour peaking mid-afternoon) + the live `Weather.tempMod()` (which already folds in the active climate zone's offset). The Kelvin/Celsius scales share one increment, so all the deltas are scale-agnostic — only the baseline is offset. Kept **off** `WorldClock` so the clock stays the pure temporal authority. The HUD shows the weather condition + temperature via **`Temperature.display()`**, which formats `now()` in the `tempUnit` Setting (`"K"`|`"C"`|`"F"`, default `"K"`; toggled in the inventory **Settings** tab); the bundled locale fonts carry the `°` glyph, so `°C`/`°F` render.

**Weather.** **`Weather`** (`scripts/Weather/`, Demo) is the global sky — a static singleton like `WorldClock` (one sky), holding the current condition + a **season-biased transition**. Conditions are a fixed built-in literal table (`_COND` — `clear`/`cloudy`/`rain`/`storm`/`snow`), each carrying its render look (`{ c, a }` tint + `particle`/`density` + `cloud` shadow coverage) and a **Kelvin `temp` delta** (scale-agnostic, folded into `Temperature.now()`). `update(dt)` (driven from `sceneRpg.step()` by `Time.delta`, so weather **freezes when the game pauses** and dilates with `Time.scale`, like the clock; it also accumulates **`Weather.time()`**, the cumulative sim-second clock the weather **visuals** — rain/snow fall, cloud drift — scroll on, so they pause/dilate too) counts down a 25–70 s hold then re-rolls the next condition by `_WEIGHTS[season]` (winter favors snow + bans rain, summer favors clear + the odd storm, …), **excluding** the current one so a change always changes the weather. A change **cross-fades** over `_fadeTime` (2.5 s): `previous()`/`current()`/`blend()` let the render pass + `tempMod()` lerp the outgoing→incoming conditions so weather eases in/out instead of snapping. `reset()` (scene `create()` once, like `WorldClock.reset()`) settles a clear sky and survives map changes. The **`RenderWeather`** pass (see Renderer) draws it; the HUD reads `current().name`.

**Climate zones (regional weather).** A **climate `ZoneMap` channel** lets a region **override** the open sky. `Weather.enterRegion(zone)`/`exitRegion()` read the zone's flat `data` — `weather` (a forced condition id) + `tempMod` (a Kelvin offset) — into an `_override`/`_regionTemp` slot; the _displayed_ condition is the effective one (`override ?? ambient`), so the season-rolled ambient keeps running underneath and resumes on exit (the cross-fade handles both edges). Climate zones are **data-driven** from a level file's optional `meta.climate` array (`[{ name, rect: [gx1,gy1,gx2,gy2], weather?, tempMod?, color? }]`), painted into the `"climate"` channel by `RpgMap.build` (once, right after the buildable channel — a map builds only on its first visit). `sceneRpg._updateClimate()` tracks the **player's** climate cell directly each frame (a single-entity `ZoneMap.idAt` lookup — cheaper than `ZoneSystem`'s all-entity sweep) and fires enter/exit on a border cross; `RpgMap.suspend` calls `exitRegion()` so a portal trip clears it (the resumed/built map re-detects on its first step). The reference is `overworld.json`'s **Frostlands** (`weather: "snow"`, `tempMod: -15`) — walking in turns the sky to snow and drops the temperature ~23 K. **Indoor maps** (`meta.indoor`, e.g. `interior_01`) skip the `RenderWeather` pass entirely — no open sky inside a cave (the global `Weather` keeps running; only its visual is suppressed).

The combat/loot plumbing the RPG scene (`sceneRpg`) uses lives in **`RpgScene`** (`scripts/RpgScene/`, Demo) — free functions taking the scene (composition; no class inheritance on GMRT): `trackDamage(scene, yOffset)` (also pops ally numbers for every `Follower` entity, by live query), the `Mortal`-driven death pair `resolveHealth(scene, handlers)` + `updateDowned(scene, handlers)` (see _Death_ above — these replace the old `resolveDeaths`/`checkPlayerDeath`), `spillLoot`/`spawnDrop`, `collectDrops(scene, onCollect?)`. Scene-specific side effects (quest/profile counters, the player respawn reset, the companion recovery spot, down/recover toasts) are the handlers; the scene supplies the contract fields `world`/`playerId`/`_hpTrack`/`_invDirty` (the enemy set is derived live by **`Faction`** — Health-bearing bodies hostile to the player — not stored, and not a marker/tag).

The **character window** is centralized in **`RpgInventoryUI`** (`scripts/RpgInventoryUI/`, Demo) — a **near-fullscreen, fixed** (non-draggable, non-resizable) **`gemsTabs`-based** overlay modeled on the `SystemMenu` panel: an absolute full-screen host with a dim backdrop (shown/hidden via `scene._invWin.enabled`, **not** a `UIModal`) centering a full-height card whose tab host flex-grows, built once in `build(scene)` on `scene._invWin`, with seven tabs: **Items** (a bag slot **GRID** (`gemsSlots`/`UISlots`) beside a **detail pane** — icons carry recognition, the pane carries the per-item metadata the old table spread across always-visible columns: icon + name/rarity head, the **`Manufacturer`** name + lore in brand color, the `description` (its first in-bag home), the selected instance's **composed weapon profile** (`EquipmentSystem.composeWeapon` — maker ops + attachments included) or ammo ballistics, `Equippable.mods` bonus lines, installed attachments, and a qty/weight/value footer (`_refreshDetail`, rebuilt on selection — the CraftingUI pattern). Grid cells show qty counts, **rarity-tinted borders**, and worn `E` / favorite `*` corner badges; the unfiltered view pads with empty cells to `Inventory.capacity` so bag size reads at a glance, and `_refreshGrid` resizes the host element via flexpanel point mutation (the `UIText` idiom). Above: a usage line + category-filter `gemsSelectCustom` (filters the view in `_refreshGrid`; the free-text search was retired with the table) + a **Sort** button (`InventorySystem.sort` on the REAL bag). Below: the select/action row (click selects, double-click / the context **Use/Equip/Unequip** button / a browse-mode confirm acts). The grid+detail row deliberately uses **no `gemsScroll`** — a clipped scroll beside a non-clipped sibling is the GMRT batch-flush trap (see `CraftingUI`); the grid fits the tall card instead), **Equipment** (worn-slot rows, click to unequip — `scene._invEquipHost`), **Squad** (the companion roster — one `gemsCard` per squad member (live `FollowerSystem.members` query, player excluded) into `scene._invFollowerHost`, with the follower's name + a **live** follow/wait status & carry-bonus line + a **Kick from squad** button (`scene._kickFollower`, live-disabled once out or while down) + a binding-aware rehire hint; the host is repopulated per `rebuild` since membership changes, but each row's text/disabled-state reads the live components so an F-toggle/kick updates with no rebuild), **Stats** (the live sheet + the genre's extra records — `scene._invExtraHost`), **Quests** (a live `gemsQuestTracker` bound to `QuestLog`), **Achievements** (one `gemsCard` per registered `Achievement` def — built once, since the set is static after registration; the Unlocked/Locked status is a live `gemsRichText`, so an unlock or the Debug panel's Unlock/Clear All shows with no rebuild), **Settings** (per-column toggles). The `invCol*` **Settings** toggles (`gemsCheckbox` → `Settings.set`/`save`, persisted across launches: **Rarity** / **Maker** / Type / Weight / Value) now govern only the **chest/trade tables** (`InvTable.columns`, shared by `StorageUI`/`TradeUI` — `_applyColumns` syncs an open chest); the bag grid has no columns. `rebuild(scene, { equipSlots, extraRows? })` only refreshes live data: `_refreshGrid` + `_refreshDetail` (the category filter + active tab survive every equip/use; selection re-maps by instance `uid`, else `itemId`), then repopulates the equipment + extra sections. `equipSlots` is the rows to show (RPG adds `backpack`); `extraRows(scene, host)` appends genre lines (RPG Profile records). The scene keeps only `invOpen` (toggled on the `inventory` key) and calls `build` in `create()` + `rebuild` when `_invDirty`. (The HUD stays per-scene — `sceneRpg._buildHud` = HP + quest tracker.)

`sceneRpg.step()` is the reference RPG orchestration: edge-toggle the inventory window → per tick: `snapshot` → `physics` Pipeline (headed by `PlayerSystem`, the player brain) → `RpgScene.trackDamage` → `RpgScene.resolveHealth` (despawn/respawn/down by `Mortal`) → `RpgScene.updateDowned` (revive timer) → `RpgScene.collectDrops` → reach/quest/achievement checks → `flush`; then once per frame: `AnimationSystem.update`, NPC proximity + dialogue, `Interactable.update`, `BuildMode.update`, `camera.update`, an inventory rebuild when `_invDirty`, and finally `_checkPortals()` **last** (a door swaps the world out from under everything). (No pause gate in `step()` — `obj_game` skips `scene.step()` entirely while the `SystemMenu` overlay is open.)

**Map graph (overworld / sub-levels / side-islands).** Maps are discrete level files connected by portals, not one streamed world (the deliberate fit for the `JSON.parse`-on-large-files limit and the one-`World`-per-scene model). The world graph is the seed registry **`RpgLevel.MAPS`** (`{ mapId → "levels/x.json" }`) + `RpgLevel.START`; extract to a `maps.json` manifest if it grows. A level file gains two things over the base format: `meta.entries` (a named-point map, e.g. `{ default, from_interior }` — the matching side of a door; `RpgLevel.build(world, data, entryId)` resolves the spawn from it, falling back to `entries.default` then legacy `meta.playerSpawn`) and a **`portal`** spawn preset (`{ toMap, toEntry, label?, color? }` → a non-solid sensor entity, returned in `RpgLevel.spawn`'s `portals[]`). `sceneRpg.create()` builds the **persistent** UI once (HUD/dialogue/inventory/Interactable/BuildMode — they read `world`/`playerId` live, so they survive a map swap), then calls **`RpgMap.go(scene, mapId, entryId)`** — the portal-travel orchestrator. Rather than destroy + rebuild on every door, `go` keeps each visited map's `World` **alive and suspended** in the **`World.levels` registry** (the map pool — the registry entry IS the park bundle; there is no scene-side pool): it **parks** the current map (`suspend` → stash its `world`/`level`/`renderer`/`camera`/`pipeline` references into the registry entry, no teardown) and then either **resumes** the target's parked bundle (`World.levels.entryOf` — a revisit: no file reload, no rebuild) or **builds** it from file (`RpgMap.build` — a first visit only, registering a minimal `{ world, level }` entry that the next suspend overwrites). Only the **squad** crosses worlds: `go` collects every entity sharing the player's `Squad` id (player first — there is **no per-map player** and no carried component subset), forces any `"wait"` member back to `"follow"` (+carry bonus — waiting is map-local, never a way to stay behind), and moves each one as a **whole entity** through **`World.levels.take`/`put`** (the same registry transfer the wandering trader uses), landing them at the target's named entry with Position/Velocity overrides; `scene.playerId` re-latches to the transferred player's new id (and is re-derived from the live `Playable` query each frame anyway — there is no stored player handle to dangle). Everything else (kicked/unhired companions, built tiles/entities, the buildable zone, dead enemies) just stays resident in its parked world, so nothing has to be hand-marked for persistence. A resume re-binds the map-context statics (`MotionPlanner` grid + `CombatAI.bind`). The player-centered radar (`RadarArrows`) reads `world`/`playerId` live, so it needs no per-map rebuild. `RpgMap.checkPortals` (step's last line) travels through the first portal the player overlaps. The editor's Test Play still works: a `playtestFile` is registered under a synthetic `_playtest` map id and booted as a single portal-less map. `_updateNpc`/`_checkReach` guard the no-NPC / no-reach-marker maps (interiors). The reference graph is `overworld` ⇄ `interior_01` (a cave door).

**Map persistence (everything, always — for the session).** A map builds from file exactly **once** (its first visit) and thereafter only freezes/thaws **as-is**: the map's `World`/`Level` are **kept alive** in the `World.levels` registry (the map pool) for the whole session — there is **no eviction, no cold serialize, and no respawn-from-file reconcile** (the old `Persistent`/gone-ledger machinery is deleted). So _everything_ persists across a door trip by construction — player edits (claimed buildable zone, built tiles, placed entities), kicked/unhired resident companions, dead enemies (a killed unique is simply absent from the live world), moved/hurt bodies, and file spawns (which run once, ever — nothing re-spawns on a revisit). The pool is session-scoped: `Quit to Lobby` / scene destroy parks the active map, frees every registry entry (`sceneRpg.destroy` → `RpgMap.suspend` + a `World.levels.ids()` walk of `RpgMap._free`), and resets the registry (a fresh RPG open is a new world). Memory pressure is bounded by the map-graph size (currently 2). The session pool is what a **disk save** serializes — see _Save/Load_ below.

**Save/Load (disk persistence).** The session serializes to disk via **`SaveGame`** (`scripts/SaveGame/`, Demo) over the Core **`Snapshot`** pass frame + **`Json`** codec (see [utilities.md](utilities.md)). A slot is a directory `saves/<slot>/` (a `manifest.json` + optional binary blobs), listed by `saves/index.json` — the load menu reads that index because GMRT's `file_find_first` scans the build dir, not the save area (see [GMRT.md](../GMRT.md)). Three passes, each owning both directions: **meta** (the slot card — timestamp / day / clock / map / credits), **sim** (`WorldClock` hour+day, `Weather.export/import`, `Profile` counters, `Achievement` unlocks), and **maps** (per resident map in `World.levels`: the component export minus chunk-owned + transient components, `built`/`builtEnts`, the claimed buildable zone, and the deep chunk cache). **Restore** boots a fresh RPG scene whose `create()` load-branch runs the passes: it re-lands the SQUAD through the existing portal-transfer machinery (`RpgMap.build` with the extracted squad, so the character arrives intact), stashes every saved map in `SaveGame._pendingMaps`, and applies each map's state on its first build — the active map now, a parked map when the player next portals to it (`RpgMap.build` consults `takePendingMap`). The **deep chunk cache** imports before the first stream (`ChunkManager.exportCache`/`importCache` — only touched chunks' entity-state delta; terrain/walls/spawns regenerate deterministically from the seed), so distant killed mobs stay dead and moved/hurt ones keep their state. Player builds replay via **`Blueprint`**; the dense resident tile grid is **not** serialized (it replays from `built`). The user-facing entry is the **Save/Load tab** injected into `SystemMenu` (`SystemMenu.addTab`, wired in `obj_game` Create_0 — the seam keeps Core free of the Demo's `SaveGame`/`SceneRpg`).

**`Blueprint`** (`scripts/Blueprint/`, Demo) is the serializable build-set: `capture(scene, x1,y1,x2,y2, {withState})` → a `Json`-safe plan `{ tiles, ents }`, and `stamp(scene, ox, oy, plan)` re-lays it (tiles first so a door reads finished walls, one wall remesh at the end). All placement routes through **`BuildMode.applyItem`** (the shared core factored out of `_tryPlace` — no cost/gate, updating `_built`/`_builtEnts`), so a stamped build is identical to a hand-placed one. The Build Mode blueprint feature (ROADMAP — capture/place + drag-select) and save-game build-state restore are the **same operation** over it; a built entity's optional `snapshot` restores exact state (a chest keeps its contents) rather than a fresh `make()`.

**The squad (dynamic-world entities).** The party concept is a **component, not scene data**: **`Squad`** (`scripts/Squad/`, Gameplay/Squad, `{ id }`) marks membership — the player mints a unique id at spawn (`RpgPlayer.spawn`, `uuid()`), and every hired companion carries the same id. There is **no roster list anywhere**; every consumer (travel, the F toggle, the Squad tab, ally damage numbers) resolves membership by live query (`FollowerSystem.members(world, squadId, playerId)` — player first). `Follower` (`scripts/Follower/`, `{ state: "follow"|"wait", speed, range, bonusCapacity, bonusWeight }`) is the **behavior** component; `FollowerSystem.update(world, playerId)` drives every `Follower` entity per tick (a `"follow"` member steers toward the player, easing to a stop within `range`; `"wait"` and non-members hold still). The player id is **passed in, never stored**, so a transferred companion needs no re-link. It's a dynamic solid body; `RpgSpawn.spawnFollower(world, x, y, opt)` builds it via the `follower` `EntityPreset` def — spawning **unhired**: a map resident with an `Interaction { kind: "rehire" }` (talk to recruit). **Hire/kick own the membership transitions** (`FollowerSystem.hire`/`kick`): hire = `Squad` + follow + carry bonus + drop the rehire prompt; kick = the reverse, **permanently and in place** — a kicked companion stays a resident of that map until re-hired by talking. `sceneRpg` seeds the starting companion programmatically once in `create()` (spawn + `hire`); the `F` key flips the nearest **member** between follow and wait — but waiting is **map-local only**: a portal forces every member back to `"follow"` (+bonus) and takes the whole squad (see _Map graph_). A companion carries `Health` + a `down`-kind `Mortal`, so it's an **attackable combatant**; at 0 hp it goes **Down** and later revives at the recovery spot (see _Death_).

A member also **helps carry**: while following it grants the player **`bonusCapacity`/`bonusWeight`** (extra `Inventory` slots + weight cap) via `FollowerSystem.applyBenefit` — a balanced +/- delta exactly like `EquipmentSystem`'s `Container` bonus, paired with the state flip in **one place** (`FollowerSystem.setState`) so it can't half-apply; hire/kick and the portal's forced-follow all route through it. Because the bonus is baked into the player's live `Inventory` and the player transfers **whole**, it rides across maps with no re-apply. Only the programmatic seed grants a bonus; the `follower` preset leaves it 0, so file-authored followers stay benefit-free. Kicking happens from the inventory **Squad** tab (`scene._kickFollower`) or not at all — there is no dismiss-and-recall; re-hiring is the `rehire` interaction (walk up + E).

**Chunk streaming & sim-LOD (scalable overworld).** A **chunked map** (`meta.chunked: true` in the level file) streams its terrain + entities around the player so the `World` only ever holds what's nearby — entity count + per-tick cost stay bounded no matter how far the player roams (the overworld; interiors keep the plain build-everything path). The engine is the Core **`ChunkManager`** (`scripts/ChunkManager/`, a plain instance class owned by the scene as `this.chunks`, like `LevelManager`); content comes from the **generator** it's handed (the RPG's pass-composed `OverworldGen.create` `ChunkGenerator`) plus the injected `opts.spawn` adapter. Built on `EntitySnapshot` (the capture/restore foundation) + `Portal` (`scripts/Portal/`, `{ toMap, toEntry }` on the doorway entity, so a streamed door resolves via a live `world.query(Portal)`).

- **Two-ring sim-LOD** (Chebyshev chunk distance from the player's chunk): `d ≤ simRadius` → **SIM ring** (entities live in the World, walls have colliders, full simulate + render); `simRadius < d ≤ loadRadius` → **LOAD ring** (entities held as snapshots, **not** in the World / not simulated, drawn statically by `RenderChunks`; walls drawn, no colliders); `d > loadRadius` → **UNLOADED** (the whole record parked in an in-session cache keyed by chunk, restored on return so hurt/killed/moved entities persist). `ChunkManager.update(centerX, centerY)` (called once per frame from `step()`, outside the tick loop) diffs the rings on a chunk-border crossing and **promotes** (restore → World + mesh colliders) / **demotes** (capture → snapshot + drop colliders) / loads / unloads, then `world.flush()`es its own removals. **The world is pregenerated** ("generate the level once, then only load/unload"): `RpgMap.build` calls **`ChunkManager.pregenerate()`** once (the finite 8×8 = 64 chunks, ~130 ms, behind the scene fade), generating every in-bounds chunk's record into that cache up front — mid-game streaming is pure load/unload (`generate()` never runs during play; entity _spawning_ still LODs — descriptors stay dormant until a chunk first enters the SIM ring), and the manager's **store-backed samplers** (`materialAt`/`costAt`, falling back to the generator's pure sampler outside the store) feed `TerrainStream`'s seam apron, `NavGrid`'s weights, and `PathFollow`'s pricing from stored terrain instead of re-sampling noise (`RpgMap._terrainCost` wires `chunks.costAt`). Pregeneration runs **once per session** (a map is never rebuilt); determinism (same seed → same world) still holds per build. (A non-pregenerated chunk still generates lazily on first load; the old amortizing load queue is gone — moot once loads became cache moves.) The **squad (player + hired companions) is never chunk-managed** — the scene keeps it in the World always.
- **Resident grid vs streamed terrain.** A chunked map's `Level` is a large **resident** grid (`meta.worldCols/worldRows`, built by `RpgLevel.buildChunked`) whose `wallLayer`/`floorLayer` hold **player builds only** (build mode + `TileEdit` colliders, unchanged) — the streamed terrain (authored hub + procedural wilderness) is owned by the `ChunkManager` with its own colliders + `RenderChunks` pass, never written into those layers, so the two never conflict. The world is a **finite `worldCols × worldRows` rectangle** (the resident-grid extent, anchored at cell 0): `ChunkManager` clamps streaming to chunks inside it (`opts.worldCols/worldRows` → it skips out-of-bounds chunks, so the active set shrinks near an edge — e.g. 9 at a corner vs the usual 25), and `RpgLevel.buildWorldBorder` rings it with 4 always-present kinematic-solid edge colliders so the player/slimes can't leave (procedural fills the rectangle out to the border; building is gated to the claimed origin zone). `IdPool` reuses freed indices, so streaming churn keeps the high-water mark bounded.
- **`OverworldGen` (composition) over `ChunkGenerator` (frame) + `AuthoredStamp`/`PrefabStamp` (passes) + `TerrainField`/`Rand`/`Prefab` (Core machinery), with `RpgBiomes` (data) + `RpgPrefabs` (templates).** Generation is **not fixed** — it's split so a different world is a swap, not a rewrite:
  - **`AuthoredStamp`** (`scripts/AuthoredStamp/`, Core/Level) is the authored-overlay **pass** (it replaced the old `ChunkSource` router layer): the level file's walls + spawns are indexed per chunk at construction, and any chunk inside the authored **bounding box** takes exactly that content — the pass runs first and sets `ctx.authored`, which the procedural passes (`PrefabStamp`, the scatters) respect by early-outing, so the hand-built hub (Elder, cave portal, chest, workbench, survey post) stays procedural-free even where sparse. With the router gone, `ChunkManager` holds the **generator directly** and takes an injected **`opts.spawn`** adapter (`(world, level, desc) → id`; the RPG wraps **`RpgSpawn.spawnEntity`** — the descriptor adapter over the `EntityPreset` defs — so streamed + up-front spawns build through one code path; fail-fast if a chunk carries spawns with no adapter). `TerrainStream` reads the material table off `chunks.generator.palette` (the generator instance's field, never a class static, so a swapped-in generator brings its own tilesets).
  - **`ChunkGenerator`** (`scripts/ChunkGenerator/`, Core/Level) is the generation **frame** — `Renderer`:`RenderPass` :: `ChunkGenerator`:gen pass: an ordered list of **passes** (each `{ salt?, apply(ctx) }` or a bare `fn(ctx)`, wrapped on `insert` like a `Pipeline` step; `insert(pass, index?)`/`remove(pass)` mirror `Renderer`) builds a chunk's `walls`/`spawns` into a shared ctx (`{ gen, field, cx, cy, gx0, gy0, cols, rows, rng, out }`), while the terrain base comes from the composed **`field`** (a `TerrainField`-like sampler, required) — so the frame satisfies the whole generator surface `ChunkSource` routes (`generate(cx,cy) → { terrain, solid, walls, spawns }` + `palette` + the four samplers). **Each pass draws from its own rng stream**, seeded from `(cx, cy, seed, pass salt)`: a chunk regenerates identically every visit (the streaming contract), **and** inserting/removing a pass never reshuffles the other passes' output — declare a unique small-int `salt` per pass (an undeclared salt falls back to list index, which re-couples streams to order). All randomness through **`Rand`** (Core/Util; MINSTD, not xorshift — the GMRT-Safe Idiom).
  - **`PrefabStamp`** (`scripts/PrefabStamp/`, Core/Level) is the generic prefab-stamp **pass**: chance roll → weighted pick from `Prefab.byTag(tag)` (resolved at construction — register prefabs first) → `Prefab.stamp` at a random interior offset (`margin` cells off the chunk border so stamped walls can't merge across a seam), deep-copying `loot`/`items` per stamp. Policy enters via two hooks so the pass stays content-free: `spawnFilter(s, field)` (keep a stamped spawn?) and `defaultLoot(s, rng)` (loot for a spawn that authored none — drawn **before** the filter verdict so a skipped spawn consumes the same rng draws). Warns at construction if an eligible prefab carries `tiles`/`zones` (chunk output has no channel for them).
  - **`OverworldGen`** (`scripts/OverworldGen/`, Demo/System) is now the RPG **composition**: `OverworldGen.create(opts) → ChunkGenerator`, wiring the RPG `TerrainField` (data in `RpgBiomes`) + four passes — a `PrefabStamp` carrying the RPG spawn policy (`spawnFilter` default keeps mobile combatants (raider) off water — nothing spawns swimming; `defaultLoot` default rolls the wilderness raider loot table, `OverworldGen.rollLoot`), a **rocks** scatter, a **pines** scatter (`tree` preset — trunk collider under an overhanging canopy mesh, position-hashed yaw/size variety), and a **rats** scatter (wildlife + trees kept off water) — the scatter passes are plain pass objects defined here (content, not machinery). A different world (cave/desert/…) is a different composition of the same Core pieces; a variant overworld overrides the policy hooks via `opts` (`seed`/`chunkCols`/`chunkRows`/`prefabChance`/`prefabTag`/`spawnFilter`/`defaultLoot`). The terrain machinery is **`TerrainField`** (`scripts/TerrainField/`, Core/Level — held as `gen.field`, a palette-driven pure-coordinate sampler; a cave generator composes the same class with its own palette), and the RPG's DATA is **`RpgBiomes`** (`scripts/RpgBiomes/`, Demo/Content — the `TERRAIN` palette, the design-reference `PALETTE`, and the noise tuning `LATTICE`/`GROUND_LATTICE`/`GROUND_SALT`; a plain top-level data literal, no registration step): per cell it picks a material from **two value-noise channels** (`materialAt`) — an **elevation** gradient (`threshold` entries — deep water → water → sand; past the last one the cell is land) plus an independent **ground-detail** channel (`ground` entries — mud/soil/rich soil/grass/gravel/rocky, grass dominant with wet depressions and gravel-ringed rock outcrops as patchy features — one shared gradient would instead ring every shoreline with fixed contour bands). Each palette entry carries a **weighted `pathCost`** (TileType convention: `null` → impassable) that prices both routes (`NavGrid` samples it via `costAt`, `MotionPlanner` multiplies it into step distance) and movement-point consumption (`PathFollow.speedScale` — a mover's speed × `1/cost`): easy ground 1, sand/gravel 1.5, mud/rocky 2, shallow water **wadeable** at 3 (A* only wades when it beats walking around) but **`spawnable: false`** (`TerrainField.spawnable` — travel yes, homes no); only **deep water** is `null` → `solidTerrain(cx,cy)` greedy-meshes those cells into `solid` rects in `generate()`'s output, which `ChunkManager` turns into **collide-only** colliders (not rendered — `TerrainStream` already draws the water) that physically block bodies **and** feed `NavGrid`.
  - **`Prefab`** (`scripts/Prefab/`, **Core/Level**) is a registry of reusable mini-layouts, mirroring `Item`/`Rarity`: a `cols/rows` footprint + scope `tags`/`weight` + up to four **prefab-local** content channels (all optional) — `walls` (bare collide-only rects `[[lx,ly,w,h]]`), `tiles` (writes into a **named** `TileLayer`: `{ layer, type, rects }`), `zones` (a region painted into a `ZoneMap` channel: `{ channel, name?, tags?, data?, rects }`), and `spawns` (**opaque** consumer-shaped descriptors `{ lx, ly, ... }` — Core never reads their fields). `register()` **fail-fast validates** every channel against the footprint (an out-of-footprint rect would silently break a generator's seam margin). Two consumption modes: **`stamp(ox, oy)`** translates all channels local→absolute (pure data — the chunk path), and **`apply(opts)`** writes the Core-expressible channels into a level (`tiles` via `TileEdit.set` — the caller remeshes a solid layer's colliders once after its stamps; `zones` defined + painted, channel created on demand; `walls` as kinematic colliders in the passed entity store) and returns the translated `spawns` for the caller's own adapter (e.g. `RpgSpawn.spawnEntity`). The chunk pipeline consumes only `walls` + `spawns` — the **`PrefabStamp`** pass (see above) does the picking/stamping and warns when an eligible prefab carries `tiles`/`zones` (an `apply()`-based generator is the consumer for those). The RPG's defs (`boulder_cluster`/`raider_camp`/`ruin` — walls + spawns only) live in **`RpgPrefabs`** (Demo/Content), registered by `RpgContent.register()` alongside items/recipes.
  - Slimes survive capture/restore because state callbacks receive `(world, id)` from `StateSystem` (no world static), `State` holds pool-id **strings**, and `Brain` carries no self-id; the one per-map static left is `CombatAI._level` (pathfinding), refreshed on each `attach` and re-pointed by `CombatAI.bind` when a parked map is _resumed_ without re-attaching — see _Map graph_.
- **Scene wiring** (`sceneRpg`): `RpgMap.build` branches on `meta.chunked` — chunked builds the resident grid + creates `this.chunks`/`this.generator` + pregenerates + an initial `chunks.update(spawn)` + inserts `RenderChunks`; plain is unchanged. The scene reads NPC / portal / enemy handles **live by tag** (`Query.nearest({tag:"npc"})`, `world.query(Portal)`, `RpgScene._enemies`) rather than stored id lists, so chunk churn never dangles a handle. A map switch **parks** the manager with its world (a suspended chunked map just stops streaming; `resume` re-centers it on the entry), and `RpgMap._free` drops it only at scene end.
