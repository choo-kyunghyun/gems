# G.E.M.S. Architecture — Gameplay / RPG Layer

Area reference split out of the always-loaded core ([ARCHITECTURE.md](../ARCHITECTURE.md)). Loaded on demand: **Read this file before designing or modifying anything in this area.** Runtime quirks live in [GMRT.md](../GMRT.md).

## Gameplay / RPG Layer

The **RPG** scene (`sceneRpg`) is the action-RPG (the platformer is a movement showcase with no RPG layer). The pieces split across two pillars — genre-agnostic modules in the **`Gameplay` kit**, content/model-specific glue in **`Demo`** (`Stats`, all `Rpg*`, `CombatAI`, the world-sim, build mode) — and are driven explicitly from the scene's `step()`, never auto-run by `World`. Composition over inheritance throughout (see ARCHITECTURE.md): "kinds of item" are a flat `Item` + `components: []` queried by `instanceof`.

**Items & registry.** `Item` is a definition registry (`Item.register`/`get`), like `Rarity`. A definition is identity + universal scalars (`name` i18n key, `sprite`, `stack`, `weight`, `value`, `rarity`) plus `components`. **Definition vs instance** (`item.isInstanced()` → has `Equippable`): a _fungible_ item is a shared definition with stacking `qty`; an _instance_ (all equippable gear) is unique — an `Inventory` slot `{ itemId, qty:1, uid, mods }` (a gun also carries `ammo`/`rounds`) with per-instance state inline, so two of one itemId can differ and `Equipment`/drops reference the specific one by `uid`. The components:

- `Equippable` (`{ slot, mods, worn? }`) — wearable in an `Equipment` slot (`weapon`/`armor`/`trinket`/`backpack`); `mods` are flat `Stats` deltas folded onto the wearer's base by `StatModel.recompute` while worn; `worn` (sprite NAME, `""` = invisible) is the paper-doll overlay sheet (see _Paper-doll appearance_).
- `Weapon` (`{ slots, fireCd?, damage?, reach? }`) — the universal weapon profile that **fully drives the action** (the controller hardcodes no built-in attack): named, typed attachment `slots` (`[{ id, accepts }]`; `accepts` = an attachment category or `"*"`), the melee numbers (`damage`/`reach`), and the shared cadence `fireCd`. **Melee vs gun is decided by a sibling `Gun` component, not a flag.** When unarmed, `PlayerSystem` falls back to the pre-composed shared `PLAYER_FIST` profile — so being unarmed never fires a free bullet.
- `Gun` (`{ caliber, magazine, ops }`) — presence ⇒ ammo-driven ranged. It fires the loaded `Ammo`'s base stats through the OPERATOR pipeline (`EquipmentSystem.composeWeapon`/`_applyOps`): ammo base → gun `ops` → each installed attachment's `ops`, `final = (base + Σadd)·Πmul` per field. Power is kinetic — `power = ammoPower + KIN_K·mass·(velocity/KIN_REF)² + wielder Stats.attack` — and the round's `penetration` rides the shot to lower target defense at the hit. `caliber` gates which `Ammo` chambers; ammo is consumed per shot from the magazine; R / auto-on-empty reloads from the bag (`EquipmentSystem.reload`/`loadAmmo` + the `*Slot` variants); a gun with no ammo type chosen yet auto-loads the first caliber-compatible ammo on R or on fire (`reloadSlot` → `_firstAmmo`), so firing a new gun never needs the mod panel (deliberate type _switching_ stays there).
- `Ammo` (`{ caliber, mass, velocity, power, penetration }`) — a fungible round; its stats are the BASE of the gun pipeline. `velocity` also scales the hitscan reach (shots are instant — no travel time).
- `WeaponMod` (`{ slot, ops, stat }`) — an installable attachment: `slot` matches a weapon slot's `accepts`; `ops` are per-field operators (`{ field: { add?, mul? } }`) over the composed profile (an op on a field the weapon doesn't expose is inert); `stat` deltas fold into the wearer's derived `Stats` (`StatModel._foldInstanceMods`). A weapon instance's `mods` is a map `{ slotId → attachmentItemId }`, edited at a workbench with the weapon-mod module slotted (`WeaponModUI`). The consumed item IS the definition — no parallel registry.
- `WorkbenchModule` (`{ kind }`) — marks an item as a workbench upgrade slotted into the bench's single module slot (`Interaction.module`); one bench is upgraded by swapping modules, not a station per category. `kind:"recipes"` (default) unlocks the recipes declaring `requires: <this itemId>` (base recipes — no `requires` — are always available); `kind:"weaponmod"` switches the bench window into the weapon-mod panel. Modules are crafted at the **bare** bench, so it bootstraps its own upgrades.
- `Consumable` (`{ heal }`) — usable from the bag (see `ConsumableSystem` below).
- `Container` (`{ capacity }`) — while equipped, grows the wearer's `Inventory.capacity`.

`Rarity` is a parallel registry of tiers (`{ id, name, color, valueMod }`); rarity color drives loot/inventory tinting. **`Manufacturer`** (Gameplay/Items) is the parallel registry of companies (`{ id, name, lore, color, ops? }`) referenced by the def field `maker` (default `""` = unbranded): a maker's optional `ops` is its signature weapon layer (same operator shape as `WeaponMod.ops`), folded by `composeWeapon`'s `_modLayers` on top of the authored base — brand identity is mechanical, not just cosmetic. **`RpgContent`** (Demo) registers all shared RPG content (rarities, the item set, recipes); the scene's own content is `RpgQuests` + `RpgAchievements`. Registration runs from `create()` (`RpgQuests.register()` calls `RpgContent.register()` first), never at top level (the cross-cutting registry rule).

**Achievements (push model).** `Achievement` (Demo) is a registry (`{ id, name, desc }` — pure data, **no conditions**) + unlock persistence (via `SaveData`). It never evaluates or sweeps: an outside trigger calls `Achievement.unlock(id)`, and the engine checks the request (registered? still locked?), persists, and returns whether it was newly unlocked. The demo triggers live in `RpgAchievements`: declarative threshold `RULES` per lifetime counter; a gameplay chokepoint that bumps a `Profile` counter calls `sceneRpg._reportAchievements(key)` → `RpgAchievements.report(key, value)` → unlock requests, toasting the newly-unlocked. An RPG-scoped Debug-overlay panel (Unlock All / Clear All) registers in `create()` and is removed in `destroy()`.

**Inventory & equipment (pure systems over components).** Systems take the component (or `world` + entity id) directly, with no world tick:

- `Inventory` = `{ slots: [{ itemId, qty }], capacity, maxWeight? }` (an instance slot adds `uid` + `mods`) — every player, enemy (its loot table), and chest owns one. `InventorySystem.add` stacks fungibles per `Item.stack`; an instanced item never stacks — `add` mints one slot per unit with a fresh `uid` + empty `mods` (a gun's `ammo`/`rounds` are added lazily by the firing path), `addSlot` re-inserts a pre-existing instance preserving `uid`/`mods` (transfer/drop), and `findByUid`/`removeByUid` reach a specific one. `sort` merges only fungible stacks. `add` is gated first by `maxWeight` then by `capacity`, returning the amount that did **not** fit.
- `Equipment` = `{ slots: { weapon, armor, trinket, backpack } }` of instance **`uid` strings** (two of one itemId may differ by mods, so an itemId can't say "which one"; flat → `world.export`-safe). `EquipmentSystem.equip(world,id,uid)` (or `equipFirst(...,itemId)` for the itemId-keyed entry points) keeps the item in the `Inventory` (it still counts toward capacity/weight) and re-derives the wearer's `Stats` via `StatModel.recompute` — recompute-from-source, so no +/- delta can drift (a `Container.capacity` bonus stays a direct `Inventory.capacity` delta). `weaponSlot`/`weaponProfile` resolve the equipped weapon → a **fresh composed profile** via `composeWeapon`, or `null` when unarmed → `PLAYER_FIST`.
- `ConsumableSystem.use` applies a `Consumable` and removes one unit; it refuses an item that would do nothing (e.g. healing at full HP). A `Consumable` carries three independent effects: `heal` (clamped to `Stats.maxHp`), a permanent attribute grant `{ attr, amount }` through the **injected `grantAttr` hook**, and a status grant `status` via `StatusSystem.apply` — kit defaults no-op; the Demo wires the `Attributes`+`StatModel` policy in `sceneRpg.create` (the injection idiom). An optional `yields` item id is left behind after use (best-effort add).
- `Encumbrance` (`{ threshold, minScale }`) — the speed penalty is delivered **through the Status system**, not by the mover directly: `EncumbranceSystem.update` maintains an `"encumbered"` status (`StatusSystem.maintain`) whose live `{ speed }` mult is the weight gradient, and the mover reads `StatusSystem.scale(world, id, "speed")` — so encumbrance composes with any other speed status and shows in the HUD. This module still owns the weight→penalty mechanic.

**Combat & stats.** `Health` = `{ hp }`; `Stats` = the session character sheet (`maxHp`/`attack`/`defense`/`speed`/`maxStamina`), derived from `Attributes`. There is **no `level`/`xp`** by design — permanent power comes from equipment and attribute-granting consumables, never an XP grind. `MeleeSystem.swing(world, attackerId, dirX, dirY, reach, damage)` resolves a melee hit immediately: an AABB hitbox extends `reach` in the facing direction (snapped to the dominant axis → 4-way) and damages every `Health` body except the attacker and its faction allies, returning the struck ids. Ranged is instant hitscan — **`Combat.hitscan(world, x0,y0,x1,y1, { owner, damage, penetration?, pierce? })`** (`Gameplay/Combat`): `Raycast.castAll` walks every solid body along the ray in order — each hostile `Health` takes `damage`, the shot passing through up to `pierce` targets (default 1) until a wall or a faction-allied body blocks it (an ally eats the shot like a wall) — returning the impact endpoint (for a tracer) + the struck ids. (The travel-time `Projectile`/`ProjectileSystem` path stays in the kit for lobbed projectiles; guns don't use it.) All damage lands through **`Combat.applyDamage(world, target, amount, penetration?)`**: the kit applier subtracts hp after the **injected `Combat.mitigate`** (default identity; `sceneRpg.create` sets `max(1, amount − max(0, defense − penetration))`) — the _attack_ side (`weaponPower + attacker.Stats.attack`) is composed by the callers. Every combatant carries a `Stats` sheet, and the damage paths only **subtract** hp — the reaction at ≤ 0 is decided centrally by the `Mortal` death pass (see _Death_). `Combat.hitscan`/`ProjectileSystem` live in the kit (not Core) because they need `Health`/`Faction`.

**`CombatAI`** (Demo) is the one AI for every non-player combatant: `CombatAI.register()` (via `RpgContent.register`) registers the named states `combat.idle`/`combat.chase`/`combat.attack` into the `StateSystem` pool (separate entries transitioned by NAME — the seam for preset-composed state sets); `CombatAI.attach(world, id, level, opt?)` seeds `State { next: "combat.idle" }` + a flat `Brain` whose `mobile`/`ranged` flags pick the behavior (default: mobile melee, a dynamic solid body; `{ mobile:false, ranged:true }`: an immovable actor that stands and fires hitscan — the built turret). `Brain` holds `home`/`aggro`/`deAggro`/`attackRange`/`bulletSpeed` + a `pathCd` replan throttle — damage is the actor's `Stats.attack`, not on the `Brain`; targets are the nearest hostile by faction. Chase is line-of-sight-first: a clear shot is a straight seek; a wall triggers an A\* detour over the `NavGrid` (see ecs.md → Pathfinding).

**Attributes & derivation.** `Attributes` is a flat `{ key: number }` bag, opt-in (the player carries one; monsters author `Stats` directly). **`StatModel`** is the swappable model: `ATTRS` (`POW`→attack, `VIT`→maxHp + a little defense, `AGI`→speed, `END`→maxStamina, each with a default) + `derive(attrs)` + `recompute(world, id)`. **`recompute` is recompute-from-source**: derived `Stats` = `derive(attrs)` + Σ equipped `Equippable.mods` + Σ active status `mods`, rebuilt from scratch each call (so it can't drift); a no-op without `Attributes`; clamps `Health`/`Stamina` to the new maxima. It runs on spawn, on equip/unequip, and on an attribute change — which comes from attribute-granting consumables (the shard items, one per `ATTRS` key, via the injected `grantAttr` hook), obtained by crafting and quest reward, so growth is gated on gathering/exploring, not playtime. `Attributes` ride the carried sheet across a map change (else shard gains would silently reset). Swapping the model (D&D-6, SPECIAL, …) is a `StatModel`-only edit — combat, equipment, and saves read only the derived `Stats`. The inventory Stats tab is data-driven from `ATTRS`.

**Buffs & statuses.** The `Status` module (`Gameplay/Status`) is the generic buff/debuff layer, stat-model-agnostic like the rest of the kit. Three pieces: `Status` (the def registry), `StatusEffects` (the per-entity active list `{ id, remaining, accum, mult? }` — flat, export-safe), `StatusSystem` (runs them). A def carries up to three effect kinds, each routed the idiomatic way: **`dot`/`hot`** (HP per `interval`, applied straight to `Health` — DoT bypasses `Combat.mitigate`; the ≤0 reaction stays the `Mortal` pass), **`mult`** (live multiplicative factors read at point of use via `StatusSystem.scale(world, id, key)` — never folded into the sheet, so effects compose by multiplication), and **`mods`** (flat additive `Stats` deltas folded by `StatModel._foldStatuses` — needs a re-derive on apply/expire, so it routes through the **injected `StatusSystem.onStatsChanged` hook**; `sceneRpg.create` wires `StatModel.recompute`). API contracts: `apply` (timed; `opts.duration` overrides the def; a refresh keeps the longer remaining — no magnitude stacking), `remove`, `maintain` (a live-driven permanent status whose per-instance `mult` a driver refreshes each tick — the encumbrance path; carries no `mods`, so no re-derive), `has`/`list` (the HUD reads `list`, tinted by def `color`), `scale`, and the per-tick `update`. `sceneRpg.step` ticks `StatusSystem.update` then `EncumbranceSystem.update` at the top of the tick loop, before the mover reads `scale`. The demo defs live in `RpgStatuses` (`encumbered`/`regen`/`fortify` + the survival debuffs).

**Survival needs.** The `Survival` module (`Gameplay/Survival`) — `Thirst`/`Hunger`/`Drowsiness`, each a rising-meter component `{ value, max, rate, critical, status }` (0 = fine, `max` = critical) with a thin system over a shared core: `Survival.tick` raises + clamps the meter and, at `value/max >= critical`, applies the named debuff `Status` (reusing the Status kit, so the consequence shows in the HUD); `Survival.restore` lowers it (returning whether it changed, so a no-op drink/food is refused). Opt-in (only the player carries them) and carried across map changes like `Stamina`. Restores: a `Consumable` with `thirst`/`hunger`; Drowsiness restores by **sleeping** — the bed's `"bed"` interaction sets `_sleeping` → `step()` ramps `Time.scale` multiplicatively **on `Time.raw`** (`Time.delta` is itself scaled) up to `RPG_SLEEP_SCALE_MAX`, with `WorldClock`/`Weather` running at the full scale while the tick-bound sim caps at `World.sim.maxTicks`, draining `Drowsiness` each tick; hitting the ceiling fires the time-skip achievement once per sleep (`_sleepPeaked` guard); any key/click wakes (checked before the tick loop) and restores `Time.scale = 1`. Sleeping skips time but costs water/food (those needs keep rising). The HUD shows the needs as reserve bars (`1 − value/max`).

**Death (`Mortal` / `Downed`).** What happens at 0 hp is configured per spawn preset by the opt-in `Mortal` component (`Gameplay/Combat`), resolved in one place — `RpgScene.resolveHealth` (the instant reaction) + `RpgScene.updateDowned` (the down-timer) — so the damage systems just subtract, and a `Health` body with **no** `Mortal` is left alone. Kinds:

- **`corpse`** (mobs) leaves a lootable body: `_toCorpse` strips the combatant **in place** (detaches `Health`/`Stats`/`Brain`/`State`/`Velocity`/`PrevPosition`/`Faction`/`Animator`, makes the collider non-solid, dims + flattens the `Visual`) and tags `Interaction { kind: "corpse" }` — E opens the standard `StorageUI` over the body's own `Inventory`. Pickup credit (quest/achievement `collect`) flows through the per-open `scene._storeOnTake` hook that only the `"corpse"` action sets — a plain chest never sets it, so withdrawing can't farm collect quests (`StorageUI.close` clears it). `reapCorpses` (tick loop) removes a corpse once its `Inventory` empties (a lootless kill reaps the same tick). The corpse is the **same entity**, so chunk demote/unload snapshots it like any resident; the scene's `onKill` detaches the species marker so the radar stops blipping the body.
- **`despawn`** spills the `Inventory` as ground drops then removes the entity (kit path; no live preset uses it).
- **`respawn`** (player) refills to `Stats.maxHp` and repositions.
- **`down`** (companions) — detaches `Health` (so `FactionSystem.nearestHostile` stops targeting it and the death scan skips it), zeroes velocity, dims the sprite, attaches `Downed { timer }`; after `Mortal.recoverSecs` of sim time `updateDowned` re-adds `Health` (`reviveHp`), un-dims, and teleports it to the recovery spot — `sceneRpg._recoverSpot()` = the player's settlement centroid, else the map spawn. A downed companion round-trips a map change via `EntitySnapshot` (it carries `Downed`, not `Health`).

The scene injects the side effects as handlers (`onKill` — fired for `despawn` + `corpse`, before the body transform — plus `onRespawn`/`onDown`/`downSpot`/`onRecover`). `FollowerSystem` holds a `Downed` companion still; the Squad tab shows its status and disables Kick; the carry bonus is untouched (it tracks `Follower.state`, which a down→recover cycle doesn't change).

**Loot, progression & dialogue.** `ItemDrop` = `{ itemId, qty }` on a non-solid sensor entity collected on overlap. `QuestLog` holds quest defs + active progress (objectives `{ kind: "kill"|"collect"|"reach", target, count }`, **item-only rewards** — there's no XP); `RpgProgression.applyReward` is the single apply path. The scene calls `QuestLog.report(kind, target)` after gameplay events and turns in on NPC interaction. `NPC` = `{ name, lines, questId? }` — a proximity dialogue panel that can offer/turn in the linked quest. `Animator`/`AnimationSystem` are a data-driven sprite state machine: a `graph` of named `AnimState`s (`{ sprite, start?, frames, fps, loop }`); the controller picks `state`, `update` advances playback into the entity's `Visual` (clamping `frames ≥ 1` — the SVG quirk, GMRT.md §3). `start` offsets the state into a **shared strip** (`vis.subimg = start + frame`) — how the unified humanoid sheet packs its animations into one sprite.

**Paper-doll appearance (`Appearance` / `AppearanceSystem`).** Humanoids are one unified, tintable body sprite with worn gear drawn as **overlay layers**, not a baked sprite per outfit.

- **`spr_human`** is the canonical humanoid strip, hand-drawn in Aseprite — the source of truth is `tools/pixel-art-kit/templates/human/sheet.png` + `sheet.json` (edit/re-export THOSE and re-run the importer; the sprite folder is importer-owned): 11 foot-anchored 32×32 frames in 2-color art (white fill + dark outline), tagged idle 0 / walk 1–2 / fist 3–5 / kick 6–10, with head/torso/hands/feet kept as disconnected blobs because `human_sprites.py` segments each frame's parts to cut the worn/held overlays from them (hand/foot pairs told apart by blob SIZE, learned from the neutral frame; the importer **fails fast** if a redraw breaks the 6-blob contract). The white fill is tinted per entity via `Visual.color` = the skin tone (`RpgPlayer.SKIN` is a literal GM color int — a top-level `Color.parse` would race script load order); the outline stays dark under the multiply. The animation graph is defined once in `RpgPlayer.animGraph()`; the unarmed fist-fallback swing alternates punch/kick (`PlayerSystem` latches `Playable.attackAnim` per swing); armed melee and gun-fire always play the punch thrust, so a held weapon rides the hand.
- **`Appearance`** (Core/Component — `RenderBillboard` reads it) is the layer stack `{ back: [{sprite,color}], front: [...] }`: `RenderBillboard` draws `back`, the body (`Visual`), then `front`, all at the same subimg. **Coplanar depth equality cannot be relied on** (sprite auto-trim gives each sheet's quad different vertices, so interpolated depth diverges by float rounding under the depth-writing pass — a later layer randomly loses `cmpfunc_lessequal`), so each layer is **Y-biased** by draw order (`BB_LAYER_DY` world px per step: front layers toward the south-side camera at +y, back layers away at −y) — decisive in the depth buffer, invisible on screen; `sh_meshlit`'s texel cutout keeps transparent texels from writing depth. It must be **Y, not Z**: an upright sprite's quad is a constant-y vertical plane, so a z offset slides the layer within the plane with zero depth separation. Overlay layers keep their **own** color — the body's `Visual.color` is the skin tint and must not bleed into outfit colors; whole-doll effects (the downed dim) ride `Visual.alpha`, which layers share.
- **`AppearanceSystem`** (Gameplay/Equipment) rebuilds the stack derived-from-source, like `StatModel.recompute`: it walks `Equipment` slots (`backpack` → back; `armor`/`trinket`/`weapon` → front) and pushes each worn item's `Equippable.worn` sprite (`asset_get_index` + `sprite_exists`-guarded). Rebuild runs at the same chokepoints as the stat re-derive — `equip`/`unequip`, plus after the carried sheet lands via `EntitySnapshot.apply` in `RpgMap.go`/`resume` (Equipment arrives there outside `equip()`); `Appearance` itself is never serialized. **Invariant: every overlay sheet mirrors `spr_human`'s strip layout** (frame count/order, cell, foot anchor) — overlays are derived by `human_sprites.py` from the hand-drawn frames themselves, never freehand, so they can't desync.
- **Held weapons are not sheets**: a weapon `Equippable` with no `worn` falls back to the item's own icon anchored at the right hand — the importer emits each part's per-frame centroid as `anchors` (origin-relative offsets), `AppearanceSystem` pushes an anchored front layer `{ sprite: item.sprite, anchor: "handR", scale: HELD_SCALE }`, and `RenderBillboard._drawLayer`'s anchored branch draws the icon (subimg 0, signed-xscale mirrored) at that frame's hand point — every weapon gets a held visual with zero dedicated art, and the hand's own motion carries the thrust/kick. Bespoke posed art can still set `worn` (the `weapon` slot stays last in `FRONT_SLOTS`). Item **icons** auto-wire by the `spr_item_<id>` naming convention with the `RpgItems.ICONS` alias fallback (many-to-one entries only, `sprite_exists`-guarded); an unmatched id keeps the UI's colored-box fallback.
- **Every humanoid is a doll.** A raider spawns as `spr_human` with a deterministic skin (`RpgSpawn.SKINS`, hashed from the spawn cell so a regenerated chunk keeps the same face) plus an **authored** outfit — an `Appearance` with **no** `Equipment`, which `AppearanceSystem.rebuild` deliberately leaves alone (only equipment-carrying dolls are derived/cleared). NPCs and companions get a hashed skin + the tintable civilian outfit (near-white sheets colored per entity via the layer color — the npc descriptor's `color` sets the shirt; a companion's `opt.color` becomes its shirt, not a whole-body wash). `CombatAI._animate` drives the mob doll (idle/walk/attack per state; facing flipped by velocity **sign**, magnitude-preserving); the aggro cue is a flush — `Color.merge` from `Brain.baseColor` (captured at attach; the skin tint) toward the state color, `k = 0` restoring the base exactly. `FollowerSystem` drives a companion the same way; static NPCs hold the idle pose. Non-humanoids: creatures and the fence keep the plain single-`Visual` path; boxy props with a vox model carry a `Mesh` instead (see renderer.md → `RenderMesh`).
- **Entity size is a baked per-preset design scale; art density divides the draw scale; `size` is the separate per-spawn scalar.** A preset def's `scale` (and `RPG_PLAYER_SCALE` via `RpgPlayer.spawn`) is the design size, baked at spawn into `Visual.scale` **and** the `BBox` — so the foot shadow (BBox-driven) and the paper-doll layers (drawn at the body's `xscale/yscale`) follow with no extra plumbing. A spawn descriptor's `size?` scalar multiplies on top (the knob for boss variants), baking BBox + Visual + `Mesh` uniformly so a sized entity's look never diverges from its collider. The draw scale is `scale / SpriteMeta.density(sprite)` (see utilities.md → SpriteMeta), so art of a different resolution lands at the same world size and never touches the BBox; bake sites are `EntityPreset.spawn` / `RpgPlayer.spawn`, and `AnimationSystem` refits when a graph state swaps sheets (mixed-density graphs are legal; a `Visual` without `scale` is legacy raw, never refitted). Overlay sheets inherit the body's draw scale — correct via the strip-layout invariant. Because `|xscale|` carries size, a facing flip must preserve magnitude (`vis.xscale = ±Math.abs(vis.xscale)`), never assign bare `±1`.

**Interactions (`Interaction` / `InteractAction`).** "Walk near + press E" is two-piece and data-driven (`Gameplay/Interaction`): an entity carries `Interaction { kind, ...params }` (flat per-instance data the action reads); the `InteractAction` registry holds the behaviors (`register([{ id, prompt, run(ctx) }])` with `ctx = { scene, world, id, comp, playerId }`) — adding an interaction is a data entry, not an engine edit. The RPG's set registers in `RpgInteractions` (via `RpgContent.register`) in two shapes: **window** actions open a UI and set `scene._interOpenId` so the engine range-closes/refreshes them (`storage`/`workbench`); **instant** actions act once per E press (claim/arcade/bed/door + the survival trio, which act on the **player**). The pick/prompt/dispatch engine is `Interactable` (Demo/UI): each frame `_pick` chooses one target (cursor-in-range, else nearest-in-range), the prompt pill reads the def's `prompt`, and E → `InteractAction.get(comp.kind).run(ctx)` — no per-kind switch; E is arbitrated once by `sceneRpg._dispatchInteract` (station vs NPC). Interactions are buildable (`BuildMode.CATALOG`) and authorable in the level editor.

**Genre UI managers.** The gameplay overlays share one window shell: a **near-fullscreen fixed overlay** — absolute full-screen host + dim backdrop + centered card — **built once** in `create()`, shown/hidden via `.enabled`, per-open state on the scene (`_store*`/`_trade*`/`_craft*`/`_mod*`, cleaned by `teardownScene`), refreshed on a `_*Dirty` flag, and threaded through `handleEscape`/`_resolveContext`/`_dispatchInteract`. Tables are built once and updated via `setRows`, so a column sort survives every refresh (a row sort is view-only — it never reorders the underlying `Inventory`). Per manager, the unique contracts:

- `SystemMenu` (Core) — the app's **one menu**: global, open-anytime, tabbed (System/Settings/About + injected tabs), on a `UIModal` root sized from `display_get_gui_height()` at open (flexpanel can't resize after layout). It pauses everything while open: `LevelManager.step()` skips `scene.step()` while `isOpen()`, the menu forces `Time.scale=0`/`Time.delta=0` each frame (UI runs on `Time.raw`), and the modal blocks pointer + nav beneath it. A scene opts into gameplay pause/nav handling with `this.gameplay = true` set in `create()` (a subclass field initializer wouldn't run — GMRT); while closed over such a scene it holds `UINav.suspended = true`. **F1** opens anywhere, gamepad **Start** during gameplay; gameplay **Esc** is context-aware — the scene's optional `handleEscape()` hook gets first refusal, then an active guest minigame's `scenes.back()`, only then the menu. `obj_game` drives `update(this)` in `Step_0` before `UINav.update` (the System tab drives the live scene via the `LevelManager` interface); `LevelManager._apply` calls `reset()` on each destroying scene swap. The dev sim controls (step frame / restart / time scale / readouts) live in the Debug overlay, not the menu.
- `StorageUI` — the Bag↔Chest transfer window: any entity tagged `"storage"` with an `Inventory` is a chest. Two sortable columns whose column set mirrors the Settings-driven `invCol*` toggles (`_applyColumns` re-applies on open and on a live toggle flip). Double-click (or a browse-mode confirm) transfers, single click selects; a fungible stack > 1 opens the shared **amount picker** (a top-of-stack modal on `scene._storeQtyModal`: `close()` dismisses it if the window closes under it, and `handleEscape` cancels the picker before the window); an instance moves whole, **by reference**, preserving `uid`/`mods`. Store All / Take All bulk-moves greedily, halting at the destination's cap. Favorited-protection + the last-copy hotbar unbind live in `_move`/`_doMove`. Contract: `build(scene)` once after player + ui exist, `refresh(scene)` when dirty (driven by `Interactable.update`), set `scene._storeDirty` when the bag changes elsewhere.
- `TradeUI` — the merchant window: an NPC carrying `Merchant` + a stock `Inventory` opens it instead of the quest dialogue. LEFT = buy (the stock), RIGHT = sell (the bag minus the currency item); worn or favorited items are refused with a toast; a finite merchant shows its till. All mechanics are **`TradeSystem`** (`Gameplay/Trade`) — this file is presentation + the gesture. An NPC window has no station range-close, so it auto-closes beyond `RPG_TRADE_RANGE`; the scene ticks `TradeSystem.update` each frame (finite restock).
- `CraftingUI` — the workbench window (`Interaction` kind `"workbench"`). A single module slot (`Interaction.module`) holds a `WorkbenchModule`; the module bar (rebuilt each refresh) offers Remove + a per-owned-module Install (swap-aware — frees the incoming bag slot first, returns the outgoing module, warns if the bag is full). The content area **swaps by module kind structurally** (`insertChild`/`removeChild` — a disabled sibling still reserves flex space): craft mode is a recipe master-detail filtered by `Recipe.requires` vs the slot (base recipes always show; `CraftSystem.canCraft`/`craft` take the module and enforce the gate); weapon-mod mode hosts `WeaponModUI`. `BuildMode` deconstruct returns a slotted module to the bag so it can't be lost.
- `WeaponModUI` — the attachment **panel** (no window of its own): `buildPanel(scene, listHost, detailHost)` + `refresh(scene)`, hosted by `CraftingUI`'s weapon-mod mode. Master-detail in plain non-clipped columns (the GMRT clip caveat, GMRT.md §1): LEFT the owned weapon instances (selected by `uid`); RIGHT the selected weapon's composed stats (`EquipmentSystem.composeWeapon`), a gun's ammo section (acting on the SELECTED instance via the `EquipmentSystem.*Slot` helpers), the named attachment slots (install into the first matching empty slot; remove refunds), and the compatible owned attachments. Install/remove run `StatModel.recompute` (an attachment may grant `Stats`) and set `_craftDirty` + `_invDirty`.
- `BuildMode` — grid build mode (stateless singleton, like `Interactable`): `build(scene)` once, `update(scene)` each frame after `Interactable.update` (outside the tick loop), `drawWorld(scene)` in `draw()`; **B** toggles. The palette is a `gemsCatBar` HUD bar over the data-driven `BuildMode.CATALOG` (tiles / furniture / lighting / stations / defense / survival). An item is a **tile** (edits its named layer via `TileEdit`; a wall item's `mat` picks the `TileType` from `scene.wallTypes`; floor edits touch no collider) or an **entity** (`make(gx, gy, scene?)` builds a descriptor through `RpgSpawn.spawnEntity`, so a built prop is identical to a file/streamed one). LMB places (per-item cost), RMB deconstructs (refunds); `_overHud` skips world edits while the cursor is over the bar. Building is **gated to a player-owned `Settlement`** (see gameplay.md → Settlement): E at a Survey Post (`"claim"`) founds the settlement via `Settlement.found` and then detaches the post's `Interaction` so it can't re-found; build mode opens only while standing on owned land, and placement is gated cell-by-cell (`Settlement.ownerAt`). The hub is an authored colony-faction settlement (`meta.settlements`) whose NPCs/stockpile chest are its `Resident`s, so the player's founded Home and the colony coexist. Per-scene state: `_built` (`"gx,gy" → tile item id`), `_builtEnts` (`"gx,gy" → { ent, itemId }`) — scene-tracked, **not** chunk-managed, like the squad — plus a static `BuildMode.active` mirror (set only while the `"build"` input context owns input) that `drawWorld` reads. Built tiles + entities persist across map changes by construction (the map pool).
- `RpgWorldOverlay` — the world-space overlay: `drawWorld(scene)` from `sceneRpg.draw()` **after `renderer.draw()`** (the chunked overworld's `RenderChunks` ground fill is opaque and would hide overlay content drawn first). Draws drop rarity squares, projectile dots + fading hitscan tracers (`pushTracer` — the firers push muzzle→impact streaks), and the reach-quest zone. The HUD/dialogue/inventory are real GUI-layer panels; walls/floors/territory render via the tile, mesh, and zone passes (see renderer.md).

**World time & day/night.** `WorldClock` (Demo) is the in-game clock — a static class like `Time` (one world clock): `hour` (0–24 float) + `day` (1-based), advanced once per frame from `sceneRpg.step()` by `Time.delta` (pauses with the game, dilates with `Time.scale`); `dayLength` = real seconds per in-game day. The scene `reset()`s it once in `create()` — **not** per map — so a portal trip keeps the hour. `phase()` derives night/dawn/day/dusk from `hour`; `tint()` interpolates a keyframe table into `{ color, alpha }`, consumed by `RenderLighting` as its injected ambient term (`RpgMap.build` passes `ambient: () => WorldClock.tint()`) — day/night is the light map with no lights.

**Seasons & temperature.** The season derives purely from `day` (no stored state): `daysPerSeason` days each, four cycling forever; season biases the `Weather` transition weights and the `Temperature` baseline. `Temperature` (Demo) is the ambient temperature in Kelvin — a **pure derivation, not a stored sim**: `now()` = `ZERO_C` + the season baseline + a diurnal cosine peaking mid-afternoon + the live `Weather.tempMod()` (which folds in the active climate zone's offset); all deltas are scale-agnostic increments over the one baseline. Kept **off** `WorldClock` so the clock stays the pure temporal authority. `display()` formats `now()` in the `tempUnit` Setting (`K`/`C`/`F`).

**Weather.** `Weather` (Demo) is the global sky — a static singleton like `WorldClock`: a fixed condition table (each entry a render look + a Kelvin `temp` delta) + a season-biased transition. `update(dt)` runs on `Time.delta` (freezes on pause, dilates with `Time.scale`) and accumulates `Weather.time()` — the cumulative sim clock the weather **visuals** scroll on, so rain/snow fall and cloud drift pause too. It counts down a hold then re-rolls by the season's weights, **excluding** the current condition (a change always changes the weather); a change cross-fades over `_fadeTime` (`previous()`/`current()`/`blend()` let the render pass + `tempMod()` lerp the outgoing→incoming). `reset()` (scene `create()`, once) settles a clear sky; the singleton survives map changes.

**Climate zones (regional weather).** A `"climate"` `ZoneMap` channel lets a region override the open sky: `Weather.enterRegion(zone)`/`exitRegion()` read the zone's flat `data` (`weather` forced condition + `tempMod` Kelvin offset) into an override slot; the displayed condition is `override ?? ambient` — the season-rolled ambient keeps running underneath and resumes on exit (the cross-fade handles both edges). Zones are data-driven from a level file's `meta.climate` array (`[{ name, rect, weather?, tempMod?, color? }]`), painted once by `RpgMap.build`. `sceneRpg._updateClimate()` tracks the **player's** climate cell directly each frame (a single `ZoneMap.idAt` lookup — cheaper than `ZoneSystem`'s all-entity sweep) and fires enter/exit on a border cross; `RpgMap.suspend` calls `exitRegion()` so a portal trip clears it (the next map re-detects on its first step). **Indoor maps** (`meta.indoor`) skip the `RenderWeather` pass — the global `Weather` keeps running; only its visual is suppressed.

**`RpgScene`** (Demo) holds the combat/loot plumbing as free functions taking the scene: `trackDamage` (also pops ally numbers for every `Follower`, by live query), the `Mortal` death pair `resolveHealth`/`updateDowned` (see _Death_), `spillLoot`/`spawnDrop`, `collectDrops`. Scene-specific side effects are the injected handlers; the scene supplies the contract fields `world`/`playerId`/`_hpTrack`/`_invDirty`. The enemy set is derived live by `Faction` (Health-bearing bodies hostile to the player) — not stored, not a tag.

**`RpgInventoryUI`** (Demo) is the character window — the shared near-fullscreen shell (on `scene._invWin`, **not** a `UIModal`) hosting `gemsTabs`: Items, Equipment, Squad, Stats, Quests, Achievements, Settings. Contracts: the Items tab is a bag slot **grid** (`gemsSlots`) beside a detail pane (`_refreshDetail`, rebuilt on selection); the grid pads with empty cells to `Inventory.capacity` (bag size reads at a glance), and `_refreshGrid` resizes the host via flexpanel point mutation (the `UIText` idiom). The grid+detail row deliberately uses **no `gemsScroll`** — a clipped scroll beside a non-clipped sibling is the GMRT batch-flush trap (GMRT.md §1). The `invCol*` Settings toggles govern only the chest/trade **tables** (`InvTable.columns`, shared by `StorageUI`/`TradeUI`); the bag grid has no columns. `rebuild(scene, { equipSlots, extraRows? })` refreshes live data only — the category filter + active tab survive every equip/use, and selection re-maps by instance `uid`, else `itemId`; `equipSlots` is the worn-slot rows to show, `extraRows(scene, host)` appends genre lines. The Squad tab repopulates per rebuild (membership changes), but each row reads live components, so follow/wait flips and down-state need no rebuild; the Achievements tab is built once (the def set is static after registration) with live status text. The scene keeps only `invOpen` + `_invDirty`; the HUD stays per-scene (`sceneRpg._buildHud`).

**`sceneRpg.step()` is the reference orchestration**: edge-toggle the inventory window → per tick: `snapshot` → the `physics` Pipeline (headed by `PlayerSystem`, the player brain) → `trackDamage` → `resolveHealth` → `updateDowned` → `collectDrops` → reach/quest/achievement checks → `flush`; then once per frame: `AnimationSystem.update`, NPC proximity + dialogue, `Interactable.update`, `BuildMode.update`, `camera.update`, an inventory rebuild when `_invDirty`, and `_checkPortals()` **last** (a door swaps the world out from under everything). No pause gate in `step()` — `obj_game` skips `scene.step()` entirely while `SystemMenu` is open.

**Map graph & persistence.** Maps are discrete level files connected by portals, not one streamed world (the fit for the JSON-parse size limit and the one-`World`-per-scene model). The graph is `RpgLevel.MAPS` (`{ mapId → file }`) + `RpgLevel.START` (extract to a manifest if it grows). A level file adds `meta.entries` (named spawn points — `RpgLevel.build(world, data, entryId)` resolves the spawn, falling back to `entries.default`) and the `portal` spawn preset (`{ toMap, toEntry, label?, color? }` → a non-solid sensor entity). `sceneRpg.create()` builds the persistent UI once (it reads `world`/`playerId` live, so it survives a map swap), then calls **`RpgMap.go(scene, mapId, entryId)`**, the portal-travel orchestrator:

- Visited maps are kept **alive and suspended** in the `World.levels` registry (the map pool — the registry entry IS the park bundle; there is no scene-side pool). `go` parks the current map (`suspend` — stash the `world`/`level`/`renderer`/`camera`/`pipeline` refs, no teardown), then **resumes** the target's parked bundle (a revisit: no file reload, no rebuild) or **builds** it from file (first visit only). A resume re-binds the map-context statics (the `MotionPlanner` grid + `CombatAI.bind`).
- Only the **squad** crosses worlds: `go` collects every entity sharing the player's `Squad` id (player first — there is no per-map player and no carried component subset), forces any `"wait"` member back to `"follow"` (+carry bonus — waiting is map-local, never a way to stay behind), and moves each as a **whole entity** through `World.levels.take`/`put`, landing at the target's entry with Position/Velocity overrides. `scene.playerId` re-latches (and is re-derived from the live `Playable` query each frame anyway).
- Everything else persists **by construction**: a map builds from file exactly once, then only freezes/thaws as-is — no eviction, no cold serialize, no respawn-from-file reconcile. Player edits (builds, founded settlements), kicked companions, dead enemies, and file spawns (which run once, ever) are simply still there on a revisit. The pool is session-scoped (`sceneRpg.destroy` parks + frees every entry — a fresh RPG open is a new world); memory is bounded by the map-graph size. The session pool is what a disk save serializes.
- `RpgMap.checkPortals` (step's last line) travels through the first portal the player overlaps. The editor's Test Play boots a `playtestFile` as a synthetic portal-less `_playtest` map. `_updateNpc`/`_checkReach` guard the no-NPC / no-reach-marker maps.

**Save/Load (disk persistence).** `SaveGame` (Demo) serializes the session over the Core `Snapshot` pass frame + `Json` codec (see utilities.md). A slot is a directory `saves/<slot>/` (`manifest.json` + optional binary blobs), listed by `saves/index.json` — the load menu reads the index because GMRT's `file_find_first` scans the build dir, not the save area (GMRT.md). Three passes, each owning capture **and** restore so they can't drift: **meta** (the slot card), **sim** (`WorldClock`, `Weather`, `Profile`, `Achievement`), and **maps** (per resident map: the component export minus chunk-owned + transient components, `built`/`builtEnts`, the `"settlement"` zone channel, the deep chunk cache). Restore boots a fresh RPG scene whose `create()` load-branch runs the passes: the squad re-lands through the existing portal-transfer machinery (`RpgMap.build` with the extracted squad), and every other saved map waits in `SaveGame._pendingMaps`, applied on that map's first build (the active map now, a parked map when first portaled to — `RpgMap.build` consults `takePendingMap`). The deep chunk cache imports before the first stream (`ChunkManager.exportCache`/`importCache` — only touched chunks' entity-state delta; terrain/walls/spawns regenerate deterministically from the seed). Player builds replay via `Blueprint`; the dense resident tile grid is not serialized (it replays from `built`). The user-facing Save/Load tab is injected into `SystemMenu` via `SystemMenu.addTab` from `obj_game` — the seam that keeps Core free of the Demo's `SaveGame`.

**`Blueprint`** (Demo) is the serializable build-set: `capture(scene, x1,y1,x2,y2, {withState})` → a `Json`-safe plan `{ tiles, ents }`; `stamp(scene, ox, oy, plan)` re-lays it (tiles first so a door reads finished walls; one wall remesh at the end). All placement routes through `BuildMode.applyItem` (the shared core of `_tryPlace` — no cost/gate), so a stamped build is identical to a hand-placed one; a built entity's optional `snapshot` restores exact state (a chest keeps its contents) rather than a fresh `make()`.

**The squad.** The party is a **component, not scene data**: `Squad { id }` (Gameplay/Squad) marks membership — the player mints a unique id at spawn, every hired companion carries the same id, and there is **no roster list anywhere**: every consumer resolves membership by live query (`FollowerSystem.members(world, squadId, playerId)` — player first). `Follower` (`{ state: "follow"|"wait", speed, range, bonusCapacity, bonusWeight }`) is the behavior component; `FollowerSystem.update(world, playerId)` drives every `Follower` per tick — the player id is **passed in, never stored**, so a transferred companion needs no re-link. `RpgSpawn.spawnFollower` spawns **unhired** (a map resident with a `rehire` `Interaction` — talk to recruit). `FollowerSystem.hire`/`kick` own the membership transitions: hire = `Squad` + follow + carry bonus + drop the rehire prompt; kick = the reverse, permanently and in place — a kicked companion stays a resident of that map until re-hired. `F` flips the nearest member between follow and wait — map-local only (a portal forces every member back to follow). A companion carries `Health` + a `down`-kind `Mortal`, so it's an attackable combatant (see _Death_). The **carry bonus** (`bonusCapacity`/`bonusWeight` onto the player's `Inventory`) is a balanced +/- delta applied by `FollowerSystem.applyBenefit`, paired with the state flip in **one place** (`FollowerSystem.setState`) so it can't half-apply — hire/kick and the portal's forced-follow all route through it; because the bonus is baked into the live `Inventory` and the player transfers whole, it rides across maps with no re-apply. Only the programmatic seed grants a bonus; the `follower` preset leaves it 0, so file-authored followers stay benefit-free.

**Chunk streaming & sim-LOD (scalable overworld).** A chunked map (`meta.chunked: true`) streams its terrain + entities around the player so the `World` only ever holds what's nearby (interiors keep the plain build-everything path). The engine is the Core **`ChunkManager`** (a plain instance class owned by the scene as `this.chunks`, like `LevelManager`); content comes from the generator it's handed plus the injected `opts.spawn` adapter. Built on `EntitySnapshot` + `Portal` (`{ toMap, toEntry }` on the doorway entity — a streamed door resolves via a live `world.query(Portal)`).

- **Two-ring sim-LOD** (Chebyshev chunk distance from the player's chunk): `d ≤ simRadius` → **SIM** (entities live in the World, walls have colliders, full simulate + render); `≤ loadRadius` → **LOAD** (entities held as snapshots, **not** in the World, drawn statically by `RenderChunks`; walls drawn, no colliders); beyond → **UNLOADED** (the whole record parked in an in-session cache keyed by chunk, restored on return — hurt/killed/moved entities persist). `ChunkManager.update(centerX, centerY)` (once per frame, outside the tick loop) diffs the rings on a chunk-border crossing, promotes/demotes/loads/unloads, then `world.flush()`es its own removals. **The squad is never chunk-managed** — the scene keeps it in the World always.
- **Pregenerated world**: `RpgMap.build` calls `ChunkManager.pregenerate()` once (the finite chunk grid, behind the scene fade), generating every in-bounds chunk's record up front — mid-game streaming is pure load/unload (`generate()` never runs during play; entity _spawning_ still LODs — descriptors stay dormant until a chunk first enters the SIM ring). The manager's **store-backed samplers** (`materialAt`/`costAt`, falling back to the generator's pure sampler outside the store) feed `TerrainStream`'s seam apron, `NavGrid`'s weights, and `PathFollow`'s pricing from stored terrain instead of re-sampling noise. Determinism (same seed → same world) holds per build; a non-pregenerated chunk still generates lazily on first load.
- **Resident grid vs streamed terrain.** A chunked map's `Level` is a large resident grid (`meta.worldCols/worldRows`) whose layers hold **player builds only** — the streamed terrain (authored hub + procedural wilderness) is owned by the `ChunkManager` with its own colliders + the `RenderChunks` pass, never written into those layers, so the two never conflict. The world is a finite rectangle: `ChunkManager` clamps streaming to in-bounds chunks, and `RpgLevel.buildWorldBorder` rings it with 4 always-present kinematic edge colliders. `IdPool` reuses freed indices, so streaming churn keeps the id high-water mark bounded.
- **Generation is a composition**, split so a different world is a swap, not a rewrite. **`ChunkGenerator`** (Core/Level) is the frame: an ordered list of passes (`{ salt?, apply(ctx) }`; `insert`/`remove` mirror `Renderer`) building a chunk's `walls`/`spawns` into a shared ctx, with the terrain base from the composed `field` sampler (required). **Each pass draws from its own rng stream**, seeded from `(cx, cy, seed, pass salt)`: a chunk regenerates identically every visit (the streaming contract), and inserting/removing a pass never reshuffles the other passes' output — declare a unique small-int `salt` per pass (an undeclared salt falls back to list index, which re-couples streams to order). All randomness through `Rand` (the GMRT-safe idiom).
- **`AuthoredStamp`** (Core/Level) is the authored-overlay pass: the level file's walls + spawns are indexed per chunk at construction, and any chunk inside the authored bounding box takes exactly that content — the pass runs first and sets `ctx.authored`, which the procedural passes respect by early-outing, so the hand-built hub stays procedural-free even where sparse. The injected `opts.spawn` adapter (`(world, level, desc) → id`; the RPG wraps `RpgSpawn.spawnEntity`) makes streamed + up-front spawns build through one code path (fail-fast if a chunk carries spawns with no adapter). `TerrainStream` reads the material table off `chunks.generator.palette` — an instance field, never a class static, so a swapped-in generator brings its own tilesets.
- **`PrefabStamp`** (Core/Level) is the generic prefab-stamp pass: chance roll → weighted pick from `Prefab.byTag(tag)` (resolved at construction — register prefabs first) → `Prefab.stamp` at a random interior offset (`margin` cells off the chunk border so stamped walls can't merge across a seam), deep-copying loot per stamp. Policy enters via two hooks so the pass stays content-free: `spawnFilter(s, field)` and `defaultLoot(s, rng)` — loot is drawn **before** the filter verdict so a skipped spawn consumes the same rng draws (determinism). Warns at construction if an eligible prefab carries `tiles`/`zones` (chunk output has no channel for them).
- **`OverworldGen`** (Demo/System) is the RPG composition: `create(opts) → ChunkGenerator`, wiring the RPG `TerrainField` (data in `RpgBiomes`) + the RPG passes (a `PrefabStamp` carrying the RPG spawn/loot policy hooks, plus scatter passes — content, not machinery). A different world (cave/desert/…) is a different composition of the same Core pieces; a variant overrides the policy hooks via `opts`. **`TerrainField`** (Core/Level) is a palette-driven pure-coordinate sampler; `RpgBiomes` (Demo/Content) is its data — per cell, **two value-noise channels** (an elevation gradient for water/sand/land plus an independent ground-detail channel; one shared gradient would instead ring every shoreline with fixed contour bands). Each palette entry carries a weighted `pathCost` (TileType convention: `null` → impassable) pricing `NavGrid`, `MotionPlanner`, and movement (`PathFollow.speedScale` — a mover's speed × `1/cost`); shallow water is wadeable but `spawnable: false` (travel yes, homes no); only deep water is `null` → greedy-meshed into `solid` rects that become **collide-only** colliders (not rendered — `TerrainStream` already draws the water) blocking bodies and feeding `NavGrid`.
- **`Prefab`** (Core/Level) is the registry of reusable mini-layouts, mirroring `Item`/`Rarity`: a `cols/rows` footprint + scope `tags`/`weight` + four optional prefab-local channels — `walls` (bare collide-only rects), `tiles` (into a named `TileLayer`), `zones` (into a `ZoneMap` channel), and `spawns` (**opaque** consumer-shaped descriptors — Core never reads their fields). `register()` fail-fast validates every channel against the footprint (an out-of-footprint rect would silently break a generator's seam margin). Two consumption modes: `stamp(ox, oy)` translates all channels local→absolute (pure data — the chunk path), and `apply(opts)` writes the Core-expressible channels into a live level (the caller remeshes a solid layer once after its stamps) and returns the translated `spawns` for the caller's adapter. The chunk pipeline consumes only `walls` + `spawns`. The RPG's defs live in `RpgPrefabs` (Demo/Content).
- **Capture/restore safety**: mobs survive demote/restore because state callbacks receive `(world, id)` from `StateSystem` (no world static), `State` holds pool-id **strings**, and `Brain` carries no self-id; the one per-map static (`CombatAI._level`, pathfinding) is refreshed on each `attach` and re-pointed by `CombatAI.bind` when a parked map resumes.
- **Scene wiring**: `RpgMap.build` branches on `meta.chunked` (chunked = the resident grid + `this.chunks`/`this.generator` + pregenerate + an initial `chunks.update(spawn)` + insert `RenderChunks`; plain is unchanged). The scene reads NPC/portal/enemy handles live by query, so chunk churn never dangles a handle. A map switch parks the manager with its world — a suspended chunked map (including its chunk cache) just stops streaming; `resume` re-centers it on the entry — and `RpgMap._free` drops it at scene end.
