# G.E.M.S. Architecture — UI & Input Systems

Area reference split out of the always-loaded core ([ARCHITECTURE.md](../ARCHITECTURE.md) — the layer map, cross-cutting invariants, and reference index). Loaded on demand: **Read this file before designing or modifying anything in this area.** Cross-references to sections of other areas resolve via the core index; runtime quirks live in [GMRT.md](../GMRT.md).

## UI System

The GUI layer is a **fixed design resolution** (`UI.designW`×`UI.designH` = 1920×1080) divided by the `uiScale` Setting, set via `UI.applyScale()` in `obj_game` `Create_0` — **not** `display_set_gui_maximise`. So UI lays out the same on every monitor and GameMaker scales the GUI to the window; the SDF locale fonts keep text crisp at any GUI→window ratio. The `uiScale` slider applies **live**: it calls `UI.applyScale(v)`, which resizes the GUI layer and `markDirty`s every root so they reflow. For that reflow to be clean, full-screen chrome must fill via flex rather than snapshot `display_get_gui_height()` at build — the lobby and `SystemMenu` use `gemsTabs({ grow: true })` (root + content host flex-grow) over `gemsScroll({ grow: true })`, so they re-lay-out to the new GUI size with no rebuild (fixed-size windows like the RPG inventory keep `gemsTabs({ height })`). World cursor picking under a **flat** matrix camera can use GameMaker's `mouse_x`/`mouse_y` (the level editor's `CameraPan` does), but under the RPG's **pitched** 2.5D camera they are wrong — the world cursor there is **`Camera.cursorWorld()`** (GUI mouse → surface px → `Camera.unproject`, the pitch-aware ground-plane inverse of `Camera.project`), latched once per frame by `sceneRpg.step` into `scene.mouseWorld` (+ the player's `Playable.cursorX/Y`) for `PlayerSystem` aim, `BuildMode`, and `Interactable`. Cursor-over-entity tests hit the ground-plane point (an entity's FEET) — pointing at a tall billboard's upper body lands behind it. The one place mixing GUI-mouse with the application surface (`CameraPan`) scales GUI→surface explicitly.

- **`UIElement`** (`scripts/UIElement/`): tree node backed by `flexpanel` (GameMaker Flexbox). `insertChild`, `removeChild`, `addComponent(c)`, `getComponent(Class)`, `getComponents(Class)`, `removeComponent(c)`. `markDirty()` propagates to root; `refresh()` calls `flexpanel_calculate_layout`. **`element.state`** is the shared per-element blackboard (`UIState` typedef: `hover`/`held`/`clicked`/`disabled`/`selected`) — behavior components write it, any sibling reads it; flat scalars only (no Map/Set — GMRT #15567), and component array order is write order (a writer must precede its readers on the element).
- **`UI`** (`scripts/UI/`): static root registry. `UI.insert(root, index?, enabled?)` (refreshes the root at registration), `UI.remove(root)`, `UI.setEnabled(root, bool)`. `update()` traverses in reverse (highest index blocks lower); `draw()` forward, refreshing any still-dirty root before drawing it.
- **`UIComponent` interface**: `{ onUpdate?(element, block), onDraw?(element), onDestroy?(element) }`. Built-ins: `UITrigger` (**the canonical pointer FSM** — hover/press/release-inside-commit; fires onEnter/onHover/onLeave/onDown/onUp/onClick and writes `element.state.hover/held/clicked`; a bare `new UITrigger({})` is a click swallower, and every clickable widget below runs one internally instead of cloning the logic — UIButton/UICheckbox/UISelect/UIStepper/UIDropdown/UIRebind/UISlider/UIAccordion); `UIButton` (the themed variant over the delegate: eases panel color/border/shadow, greys its label, live `getDisabled`/`getSelected` predicates written to `state.disabled/selected`); `UIText`; `UIRichText` (markup → colored spans `[c=#hex]…[/c]` + inline icons `[spr=name]`; self-sizes like `UIText`, host stacked lines in fixed-height rows); `UIImage`; `UIPanel`; `UISlider` (always-on value readout — `format`/`showValue`); `UISelect` (`< value >` cycler); `UIDropdown` (combobox field + chevron → popup list; the popup is an injected `onOpen(dropdown, field)` so Core stays theme-agnostic — `gemsDropdown` supplies a `UIModal` one, `UINav`-navigable + scrolling); `UIInput`; `UIRebind` (key-rebind row — click to arm "press a key…", next press rebinds. The capture **scans** the keycode range for the code whose `keyboard_check_pressed` is live this frame (`_scanKey`, 8..255) — `keyboard_lastkey` holds the PREVIOUS frame's key by design (documented behaviour), so reading it on the pressed-edge frame binds the stale key); `UIProgress` (0–1 fill bar); `UICheckbox` (`style:"check"` box+tick or `"switch"` pill+knob); `UITooltip` (self-detecting hover tooltip, feeds the global `Tooltip`); `UIStepper` (`< n >` over min/max/step); `UISlots` (inventory-slot grid; `draggable` opts into `SlotDrag`; immediate-mode; per-item entries carry optional `borderColor` (rarity tint) + `badge`/`badgeColor` (worn/favorite corner marks); **browse mode** mirrors `UITable`'s — `navActivate` enters it, arrows (read via the shared `UINav.readEdge()`) drive a 2D slot cursor (select on move, `onActivate` on confirm) via a per-frame `UINav.claimKeys(this)` claim that `UINav.update` consumes; built by `gemsSlots`, the RPG bag's grid); `UITabs` (tab strip — one focus stop, swaps content by `enabled`, no reflow; selects on press — deliberately snappier than the FSM widgets' release-commit); `UIAccordion` (collapsible; toggles on release-inside — deliberately normalized off press-commit when it adopted the shared FSM; confirm expands); `UIScroll` (vertical scroll for a `clip` viewport — draw-time `scrollY`, never flex mutation; the bar itself is the shared **`UIScrollbar`** model — track/thumb metrics + drag latch + draw over a normalized t ∈ [0,1], also consumed by `UITable`'s row-quantized bar); `UIModal` (full-screen exclusive backdrop, blocks pointer + nav, Esc/backdrop close; built by `gemsModal`); `UIDrag` (window drag handle — accumulates into `target.dragX/dragY`, offset-not-mutation); `UIResize` (window resize grip — companion to `UIDrag`, lives on a bottom-right grip; captures the target's current laid-out size on grab then sets `target` width/height via flexpanel mutation (`setWidth`/`setHeight`), clamped to `[minWidth/minHeight, GUI]`. Unlike drag it genuinely changes layout, so it mutates style rather than offsetting — the reliable-on-0.20 path `UIText` self-sizes with); `UINineSlice` (sprite-skinned panel; the source sprite needs nine-slice enabled in its `.yy`); `UIMinimap` (radar-blip view of a `World`, `rules` `[{ has, color }]` where `has` is a component token — an entity blips when it carries that component); `UIQuestTracker` (live list bound to an **injected quest source** — `opts.source`, the RPG passes its `QuestLog` — so this Core widget never references the RPG layer; immediate-mode, resolves `I18n.font(key)` at draw time); `UITable` (data table — declarative columns with text/color/icon accessors, a multi-key sort stack (click a header → primary key, re-click flips), external `setFilter`, `setColumns` (remaps the sort by each column's stable `key`), identity row-selection, sticky header, row-based scroll, zebra striping. Immediate-mode over ONE element so re-sort/filter never reflows; draw geometry recomputed each `onDraw` so it stays glued to a dragged window. **Browse mode**: `navActivate` enters it, then the table owns the arrows (via the shared `UINav.readEdge()`) with a per-frame `UINav.claimKeys(this)` claim that `UINav.update` consumes. Built by `gemsTable`; public reads are METHODS (`getView`/`getRows`/`getSelected`) — house style; the old "a getter shadowing a GM name faults on GMRT" report was dismissed by the 2026-07 re-audit).
- **`Tooltip`**: standalone static class (not a `UIComponent`). `Tooltip.set(str)` from anywhere; renders once per frame at mouse position via `Tooltip.draw()` in `Draw_75`.
- **`Toast`**: standalone static class (not a `UIComponent`), same pattern as `Tooltip`. `Toast.push(str, opts)` from anywhere; `Toast.draw()` in `Draw_75` (after `Tooltip`) ages the stack by `Time.raw` and renders a bottom-center timed stack (newest at bottom). `opts`: `{ duration, type ("info"|"success"|"warn"|"error"), accent }` — `type` picks the left accent-stripe color; entries fade/slide in+out and are culled when expired (`Toast.maxItems` cap drops the oldest).
- **`UIPointer`**: standalone static class (not a `UIComponent`) — the UI's frame-latched pointer state. `UIPointer.poll()` runs in `Step_0` before `UI.update` and latches the left-button edges + level + wheel once per frame into `UIPointer.pressed`/`released`/`down`/`wheel`. Every UI widget + UI-layer reader (`SlotDrag`/`BuildMode`/`DebugInspector`/`Dialogue`) reads those static fields instead of calling `mouse_check_button*`/`mouse_wheel*` directly — one query per frame, shared. (The original "realtime-sampled, can diverge within a frame" rationale is UNVERIFIED — the manual implies per-step sampling and it can't be tested headless — but poll-once stays the rule; a per-widget `const pressed = …` is also the `&&`/`||` left-operand clobber pattern, [#15549](https://github.com/YoYoGames/GameMaker-Bugs/issues/15549) in GMRT.md.)
- **`SlotDrag`**: standalone static class (not a `UIComponent`) backing drag-and-drop between `UISlots` grids (built with `draggable: true`). Reads the latched pointer edges from `UIPointer` (never `mouse_check_button*` directly — the `UIPointer` poll-once rule). A grid calls `SlotDrag.begin(grid, i)` on `pressed` over a filled slot (picks it up; source slot empties, floating icon drawn in `SlotDrag.draw()` in `Draw_75`), then `SlotDrag.hover(grid, j)` each frame the cursor is over one of its slots to **record** the drop target. `SlotDrag.update()` (`Step_0`, after `UI.update`) resolves on the release edge: drop onto the last-recorded slot (swaps occupants, works across grids), or — if none was ever hovered — restore to source. The recorded target is _persisted_ (not cleared when the cursor leaves a slot), so a small drift off the slot as the button comes up still drops. (Note: `UISlots.onUpdate` keeps the hit-test in instance fields `this._inside`/`this._hover`, not boolean local consts — those get clobbered mid-function on GMRT; that was the long drag-drop bug.)
- **`VirtualKeyboard`**: standalone static class (not a `UIComponent`) — on-screen keyboard for gamepad/mouse text entry into a `UIInput`. `VirtualKeyboard.open(input)` pops a `gemsModal` (exclusive backdrop, blocks background nav, Esc/backdrop cancels) whose body is a preview line + a grid of character keys; the keys are ordinary `gemsButton`s, so the whole keyboard is `UINav`-navigable for free (dpad/stick to move, A/Enter to type). Keys edit an in-memory buffer; **Done** commits to the field (`setValue` + `onConfirm`), Cancel/Esc/backdrop discard — the field is untouched until Done. Shift toggles letter case via live key labels (no relabel). `VirtualKeyboard.isOpen()` is a **method, not a `static get`** — house style; the old static-getter miscompile (real on 0.19) was dismissed on 0.20 by the 2026-07 re-audit.
- **`UINav`**: standalone static class — keyboard/gamepad menu navigation, touching neither `UI` nor `UIElement`. An element is **focusable** by duck-typing: a component implements `navActivate(element)` (confirm) and/or `navAxis(element, dir)` (horizontal adjust, `dir` = ±1). `UINav.update()` (`Step_0`, after `UI.update`) walks the enabled roots, collects focusables with a valid on-screen rect, and routes input: arrows/dpad/stick move focus to the geometrically nearest focusable in that direction (edge-aware `_pick` — the perpendicular term is the gap between rects, ties broken by collection order, so Down lands on the leftmost item below); a horizontal press over a `navAxis` widget tweaks it; Enter/Space/`gp_face1` → `navActivate`; Esc/`gp_face2` disengages. `UINav.draw()` (`Draw_75`) draws a pulsing focus ring. Collection **stops at an exclusive root** (`navExclusive() → true`, e.g. an open `UIModal`), mirroring the modal's pointer block. Focusables scrolled out of a `UIScroll` stay collectable; when focus lands on one, `_scrollIntoView` nudges each `UIScroll` ancestor so it comes into view. Engagement: the first nav input only engages + focuses; moving the mouse disengages; while a field is typed (`UIInput.active`) or a widget holds the browse-mode key claim (`UINav.claimKeys(owner)`, re-asserted per frame by `UITable`/`UISlots` and consumed once per `UINav.update` — released on owner destroy via `UINav.releaseClaim`), nav is suspended so the caret/browse cursor keeps the keys. `UINav.readEdge()` is the shared discrete edge read (keyboard arrows + dpad + confirm/cancel) those browse modes reuse; the analog-stick latch stays inside UINav's own `_readInput`. `obj_game` calls `UINav.reset()` on each scene swap and seeds `UINav.color` from the theme. Nav hooks live on `UIButton`/`UICheckbox`/`UISelect`/`UIDropdown`/`UIStepper`/`UISlider`/`UITabs`/`UIAccordion`/`UITable`/`UISlots`/`UIInput`; any new widget becomes navigable by adding `navActivate`/`navAxis` (a blocking root by adding `navExclusive`). **Debug**: hold `UINav.debugKey` (Tab) to draw every focusable boxed + numbered with direction lines from the focused element.
- **`SceneTransition`**: standalone static singleton — full-screen fade between scenes, replacing `obj_game`'s hard cut on `openScene`. `start(applyFn)` fades OUT to a solid cover, swaps the scene at full cover (`applyFn` rebuilds the UI hidden under the cover), then fades back IN. Wiring: `SceneTransition.update()` in `Step_0` (drives the timer + fires the swap at mid-fade, gated by `isBusy()`); `SceneTransition.draw()` **last** in `Draw_75` so the cover veils the UI teardown/rebuild too. Timer uses `Time.raw`.
- **`Dialogue`**: standalone static singleton — RPG paged dialogue box with typewriter reveal. `Dialogue.start(pages, opts)` (a page is a string or `{ speaker, text }`); reveals at `opts.speed` chars/sec (`Time.raw`), advances on Enter/Space/`gp_face1`/click. `Dialogue.update()` in `Step_0`, `Dialogue.draw()` in `Draw_75` (over the UI). Static fields are initialized with literals, not `Dialogue.x` self-references (the static-initializer self-reference quirk in GMRT.md).
- **`FloatingText`**: standalone static singleton — **world-space** floating combat numbers (damage/heal) that rise + fade. `FloatingText.push(x, y, value, opts)`; drawn from a **scene's own `draw()`** (inside the camera view), _not_ `Draw_75`. `obj_game` calls `FloatingText.clear()` on each scene swap (a number must not survive into the next scene). Ages by `Time.delta` (sim time — slow-mo slows the numbers too), unlike the GUI singletons on `Time.raw`.
- **Central layout guarantee** — components never observe NaN layout, so widgets carry **no per-widget NaN guards** (don't add them back). Flexpanel layout reads are NaN before the first `flexpanel_calculate_layout` (probe-verified on 0.20, including a child inserted into an already-calculated tree); three mechanisms close every path: (1) `UI.insert` refreshes the root at registration (covers a modal/dropdown root inserted mid-frame from an onClick, drawn the same frame); (2) `UIElement.update` refreshes a dirty root at end-of-update (mid-pass mutations); (3) `UI.draw` refreshes any still-dirty root before drawing it (insert-then-build scene roots, post-`UI.update` mutations like a UINav-driven accordion expand). Residual watch-item: a subtree inserted mid-update-pass into a not-yet-traversed sibling branch can still see NaN in that frame's `onUpdate` — hit-tests are NaN-safe (`point_in_rectangle` with NaN is false), and the two persistent-scalar sinks (`UITable._top`, `UIScroll.scroll`/`_track`) use positive-test clamps so NaN can't poison them. `UIElement._drawClipped` keeps its zero-size check (it also protects `gpu_set_scissor`).
- **Resolve `I18n.font(key)` at DRAW time — never cache the handle at construction.** A cached handle breaks two ways: `I18n.font` falls back to `draw_get_font()` for an undeclared key (freezing the wrong font), and a language switch (`I18n.load`) `font_delete()`s every old handle so a cached one dangles (renders the GM default 12pt Arial, or nothing). **Every font-taking widget** takes `font` polymorphically — a raw handle (number) OR an I18n font KEY (string) — and resolves live each draw via the shared **`resolveUIFont(f)`** (`scripts/UIDraw`); `UIQuestTracker` stores `*FontKey` fields. The GemsUI factories pass the **key**, never a pre-resolved handle. Widgets bracket a font/align/color-mutating `onDraw` with **`uiDrawSave()`/`uiDrawRestore(st)`** (also `scripts/UIDraw`) instead of hand-rolled `draw_get_*`/`draw_set_*` pairs. Exception: world-space render passes (`RenderChunks`/`RenderZoneLabel`/`RenderDebugTileMap`) still take a handle — they rebuild on map reload but not on a locale switch, so their labels keep the old font until the next map load (acceptable for debug-ish world labels).
- Many `flexpanel_node_style_*` setters in `UIElement` stay commented to keep the class under the 50-method ceiling (#15065); enable one on demand (see the flexpanel GMRT-Safe Idiom).

## Input System

**`Input`** / **`InputAction`**: `Input.register(key, action)`, `Input.get(key)` → `InputAction`. Query: `.down()`, `.pressed()`, `.released()`, `.value()`. Bind: `.bindButton(source, button)` / `.bindAxis(mode, axis)`. Display: `action.label()` → the primary binding as UI text (e.g. `"W"`/`"Shift"`/`"LMB"`), delegating to `InputButton.label()` / `InputButton.keyName(code)` (the one keycode→string table). This is the single binding→text source shared by the rebind row (`UIRebind`) and the live hint bar (`gemsKeyHints`), so a remap renders the same string everywhere. Bulk: `Input.bindAll({ key: [source, button], … })` registers a whole keymap in one call; `Input.unbindAll([keys])` removes them — used by the genre controllers. **All four query methods return falsy while a text field owns the keyboard** (`UIInput.active !== null`, via `InputAction.captured()`): typing in a UI field (e.g. the RPG inventory search) must not also drive gameplay hotkeys/movement — pressing `i` while typing "Hi" can't toggle the inventory. This is the same `UIInput.active` signal that suspends `UINav`; `UIInput` clears it on blur **and on destroy** (so tearing a focused field down at a scene change can't strand the capture).

**`InputContext`** (`scripts/InputContext/`, Core) — a named-context **stack** over the Input layer that generalizes `captured()` from "a text field mutes everything" to "the active context decides which actions are live." The active context is the top of the stack (base is always `"default"`); `push(name)`/`pop()`/`set(name)` (replace top — auto-pushes if only the base remains, so a forgotten `push` can't clobber `"default"`)/`reset()` (back to `["default"]`)/`active()`/`is(name)`. An `InputAction` may declare the contexts it is live in via `action.inContext(["play","window"])` — or, declaratively, an **optional 3rd element** in a `bindAll` spec entry (`fire: [INPUT_SOURCE.MOUSE, mb_left, ["play"]]`). The query methods then add `_blocked()` (`contexts !== null && !InputContext.allows(contexts)`) to the existing `captured()` guard. An action with **no** declared contexts (the default, `contexts === null`) is live in every context, so all existing keymaps (platformer/UI) are unaffected — only opt-in tagged actions are gated. `captured()` still wins (a focused field mutes regardless of context). Contexts/tags are **not serialized** (`Input.export`/`import` ignore them) — a controller re-applies them in `create()` each scene, so a saved/rebound keymap never loses its tags.

The **RPG scene** is the reference consumer: `PlayerSystem.bindKeys` tags its keymap — movement live in `["play","build","window"]` (the player keeps walking with a window open), `fire` `["play"]` only (so it **self-mutes** while building — LMB places tiles — or with a gameplay window open — clicks don't shoot — replacing the old `!BuildMode.active` reach-in), `interact` `["play","window"]` (open in play, close a station window in window; inert while building), `build`/`follow` `["play","build"]`. `sceneRpg` pushes `"play"` in `create()`, resets in `destroy()`, and each `step()` (before the tick loop, so the tick's movement/fire reads see it) calls `_resolveContext()` → `InputContext.set(...)` with **window > build > play** priority (`invOpen`/`_storeOpen`/`_craftOpen` → `window`; else `_buildActive` → `build`). A window thus **pauses** build mode (`BuildMode.update` gates `active` on `InputContext.is("build")`, so LMB/RMB on the window can't place/remove tiles) and resumes it on close. The single `E` press is arbitrated in one place — `sceneRpg._dispatchInteract()`: a station window open → `E` closes it; else pick station-vs-NPC by **cursor (`Interactable.isCursorOver`), then nearest to the player**, and call `Interactable.activate(scene)` or `scene._npcActivate()`. `Interactable.update`/`_updateNpc` only do proximity/prompt/dialogue text — no input reads.
