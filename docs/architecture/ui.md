## UI System

The GUI layer is a **fixed design resolution** (`UI.designW`×`UI.designH` = 1920×1080) divided by the `uiScale` Setting, set via `UI.applyScale()` in `obj_game` `Create_0` — **not** `display_set_gui_maximise`. UI lays out the same on every monitor; GameMaker scales the GUI to the window, and the SDF locale fonts keep text crisp at any ratio. The `uiScale` slider applies **live**: `UI.applyScale(v)` resizes the GUI layer and `markDirty`s every root. For that reflow to be clean, full-screen chrome must fill via flex rather than snapshot `display_get_gui_height()` at build — the lobby and `SystemMenu` use `gemsTabs({ grow: true })` over `gemsScroll({ grow: true })` (fixed-size windows keep `gemsTabs({ height })`). World cursor picking under a **flat** matrix camera can use `mouse_x`/`mouse_y` (the editor's `CameraPan` does), but under the RPG's **pitched** 2.5D camera they are wrong — the world cursor there is **`Camera.cursorWorld()`** (GUI mouse → surface px → `Camera.unproject`, the pitch-aware ground-plane inverse), latched once per frame by `sceneRpg.step` into `scene.mouseWorld` (+ `Playable.cursorX/Y`) for `PlayerSystem` aim, `BuildMode`, and `Interactable`. Cursor-over-entity tests hit the ground-plane point (an entity's FEET) — pointing at a tall billboard's upper body lands behind it. The one place mixing GUI-mouse with the application surface (`CameraPan`) scales GUI→surface explicitly.

- **`UIElement`**: tree node backed by `flexpanel` (GameMaker Flexbox). `markDirty()` propagates to root; `refresh()` calls `flexpanel_calculate_layout`. **`element.state`** is the shared per-element blackboard (`UIState`: `hover`/`held`/`clicked`/`disabled`/`selected`) — behavior components write it, any sibling reads it; flat scalars only (no Map/Set — GMRT #15567), and component array order is write order (a writer must precede its readers).
- **`UI`**: static root registry (`insert`/`remove`/`setEnabled`). `update()` traverses in **reverse** (highest index blocks lower); `draw()` forward, refreshing any still-dirty root before drawing it.
- **`UIComponent` interface**: `{ onUpdate?(element, block), onDraw?(element), onDestroy?(element) }`. The built-in contracts (plain visual widgets — `UIText`/`UIImage`/`UIPanel`/`UISlider`/`UISelect`/`UIProgress`/`UICheckbox`/`UIStepper`/`UINineSlice` — are JSDoc in the source):
  - **`UITrigger`** is the canonical pointer FSM — hover/press/release-inside-commit, writing `state.hover/held/clicked`. A bare `new UITrigger({})` is a click swallower; **every clickable widget runs one internally** instead of cloning the logic.
  - **`UIRichText`** renders markup — colored spans `[c=#hex]…[/c]` + inline icons `[spr=name]` — and self-sizes like `UIText`.
  - **`UIDropdown`**'s popup is an **injected** `onOpen(dropdown, field)` so Core stays theme-agnostic — `gemsDropdown` supplies a `UIModal` one, `UINav`-navigable + scrolling.
  - **`UIRebind`**'s capture **scans** the keycode range for the code whose `keyboard_check_pressed` is live this frame — `keyboard_lastkey` holds the PREVIOUS frame's key by design, so reading it on the pressed-edge frame would bind the stale key.
  - **`UISlots`** (inventory-slot grid, built by `gemsSlots`): immediate-mode; entries carry optional `borderColor` (rarity tint) + `badge`/`badgeColor` (corner marks); `draggable` opts into `SlotDrag`. Its hit-test lives in instance fields, not boolean local consts (the `&&`-clobber quirk, GMRT #15549). **Browse mode** mirrors `UITable`'s (below).
  - **`UITabs`** selects on **press** — deliberately snappier than the FSM widgets' release-commit; swaps content by `enabled`, no reflow. **`UIAccordion`** toggles on release-inside (normalized onto the shared FSM).
  - **`UIScroll`** scrolls a `clip` viewport via draw-time `scrollY` — never flex mutation. Its bar is the shared **`UIScrollbar`** model (track/thumb metrics + drag latch over a normalized t ∈ [0,1]), also consumed by `UITable`'s row-quantized bar.
  - **`UIModal`** is the full-screen exclusive backdrop — blocks pointer + nav (`navExclusive`), Esc/backdrop close.
  - **`UIDrag`** accumulates into `target.dragX/dragY` (offset, not mutation). **`UIResize`** genuinely changes layout, so it **mutates** style (`setWidth`/`setHeight`, clamped to `[min, GUI]`) — the same reliable-on-0.20 path `UIText` self-sizes with.
  - **`UIMinimap`**: radar-blip view of a `World`; `rules` are `[{ has, color }]` where `has` is a component token — an entity blips when it carries that component.
  - **`UIQuestTracker`** binds to an **injected** quest source (`opts.source`; the RPG passes `QuestLog`) — this Core widget never references the RPG layer.
  - **`UITable`** (built by `gemsTable`): declarative columns with accessors, a multi-key sort stack, external `setFilter`/`setColumns` (remaps the sort by each column's stable `key`), identity row-selection. **Immediate-mode over ONE element**, so re-sort/filter never reflows; draw geometry recomputes each `onDraw`, so it stays glued to a dragged window. Public reads are METHODS (`getView`/`getRows`/`getSelected`) — house style. **Browse mode** (shared with `UISlots`): `navActivate` enters it, then the widget owns the arrows via the shared `UINav.readEdge()` with a per-frame `UINav.claimKeys(this)` claim that `UINav.update` consumes.
- **`Tooltip`** / **`Toast`**: standalone static classes. `Tooltip.set(str)` from anywhere, rendered once per frame at the mouse in `Draw_75`; `Toast.push(str, opts)` renders a bottom-center timed stack aged by `Time.raw` (`opts.type` picks the accent stripe; `maxItems` drops the oldest).
- **`UIPointer`**: the UI's frame-latched pointer state. `poll()` runs in `Step_0` before `UI.update` and latches the left-button edges + level + wheel into static fields; **every UI widget + UI-layer reader reads those fields** instead of calling `mouse_check_button*`/`mouse_wheel*` directly — poll once, share. (A per-widget `const pressed = …` local is also the `&&`-clobber pattern, GMRT #15549.)
- **`SlotDrag`**: drag-and-drop between `UISlots` grids. A grid calls `begin(grid, i)` on `pressed` over a filled slot (source empties; floating icon drawn in `Draw_75`), `hover(grid, j)` each frame to **record** the drop target, and `update()` (`Step_0`, after `UI.update`) resolves on the release edge — drop onto the last-recorded slot (swaps occupants, works across grids), or restore to source if none was ever hovered. The recorded target is **persisted** (not cleared when the cursor leaves), so a small drift off the slot as the button comes up still drops.
- **`VirtualKeyboard`**: on-screen keyboard for gamepad/mouse text entry into a `UIInput`. `open(input)` pops a `gemsModal` whose keys are ordinary `gemsButton`s — the whole keyboard is `UINav`-navigable for free. Keys edit an in-memory buffer; **Done** commits (`setValue` + `onConfirm`), Cancel/Esc/backdrop discard — the field is untouched until Done. `isOpen()` is a method, not a `static get` — house style.
- **`UINav`**: keyboard/gamepad menu navigation, touching neither `UI` nor `UIElement`. An element is **focusable by duck-typing**: a component implements `navActivate(element)` (confirm) and/or `navAxis(element, dir)` (±1 adjust); a blocking root adds `navExclusive()` (e.g. an open `UIModal` — collection stops there, mirroring the pointer block). `update()` (`Step_0`, after `UI.update`) collects focusables with a valid on-screen rect and routes input: arrows/dpad/stick move focus to the geometrically nearest in that direction (edge-aware; ties broken by collection order), horizontal presses tweak `navAxis` widgets, Enter/Space/`gp_face1` → `navActivate`, Esc/`gp_face2` disengages. Focusables scrolled out of a `UIScroll` stay collectable — on focus, `_scrollIntoView` nudges each `UIScroll` ancestor. Engagement: the first nav input only engages; moving the mouse disengages; while a field is typed (`UIInput.active`) or a widget holds the browse-mode claim (`UINav.claimKeys(owner)`, re-asserted per frame, consumed once per `update`, released on owner destroy), nav is suspended. `UINav.readEdge()` is the shared discrete edge read the browse modes reuse. `obj_game` calls `UINav.reset()` on each scene swap and seeds `UINav.color` from the theme. Debug: hold Tab to draw every focusable boxed + numbered.
- **`SceneTransition`**: full-screen fade between scenes. `start(applyFn)` fades OUT, swaps at full cover (`applyFn` rebuilds the UI hidden under it), fades back IN. `update()` in `Step_0`; `draw()` **last** in `Draw_75` so the cover veils the UI teardown/rebuild too. Timer on `Time.raw`.
- **`Dialogue`**: paged dialogue box with typewriter reveal (`Time.raw`), advanced on confirm/click. Static fields are initialized with literals, never `Dialogue.x` self-references (the static-initializer quirk, GMRT.md §2).
- **`FloatingText`**: **world-space** floating combat numbers — drawn from a **scene's own `draw()`** (inside the camera view), _not_ `Draw_75`; cleared by `obj_game` on each scene swap. Ages by `Time.delta` (sim time — slow-mo slows the numbers too), unlike the GUI singletons on `Time.raw`.
- **Central layout guarantee** — components never observe NaN layout, so widgets carry **no per-widget NaN guards** (don't add them back). Flexpanel layout reads are NaN before the first `flexpanel_calculate_layout` (probe-verified on 0.20); three mechanisms close every path: (1) `UI.insert` refreshes the root at registration (covers a modal/dropdown root inserted mid-frame from an onClick, drawn the same frame); (2) `UIElement.update` refreshes a dirty root at end-of-update; (3) `UI.draw` refreshes any still-dirty root before drawing it. Residual watch-item: a subtree inserted mid-update-pass into a not-yet-traversed sibling branch can still see NaN in that frame's `onUpdate` — hit-tests are NaN-safe (`point_in_rectangle` with NaN is false), and the two persistent-scalar sinks (`UITable._top`, `UIScroll.scroll`/`_track`) use positive-test clamps so NaN can't poison them. `UIElement._drawClipped` keeps its zero-size check (it also protects `gpu_set_scissor`).
- **Resolve `I18n.font(key)` at DRAW time — never cache the handle at construction.** A cached handle breaks two ways: `I18n.font` falls back to `draw_get_font()` for an undeclared key (freezing the wrong font), and a language switch `font_delete()`s every old handle so a cached one dangles. Every font-taking widget takes `font` polymorphically — a raw handle (number) OR an I18n font KEY (string) — and resolves live each draw via the shared **`resolveUIFont(f)`** (`scripts/UIDraw`); the GemsUI factories pass the **key**. Widgets bracket a font/align/color-mutating `onDraw` with **`uiDrawSave()`/`uiDrawRestore(st)`** instead of hand-rolled pairs. Exception: world-space render passes still take a handle — they rebuild on map reload but not on a locale switch (acceptable for debug-ish world labels).
- **`UIDraw` is the shared-widget-primitive bucket** (Core) — it owns the idioms two or more widgets used to hand-copy; reuse these instead of re-rolling: `drawUIArrow`/`drawUICheck` (glyphs), `drawUIArrowPair` + `uiPointerSide` (the ◀ ▶ cycler chrome + half-hover latch, stashed BEFORE the FSM runs), `drawUIOutline` (fake-thickness nested strokes), `drawUIBar` (capsule track+fill), `uiContainRect` (aspect-preserving CONTAIN fit), `uiResizeTo` (no-op-when-unchanged flexpanel self-size), `uiTextRef` (string-or-fn → live textRef), `uiItemValue`/`uiItemName` (the `{name,value}[]` selection fallbacks).
- Many `flexpanel_node_style_*` setters in `UIElement` stay commented to keep the class under the 50-method ceiling (GMRT #15065); enable one on demand.

## Input System

**`Input`** / **`InputAction`**: `Input.register(key, action)`, `Input.get(key)`; query via `.down()`/`.pressed()`/`.released()`/`.value()`, bind via `.bindButton`/`.bindAxis`, bulk via `Input.bindAll({ key: [source, button], … })` / `Input.unbindAll([keys])`. `action.label()` → the primary binding as UI text, delegating to `InputButton.label()`/`keyName(code)` — the **single binding→text source** shared by `UIRebind` and `gemsKeyHints`, so a remap renders the same string everywhere. **All four query methods return falsy while a text field owns the keyboard** (`UIInput.active !== null`, via `InputAction.captured()`) — typing must not drive gameplay hotkeys. `UIInput` clears the capture on blur **and on destroy** (tearing a focused field down at a scene change can't strand it).

**`InputContext`** (Core) — a named-context **stack** over the Input layer generalizing `captured()` to "the active context decides which actions are live." The active context is the top of the stack (base always `"default"`); `push`/`pop`/`set` (replace top — auto-pushes if only the base remains, so a forgotten `push` can't clobber `"default"`)/`reset`/`active`/`is`. An `InputAction` declares its live contexts via `action.inContext([...])` or an optional 3rd element in a `bindAll` spec entry. An action with **no** declared contexts is live everywhere, so untagged keymaps are unaffected. `captured()` still wins. Contexts are **not serialized** (`Input.export`/`import` ignore them) — a controller re-applies them in `create()`, so a saved/rebound keymap never loses its tags.

The **RPG scene** is the reference consumer: `PlayerSystem.bindKeys` tags movement `["play","build","window"]` (the player keeps walking with a window open), `fire` `["play"]` only (self-mutes while building or with a window open — no reach-ins), `interact` `["play","window"]`, `build`/`follow` `["play","build"]`. `sceneRpg` pushes `"play"` in `create()`, resets in `destroy()`, and each `step()` — **before** the tick loop, so the tick's reads see it — calls `_resolveContext()` → `InputContext.set(...)` with **window > build > play** priority. A window thus pauses build mode (`BuildMode.update` gates `active` on `InputContext.is("build")`) and resumes it on close. The single `E` press is arbitrated in one place — `sceneRpg._dispatchInteract()`: a station window open → close it; else pick station-vs-NPC by cursor, then nearest; `Interactable.update`/`_updateNpc` do proximity/prompt only — no input reads.
