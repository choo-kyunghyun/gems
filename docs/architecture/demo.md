## Demo Layer — `obj_game`, `Level` & `LevelManager`

`obj_game` is the unified controller — it drives global system ticks each event and **delegates the scene lifecycle to `LevelManager`** (held as `this.scenes`, an alias of `World.levels`).

```
Create_0 → display/GPU setup; Log.clear/info; Settings defaults + load; I18n.load for `Settings.language`; this.scenes = World.levels (= new LevelManager()); scenes.start(SCENES.lobby) [the lobby is the boot scene + dev launcher; F2 returns to it] + SceneTransition.reveal()
Draw_0   → draw_clear(background), this.scenes.draw()
Step_0   → Time.update(), UIPointer.poll(), UI.update(), SlotDrag.update(), SystemMenu.update(this), UINav.update(), Dialogue.update(), this.scenes.update() [pending→SceneTransition.start + SceneTransition.update()], this.scenes.step() [skipped while SystemMenu open or Debug-paused, except a one-frame Step], Log.flush()
Draw_75  → UI.draw(), UINav.draw(), SlotDrag.draw(), Tooltip.draw(), Toast.draw(), Dialogue.draw(), SceneTransition.draw(), F5 screenshot
CleanUp  → Log.info("game end"); this.scenes.destroy() (before UI.destroy — it removes the scene's UI roots), UI/Input/I18n cleanup; Log.flush() last (Step_0's flush won't run again, so teardown logs would otherwise be lost)
Other_72 → Async - Save/Load (event-driven): completion of File.saveAsync/loadAsync — reads `async_load` `id` + `status` and calls File._resolve to fire the request's callback
Other_75 → Async - System (event-driven, not per-frame): gamepad connect/disconnect — reads `async_load` `event_type` ("gamepad discovered"/"gamepad lost") + `pad_index` and logs it
```

GameMaker's built-in per-instance events: **Create** (`Create_0`) runs once at boot; **Step** (`Step_0`) every frame (game logic); **Draw** (`Draw_0`) every frame to the `application_surface` (camera-transformed world view); **Draw GUI End** (`Draw_75`) every frame on the **GUI layer** (own resolution, not camera-transformed — so HUD / windows / overlays live here; it's the _End_ sub-event because `screen_save()` is only permitted there). **Clean Up** (`CleanUp_0`) fires at game end (single room, no transitions). The two **Async events** (`Other_72` Save/Load, `Other_75` System) are event-driven, not per-frame — the runtime triggers them on a callback and passes a `ds_map` in `async_load`, read via `ds_map_find_value` (the `[? ]` accessor is GML-only). `Other_75` (System) fires on a system-level callback (here, a gamepad being plugged in or removed) and only because the project already calls `gamepad_*` functions (`UINav`/`UITable`/`SystemMenu`/`Dialogue`) — the runner skips initialising the pad subsystem otherwise. `Other_72` (Save/Load) fires on a `File.saveAsync`/`loadAsync` completion (see _Utility Modules → File_).

**`LevelManager`** (`scripts/LevelManager/LevelManager.js`, Core — held as `World.levels`, aliased as `obj_game`'s `this.scenes`) owns the level lifecycle as a **flat collection with one active pointer** — there is **no scene stack**. **Only the active level is stepped + drawn**; **`switchTo(factory, opts)`** is the single transition: by default it **destroys every live level** and fades to the new one (plain navigation), while `keep: true` **freezes the current level as-is** (`suspend()` hides its UI; its world/state stay untouched in the collection) and **`back()`** later thaws it. `current` (an instance getter) exposes the active level. `obj_game` delegates `update()`/`step()`/`draw()`/`destroy()` to its `this.scenes` instance; `SystemMenu` reads/restarts/quits the live level through the manager (`scenes.current`, `scenes.label()`, `scenes.restart()`, `scenes.retheme()` — a live theme swap that rebuilds the active level's UI without the world regen `restart()` does — `scenes.switchTo(factory)`). A plain instance class, not a static singleton (house convention for stateful singletons — the old GMRT static-getter bug was dismissed). It also carries the **resident-map registry** (`register`/`entryOf`/`ids`/`take`/`put`/`transfer`, the old Universe) — which **is the RPG's map pool**: a registry entry is opaque to Core beyond `{ world, level }`, and `RpgMap` parks its full map bundle there at each suspend. See _Map graph_.

- **Base navigation** — `switchTo(factory)` (the `openScene` callback handed to each `create()`) queues a faded swap that **destroys every live level** first (a quit from a guest also drops its frozen host); `_apply` resets the cross-scene singletons (`UINav`/`SystemMenu`/`Dialogue`/`FloatingText`/`ParticleFx`). The app **boots into the lobby** (`scenes.start(SCENES.lobby)`) — the dev launcher / scene catalogue, also reached via **F2** (gated by `DEV_MODE`); from it the RPG + other genres open.
- **Guest minigames** — `switchTo(factory, { keep: true, onResult })` freezes the host and runs a guest in front (no fade — an instant in-world switch); `back()` reads the guest's optional `result()`, destroys it, thaws the host, and fires `onResult(result)`. **One kept level at a time** (no nesting — a second keep-switch warns and refuses). The world-space singletons (`FloatingText`/`ParticleFx`/`Dialogue`) are cleared across both boundaries so a host's leftovers don't bleed into the guest. The reference consumer is the RPG **arcade cabinet** (an `Interaction` of kind `"arcade"` → `sceneRpg._openArcade` → a kept switch to `ScenePlatformer`, rewarding coins from the run's `result()` score). A guest is exited with **Esc / gamepad-B** — `SystemMenu` calls `back()` (returns false when nothing is kept), before falling through to the pause menu. The genre showcases (`scenePlatformer`, …) are thus reusable as embedded minigames unchanged; the host depends on a guest only via the factory it switches to.

**`Level`** (`scripts/Level/Level.js`) is **not a base class to extend** — it is (1) the **duck-typed screen contract** LevelManager drives, and (2) the **blank screen** menus instantiate bare (the lobby's `Object.assign(new Level(), { create, destroy })`, its no-op stubs covering the rest). The contract: `create(openScene)` / `step()` / `draw()` / `destroy()` are required (called unconditionally); `suspend()`/`resume()` (keep-switch freeze/thaw), `result()` (a guest's return value), `handleEscape()` (SystemMenu's Esc hook), `retheme()` (rebuild `this.ui` in place for a live theme swap — see _GemsUI kit_; the RPG closes open windows via the `handleEscape` chain then re-runs its `_buildUI`, the lobby just rebuilds), and the `label`/`gameplay` fields are optional. The genre screens (`sceneRpg`/`scenePlatformer`/`sceneEditor`/`sceneUIKit`) are **standalone classes** satisfying it — composition, never `extends Level` (GMRT subclassing is broken: subclass field inits don't run, `super` faults). Screens are **factory functions** returning a fresh instance each time they open. `create(openScene)` receives the navigation callback (`LevelManager.switchTo`); the manager also sets `scene.manager` (the back-ref a host uses to open guests — `switchTo` with `keep: true`). **`suspend()`/`resume()`** freeze/thaw a screen while a guest runs in front — a host with extra state defines its own (the RPG re-binds its keymap on `resume`, since a guest controller's `destroy` unbinds shared action names like `moveLeft`/`moveRight`).

**Scene navigation**: call `openScene(factory)` to queue a base transition (applied after the current UI update completes). The only **built-in scene** (`scripts/sceneLobby/sceneLobby.js`) is `SCENES.lobby` — the merged **title + lobby**, the **boot scene** + dev launcher (also reached via **F2**): a G.E.M.S. header, a **tabbed** scene catalogue (registry categories grouped into RPG / Showcase tabs), and a footer of global actions (Settings → SystemMenu, Credits → SystemMenu's About tab, Quit). There is no separate title or credits scene; Settings/Pause are the **`SystemMenu`** overlay, not scenes (see _Genre UI managers_ in [rpg.md](rpg.md)).

**`SceneRegistry`** (`scripts/demo/demo.js`) is the lobby catalogue. Register at the top level of a scene's script:

```js
SceneRegistry.add(() => new MyScene(), {
  label: "My Scene",
  category: "SCENE_CAT_FOO",
});

// standalone — never `extends Level` (GMRT); declare the full required contract
class MyScene {
  label = "My Scene";
  create(openScene) {
    /* build UI; openScene(SCENES.lobby) to go back */
  }
  step() {}
  draw() {}
  destroy() {
    /* remove UI, clean up */
  }
}
```

`SceneRegistry.byCategory()` returns entries grouped by category string. To add a scene: create the script asset (see CLAUDE.md → Resourcetool), define the class, then `SceneRegistry.add(...)`.

**GemsUI kit** (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`): a themed factory library so scenes build UI declaratively instead of hand-wiring `UIElement`/`UIPanel`/`UIText`. Factories are assigned via `globalThis.X = function X(…)` and split across small files (large-file global-hoisting fault). All visual constants live in **`GemsTheme`** (colors as hex, geometry as numbers); the `gems*` functions parse + compose them. **Theme modes** (dark/light): the color keys live in two palettes (`GemsTheme.palettes.dark`/`light`) and **`GemsTheme.setMode(mode)`** copies the active one onto the flat color keys — so every `GemsTheme.<color>` read is mode-current, and semantic keys (`good`/`warn`/`onAccent`) + the `bg` backdrop swap with it. Factories **bake** colors into components at build time, so a LIVE swap must **rebuild** the UI: the `SystemMenu` Settings-tab Theme control calls `SystemMenu._applyTheme` → fades to cover, `setMode`s, re-seeds the Core `UINav.color` + the `obj_game` backdrop, then `World.levels.retheme()` (each scene's optional `retheme()` rebuilds its `this.ui` in place — no world regen) and reopens the menu. Seeded at boot from the `theme` Setting; geometry/motion keys are theme-independent.

- **Containers**: `gemsRoot` (full-screen scene root), `gemsList` (vertical stack), `gemsGrid` (horizontal wrap row), `gemsPanel`/`gemsCard` (rounded panel; card adds gradient+border+shadow), `gemsHeader` (title bar), `gemsSection` (titled card with divider), `gemsRow(label, control)`, `gemsDivider`, `gemsCatBar(categories, opts?)` (a bar of category buttons; clicking one toggles a pop-up flyout of its items above the bar — one open at a time; selecting an item highlights it + fires `onSelect`. Driven by structural insert/remove, not flex mutation; `root.catbar` exposes `open/close/select`. Shared by the RPG build-mode HUD + level-editor palette), `gemsWindow(title, opts?)` (a centered, **draggable + resizable** floating window — title bar with `UIDrag` + optional close, a `body` callers fill. Resizable by default via a bottom-right `UIResize` grip clamped to `opts.minWidth`/`opts.minHeight` (opt out with `resizable:false`); the card + body flex-grow so content fills the resized frame. Pass `opts.height` for a fixed starting size when the content itself flex-grows (a grow `gemsTabs`/`gemsTable`), else the window opens content-sized and fixes its size on first resize. Size is within-session only — not persisted. Used by the RPG inventory + `StorageUI`).
- **Widgets**: `gemsLabel`, `gemsHint` (one-line help on a readable card, for overlays over a scene's render), `gemsKeyHints(entries, opts?)` (a **live, context-aware key-bind hint bar** — replaces a hardcoded "WASD: Move · …" string. Each entry `{ label, contexts?, actions? | text? }` shows an action's i18n name next to its CURRENT binding, read **live** from `Input.get(action).label()` each frame — so a future key remap updates the hint with zero wiring — or a literal `text` key for non-rebindable hints (raw build-mode `LMB`/`RMB`, `Esc`). `contexts` gates an entry to the matching `InputContext`, so the bar swaps its hints as the scene changes context (play / build / window). Multi-key `actions` join to "WASD" when single-glyph else "Up/Left/…". Built on `gemsLabel`), `gemsButton(label, onClick, opts?)` (`opts.primary` accent CTA; `opts.disabled` a bool **or live `() => bool`** evaluated each frame; `opts.selected` a live `() => bool` tints toward the accent for an active toggle/palette button — hover/press win on top), `gemsIconButton`, `gemsToggle` (renders `label: ON/OFF`), `gemsCheckbox` (`opts.style` `"check"`/`"switch"`), `gemsProgress` (non-interactive 0–1 bar), `gemsSlider`/`gemsSelect`/`gemsDropdown` (Settings-bound) + `gemsSelectCustom`/`gemsDropdownCustom` (caller-driven; the `*Dropdown*` pair opens a navigable popup list rather than cycling in place — the fit for many options like resolutions/locales, scrolls past `opts.maxVisible`), `gemsTable(columns, opts?)` (a sortable/filterable `UITable` sized to `opts.rows` whole rows, or `opts.grow` to flex-fill the parent's height — `UITable` then reflows its visible-row count to the live layout height, so a table in a resizable `gemsWindow` shows more/fewer rows as it resizes; reach the component via `el.getComponent(UITable)`).
- **Tooltips**: `gemsTooltip(element, label, opts?)` attaches a hover `UITooltip`; every interactive factory also takes `opts.tooltip` (string or `() => string`).

`label`/`onText`/`offText` accept a string or `() => string` (live `I18n.textRef`); color opts accept a `GemsTheme` key, hex string, or color int. Styling lives in `GemsTheme` + **`UIPanel`** options: `color2` (edge tint; `draw_roundrect`'s two colors run center→edge/radial), `border`/`borderColor`, soft multi-pass `shadow`/`shadowColor`/`shadowAlpha`, `highlight`/`highlightColor`/`highlightAlpha` (inner top-bevel sheen) — all default off. `UIButton` eases color/glow/shadow between hover/press on `Time.raw`; `UISlider`/`UISelect`/`UIProgress`/`UICheckbox` render directly in `onDraw` (`UISelect` shows `< value >` arrows, steps by click side). **`teardownScene(scene)`** releases the `world`/`renderer`/`camera`/`ui` a scene holds on `this`, in dependency order (missing fields skipped) — call from `destroy()` after releasing scene-specific resources (controllers, levels).
