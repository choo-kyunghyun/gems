## Demo Layer — `obj_game`, `Level` & `LevelManager`

`obj_game` is the unified controller — it drives global system ticks each event and **delegates the scene lifecycle to `LevelManager`** (held as `this.scenes`, an alias of `World.levels`). The per-event order is a contract (later systems read what earlier ones wrote this frame):

```
Create_0 → display/GPU setup; Log.clear/info; Settings defaults + load; I18n.load for `Settings.language`; this.scenes = World.levels (= new LevelManager()); scenes.start(SCENES.lobby) + SceneTransition.reveal()
Draw_0   → draw_clear(background), this.scenes.draw()
Step_0   → Time.update(), UIPointer.poll(), UI.update(), SlotDrag.update(), SystemMenu.update(this), UINav.update(), Dialogue.update(), this.scenes.update() [pending→SceneTransition.start + SceneTransition.update()], this.scenes.step() [skipped while SystemMenu open or Debug-paused, except a one-frame Step], Log.flush()
Draw_75  → UI.draw(), UINav.draw(), SlotDrag.draw(), Tooltip.draw(), Toast.draw(), Dialogue.draw(), SceneTransition.draw(), F5 screenshot
CleanUp  → Log.info("game end"); this.scenes.destroy() (before UI.destroy — it removes the scene's UI roots), UI/Input/I18n cleanup; Log.flush() last (Step_0's flush won't run again, so teardown logs would otherwise be lost)
Other_72 → Async - Save/Load: completion of File.saveAsync/loadAsync — reads `async_load` and calls File._resolve to fire the request's callback
Other_75 → Async - System: gamepad connect/disconnect — reads `async_load` and logs it
```

Non-obvious event facts: the GUI drawing sits in **Draw GUI End** (`Draw_75`) because `screen_save()` is only permitted there; the Async events read `async_load` via `ds_map_find_value` (the `[? ]` accessor is GML-only); `Other_75` fires only because the project already calls `gamepad_*` functions — the runner skips initialising the pad subsystem otherwise.

**`LevelManager`** (Core — held as `World.levels`, aliased as `obj_game`'s `this.scenes`) owns the level lifecycle as a **flat collection with one active pointer** — there is **no scene stack**, and **only the active level is stepped + drawn**. `switchTo(factory, opts)` is the single transition: by default it **destroys every live level** and fades to the new one; `keep: true` **freezes the current level as-is** (`suspend()` hides its UI; its world/state stay untouched in the collection) and `back()` later thaws it. `obj_game` delegates `update()`/`step()`/`draw()`/`destroy()`; `SystemMenu` drives the live level through the manager interface (`current`, `label()`, `restart()`, `retheme()` — a live theme swap that rebuilds the active level's UI **without** the world regen `restart()` does — `switchTo(factory)`). A plain instance class, not a static singleton (house convention for stateful singletons). It also carries the **resident-map registry** (`register`/`entryOf`/`ids`/`take`/`put`/`transfer`) — which **is the RPG's map pool**: a registry entry is opaque to Core beyond `{ world, level }`; `RpgMap` parks its full map bundle there at each suspend (see rpg.md → _Map graph_).

- **Base navigation** — `switchTo(factory)` (the `openScene` callback handed to each `create()`) queues a faded swap that destroys every live level first (a quit from a guest also drops its frozen host); `_apply` resets the cross-scene singletons (`UINav`/`SystemMenu`/`Dialogue`/`FloatingText`/`ParticleFx`). The app boots into the lobby (also reached via **F2**, gated by `DEV_MODE`).
- **Guest minigames** — `switchTo(factory, { keep: true, onResult })` freezes the host and runs a guest in front (no fade — an instant in-world switch); `back()` reads the guest's optional `result()`, destroys it, thaws the host, and fires `onResult(result)`. **One kept level at a time** — a second keep-switch warns and refuses. The world-space singletons (`FloatingText`/`ParticleFx`/`Dialogue`) are cleared across both boundaries so a host's leftovers don't bleed into the guest. A guest exits with Esc / gamepad-B — `SystemMenu` calls `back()` (false when nothing is kept) before falling through to the pause menu. The genre showcases are thus reusable as embedded minigames unchanged (the RPG arcade cabinet keep-switches to `ScenePlatformer` and rewards from its `result()`); the host depends on a guest only via the factory it switches to.

**`Level`** is **not a base class to extend** — it is (1) the **duck-typed screen contract** LevelManager drives, and (2) the blank screen menus instantiate bare (`Object.assign(new Level(), { create, destroy })`, its no-op stubs covering the rest). The contract: `create(openScene)` / `step()` / `draw()` / `destroy()` are required (called unconditionally); `suspend()`/`resume()` (keep-switch freeze/thaw), `result()` (a guest's return value), `handleEscape()` (SystemMenu's Esc hook), `retheme()` (rebuild `this.ui` in place for a live theme swap), and the `label`/`gameplay` fields are optional. Genre screens are **standalone classes** satisfying it — composition, never `extends Level` (GMRT subclassing is broken, GMRT.md §1) — registered as **factory functions** returning a fresh instance each open. `create(openScene)` receives the navigation callback; the manager also sets `scene.manager` (the back-ref a host uses to open guests). A host with extra state defines its own `suspend`/`resume` — the RPG re-binds its keymap on `resume`, because a guest controller's `destroy` unbinds shared action names.

**Scene navigation & the lobby.** `sceneLobby` is the one built-in scene — the merged title + lobby boot scene and dev launcher: a tabbed scene catalogue (registry categories grouped into tabs) + a footer of global actions. There is no separate title or credits scene; Settings/Pause are the `SystemMenu` overlay, not scenes (see rpg.md → _Genre UI managers_). **`SceneRegistry`** is the catalogue: scenes call `SceneRegistry.add(factory, { label, category })` at the **top level** of their script (unlike content registries, which register at `create()` time), and `byCategory()` groups entries for the lobby tabs.

## GemsUI kit

**GemsUI** (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`): a themed factory library so scenes build UI declaratively instead of hand-wiring `UIElement`/`UIPanel`/`UIText`. Factories are assigned via `globalThis.X = function X(…)` and split across small files (the top-level-function hoisting fault, GMRT.md §1). The factory inventory lives in the four source files — signatures and per-factory options are JSDoc there. The kit-wide contracts:

- **All visual constants live in `GemsTheme`** (colors as hex, geometry as numbers); the `gems*` functions parse + compose them. **Theme modes**: the color keys live in two palettes (`GemsTheme.palettes.dark`/`light`) and `setMode(mode)` copies the active one onto the flat color keys — every `GemsTheme.<color>` read is mode-current. Factories **bake** colors into components at build time, so a live swap must **rebuild** the UI: `SystemMenu._applyTheme` fades to cover, `setMode`s, re-seeds `UINav.color` + the `obj_game` backdrop, then `World.levels.retheme()` (each scene rebuilds its `this.ui` in place — no world regen) and reopens the menu. Seeded at boot from the `theme` Setting; geometry/motion keys are theme-independent.
- **`gemsOverlay`** is the near-fullscreen gameplay-window shell the RPG windows share (bag/workbench/chest/trade): absolute dim backdrop that veils the HUD + swallows clicks, centered full-height card capped for ultra-wide, title row + close over a divider. **Built once and toggled via `.enabled`** (starts hidden) so rebuilt-in-place content keeps sort/filter/selection; content goes into `.body`, extra title-row items insert into `.titleRow` before the close button. `gemsWindow` (the draggable/resizable floating sibling) is currently unwired — kit inventory.
- **`gemsCatBar`** (the category bar + flyout shared by the build-mode HUD and the editor palette) is driven by structural insert/remove, not flex mutation (the flexpanel idiom, GMRT.md §4); `root.catbar` exposes `open/close/select`.
- **Live-value opts**: `label`/`onText`/`offText` accept a string or `() => string` (live `I18n.textRef`); `gemsButton`'s `disabled`/`selected` accept a live `() => bool` evaluated each frame; `gemsKeyHints` entries read their binding from `Input.get(action).label()` **each frame** (a remap updates the hint with zero wiring) and gate on `contexts`, so the bar swaps as the scene's `InputContext` changes. Color opts accept a `GemsTheme` key, hex string, or color int.
- **`gemsTable`** sizes to `opts.rows` whole rows, or `opts.grow` flex-fills the parent and `UITable` reflows its visible-row count to the live layout height; reach the component via `el.getComponent(UITable)`.
- **`gemsAmountPicker`** (the quantity modal of the chest/trade transfer flows): all labels are opts with English defaults so the kit stays content-agnostic; `closeOnEscape` defaults off because the RPG's `handleEscape` cancels the picker before the window under it.
- Panel styling (edge tint, border, shadow, highlight) rides `UIPanel` options, all default off; widget hover/press easing runs on `Time.raw` (the clock split, ARCHITECTURE.md).

**`teardownScene(scene)`** releases the `world`/`renderer`/`camera`/`ui` a scene holds on `this`, in dependency order (missing fields skipped) — call it from `destroy()` after releasing scene-specific resources (controllers, levels).
