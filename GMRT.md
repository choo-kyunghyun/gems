# GMRT-Safe Idioms

Runtime-quirk reference for **G.E.M.S.** on the GMRT runtime, imported into context by [CLAUDE.md](CLAUDE.md) (via its `@GMRT.md` line) so it is always loaded alongside it.

The GMRT JS runtime/compiler miscompiles or chokes on several standard JS forms — the quirks below are the ones still live on 0.20. Avoid them, don't "clean up" code back into them, and leave a one-line comment where one forces an unusual idiom so it isn't "fixed" back. Add new quirks here as found.

## Language / compiler

- **No `for...of` over a Map/Set iterator** (`.values()`/`.keys()`/`.entries()`, or a `Set`) — breaks the runtime. Keep parallel arrays and index-loop (see `World._keys`/`_storages`). `for...of` over an array/string and `for...in` over a plain object are fine.
- **A `Map` keyed by an ASSET REF (sprite handle) crashes NATIVELY at `.get`** — hard process death (`Bad optional access`), not a JS exception, so `Log.exception` records nothing and `game.log` just stops mid-run (verified 0.20). Every shipping Map is string-keyed (`Item`/`Rarity`/`I18n`/…) — those are fine. For a ref-keyed registry use parallel arrays + an `===` identity scan — asset-ref `===` works (see `SpriteMeta`).
- **An asset ref reports `typeof "object"`, and `Object.keys(ref)` is `[]` without throwing** — so a generic deep copy silently turns a stored sprite handle into `{}`. Discriminate plain data by `v.constructor === Object` (`true` for object literals, `false` for asset refs — probed on 0.20); pass refs through by reference (see `EntityPreset._clone`).
- **No array destructuring in `for...of`** (`for (const [a,b] of arr)`) — runtime `ReferenceError`. Use `arr[i][0]`. (Object destructuring and a `.forEach(([a,b]) => …)` param are fine.)
- **No empty `for` initializer** (`for (; c<n; c++)`) — crashes the compiler. Use `while`.
- **`Array.sort` comparator must return a SIGN, not a raw difference** — GMRT truncates the comparator's return to an int, so a fractional `(a, b) => a.t - b.t` over sub-1 values collapses every pair to `0` ("equal") and the array stays in its original (arbitrary) order — a silent no-op sort, not an error. Return `a < b ? -1 : a > b ? 1 : 0` (verified: `Raycast.castAll`'s by-`t` ordering of `[0,1]` hit distances). A difference comparator only happens to work when the values are far-enough-apart integers.
- **Don't cache a primitive boolean in a local across a function** — it can flip mid-function. Cache the component object and read the property live each use (see `PlatformerController.update` → `groundedComp.isGrounded`).
- **Top-level bare `const` isn't visible to other scripts** — share via `globalThis.Name`. Bare top-level `function` declarations are mostly global, **but past a certain file size GMRT stops hoisting some and faults at startup** (`cannot coerce undefined or null...`). Assign explicitly (`globalThis.X = function X(…)`) and keep files small (why the GemsUI kit is split).
- **A class with >50 methods crashes the runtime** ([#15065](https://github.com/YoYoGames/GameMaker-Bugs/issues/15065), open) — 50 OK, 51+ faults. Split a fat class into collaborators, lift helpers into free functions / a `globalThis` module object, or use composition (a flat base + `components:[]` queried by `instanceof`, as `UIElement`/`Item` do).
- **Class inheritance / `super` is broken** — `super.method()` is a compile error, and **a subclass's instance field initializers never run** (`class Foo extends Bar { label="x" }` leaves `label` undefined). Model "kinds of X" as composition (`addComponent`/`getComponent(Class)`, `instanceof` on a flat class). The genre scenes hit the field-init gap: `scene.label` is undefined, so the lobby/`SystemMenu` read the name from `SceneRegistry`, not the instance. Assign such fields in a method that runs (e.g. `create()`).
- **A `static` field initializer can't reference its own class name** — `static x = ClassName.y` throws at load. Use a literal and read `ClassName.y` from methods (hit on `Dialogue`). Referencing another already-loaded class is fine.
- **`static get` with a computed (expression/comparison) body miscompiles to a constant** — a getter reading `_modal !== null` returned `false` while `_modal` was live. Expose derived static state as a `static` METHOD (`SystemMenu`/`Dialogue`/`VirtualKeyboard.isOpen()`), never a static accessor. A getter returning a _stored_ value works; instance `get`/`set` mostly work (but see the next bullet). Read-write static state stays a plain field (`UIInput.active`, `UITable.active`, `SlotDrag.active`, `BuildMode.active`).
- **An instance `get` whose NAME shadows a GameMaker built-in faults on access** — `get index()` / `get value()` on `UIDropdown` threw `cannot coerce undefined or null value into object` at the read site on 0.20 (even `get index() { return this._index; }` — a stored value), while a sibling `get name()` and `LevelManager`'s `get current()` work. The reserved-ish name (GM uses `index`/`value` pervasively) is the trigger, not the body. Expose such state as a `get*()` METHOD (`UIDropdown.getIndex()`/`getValue()`, pairing with `setIndex()`); reach the backing field directly inside the class. When in doubt, prefer a method over an accessor for any GM-flavored property name.

## Strings / serialization / PRNG

- **`toUpperCase()`/`toLowerCase()` return garbage Unicode** (`"q".toUpperCase()` → `"ଊ"`). Map case via char codes (`String.fromCharCode(c-32)` for a–z→A–Z; see `VirtualKeyboard._upper`, `InvTable.lower`).
- **`JSON.stringify` faults on nested objects/arrays** — a flat `{key: scalar}` is fine; a value that's an object/array hard-faults. Persist only flat scalar blobs; serialize structure yourself (`ids.join(",")`, `"k=v;k=v"`) — see `SaveData`/`Profile`/`Achievement`.
- **32-bit xorshift PRNGs collapse to a constant** — the chained `s ^= s<<13; s ^= s>>17; s ^= s<<5` returns `0.5` for many seeds (different seeds, identical output). Use integer-float math with no bitwise — a Park–Miller MINSTD LCG (`s = (s*48271) % 2147483647`); **`Rand`** (`scripts/Rand/`, Core/Util) is the one home for the idiom (position hashes + value noise + streams) — use it, don't hand-roll another copy. (Single bitwise ops like `IdPool`'s id packing are fine; only the overflowing chain breaks.)
- **The `random_*` built-ins work on 0.20 — EXCEPT `random_get_seed()` doesn't track the stream, and same-frame `randomize()` repeats** (probed 2026-07-03): `random`/`random_range` honor `[lo, hi)`, `irandom`/`irandom_range` are inclusive-integer and uniform, `random_set_seed` replays the identical sequence across runs, adjacent seeds decorrelate, and both `randomize`/`randomise` spellings exist. But `random_get_seed()` returns the last seed SET, not the advanced state — after `set_seed(4242)` + 2 draws it still reports `4242`, so the manual's capture-mid-stream-and-restore workflow silently rewinds to the seed's start. And `randomize()` is time-seeded so coarsely that two calls in one frame can return the SAME seed (and stream). Fine for one-shot gameplay randomness; deterministic worldgen keeps the hand-rolled MINSTD (**`Rand`**) — it needs pure position hashing + per-chunk streams a single global-stream RNG can't provide (and the get_seed defect forecloses save/restore emulation).

## Sprites / assets / camera

- **No SVG sprites** (`spr_choo`/`spr_play`/`spr_hana`) — `sprite_get_number()` returns `0`, so frame math can go negative and `draw_sprite_ext` throws. Use raster sprites; clamp frame count `≥1` and `subimg` `≥0` (see `AnimationSystem`).
- **`asset_get_index(name)` returns an opaque ref, not a number** — a `>=0` test is always false. Validate with `sprite_exists()` (a not-found name is `-1`, which it also rejects). See `UISlots`/`SlotDrag`, `UIRichText._icon`.
- **`view_camera[]` isn't exposed** — indexing faults. Hold the `Camera` instance and read the view rect from its own fields (`toX`/`toY`/`width`/`height`), **not `camera_get_view_*`** — the project's `Camera` drives the view by matrix, so `camera_get_view_*` returns 0. An ORTHO `CameraFollow.create2d` camera is centered on `(toX,toY)` spanning `width×height` world px. The view-culling passes (`RenderLighting`/`RenderWeather`/`RenderDebugTileMap`/`RenderGrid`) read the Camera fields for this reason.
- **`mouse_x`/`mouse_y` are WRONG under a pitched matrix camera** (probed on 0.20 at a 35° pitch: ~118 world px off at the screen edge — matching neither the flat linear mapping nor the correct one; the RPG now pitches 42–58° by zoom, where the error is larger still; flat matrix cameras map fine, so the level editor's `CameraPan` still uses them). Convert the cursor yourself: **`Camera.unproject(sx, sy)`** (surface px → ground-plane world, the exact inverse of `Camera.project`, pitch-aware via the up vector) / **`Camera.cursorWorld()`** (GUI mouse → unproject). `sceneRpg.step` latches it once per frame into `scene.mouseWorld` + the player's `Playable.cursorX/Y` (mouse positions are realtime-sampled like buttons — latch and share); consumers: `PlayerSystem` aim, `BuildMode` cell pick, `Interactable` cursor targeting, `DebugInspector` click-pick/marker. Cursor-over-entity tests hit the ground-plane point (an entity's FEET) — pointing at a tall billboard's upper body lands behind it; screen-space billboard picking is a possible follow-up.

## Rendering / shaders / clip

- **NaN-width guard before drawing filled geometry/sprites in a UI component** — on the first frame after a scene transition the flexpanel layout isn't computed, so `getLayoutPosition()` returns NaN width/height and drawing with NaN coords faults. Guard `!(pos.width > 0)` (test `>0`, not `<=0` — `NaN <= 0` is false). See `UIStepper`/`UISlider`/`UIProgress`/`UISelect`/`UICheckbox`/`UIInput`. **Don't add it to text widgets** (`UIText`/`UIRichText`): they self-size and draw from `pos.left/top`, never reading `pos.width`, so the transient NaN is harmless.
- **`gpu_set_scissor` is the UI clip mechanism (verified on GMRT 0.20)** — `UIElement._drawClipped` clips a scroll/viewport's children with it. It clips, doesn't crash, and does NOT leak **as long as you save/restore** (`var prev = gpu_get_scissor(); …; gpu_set_scissor(prev)`); the old "leaks globally" lore was a 0.19-era discipline issue, not a defect. Two gotchas: coords are render-target **PIXELS**, not GUI units, so convert by `k = target/gui` (the GUI layer is scaled to the window). The render target is the **window back buffer** — windowed client area, or the monitor in fullscreen — but it does **not** track `window_get_width/height()` or the application surface: those queries lag it by a frame (the OS resize arrives async via an SDL event), _and_ the back buffer's own resize is **asymmetric** — a SHRINK resizes it **synchronously** (probed on 0.20: back buffer already 1280×720 while `window_get_width()` still returned 2560), a GROW lags it **one frame** (still the old smaller size while the queries already report the new bigger one). So a scissor sized from any single query overflows the target on a resize frame → a **fatal** "scissor rect not contained in the render target" validation error. Size it from **`Display.clipW/clipH`** instead — `min(renderW, _prevW)`: the intended size (set synchronously by `Display.apply()`; authoritative because the window isn't drag-resizable, `options_windows resize_window:false`) min'd with its **1-frame-lagged self** (`advanceFrame` at the end of `UI.draw`), which never exceeds the live back buffer in _either_ direction (a grow just under-clips one invisible frame). **GameMaker also does not clear the scissor between frames**, so a clip's leftover rect survives — and after a shrink that leftover is bigger than the new back buffer, which the next frame's outermost clip reads via `gpu_get_scissor()` as a "nested" parent and replays _forever_ (self-perpetuating fault). `UI.draw()` therefore re-anchors the scissor to the full target (`gpu_set_scissor(0, 0, Display.clipW(), Display.clipH())`) once at the start of each frame before drawing roots. And `gpu_get_scissor()` returns `{0,0,0,0}` when unset (the full-target default, **not** the target dims) — so for nesting only intersect with it when its `w`/`h` are positive, and **don't restore by replaying a saved `{0,0,0,0}`**: that doesn't re-enable drawing, it clips everything afterward to an empty rect (footers/popups/later roots vanish). At top level reset to the full render target (`gpu_set_scissor(0, 0, Display.clipW(), Display.clipH())`); only a genuinely nested clip restores its parent's positive rect. Clipping at the rasterizer means children draw **directly** to the back buffer at full window density — crisp SDF text, correct blending, no surface. **Nested scrolls (a `gemsScroll` within a `gemsScroll`) clip correctly** by intersecting the two rects — with no clip surfaces, the old "`draw_text` loses the world matrix when double-nested" bug is retired. A text-only clip (caret/overflow in one widget) can still compute the visible substring/offset itself (see `UIInput.onDraw`). **`gpu_set_scissor` does NOT flush the pending vertex batch**, so the **LAST** geometry drawn under a clip stays pending and is only submitted by a _later_ texture swap (a following sibling/root) — by which time the scissor has been restored to the full target, so that last item renders **UNCLIPPED at its true layout position** (a long-list scroll leaked its 12th button's text far below the viewport; the earlier items flushed mid-loop because each button alternates panel-texture → font-texture, swapping the texture and flushing the prior item while the clip was still active). Fix: `draw_flush()` at the end of `_drawClipped` **before** the scissor restore, so the batch is submitted while the clip rect is still set. `draw_flush` is manual-flagged debug-only, but it's the only batch-flush primitive and runs once per clip container per frame (a handful), not indiscriminately. **The same "no flush on scissor set" rule also bites a PRECEDING sibling** (verified 2026-06): a clip captures the still-pending LAST primitive of whatever drew just _before_ it and submits it under the clip's tighter scissor — clipping it AWAY (the System Menu's rightmost "About" tab label vanished under the tab content's scroll clip). You **cannot** fix this with a _start_-of-`_drawClipped` `draw_flush()` — flushing immediately before `gpu_set_scissor` corrupts the clip on 0.20 (`No pipeline set`/`Invalid CommandBuffer` → the clip's OWN content blanks, every overflowing scroll). Instead the preceding drawer must end with a harmless trailing UNTEXTURED primitive to force the texture swap that flushes its text (`UITabs.onDraw` re-strokes its baseline last — redundant with the one drawn first, so harmless if itself clipped). And a clip with a **non-clipped sibling drawn AFTER it in the same parent** can fail outright (the sibling renders nothing) — every clipped layout just relocates the lost primitive, so `CraftingUI` avoids any clip in its master-detail row entirely (see its comment for the full whack-a-mole).
- **A `UIComponent` must resolve `I18n.font(key)` at DRAW time, not cache the handle at construction** — two ways a cached handle breaks: (1) `I18n.font` falls back to `draw_get_font()` for an _undeclared_ key, so a handle captured in a constructor freezes the wrong font; (2) a **language switch** (`I18n.load`) `font_delete()`s every old handle and `font_add()`s new ones, so a previously-captured handle **dangles** — it renders the GM default fallback (12pt Arial) or nothing (a font with no glyph for the new locale). So the text widgets take `font` **polymorphically** — a raw handle (number) OR an **I18n font KEY** (string) — and resolve it live each draw: `const f = typeof this.font === "string" ? I18n.font(this.font) : this.font;` (`UIText`/`UIRichText`/`UITabs`/`UIAccordion`/`UISlider`/`UITable`; `UIQuestTracker` stores explicit `*FontKey` fields). The GemsUI factories pass the **key** (`gemsLabel(…, { font: "header" })`, `gemsTabs`/`gemsSlider`/`gemsTable` default to `"header"`/`"default"`), never a pre-resolved handle. **Exception:** world-space **render passes** (`RenderChunks`/`RenderZoneLabel`/`RenderDebugTileMap`) still take a handle (`I18n.font("default")`) — they're rebuilt when the map/level reloads, but **not** on a bare locale switch, so a label they draw keeps the old font until the next map load (acceptable for debug-ish world labels; convert them too if it ever matters).
- **Screen-space overlay matrices: up +1 AND negative ortho height (probed on 0.20)** — a pass that resets view/projection to surface-pixel ortho to draw over the whole screen (`RenderLighting`'s composite, `RenderWeather`) must use `matrix_build_lookat(w/2, h/2, -1, w/2, h/2, 0, 0, 1, 0)` + `matrix_build_projection_ortho(w, -h, 0, 2)` — the **negative height**. The overlay path has an inherent Y-flip vs the world camera (which renders correctly with positive height), and negating the UP vector instead is a 180° ROLL, not a y-flip — up `-1` X-MIRRORS the content about screen center. That mirror is invisible for symmetric content (ambient fill, vignette, a blob at screen center), so it long passed as verified — it surfaced as the player's lantern glow flipping to the wrong side whenever the blob left screen center (camera clamped at a map border; follow-lerp trailing a fast player). Probed with two off-center axis lights (red = X, green = Y) against `Camera.project` expectations.
- **Custom `GMShader`s run, but guard them** — `shaders_are_supported()` + `shader_is_compiled(asset_get_index("name"))` before `shader_set`, with a non-shader fallback. A shader on an **untextured** primitive reads `gm_BaseTexture` as black, so compute output from uniforms only — don't sample. (**`sh_meshlit` is now the ONE world shader** — every world pass (meshes, walls, billboards, streamed terrain, resident tiles) submits through it in vox or textured mode, with the texel cutout as a uniform mode (`u_alphaRef`; the old separate `sh_alphatest` is deleted); day/night + the night vignette are still the `RenderLighting` light map, not a shader.)
- **Declare every shader uniform in the FRAGMENT stage — a uniform declared in the `.vsh` never receives its value (probed 0.20)** — `shader_get_uniform` returns a valid handle and `shader_set_uniform_f` runs without error, but the vertex stage keeps reading the default 0 (sh_meshlit's `u_useTex`/`u_normal`, first declared in the vsh for a vertex-side branch, never switched modes — walls silently rendered down the wrong path; symptom is a "working" shader ignoring its flag, not a compile error). Moved to fsh-only declarations the same uniforms apply correctly. So: keep the vsh attribute+matrix only, declare uniforms once in the `.fsh`, and do uniform-driven selection there (`sh_meshlit`'s vox-vs-textured `mix`es) — and don't declare one uniform in both stages either (that was the failing configuration).
- **The fixed-function alpha test is INERT on GMRT — `discard` in a fragment shader instead** — `gpu_set_alphatestenable`/`gpu_set_alphatestref` ROUND-TRIP through their getters (after `set(true,123)`, `gpu_get_alphatestenable()`/`alphatestref()` report `true`/`123` **exactly** — verified) but have **no effect at draw time**: a sub-ref / transparent fragment is **not** discarded, so it still writes depth. This bit the 2.5D billboards — with the depth buffer on (`gpu_set_ztestenable`), a sprite's fully-transparent pixels wrote depth and occluded whatever overlapped behind them (an entity behind the player showed the **background** through the player's empty pixels; `gpu_set_alphatestref` "did nothing" exactly because the test is inert, not misconfigured). Fix: do the cutout explicitly in the **fragment shader** — `sh_meshlit`'s **`u_alphaRef`** uniform (0 = off; billboards/sprite faces pass ~0.5) `discard`s fragments whose `gm_BaseTexture` **texel** alpha is below it; a `discard`ed fragment writes no depth. `RenderBillboard` sets it around its draw loop (guarded per the bullet above, no-shader fallback; `RenderMesh._setupLights` pins it 0 so vox/wall submits never discard). Key: discard on the **texel** alpha (sprite SHAPE), **not** the final `v_vColour*tex`, so a dimmed/tinted entity (`v_vColour.a < 1`, e.g. a downed companion) stays fully visible — only the shape is cut. (Originally shipped as a dedicated `sh_alphatest`, folded into `sh_meshlit` when every world pass unified under it.) `gpu_set_alphatestenable(true)` is left **commented out** in `obj_game` Create_0 as a record of the dead end.
- **Don't ease a _packed_ color int every frame — ease its float r/g/b channels** — two GMRT traps make per-frame easing of a packed color int wrong, both acute at high/unlimited FPS (tiny per-frame `t`): (1) `merge_color(c1, c2, t)` floors `c1*(1-t)` and `c2*t` separately, so even `merge_color(c, c, t)` returns `c` minus ~1/channel — re-merging its own result every frame drifts the color to **black**; (2) a _rounded_ packed-int lerp instead loses a sub-1 per-frame step (`round(c + 0.4) == c`), so the tween **freezes** (no hover/press animation). One-shot merges are fine (`Color.merge`, day/night ambient). For an animated color, keep the `r/g/b` as **floats** and `Tween.approach()` each channel, rounding only the final `make_colour_rgb` — float state accumulates correctly at any frame rate and rests exactly at target (see `UIButton._easeColor`, mirroring the scalar shadow ease). Symptom was button fills going black, or the tween dead at "Unlimited" FPS; text/static-color widgets were unaffected.

## Timing / input

- **UI timers/easing use `Time.raw`, not `Time.delta`** — `Time.delta` is scaled by `Time.scale`, so UI on it freezes/slows when the sim dilates or pauses. Use `Time.raw` (wall-clock) for hover/press fades, caret blink, key-repeat, toggle easing (`UIButton`/`UIInput`/`UICheckbox`).
- **`mouse_check_button*` are sampled realtime, NOT latched per frame** — calling the same query twice in a frame can return different values. Call each edge query once at frame start and share it; don't derive edges from the button level. **`UIPointer.poll()`** (in `Step_0` before `UI.update`) latches `pressed`/`released`/`down`/`wheel` once for every widget + `SlotDrag`/`BuildMode`/`Dialogue` to read.
- **`keyboard_lastkey` lags `keyboard_check_pressed(vk_anykey)` by a frame** — on the pressed-edge frame it still holds the previous key, so a rebind handler binds the stale key. Scan the keycode range for the one whose `keyboard_check_pressed(code)` is live this frame (see `UIRebind._scanKey`, scans 8..255).

## flexpanel layout (style mutation works on 0.20 — follow the design rule)

- **Runtime style mutation applies** (`flexpanel_node_style_set_*` + `flexpanel_calculate_layout`). `UIText`/`UIRichText` use it to self-size in `onUpdate` (so a `gemsLabel` reports a real width/height). **By choice the broader live-layout drivers (scroll, drag, slider fill) stay on the draw-time offset/clip pattern** — they work, migrating is churn — and `UIElement`'s ~45 commented-out setters stay commented (re-enabling all would pass the 50-method ceiling; enable one on demand, minding the count). Set fixed layout props **once at construction**; drive runtime change with **draw-time offset/clip math** (`UIInput`/`UISlider`); show/hide a subtree with `child.enabled`, not `display`. **Structural** mutation is reliable: `insertChild`/`removeChild` → `markDirty` reflows correctly (as `UIAccordion` does) — when a layout must change _size_, insert/remove the subtree; a same-size show/hide prefers `enabled`. Property reference: `gm-cli manual read "Flex Panel Struct Members"`; Yoga docs (https://www.yogalayout.dev/docs/styling/) cover the semantics.

## Capabilities (work on 0.20 — use directly, don't avoid)

- **Trig + `draw_triangle_color`/`draw_line_width_color`/`draw_circle_color` work.** UI arrows/chevrons go through `drawUIArrow`, check/dash markers through `drawUICheck` (both in `scripts/UIDraw`); `draw_circle_color` draws `RenderLighting`'s light blobs. Trig (`Math.PI`/`cos`/`sin`/`atan2`) is used directly (`Temperature.diurnal` cosine curve, `RenderWeather` snow sway). **`WorldClock.tint`/`_KF` keeps its hand-authored keyframe table by design — don't "trig-ify" it.**
- **Off-screen surfaces + `surface_getpixel`, `bm_add`, and multiply via `gpu_set_blendmode_ext(bm_dest_colour, bm_zero)`** (no `bm_multiply` constant) work — the `RenderLighting` 2D light-map infra.
- **Baked-mesh vertex buffers work (verified 2026-07-05)** — `buffer_load` of an included binary → `vertex_create_buffer_from_buffer` → `vertex_freeze` → `vertex_submit(vb, pr_trianglelist, -1)` (untextured, custom `position_3d + colour + texcoord` format) renders vertex-colored 3D geometry in the depth pass. Colour byte order in buffer memory is **R,G,B,A**; the binary layout and the in-engine format declaration are a lockstep pair (24 B/vertex) — see `tools/vox-kit/vox2vbuf.py` ↔ `RenderMesh._model`. The colour is UNSHADED **albedo** and the texcoord carries a **packed face normal** (`u = nx, v = ny`, shader derives `nz = -sqrt(1-u²-v²)` — no bottom faces are emitted, so `nz ≤ 0`): `sh_meshlit` lights it live (N·L directional sun + point-light **uniform arrays** — `shader_set_uniform_f_array` works on 0.20, verified with 3 simultaneous lights; GLSL ES `mat3(mat4)`, `#define`, and loop `break` all compile). The texcoord can carry real UVs instead **only via the shader's textured mode** (`u_useTex` = 1 + a per-submit `u_normal` uniform — how `RenderWalls` textures wall faces with the same 24 B format); a per-vertex-normal + UV combination would need a format split.
