# GMRT-Safe Idioms

Runtime-quirk reference for **G.E.M.S.** on the GMRT runtime, imported into context by [CLAUDE.md](CLAUDE.md) (via its `@GMRT.md` line) so it is always loaded alongside it.

**Everything below is verified against GMRT 0.20** (the toolchain pinned by `gm-options.json`) — re-audit this document on a runtime upgrade. The GMRT JS runtime/compiler miscompiles or chokes on several standard JS forms. Avoid the quirks, don't "clean up" code back into them, leave a one-line comment where one forces an unusual idiom so it isn't "fixed" back, and record new quirks here as found.

## Language / compiler

- **`for...of` over a Map iterator hangs the game** ([#15095](https://github.com/YoYoGames/GameMaker-Bugs/issues/15095), open) — the `Map` iterator's `next()` never advances, so iterating `.values()`/`.keys()`/`.entries()` or the bare `Map` loops forever: no exception, no crash, `game.log` just stops at its last flush. Keep parallel arrays and index-loop (see `World._keys`/`_storages`). `Set` iteration works (bare `Set` and `Set.values()`); `for...of` over an array/string and `for...in` over a plain object are fine.
- **A `Map` keyed by an ASSET REF (sprite handle) crashes natively at `.get`** — hard process death (`Bad optional access`), not a JS exception, so `Log.exception` records nothing. String-keyed Maps are fine (`Item`/`Rarity`/`I18n`/…). For a ref-keyed registry use parallel arrays + an `===` identity scan — asset-ref `===` works (see `SpriteMeta`).
- **An asset ref reports `typeof "object"`, and `Object.keys(ref)` is `[]` without throwing** — so a generic deep copy silently turns a stored sprite handle into `{}`. Discriminate plain data by `v.constructor === Object` (`true` for object literals, `false` for asset refs); pass refs through by reference (see `EntityPreset._clone`).
- **No array destructuring in a `for...of` header** ([#15194](https://github.com/YoYoGames/GameMaker-Bugs/issues/15194), open) — `for (const [a,b] of arr)` throws `ReferenceError: a is not defined`. Use `arr[i][0]`, or destructure inside the loop body. (Object destructuring and a `.forEach(([a,b]) => …)` param are fine — only the loop header is broken.)
- **No empty `for` initializer** — `for (; c<n; c++)` crashes the compiler. Use `while`.
- **No optional chaining (`?.`)** ([#15079](https://github.com/YoYoGames/GameMaker-Bugs/issues/15079), open) — any `a?.b` crashes the compiler (`Visit function for ?. expression not found`), not a code error pointing at the offending line. Write the guard explicitly (`a !== null && a !== undefined ? a.b : fallback`, or an `if`). **Nullish `??` and `??=` are fine** — exact null/undefined-only semantics (`0 ?? 7` → `0`); `??` is already used project-wide.
- **`Array.sort` comparator must return a SIGN, not a raw difference** — the comparator's return is truncated to an int, so a fractional `(a, b) => a.t - b.t` over sub-1 values makes every pair "equal" and the array keeps its original order — a silent no-op sort. Return `a < b ? -1 : a > b ? 1 : 0` (see `Raycast.castAll`). A difference comparator only happens to work for far-enough-apart integers.
- **Don't cache a primitive boolean in a local across a function** — it can flip mid-function. Cache the component object and read the property live each use (see `PlatformerController.update` → `groundedComp.isGrounded`).
- **Top-level bare `const` isn't visible to other scripts** — share via `globalThis.Name`. Bare top-level `function` declarations are mostly global, **but past a certain file size some stop hoisting and the game faults at startup** (`cannot coerce undefined or null...`). Assign explicitly (`globalThis.X = function X(…)`) and keep files small (why the GemsUI kit is split).
- **A class with >50 methods faults** ([#15065](https://github.com/YoYoGames/GameMaker-Bugs/issues/15065) — fix slated for GMRT **0.22**, in QA) — 50 OK; calling the 51st method throws `Invalid call target`. Split a fat class into collaborators, lift helpers into free functions / a `globalThis` module object, or use composition (a flat base + `components:[]` queried by `instanceof`, as `UIElement`/`Item` do). The 0.22 upgrade lifts the ceiling (then e.g. `UIElement`'s commented-out flexpanel setters can return).
- **Class inheritance / `super` is broken** ([#15067](https://github.com/YoYoGames/GameMaker-Bugs/issues/15067), open) — `super.method()` is a compile error (`Unsupported expression [ R_SUPER="super" ]`), and the implicit parent-constructor chain never runs: constructing a subclass skips the **BASE** class's field initializers/constructor, leaving inherited fields `undefined` (`class Bar { a = 1 }` / `class Foo extends Bar { b = 2 }` → `b` is `2` but `a` is `undefined`; the subclass's OWN field initializers do run). Model "kinds of X" as composition (`addComponent`/`getComponent(Class)`, `instanceof` on a flat class); anything a base class would have initialized must be assigned in a method that runs (e.g. `create()`).
- **A `static` field initializer can't reference its own class name** — `static x = ClassName.y` throws at load. Use a literal and read `ClassName.y` from methods (hit on `Dialogue`). Referencing another already-loaded class is fine.
- **`static get` with a computed (expression/comparison) body miscompiles to a constant** — a getter reading `_modal !== null` returned `false` while `_modal` was live. Expose derived static state as a `static` METHOD (`SystemMenu`/`Dialogue`/`VirtualKeyboard.isOpen()`), never a static accessor. A getter returning a _stored_ value works; instance `get`/`set` mostly work (but see the next bullet). Read-write static state stays a plain field (`UIInput.active`, `UITable.active`, `SlotDrag.active`, `BuildMode.active`).
- **An instance `get` whose NAME shadows a GameMaker built-in faults on access** — `get index()` / `get value()` on `UIDropdown` threw `cannot coerce undefined or null value into object` at the read site (even returning a stored value), while a sibling `get name()` and `LevelManager`'s `get current()` work — the reserved-ish name is the trigger, not the body. Expose such state as a `get*()` METHOD (`UIDropdown.getIndex()`/`getValue()`); when in doubt, prefer a method over an accessor for any GM-flavored property name.

## Strings / serialization / PRNG

- **`toUpperCase()`/`toLowerCase()` return garbage Unicode** (`"q".toUpperCase()` → `"ଊ"`). Map case via char codes (`String.fromCharCode(c-32)` for a–z→A–Z; see `VirtualKeyboard._upper`, `InvTable.lower`).
- **`JSON.stringify` faults natively on nested objects/arrays** — a flat `{key: scalar}` is fine; a value that's an object/array kills the process. Persist only flat scalar blobs; serialize structure yourself (`ids.join(",")`, `"k=v;k=v"`) — see `SaveData`/`Profile`/`Achievement`.
- **Chained 32-bit xorshift PRNGs compute silently WRONG values** — `s ^= s<<13; s ^= s>>17; s ^= s<<5` diverges from real JS int32 semantics on some iterations (e.g. seed `123456789` is wrong from its 2nd round vs Node) and nothing ever throws — a stream is neither correct nor portable. Use integer-float math with no bitwise — a Park–Miller MINSTD LCG (`s = (s*48271) % 2147483647`); **`Rand`** (`scripts/Rand/`, Core/Util) is the one home for the idiom (position hashes + value noise + streams) — use it, don't hand-roll another copy. (Single bitwise ops like `IdPool`'s id packing are fine; only the overflowing chain breaks.)
- **The `random_*` built-ins work — EXCEPT `random_get_seed()` doesn't track the stream, and same-frame `randomize()` repeats**: `random`/`random_range` honor `[lo, hi)`, `irandom`/`irandom_range` are inclusive-integer and uniform, `random_set_seed` replays the identical sequence across runs, adjacent seeds decorrelate, and both `randomize`/`randomise` spellings exist. But `random_get_seed()` returns the last seed SET, not the advanced state — so the manual's capture-mid-stream-and-restore workflow silently rewinds to the seed's start. And `randomize()` is time-seeded so coarsely that two calls in one frame can return the SAME seed (and stream). Fine for one-shot gameplay randomness; deterministic worldgen keeps the hand-rolled MINSTD (**`Rand`**) — it needs pure position hashing + per-chunk streams a single global-stream RNG can't provide (and the get_seed defect forecloses save/restore emulation).

## Sprites / assets / camera

- **No SVG sprites** (the remaining SVG assets: `spr_choo`/`spr_play`/`spr_exit`/`spr_back`/`spr_revert`) — SVG Assets are on the release notes' official known-incompatibility list (see _Officially unsupported_ below), a declared gap rather than a bug awaiting a fix: `sprite_get_number()` returns `0`, so frame math can go negative and `draw_sprite_ext` throws. Use raster sprites; clamp frame count `≥1` and `subimg` `≥0` (see `AnimationSystem`).
- **`asset_get_index(name)` returns an opaque ref, not a number** — a `>=0` test is always false. Validate with `sprite_exists()` (a not-found name is `-1`, which it also rejects). See `UISlots`/`SlotDrag`, `UIRichText._icon`.
- **`view_camera[]` isn't exposed** — indexing faults. Hold the `Camera` instance and read the view rect from its own fields (`toX`/`toY`/`width`/`height`), **not `camera_get_view_*`** — the project's `Camera` drives the view by matrix, so `camera_get_view_*` returns 0. An ORTHO `CameraFollow.create2d` camera is centered on `(toX,toY)` spanning `width×height` world px. The view-culling passes (`RenderLighting`/`RenderWeather`/`RenderDebugTileMap`/`RenderGrid`) read the Camera fields for this reason.
- **`mouse_x`/`mouse_y` are WRONG under a pitched matrix camera** (~118 world px off at the screen edge at a 35° pitch, worse at the RPG's 42–58°; flat matrix cameras map fine, so the level editor's `CameraPan` still uses them). Convert the cursor yourself: **`Camera.unproject(sx, sy)`** (surface px → ground-plane world, the pitch-aware inverse of `Camera.project`) / **`Camera.cursorWorld()`** (GUI mouse → unproject). `sceneRpg.step` latches it once per frame into `scene.mouseWorld` + the player's `Playable.cursorX/Y` (mouse positions are realtime-sampled like buttons — latch and share); consumers: `PlayerSystem` aim, `BuildMode` cell pick, `Interactable` cursor targeting, `DebugInspector` click-pick/marker. Cursor-over-entity tests hit the ground-plane point (an entity's FEET) — pointing at a tall billboard's upper body lands behind it.

## Rendering / shaders / clip

- **NaN-width guard before drawing filled geometry/sprites in a UI component** — on the first frame after a scene transition the flexpanel layout isn't computed, so `getLayoutPosition()` returns NaN width/height and drawing with NaN coords faults. Guard `!(pos.width > 0)` (test `>0`, not `<=0` — `NaN <= 0` is false). See `UIStepper`/`UISlider`/`UIProgress`/`UISelect`/`UICheckbox`/`UIInput`. Don't add it to text widgets (`UIText`/`UIRichText`): they self-size and draw from `pos.left/top`, never reading `pos.width`.
- **`gpu_set_scissor` is the UI clip mechanism** (`UIElement._drawClipped` clips scroll/viewport children with it) — it clips reliably, doesn't leak, and draws children directly to the back buffer (crisp SDF text, no clip surfaces; nested scrolls clip by intersecting rects). The rules:
  1. Coords are render-target **PIXELS**, not GUI units — convert by `k = target/gui`.
  2. The render target is the **window back buffer**, and `window_get_width/height()` / the application surface lag it on a resize (a SHRINK resizes the back buffer synchronously, a GROW lags one frame) — a scissor sized from any single query can overflow the target on a resize frame → a **fatal** "scissor rect not contained in the render target" error. Size clips from **`Display.clipW/clipH`** (the intended size min'd with its 1-frame-lagged self), which never exceeds the live back buffer in either direction.
  3. The scissor is **not cleared between frames** — a stale rect survives and, after a shrink, replays forever as a bogus "nested parent". `UI.draw()` re-anchors it to the full target (`gpu_set_scissor(0, 0, Display.clipW(), Display.clipH())`) at the start of each frame.
  4. `gpu_get_scissor()` returns `{0,0,0,0}` when unset (the full-target default) — treat it as a nesting parent only when its `w`/`h` are positive, and **never restore a saved `{0,0,0,0}`** (that clips everything afterward to an empty rect); at top level reset to the full render target instead.
  5. **Setting the scissor does NOT flush the pending vertex batch.** Three symptoms: the LAST item drawn under a clip renders UNCLIPPED (it flushes later, after the restore) → `draw_flush()` at the end of `_drawClipped` **before** the scissor restore; the still-pending last primitive of the PRECEDING drawer gets captured under the clip and clipped away → the preceding drawer must end with a harmless trailing untextured primitive to force the flush (`UITabs.onDraw` re-strokes its baseline last) — a _start_-of-clip `draw_flush()` instead corrupts the clip (`No pipeline set`/`Invalid CommandBuffer`); a non-clipped sibling drawn AFTER a clip in the same parent can render nothing → `CraftingUI` avoids any clip in its master-detail row (see its comment). `draw_flush` is manual-flagged debug-only but is the only batch-flush primitive — once per clip container per frame is fine. A text-only clip (caret/overflow in one widget) can compute the visible substring itself (`UIInput.onDraw`).
- **Resolve `I18n.font(key)` at DRAW time — never cache the handle at construction** — a cached handle breaks two ways: `I18n.font` falls back to `draw_get_font()` for an undeclared key (freezing the wrong font), and a language switch (`I18n.load`) `font_delete()`s every old handle so a cached one dangles (renders the GM default 12pt Arial, or nothing). The text widgets take `font` polymorphically — a raw handle (number) OR an I18n font KEY (string) — and resolve live each draw: `const f = typeof this.font === "string" ? I18n.font(this.font) : this.font;` (`UIText`/`UIRichText`/`UITabs`/`UIAccordion`/`UISlider`/`UITable`; `UIQuestTracker` stores `*FontKey` fields). The GemsUI factories pass the **key**, never a pre-resolved handle. Exception: world-space render passes (`RenderChunks`/`RenderZoneLabel`/`RenderDebugTileMap`) still take a handle — they rebuild on map reload but not on a locale switch, so their labels keep the old font until the next map load (acceptable for debug-ish world labels).
- **Screen-space overlay matrices: up +1 AND negative ortho height** — a pass that resets view/projection to surface-pixel ortho (`RenderLighting`'s composite, `RenderWeather`) must use `matrix_build_lookat(w/2, h/2, -1, w/2, h/2, 0, 0, 1, 0)` + `matrix_build_projection_ortho(w, -h, 0, 2)` — the **negative height**. The overlay path has an inherent Y-flip vs the world camera (which is correct with positive height), and negating the UP vector instead is a 180° ROLL — it X-MIRRORS the content about screen center, invisible for symmetric content (ambient fill, vignette, a centered blob) but wrong for anything off-center.
- **Custom `GMShader`s run, but guard them** — `shaders_are_supported()` + `shader_is_compiled(asset_get_index("name"))` before `shader_set`, with a non-shader fallback. A shader on an **untextured** primitive reads `gm_BaseTexture` as black, so compute output from uniforms only — don't sample. (**`sh_meshlit` is the ONE world shader** — every world pass submits through it in vox or textured mode, with the texel cutout as a uniform mode (`u_alphaRef`); day/night + the night vignette are still the `RenderLighting` light map, not a shader.)
- **Declare every shader uniform in the FRAGMENT stage — a uniform declared in the `.vsh` never receives its value** — `shader_get_uniform` returns a valid handle and `shader_set_uniform_f` runs without error, but the vertex stage keeps reading the default 0; the symptom is a "working" shader ignoring its flag, not a compile error. Keep the vsh attribute+matrix only, declare uniforms once in the `.fsh`, and do uniform-driven selection there (`sh_meshlit`'s vox-vs-textured `mix`es) — and don't declare one uniform in both stages either (that is the failing configuration).
- **The fixed-function alpha test is INERT — `discard` in a fragment shader instead** — `gpu_set_alphatestenable`/`gpu_set_alphatestref` ROUND-TRIP through their getters but have **no effect at draw time**: a transparent fragment is not discarded, so it still writes depth (with the depth buffer on, a sprite's empty pixels occlude what's behind — the 2.5D billboard bug). Do the cutout in the **fragment shader** — `sh_meshlit`'s **`u_alphaRef`** uniform (0 = off; billboards pass ~0.5) `discard`s fragments whose `gm_BaseTexture` **texel** alpha is below it; a discarded fragment writes no depth. Discard on the texel alpha (sprite SHAPE), **not** the final `v_vColour*tex`, so a dimmed/tinted entity stays fully visible. `RenderBillboard` sets it around its draw loop; `RenderMesh._setupLights` pins it 0 so vox/wall submits never discard. `gpu_set_alphatestenable(true)` is left commented out in `obj_game` Create_0 as a record of the dead end.
- **Don't ease a _packed_ color int every frame — ease its float r/g/b channels** — two traps, both acute at high/unlimited FPS (tiny per-frame `t`): (1) `merge_color(c1, c2, t)` floors `c1*(1-t)` and `c2*t` separately, so even `merge_color(c, c, t)` returns `c` minus ~1/channel — re-merging its own result every frame drifts the color to **black**; (2) a _rounded_ packed-int lerp instead loses a sub-1 per-frame step (`round(c + 0.4) == c`), so the tween **freezes**. One-shot merges are fine (`Color.merge`, day/night ambient). For an animated color, keep the `r/g/b` as **floats** and `Tween.approach()` each channel, rounding only the final `make_colour_rgb` (see `UIButton._easeColor`).

## Timing / input

- **UI timers/easing use `Time.raw`, not `Time.delta`** — `Time.delta` is scaled by `Time.scale`, so UI on it freezes/slows when the sim dilates or pauses. Use `Time.raw` (wall-clock) for hover/press fades, caret blink, key-repeat, toggle easing (`UIButton`/`UIInput`/`UICheckbox`).
- **`mouse_check_button*` are sampled realtime, NOT latched per frame** — calling the same query twice in a frame can return different values. Call each edge query once at frame start and share it; don't derive edges from the button level. **`UIPointer.poll()`** (in `Step_0` before `UI.update`) latches `pressed`/`released`/`down`/`wheel` once for every widget + `SlotDrag`/`BuildMode`/`Dialogue` to read.
- **`keyboard_lastkey` lags `keyboard_check_pressed(vk_anykey)` by a frame** — on the pressed-edge frame it still holds the previous key, so a rebind handler binds the stale key. Scan the keycode range for the one whose `keyboard_check_pressed(code)` is live this frame (see `UIRebind._scanKey`, scans 8..255).

## flexpanel layout (style mutation works — follow the design rule)

- **Runtime style mutation applies** (`flexpanel_node_style_set_*` + `flexpanel_calculate_layout`). `UIText`/`UIRichText` use it to self-size in `onUpdate` (so a `gemsLabel` reports a real width/height). **By choice the broader live-layout drivers (scroll, drag, slider fill) stay on the draw-time offset/clip pattern** — they work, migrating is churn — and `UIElement`'s ~45 commented-out setters stay commented (re-enabling all would pass the 50-method ceiling; enable one on demand, minding the count). Set fixed layout props **once at construction**; drive runtime change with **draw-time offset/clip math** (`UIInput`/`UISlider`); show/hide a subtree with `child.enabled`, not `display`. **Structural** mutation is reliable: `insertChild`/`removeChild` → `markDirty` reflows correctly (as `UIAccordion` does) — when a layout must change _size_, insert/remove the subtree; a same-size show/hide prefers `enabled`. Property reference: `gm-cli manual read "Flex Panel Struct Members"`; Yoga docs (https://www.yogalayout.dev/docs/styling/) cover the semantics. (`flexpanel_node_get_measure()`/`set_measure()` are officially unsupported — see _Officially unsupported_ — so Yoga's measure-callback self-size path doesn't exist; style mutation IS the self-size mechanism.)

## Officially unsupported (release notes — "Known Incompatibilities with GMS2 runtimes")

Declared, not discovered: the release notes list these as features that work on the legacy GMS2 runtime but are **not yet supported on GMRT**. Don't burn a probe run re-discovering one, and don't read its absence as a project bug.

- **Prefabs** — GameMaker's asset-prefab feature. Unrelated to the project's own `Prefab` registry (`scripts/Prefab/`, plain JS — unaffected).
- **Video playback** (scoped "other platforms" in the notes) — `video_*` is unused by the project; treat as unavailable.
- **SVG Assets** — the official root of the "No SVG sprites" quirk (see _Sprites / assets / camera_).
- **`flexpanel_node_get_measure()` / `flexpanel_node_set_measure()`** — Yoga's custom measure-callback hook is absent, so a widget cannot self-size via a measure function; explicit style mutation is the self-size mechanism (see _flexpanel layout_).
- **`vertex_buffer_exists()` / `vertex_format_exists()`** — no existence probes for vertex buffers/formats; keep your own handle bookkeeping (`RenderMesh`'s vbuf cache holds its handles and never re-validates them).
- **`application_surface_is_draw_enabled()`** — absent; mind it when porting GMS2 samples.
- **Lots of error spam from SDL** — upstream-acknowledged runner console noise; don't chase SDL-looking errors in `gm-cli run` output as project faults unless the game also misbehaves.

## Capabilities (verified working — use directly, don't avoid)

- **Trig + `draw_triangle_color`/`draw_line_width_color`/`draw_circle_color` work.** UI arrows/chevrons go through `drawUIArrow`, check/dash markers through `drawUICheck` (both in `scripts/UIDraw`); `draw_circle_color` draws `RenderLighting`'s light blobs. Trig (`Math.PI`/`cos`/`sin`/`atan2`) is used directly (`Temperature.diurnal` cosine curve, `RenderWeather` snow sway). **`WorldClock.tint`/`_KF` keeps its hand-authored keyframe table by design — don't "trig-ify" it.**
- **Off-screen surfaces + `surface_getpixel`, `bm_add`, and multiply via `gpu_set_blendmode_ext(bm_dest_colour, bm_zero)`** (no `bm_multiply` constant) work — the `RenderLighting` 2D light-map infra.
- **Baked-mesh vertex buffers work** — `buffer_load` of an included binary → `vertex_create_buffer_from_buffer` → `vertex_freeze` → `vertex_submit(vb, pr_trianglelist, -1)` (untextured, custom `position_3d + colour + texcoord` format) renders vertex-colored 3D geometry in the depth pass. Colour byte order in buffer memory is **R,G,B,A**; the binary layout and the in-engine format declaration are a lockstep pair (24 B/vertex) — see `tools/vox-kit/vox2vbuf.py` ↔ `RenderMesh._model`. The colour is UNSHADED **albedo** and the texcoord carries a **packed face normal** (`u = nx, v = ny`, shader derives `nz = -sqrt(1-u²-v²)` — no bottom faces are emitted, so `nz ≤ 0`): `sh_meshlit` lights it live (N·L directional sun + point-light **uniform arrays** — `shader_set_uniform_f_array` works; GLSL ES `mat3(mat4)`, `#define`, and loop `break` all compile). The texcoord can carry real UVs instead **only via the shader's textured mode** (`u_useTex` = 1 + a per-submit `u_normal` uniform — how `RenderWalls` textures wall faces with the same 24 B format); a per-vertex-normal + UV combination would need a format split.
