# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**G.E.M.S.** (GameMaker Entity & Map System) is a UI and entity management library for GameMaker on the GMRT runtime (0.19.0). All game logic is JavaScript, not GML. Assets live in **four** top-level IDE folders:

- **Core** — the pure engine: ECS, built-in systems, level, render, the **UI system** (`UIElement`/widgets/singletons), input, utilities.
- **GemsUI** — the themed UI **factory kit** (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`) over the Core UI system, plus the UI sprites in `GemsUI/Sprite`.
- **RPG** — the self-contained RPG game, subfoldered like Core: `Component`/`System`/`Content`/`UI`/`Scene`/`Editor`.
- **Showcase** — everything else demonstrable: the `Platformer`/`RTS`/`Map` genre showcases (`Map` also holds the `sceneTileInspect*` tileset-validation scenes), the demo **app shell** (`obj_game`/`rm_game`/`sceneLobby`/`demo`), and the raster sprites.

Lobby categories (`SCENE_CAT_*`) are independent of IDE folders — e.g. `sceneRpg` lives in `RPG/Scene` but registers under `SCENE_CAT_RPG`.

The entire demo runs in a single room (`rm_game`) with `obj_game` as the unified controller — no room transitions.

## Working Guidelines

Bias toward caution over speed; for trivial tasks, use judgment.

- **Think first.** State assumptions; if uncertain or a request is ambiguous, ask rather than guess silently. Push back when a simpler approach exists.
- **Simplicity first (KISS).** Minimum code that solves the problem — no speculative features, single-use abstractions, unrequested configurability, or error handling for impossible cases. Fail fast rather than hiding errors.
- **Surgical changes.** Touch only what the task requires; match existing style; don't refactor or reformat unrelated code. Mention pre-existing dead code rather than deleting it; remove only what your own change made unused.
- **Verify by running.** There are no tests — confirm behavior by running the game (see Build & Run). For multi-step work, state a brief plan with a verification check per step.

## Build & Run

The project uses `gm-cli` (experimental GameMaker CLI) with the GMRT 0.20 toolchain. The project file is `gems.yyp`; the IDE can also build and run. (The GMRT-Safe Idioms below were found on 0.19 and are attributed to "0.19" as the version first hit on. A probe battery on **0.20** — the now-default — found the runtime fixed **some** of them but not others, so check per-idiom rather than assuming; the public changelog is silent on most of these unnumbered runtime quirks, so only a probe is authoritative. **FIXED on 0.20** (probe-verified 2026-06-15): flexpanel per-frame style mutation · `Math.PI` + trig (`cos/sin/atan2/sqrt`) · subclass field initializers (_but the base constructor chain still doesn't fire — `super()` is not invoked_) · `draw_triangle_color`/`draw_line_width_color`. **STILL BROKEN on 0.20** (probe-confirmed): `JSON.stringify` on nested values (hard native crash) · `toUpperCase`/`toLowerCase` · `asset_get_index` `>=0` (opaque ref) · xorshift32 collapse · the 50-method class crash #15065 · `for...of` over a Map/Set (hard crash) · **`static get` with an expression/comparison body** (miscompiles to a constant — verified 2026-06-16; a getter returning a _stored_ value works, but keep computed static state a `static` METHOD — see the static-get idiom below). Migrating the code off these now-fixed workarounds is tracked in ROADMAP → _GMRT 0.20 cleanup_ (0.19 is no longer supported). Not probed (compile-level or stateful): `super.method()` / empty `for`-init (both compile errors by nature), large-file global hoisting, `gpu_set_scissor` leak, `draw_text` in nested clip, SVG (changelog: still unsupported).)

```sh
gm-cli run     --toolchain GMRT@0.20 gems.yyp                 # run
gm-cli compile --toolchain GMRT@0.20 gems.yyp                 # compile only
gm-cli compile --toolchain GMRT@0.20 --errors-only gems.yyp  # compile, errors only
```

**Manual lookup — use this to confirm any built-in API.** `gm-cli manual read "<query>"` prints the GameMaker manual page for a function or topic (e.g. `gm-cli manual read buffer_save_ext`, `gm-cli manual read "Flex Panel Struct Members"`). It is the **authoritative** source for a built-in's exact signature, arguments, return value, and accepted constants — read it before relying on an unfamiliar GML/runtime function rather than guessing the API (which on GMRT often differs from what you'd assume). The query is **fuzzy-matched**, so a near-neighbor page can win (`buffer_save` lands on `game_save_buffer`); pass the exact function/page name to be sure. Note this confirms only that an API _exists_ and its intended contract — whether GMRT 0.19 actually honors it is a separate question (see GMRT-Safe Idioms for the ones it doesn't).

**Stale-cache reset.** Two ignored, regenerable dirs hold build state: `.gmcache/` (incremental compile cache — `gm-cli cache info`/`gm-cli cache clean`) and `Build/` (build _output_, not "cache", so `cache clean` won't touch it — remove it manually). When a build behaves as if an asset still has its old state (renamed/deleted asset still "present", or a compile/runtime error that doesn't match the source), wipe them and rebuild: `gm-cli cache clean` (also re-downloads the shared GMRT runtime under `%LOCALAPPDATA%\GameMakerCLI\cache`, so the next build is slower) and/or delete `Build/`. The next `gm-cli run`/`compile` does a full clean rebuild. Both dirs are git-ignored (`.gmcache` via its own auto-generated `.gmcache/.gitignore`), so this is safe.

**Visual verification (screenshot review).** To _see_ the rendered screen, add a temporary auto-capture (the agent can't press F5 in the live window): in `obj_game/Draw_75.js` add a frame counter on `this`, call `screen_save("<name>.png")` at the frame(s) you want, then `game_end()` a couple frames after the **last** capture so the run self-terminates. `screen_save` accepts **any bare filename**, so a single run can take **multiple** shots — give each a distinct name and capture at different frames to compare states or check several screens (e.g. `screen_save("boot.png")` at frame 90, force some state, `screen_save("after.png")` at frame 150, `game_end()` at ~152). Then `gm-cli run` (it blocks until `game_end`), `Read` each PNG, and **revert the temp code**. Gotchas: `screen_save` does **not** create missing dirs (`screen_save("screenshots/x.png")` fails unless the folder exists — use a bare filename); a **bare** filename lands in the run/build dir `.gmcache/build-gmrt-windows-vm/build/<name>.png`, _not_ the `%LOCALAPPDATA%\gems\` save dir (where `game.log`/`settings.json`/`save.json` live).

## Asset Creation

**Never create GameMaker assets (scripts, objects, rooms, sprites) by hand-writing files/folders or editing the `Resources` list in `gems.yyp`.** GameMaker manages asset metadata strictly — manual edits corrupt the project or are silently ignored. Two valid routes:

**A. GameMaker IDE** — right-click a folder in the Asset Browser → Add Script / Add Object / etc.

**B. `gm-cli resourcetool`** (no IDE) — for a new script `<name>`:

```sh
gm-cli resourcetool eval "RESOURCE CREATE TYPE=Script NAME=<name>"                # registers it in gems.yyp
gm-cli resourcetool eval "RESOURCE SET EXPR=<name>.scriptSource VALUE=<name>.js"  # point at .js, not the .gml stub
```

Then delete the generated `scripts/<name>/<name>.gml` stub and `Write` `scripts/<name>/<name>.js`. To file the asset under an IDE folder, **edit the asset's own `.yy`** `parent` (`path: folders/<Folder>.yy`, `name: <Folder>`) to match a sibling — this is safe local metadata. New IDE folders: `gm-cli resourcetool eval "FOLDER CREATE FOLDER=Parent/Child"`; its name validator rejects spaces/`&` (over-strict — the IDE allows them, e.g. `UI Sprites`), so for such names hand-add a `GMFolder` line to the `Folders` array in `gems.yyp` (this array — unlike `resources` — is safe to hand-edit; that's also how empty folders are deleted, as resourcetool has no FOLDER DELETE). Do **not** `RESOURCE SET` `.parent` (it mis-writes the path); left unset, the asset stays at the project root. Verify with `gm-cli resourcetool eval "CHECK PROJECTPATH=gems.yyp"`, then `gm-cli compile`.

After the asset exists, edit its `.js`/`.yy` freely. **Renaming or deleting** an asset must also go through the IDE or `resourcetool`, never by moving/removing files manually — to delete: `gm-cli resourcetool eval "RESOURCE DELETE NAME=<name> TYPE=Script"` (removes it from `gems.yyp` and deletes its `scripts/<name>/` folder).

## Code Style & Conventions

- **Language**: JavaScript (GMRT JS runtime), not GML. All scripts in `scripts/` use `.js`.
- **Script naming**: PascalCase directory and filename matching the global the script exposes (e.g. `scripts/World/World.js`). Intentional exceptions: the `cameraFollow`/`cameraFollow2d` factories (camelCase functions) and the `utils` grab-bag.
- **Global exposure**: Scripts expose globals via `globalThis.Name = ...`. Components are string tokens; systems and classes use the forms below.
- **ECS bootstrap**: Each scene owns its `World` (`this.world = new World(maxEntities, tickrate, opts)`). There is no `WORLD`/`MAX_ENTITIES` global.
- **Formatter**: [Prettier](https://prettier.io/) with `{ "bracketSameLine": true }` (MDN config). Working tree is CRLF (`core.autocrlf=true`); run `prettier --end-of-line crlf`. `.d.js` stubs and `Build/`/`.gmcache/` are in `.prettierignore`.

## GMRT-Safe Idioms

The GMRT JS runtime/compiler miscompiles or chokes on several standard JS forms. Each has caused real, hard-to-diagnose breakage — avoid them, don't "clean up" code back into them, and prefer the listed idiom:

- **No `for...of` over a Map/Set iterator** (`map.values()`/`.keys()`/`.entries()`, or a `Set`) — it _breaks_ the runtime. Keep parallel arrays and index-loop them (see `World._keys`/`_storages`). `for...of` over a plain **array** or string is fine; `for...in` over a plain **object** is fine.
- **No array destructuring in `for...of`** (`for (const [a, b] of arr)`) — `ReferenceError` at runtime. Use index access (`arr[i][0]`). (Object destructuring `const {x,y} = o` and destructuring in a `.forEach(([a,b]) => …)` callback param _are_ fine — see `Input.import`.)
- **No empty `for` initializer** (`for (; c < n; c++)`) — crashes the compiler. Use a `while` loop.
- **Don't cache a primitive boolean in a local across a function** — it can get clobbered mid-function (a `const` flips `true`→`false` in one call). Cache the **component object** and read the property live each use (see `PlatformerController.update` reading `groundedComp.isGrounded`).
- **Top-level bare `const` is not visible to other scripts** — share via `globalThis.Name`. Bare top-level `function` declarations are _mostly_ global, **but past a certain file size GMRT stops hoisting some of them into global scope and faults at startup** (`cannot coerce undefined or null value into object`). Assign factories/helpers explicitly — `globalThis.X = function X(…)` — and keep files small (the GemsUI kit was split into `GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls` for this reason).
- **A JS class with more than 50 methods crashes the GMRT 0.19 runtime** ([bug #15065](https://github.com/YoYoGames/GameMaker-Bugs/issues/15065) — open, under GameMaker-team investigation) — the ceiling is 50 plain methods (50 OK, 51+ faults at runtime). Keep a class under it: split a fat class into smaller collaborators, lift stateless helpers into free functions or a plain `globalThis` module object (the system-object pattern), or use the project's composition model (a flat base + a `components: []` array queried by `instanceof`, as `UIElement`/`Item` do) rather than piling methods onto one class. (This is the bug the `flexpanel` per-frame-mutation note used to mis-cite — that one is a separate, unnumbered GMRT 0.19 limitation.)
- **`static get` is only PARTIALLY usable on GMRT 0.20 — keep computed static state as a `static` METHOD** — static getters yielded plain `undefined` on the dropped 0.19 (hit on `VirtualKeyboard.active`, which read falsy so typing bailed). On 0.20 a getter that returns a STORED value works, but a getter whose body is an EXPRESSION/comparison **miscompiles to a constant**: verified 2026-06-16, `static get isOpen() { return SystemMenu._modal !== null; }` returned `false` while `_modal` held a live `UIModal` object (the inline `_modal !== null` returned `true` the same frame) — which would have silently broken the pause gate (`!isOpen` → scene never pauses) and virtual-keyboard typing (`!isOpen` → `type()` always early-returns). So expose derived static state as a `static` METHOD (`SystemMenu`/`Dialogue`/`VirtualKeyboard.isOpen()`), never a static accessor. Instance `get`/`set` always work (`UISelect` ships `get index/value/name`; inlining as `UIStepper` does is style, not a constraint). **Read-WRITE static state stays a plain field** (`UIInput.active`, `UITable.active`, `SlotDrag.active`, `BuildMode.active`) — a getter can't be assigned to anyway.
- **Guard `!(pos.width > 0)` before drawing filled geometry/sprites in a UI component** — on the first frame after a scene transition the flexpanel layout isn't computed, so `getLayoutPosition()` returns NaN width/height and drawing roundrects/sprites with NaN coords faults. Test `> 0`, not `<= 0` (`NaN <= 0` is `false`, so the naive guard misses it) — see `UIStepper`/`UISlider`/`UIProgress`/`UISelect`/`UICheckbox`/`UIInput`. **Do NOT add it to text-drawing components** (`UIText`/`UIRichText`, or anything that self-sizes via `setWidth` in `onUpdate`): they now self-size on 0.20, but they draw from `pos.left/top` + their own measured advances and **never read `pos.width`**, so the transient NaN width on the first post-transition frame is harmless — the guard would only suppress a legitimate draw (`draw_text` tolerates 0/NaN width anyway).
- **`flexpanel` node-style mutation now applies at runtime on GMRT 0.20** (`flexpanel_node_style_set_*` + `flexpanel_calculate_layout`) — probe-verified 2026-06-15: `set_width`/`set_height`/`set_margin`/`set_flex_grow` all apply exactly (width 100→250, margin shifts siblings, `flex_grow` absorbs free space). It was an unreliable no-op on the dropped 0.19, which is why most setters in `UIElement` are commented out. **What now relies on it:** `UIText`/`UIRichText` self-size their element via `setWidth`/`setHeight` in `onUpdate` (so a `gemsLabel` reports a real width/height and a column lays out around it) — the kit's old fixed-height label-wrapper rows (`gemsModal`/`gemsSection` titles + bodies) were retired on the back of this (screenshot-verified). **What still doesn't, by choice:** the broader live-layout drivers (scroll, drag, input scroll, slider fill) stay on the **draw-time offset/clip pattern below** — they work, migrating them is pure churn — and `UIElement`'s full commented-out setter set stays commented because re-enabling all ~45 would push the class past the 50-method ceiling (#15065, **still live on 0.20**); enable an individual setter on demand, minding the count. Set fixed layout props **once at construction** (the `new UIElement({...})` struct); drive runtime change (scroll, expand/collapse, modals, drag) with **draw-time offset/clip math** (see `UIInput`/`UISlider`), and show/hide a subtree with the project's own `child.enabled` flag (checked in `update`/`draw`), not by toggling `display`. **Structural** mutation IS reliable though (probe-verified): `insertChild`/`removeChild` → `markDirty` → `flexpanel_calculate_layout` reflows correctly even after the first layout pass — so when a layout must change _size_, insert/remove the subtree (as `UIAccordion` does) rather than animating a flex dimension; a **same-size** show/hide still prefers `enabled` (no reflow). For the full node-property reference (names, accepted values, defaults) run `gm-cli manual read "Flex Panel Struct Members"`; Yoga's docs (https://www.yogalayout.dev/docs/styling/) cover the layout semantics.
- **`String.prototype.toUpperCase()`/`toLowerCase()` return garbage Unicode** — `"q".toUpperCase()` yields `"ଊ"`, not `"Q"`. Map case yourself via char codes — `String.fromCharCode(ch.charCodeAt(0) - 32)` for a-z→A-Z. See `VirtualKeyboard._upper` (Shift key).
- **`JSON.stringify` faults on nested objects/arrays** — `JSON.stringify(["a","b"])` and a flat `{key: scalar}` object are fine (see `Settings`), but an object whose value is an object/array _hard-faults_. Persist only flat `{key: scalar}` blobs; serialize structure to a scalar string yourself (`ids.join(",")`, `"k=v;k=v"`) — see `SaveData`/`Profile`/`Achievement`.
- **GMRT 0.19 does not support SVG sprites** (e.g. `spr_choo`, `spr_play`, `spr_hana`) — `sprite_get_number()` returns `0`, so frame math can go negative and `draw_sprite_ext` throws _"Trying to draw negative subimage index on a non-instance"_. Use raster sprites; clamp any computed frame count to `≥ 1` and `subimg` to `≥ 0` (see `AnimationSystem`).
- **`asset_get_index(name)` returns an opaque asset _ref_, not a numeric index** — a `>= 0` validity test is always `false` for a found sprite (silently suppressing the draw). Validate with `sprite_exists()`, never `>= 0` (a not-found name returns `-1`, which `sprite_exists` also rejects). See `UISlots`/`SlotDrag` and `UIRichText._icon`.
- **`view_camera[]` is not exposed in the GMRT JS runtime** — indexing it faults. Hold the `Camera` instance, but read the view rect from the **instance's own fields** (`camera.toX`/`toY`/`width`/`height`), **not `camera_get_view_*(camera.id)`** — the project's `Camera` drives the view via `camera_set_view_mat`/`camera_set_proj_mat` and never calls `camera_set_view_pos`/`_size`, so `camera_get_view_x/y/width/height` return **0** (verified: `get_view_w=0` while `cam.width=1366`). An ORTHO `cameraFollow2d` is centered on `(toX, toY)` spanning `width × height` world px, so that rect is the view. All three passes that view-cull (`RenderDayNight`, `RenderDebugTileMap`, `RenderGrid`) read the Camera fields for this reason — `camera_get_view_*` would collapse the cull to a degenerate `(0,0)` rect (this was a latent bug: the RPG interior's wall tilemap and the overworld grid drew nothing until the passes were switched to the instance fields; inspector scenes were unaffected since they don't assign `pass.camera`).
- **GMRT 0.19 can run a custom `GMShader`, but guard it** — `shaders_are_supported()` + `shader_is_compiled(asset_get_index("name"))` (the opaque ref; a `>= 0` test is meaningless) before `shader_set`, and keep a non-shader fallback path (GMRT 0.19 has had shader trouble). A shader on an **untextured** primitive (e.g. `draw_rectangle`) reads `gm_BaseTexture` as black, so compute the output color from uniforms only — don't sample the texture (see `sh_daynight` + `RenderDayNight`, which derive a screen-space vignette from the clip-space position the vertex shader passes through, no UVs).
- **`gpu_set_scissor`/`gpu_get_scissor` leaks globally** — the clip state set for one element bleeds onto every subsequent UI draw, so a wrong/missed restore makes the _whole scene_ go invisible (hit while clipping `UIInput`'s text). Don't use it to clip; clip by computing the visible substring/offset yourself and drawing only what fits (see `UIInput.onDraw`).
- **`draw_text` loses the world matrix inside a NESTED clip surface** — the `clip`/`UIScroll` path (`UIElement._drawClipped`) renders children into an off-screen surface under a `matrix_world` translate. `draw_roundrect_*`/`draw_sprite_*` honor it, and so does `draw_text` for a _single_ surface — but an immediate-mode text widget nested in **two** clip surfaces (a `gemsScroll` within a `gemsScroll`) draws its text at absolute position and gets clipped away (only the text vanishes; the panel still moves correctly). Hit on `UIQuestTracker`. Don't double-nest an immediate-mode text widget; one enclosing scroll is enough. `UIText`/`UIButton` labels are unaffected.
- **A `UIComponent` must resolve `I18n.font(key)` at DRAW time, not cache the handle at construction** — `I18n.font(key)` falls back to `draw_get_font()` for an undeclared key, so a handle captured in a constructor (a Create event) freezes whatever font was active then and later renders **nothing**. Store the font _key_ (a string) and call `I18n.font(key)` inside `onDraw` (hit on `UIQuestTracker`).
- **`draw_triangle_color`/`draw_line_width_color` and `Math.PI`/trig now WORK on GMRT 0.20** (the default; all rendered nothing / were `undefined` on the dropped 0.19). The drawing primitives are migrated: every arrow/chevron/step/sort affordance (`UIAccordion`/`UISelect`/`UIStepper`/`UIDropdown`/`UITable` + `Dialogue`'s advance chevron) goes through the shared **`drawUIArrow`** helper, checkmark/dash markers (`UICheckbox` tick, `UIQuestTracker` objective marker) through **`drawUICheck`** + `draw_line_width_color`, and `UINav`'s debug lines use `draw_line_width_color` (helpers in `scripts/utils`). Trig (`Math.PI`/`cos`/`sin`/`atan2`) is safe in new code and now used directly: `Temperature.diurnal()` is a cosine day-curve (was a keyframe table) and `RenderWeather`'s snow weaves with `Math.sin` (the same change fixed the "rain/snow static" bug — it was multiplying `Time.raw`, a per-frame delta, by speed instead of a cumulative clock; now `current_time`). **`WorldClock.tint`/`_KF` keeps its keyframe table by design** — it's a hand-authored day/night _color_ script (deep-blue → dawn-orange → clear → dusk → blue), not a cosine stand-in, so don't "trig-ify" it. See ROADMAP → _GMRT 0.20 cleanup_.
- **UI timers/easing must use `Time.raw`, not `Time.delta`** — `Time.delta` is scaled by `Time.scale`, so UI on it freezes/slows when a sim dilates or pauses time. Use `Time.raw` (wall-clock) for hover/press fades, caret blink, key-repeat, toggle easing (see `UIButton`, `UIInput`, `UICheckbox`).
- **`mouse_check_button*` are sampled realtime, NOT latched per frame** — calling the _same_ query more than once in a frame can return _different values each call_ (one path read `_released` as `0` while another, the same frame, read `1`). Call each edge query **once** at frame start and share the result; don't re-query, and don't derive edges from the button _level_ (it flickers frame-to-frame even held). See `SlotDrag.poll()` (in `Step_0` before `UI.update`), which latches `mouse_check_button_pressed`/`_released` once into `SlotDrag.pressed`/`released` for `UISlots` and `SlotDrag` to read.
- **`keyboard_lastkey` lags `keyboard_check_pressed(vk_anykey)` by a frame** — on the pressed-edge frame `keyboard_lastkey` still holds the _previous_ key, so a "press a key to bind" handler that reads it binds the stale key on the first press. Instead scan the keycode range for the one whose `keyboard_check_pressed(code)` is live this frame — that stays in sync with the edge. See `UIRebind._scanKey` (scans `8..255`, skipping nokey/anykey/Esc).
- **A `static` field initializer can't reference the class's own name** — `static x = ClassName.y` throws `ReferenceError` at **load** (the class binding isn't live yet). Initialize with a **literal** and read `ClassName.y` from _methods_ instead (hit on `Dialogue`). Referencing _another, already-loaded_ class is fine (e.g. `static panelColor = Color.parse("#…")`); only self-reference breaks.
- **Class inheritance / `super` is broken** — `super.method()` is a **compile error** (`Unsupported expression [R_SUPER]`), not a runtime fault; don't design with subclassing. Model "kinds of X" as **composition**: a flat base class carrying a `components: []` array of standalone data classes queried by `instanceof` (the `UIElement` `addComponent`/`getComponent(Class)` pattern, also `Item` → `Equippable`/`Weapon`). `instanceof` against a _flat_ class works fine; only inheritance breaks. **A subclass's instance field initializers never run** either — `class Foo extends Bar { label = "x" }` leaves `label` `undefined` on the instance (neither the subclass's nor the base's `field = …` fires through the broken constructor chain). The genre scene classes (`extends Scene`) hit this: `scene.label` is `undefined`, which is why the lobby + `SystemMenu` read a scene's display name from the `SceneRegistry` entry, not the instance. Assign such fields in a method that actually runs (e.g. `create()`), or read the value from elsewhere.
- **32-bit xorshift PRNGs collapse to a constant** — the classic `s ^= s << 13; s ^= s >> 17; s ^= s << 5` xorshift32 returns **exactly `0x80000000` (→ `0.5` normalized) for many seeds**, and _different_ seeds yield _identical_ output, so a "procedural" generator produces the same chunk everywhere. The break is the shift-overflow / signed-shift chain (`s << 13` overflowing 32 bits then XORing, and `s >> 17` sign-extending a bit-31-set operand); individual ops like `(x << 13) >>> 0` and `(x >>> 0) / 2**32` are each fine, but the _chained_ xorshift dance is miscompiled (hit on `OverworldGen`'s chunk seeding). Use a PRNG over **pure integer float math with no bitwise ops** instead — a Park–Miller MINSTD LCG (`s = (s * 48271) % 2147483647`) keeps every intermediate exact below 2^53 and never touches a shift (see `OverworldGen._rng`/`_seedFor`). (`IdPool`'s bitwise id packing is fine — it's single ops on small values, not an overflowing chain.)

When a quirk forces an unusual idiom, leave a one-line comment so it isn't "fixed" back. Add new quirks here as they're found.
