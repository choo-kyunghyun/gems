# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**G.E.M.S.** (GameMaker Entity & Map System) is a UI and entity management library for GameMaker 2026.0.0.16 on the GMRT runtime (0.19.0). All game logic is JavaScript, not GML. Assets live in **four** top-level IDE folders: **Core** (the engine — ECS, systems, level, render, the **UI system** (`UIElement`/widgets/singletons), input, utilities — plus the RPG _primitives_ `Item`/`Inventory`/`Equipment`/`Stats`/`Health` and their systems), **GemsUI** (the themed UI **factory kit** — `GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls` — scenes build UI with these declaratively over the Core UI system), **RPG** (the RPG game — gameplay layer `RpgScene`/`RpgPlayer`/`RpgInventoryUI`/`RpgWorldOverlay`/`RpgContent` + combat `MeleeSystem`/`SlimeAI` + the **TopDown** genre (`sceneTopDown`/`TopDownController`/`TopDownLevel`/`BuildMode`/`TopDownContent`/`TopDownCatalog`, merged in) + the gameplay-UI managers `Interactable`/`StorageUI`/`CraftingUI`), and **Showcase** (everything else demonstrable — the `Platformer`/`RTS`/`Map` genre showcases under those subfolders (`Map` also holds the `sceneTileInspect*` tileset-validation scenes), the `Editor` (`sceneEditor`), and the demo **app shell** `obj_game`/`rm_game`/`sceneLobby`/`demo` + shared sprites). `Platformer`/`RTS` are lean movement showcases over Core (`Platformer` owns its own `Enemy`/`EnemySystem`). Lobby categories (`SCENE_CAT_*`) are independent of IDE folders — e.g. `sceneTopDown` lives in the `RPG` folder but registers under `SCENE_CAT_RPG`.

The entire demo runs in a single room (`rm_game`) with `obj_game` as the unified controller — no room transitions.

## Working Guidelines

Bias toward caution over speed; for trivial tasks, use judgment.

- **Think first.** State assumptions; if uncertain or a request is ambiguous, ask rather than guess silently. Push back when a simpler approach exists.
- **Simplicity first (KISS).** Minimum code that solves the problem — no speculative features, single-use abstractions, unrequested configurability, or error handling for impossible cases. Fail fast rather than hiding errors.
- **Surgical changes.** Touch only what the task requires; match existing style; don't refactor or reformat unrelated code. Mention pre-existing dead code rather than deleting it; remove only what your own change made unused.
- **Verify by running.** There are no tests — confirm behavior by running the game (see Build & Run). For multi-step work, state a brief plan with a verification check per step.

## Build & Run

The project uses `gm-cli` (experimental GameMaker CLI) with the GMRT 0.19 toolchain. The project file is `gems.yyp`; the IDE (GameMaker 2026.0.0.16) can also build and run.

```sh
gm-cli run     --toolchain GMRT@0.19 gems.yyp                 # run
gm-cli compile --toolchain GMRT@0.19 gems.yyp                 # compile only
gm-cli compile --toolchain GMRT@0.19 --errors-only gems.yyp  # compile, errors only
```

**Manual lookup — use this to confirm any built-in API.** `gm-cli manual read "<query>"` prints the GameMaker manual page for a function or topic (e.g. `gm-cli manual read buffer_save_ext`, `gm-cli manual read "Flex Panel Struct Members"`). It is the **authoritative** source for a built-in's exact signature, arguments, return value, and accepted constants — read it before relying on an unfamiliar GML/runtime function rather than guessing the API (which on GMRT often differs from what you'd assume). The query is **fuzzy-matched**, so a near-neighbor page can win (`buffer_save` lands on `game_save_buffer`); pass the exact function/page name to be sure. Note this confirms only that an API _exists_ and its intended contract — whether GMRT 0.19 actually honors it is a separate question (see GMRT-Safe Idioms for the ones it doesn't).

**Stale-cache reset.** Two ignored, regenerable dirs hold build state: `.gmcache/` (incremental compile cache — `gm-cli cache info`/`gm-cli cache clean`) and `Build/` (build _output_, not "cache", so `cache clean` won't touch it — remove it manually). When a build behaves as if an asset still has its old state (renamed/deleted asset still "present", or a compile/runtime error that doesn't match the source), wipe them and rebuild: `gm-cli cache clean` (also re-downloads the shared GMRT runtime under `%LOCALAPPDATA%\GameMakerCLI\cache`, so the next build is slower) and/or delete `Build/`. The next `gm-cli run`/`compile` does a full clean rebuild. Both dirs are git-ignored (`.gmcache` via its own auto-generated `.gmcache/.gitignore`), so this is safe.

**Visual verification (screenshot review).** To _see_ the rendered screen, add a temporary auto-capture (the agent can't press F5 in the live window): in `obj_game/Draw_75.js` add a frame counter on `this`, call `screen_save("auto.png")` at ~frame 150 and `game_end()` at ~152 so the run self-terminates. Then `gm-cli run` (it blocks until `game_end`), `Read` the PNG, and **revert the temp code**. Gotchas: `screen_save` does **not** create missing dirs (`screen_save("screenshots/x.png")` fails unless the folder exists — use a bare filename); a **bare** filename lands in the run/build dir `.gmcache/build-gmrt-windows-vm/build/auto.png`, _not_ the `%LOCALAPPDATA%\gems\` save dir (where `game.log`/`settings.json`/`save.json` live).

## Asset Creation

**Never create GameMaker assets (scripts, objects, rooms, sprites) by hand-writing files/folders or editing the `Resources` list in `gems.yyp`.** GameMaker manages asset metadata strictly — manual edits corrupt the project or are silently ignored. Two valid routes:

**A. GameMaker IDE** — right-click a folder in the Asset Browser → Add Script / Add Object / etc.

**B. `gm-cli resourcetool`** (no IDE) — for a new script `<name>`:

```sh
gm-cli resourcetool eval "RESOURCE CREATE TYPE=Script NAME=<name>"                # registers it in gems.yyp
gm-cli resourcetool eval "RESOURCE SET EXPR=<name>.scriptSource VALUE=<name>.js"  # point at .js, not the .gml stub
```

Then delete the generated `scripts/<name>/<name>.gml` stub and `Write` `scripts/<name>/<name>.js`. To file the asset under an IDE folder, **edit the asset's own `.yy`** `parent` (`path: folders/<Folder>.yy`, `name: <Folder>`) to match a sibling — this is safe local metadata. New IDE folders: `gm-cli resourcetool eval "FOLDER CREATE FOLDER=Parent/Child"`; its name validator rejects spaces/`&` (over-strict — the IDE allows them, e.g. `UI Sprites`), so for such names hand-add a `GMFolder` line to the `Folders` array in `gems.yyp` (this array — unlike `resources` — is safe to hand-edit; that's also how empty folders are deleted, as resourcetool has no FOLDER DELETE). Do **not** `RESOURCE SET` `.parent` (it mis-writes the path); left unset, the asset stays at the project root. Verify with `gm-cli resourcetool eval "CHECK PROJECTPATH=gems.yyp"`, then `gm-cli compile`.

After the asset exists, edit its `.js`/`.yy` freely. **Renaming or deleting** an asset must also go through the IDE or `resourcetool`, never by moving/removing files manually — to delete: `gm-cli resourcetool eval "RESOURCE DELETE NAME=<name> TYPE=Script"` (removes it from `gems.yyp` and deletes its `scripts/<name>/` folder).

## Code Style & Conventions

- **Language**: JavaScript (GMRT JS runtime), not GML. All scripts in `scripts/` use `.js`.
- **Script naming**: PascalCase directory and filename matching the global the script exposes (e.g. `scripts/World/World.js`). Intentional exceptions: the `cameraFollow`/`cameraFollow2d` factories (camelCase functions) and the `utils` grab-bag.
- **Global exposure**: Scripts expose globals via `globalThis.Name = ...`. Components are string tokens; systems and classes use the forms below.
- **ECS bootstrap**: Each scene owns its `World` (`this.world = new World(maxEntities, tickrate, opts)`). There is no `WORLD`/`MAX_ENTITIES` global.
- **Formatter**: [Prettier](https://prettier.io/) with `{ "bracketSameLine": true }` (MDN config). Working tree is CRLF (`core.autocrlf=true`); run `prettier --end-of-line crlf`. `.d.js` stubs and `Build/`/`.gmcache/` are in `.prettierignore`.

## GMRT-Safe Idioms

The GMRT JS runtime/compiler miscompiles or chokes on several standard JS forms. Each has caused real, hard-to-diagnose breakage — avoid them, don't "clean up" code back into them, and prefer the listed idiom:

- **No `for...of` over a Map/Set iterator** (`map.values()`/`.keys()`/`.entries()`, or a `Set`) — it _breaks_ the runtime. Keep parallel arrays and index-loop them (see `World._keys`/`_storages`). `for...of` over a plain **array** or string is fine; `for...in` over a plain **object** is fine.
- **No array destructuring in `for...of`** (`for (const [a, b] of arr)`) — `ReferenceError` at runtime. Use index access (`arr[i][0]`). (Object destructuring `const {x,y} = o` and destructuring in a `.forEach(([a,b]) => …)` callback param _are_ fine — see `Input.import`.)
- **No empty `for` initializer** (`for (; c < n; c++)`) — crashes the compiler. Use a `while` loop.
- **Don't cache a primitive boolean in a local across a function** — it can get clobbered mid-function (a `const` flips `true`→`false` in one call). Cache the **component object** and read the property live each use (see `PlatformerController.update` reading `groundedComp.isGrounded`).
- **Top-level bare `const` is not visible to other scripts** — share via `globalThis.Name`. Bare top-level `function` declarations are _mostly_ global, **but past a certain file size GMRT stops hoisting some of them into global scope and faults at startup** (`cannot coerce undefined or null value into object`). Assign factories/helpers explicitly — `globalThis.X = function X(…)` — and keep files small (the GemsUI kit was split into `GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls` for this reason).
- **Instance `get`/`set` accessors work; `static get`/`static set` do NOT fire** — a static getter silently yields `undefined` (hit on `VirtualKeyboard.active`, which read falsy so typing bailed). Expose static state as a plain field or a `static` method (`VirtualKeyboard.isOpen()`), never a static accessor. Instance getters are fine (`UISelect` ships `get index/value/name`); inlining (as `UIStepper` does) is style, not a constraint.
- **Guard `!(pos.width > 0)` before drawing filled geometry/sprites in a UI component** — on the first frame after a scene transition the flexpanel layout isn't computed, so `getLayoutPosition()` returns NaN width/height and drawing roundrects/sprites with NaN coords faults. Test `> 0`, not `<= 0` (`NaN <= 0` is `false`, so the naive guard misses it) — see `UIStepper`/`UISlider`/`UIProgress`/`UISelect`/`UICheckbox`/`UIInput`. **Do NOT add it to text-drawing components** (`UIText`, or anything that self-sizes via `setWidth` in `onUpdate`): `flexpanel` mutation is a no-op on 0.19, so they legitimately run at width 0 forever and the guard would suppress their draw permanently (`draw_text` tolerates 0/NaN width).
- **Don't mutate `flexpanel` node styles per-frame at runtime** (`flexpanel_node_style_set_*`) — they don't reliably apply on GMRT 0.19 ([bug #15065](https://github.com/YoYoGames/GameMaker-Bugs/issues/15065)); most are commented out in `UIElement`. Set layout props **once at construction** (the `new UIElement({...})` struct); drive runtime change (scroll, expand/collapse, modals, drag) with **draw-time offset/clip math** (see `UIInput`/`UISlider`), and show/hide a subtree with the project's own `child.enabled` flag (checked in `update`/`draw`), not by toggling `display`. **Structural** mutation IS reliable though (probe-verified): `insertChild`/`removeChild` → `markDirty` → `flexpanel_calculate_layout` reflows correctly even after the first layout pass — so when a layout must change _size_, insert/remove the subtree (as `UIAccordion` does) rather than animating a flex dimension; a **same-size** show/hide still prefers `enabled` (no reflow). For the full node-property reference (names, accepted values, defaults) run `gm-cli manual read "Flex Panel Struct Members"`; Yoga's docs (https://www.yogalayout.dev/docs/styling/) cover the layout semantics.
- **`String.prototype.toUpperCase()`/`toLowerCase()` return garbage Unicode** — `"q".toUpperCase()` yields `"ଊ"`, not `"Q"`. Map case yourself via char codes — `String.fromCharCode(ch.charCodeAt(0) - 32)` for a-z→A-Z. See `VirtualKeyboard._upper` (Shift key).
- **`JSON.stringify` faults on nested objects/arrays** — `JSON.stringify(["a","b"])` and a flat `{key: scalar}` object are fine (see `Settings`), but an object whose value is an object/array _hard-faults_. Persist only flat `{key: scalar}` blobs; serialize structure to a scalar string yourself (`ids.join(",")`, `"k=v;k=v"`) — see `SaveData`/`Profile`/`Achievement`.
- **GMRT 0.19 does not support SVG sprites** (e.g. `spr_choo`, `spr_play`, `spr_hana`) — `sprite_get_number()` returns `0`, so frame math can go negative and `draw_sprite_ext` throws _"Trying to draw negative subimage index on a non-instance"_. Use raster sprites; clamp any computed frame count to `≥ 1` and `subimg` to `≥ 0` (see `AnimationSystem`).
- **`asset_get_index(name)` returns an opaque asset _ref_, not a numeric index** — a `>= 0` validity test is always `false` for a found sprite (silently suppressing the draw). Validate with `sprite_exists()`, never `>= 0` (a not-found name returns `-1`, which `sprite_exists` also rejects). See `UISlots`/`SlotDrag` and `UIRichText._icon`.
- **`view_camera[]` is not exposed in the GMRT JS runtime** — indexing it faults. Hold the `Camera` instance and read `camera_get_view_*(camera.id)` (see `sceneTopDown.draw`).
- **`gpu_set_scissor`/`gpu_get_scissor` leaks globally** — the clip state set for one element bleeds onto every subsequent UI draw, so a wrong/missed restore makes the _whole scene_ go invisible (hit while clipping `UIInput`'s text). Don't use it to clip; clip by computing the visible substring/offset yourself and drawing only what fits (see `UIInput.onDraw`).
- **`draw_text` loses the world matrix inside a NESTED clip surface** — the `clip`/`UIScroll` path (`UIElement._drawClipped`) renders children into an off-screen surface under a `matrix_world` translate. `draw_roundrect_*`/`draw_sprite_*` honor it, and so does `draw_text` for a _single_ surface — but an immediate-mode text widget nested in **two** clip surfaces (a `gemsScroll` within a `gemsScroll`) draws its text at absolute position and gets clipped away (only the text vanishes; the panel still moves correctly). Hit on `UIQuestTracker`. Don't double-nest an immediate-mode text widget; one enclosing scroll is enough. `UIText`/`UIButton` labels are unaffected.
- **A `UIComponent` must resolve `I18n.font(key)` at DRAW time, not cache the handle at construction** — `I18n.font(key)` falls back to `draw_get_font()` for an undeclared key, so a handle captured in a constructor (a Create event) freezes whatever font was active then and later renders **nothing**. Store the font _key_ (a string) and call `I18n.font(key)` inside `onDraw` (hit on `UIQuestTracker`).
- **`draw_triangle_color` and `draw_line_width_color` render NOTHING** — both drew nothing at valid coords while `draw_roundrect_color_ext`/`draw_text` in the same `onDraw` drew fine (silently broke the `UIAccordion` chevron, the `UICheckbox` "check" tick, and `UINav` debug lines). For arrows/ticks use a **`draw_text` glyph** (`UIAccordion` draws `">"`/`"v"`), `draw_rectangle`, or sprites. Also, GML `pi`/`degtorad` **and** `Math.PI` are all `undefined` (arithmetic with them → `NaN` coords → nothing draws), so avoid trig; interpolate vertices or precompute angles as literals.
- **UI timers/easing must use `Time.raw`, not `Time.delta`** — `Time.delta` is scaled by `Time.scale`, so UI on it freezes/slows when a sim dilates or pauses time. Use `Time.raw` (wall-clock) for hover/press fades, caret blink, key-repeat, toggle easing (see `UIButton`, `UIInput`, `UICheckbox`).
- **`mouse_check_button*` are sampled realtime, NOT latched per frame** — calling the _same_ query more than once in a frame can return _different values each call_ (one path read `_released` as `0` while another, the same frame, read `1`). Call each edge query **once** at frame start and share the result; don't re-query, and don't derive edges from the button _level_ (it flickers frame-to-frame even held). See `SlotDrag.poll()` (in `Step_0` before `UI.update`), which latches `mouse_check_button_pressed`/`_released` once into `SlotDrag.pressed`/`released` for `UISlots` and `SlotDrag` to read.
- **`keyboard_lastkey` lags `keyboard_check_pressed(vk_anykey)` by a frame** — on the pressed-edge frame `keyboard_lastkey` still holds the _previous_ key, so a "press a key to bind" handler that reads it binds the stale key on the first press. Instead scan the keycode range for the one whose `keyboard_check_pressed(code)` is live this frame — that stays in sync with the edge. See `UIRebind._scanKey` (scans `8..255`, skipping nokey/anykey/Esc).
- **A `static` field initializer can't reference the class's own name** — `static x = ClassName.y` throws `ReferenceError` at **load** (the class binding isn't live yet). Initialize with a **literal** and read `ClassName.y` from _methods_ instead (hit on `Dialogue`). Referencing _another, already-loaded_ class is fine (e.g. `static panelColor = Color.parse("#…")`); only self-reference breaks.
- **Class inheritance / `super` is broken** — `super.method()` is a **compile error** (`Unsupported expression [R_SUPER]`), not a runtime fault; don't design with subclassing. Model "kinds of X" as **composition**: a flat base class carrying a `components: []` array of standalone data classes queried by `instanceof` (the `UIElement` `addComponent`/`getComponent(Class)` pattern, also `Item` → `Equippable`/`Weapon`). `instanceof` against a _flat_ class works fine; only inheritance breaks. **A subclass's instance field initializers never run** either — `class Foo extends Bar { label = "x" }` leaves `label` `undefined` on the instance (neither the subclass's nor the base's `field = …` fires through the broken constructor chain). The genre scene classes (`extends Scene`) hit this: `scene.label` is `undefined`, which is why the lobby + `SystemMenu` read a scene's display name from the `SceneRegistry` entry, not the instance. Assign such fields in a method that actually runs (e.g. `create()`), or read the value from elsewhere.

When a quirk forces an unusual idiom, leave a one-line comment so it isn't "fixed" back. Add new quirks here as they're found.

## Architecture

See @ARCHITECTURE.md for the full reference — every layer, system, component, renderer pass, and UI widget. That `@`-import expands ARCHITECTURE.md into context alongside this file at launch; consult it for any structural detail. High-level map:

- **Demo shell** (`obj_game`, `Scene`, `SceneRegistry`, the GemsUI factory kit) — the single-room app and its UI scaffolding. `obj_game` is the unified controller, driving global system ticks and the scene lifecycle each event (full Create/Step/Draw/CleanUp breakdown in ARCHITECTURE.md → Demo Layer).
- **ECS Core** (`World`, `IdPool`, string-token components, plain-object systems) — instance-based ECS with a fixed-rate tick and render interpolation.
- **Built-in systems** (gravity, movement, solid/separation/trigger collision, projectiles, state machine, lifetime, pathfinding) — genre-agnostic, dispatched explicitly from a scene's `step()` (often via a `Pipeline`).
- **Genre Templates** (`Platformer`/`RTS`/`Map` under the **Showcase** IDE folder; the **TopDown** genre is merged into the **RPG** folder) — a genre **controller** (`PlatformerController`/`TopDownController`) plus **gameplay systems** layered over Core. **TopDown** is an action-RPG (see the RPG layer below); **Platformer** and **RTS** are lean movement showcases over Core (Platformer = weighty movement + stomp-able `Enemy` patrollers + spike/void respawn; no HP/inventory/combat).
- **RPG / gameplay layer** (Core primitives + top-level `RPG` layer) — items & inventory (`Item`, `Inventory`, `Equipment`, `Consumable`, `Container`, `Encumbrance` + their systems), combat (`Health`, `Stats`, `MeleeSystem`, `ProjectileSystem`, `SlimeAI`), progression (`QuestLog`, `NPC`, `Dialogue`), loot (`ItemDrop`, `Rarity`), and sprite animation (`Animator`/`AnimationSystem`). Content registries: shared `RpgContent` registers **all** items (weapons incl., `wood_sword` melee + `blaster` ranged) + rarities + recipes; the only per-genre content is `TopDownContent` (top-down quests + achievements). The `TopDownController` honors a weapon's `melee` flag (swing vs fire). The **RPG layer `sceneTopDown` builds on lives in the top-level `RPG` folder**: `RpgContent`, `RpgPlayer` (player spawn + the bullet preset + firing), `RpgScene` (combat/loot step helpers), `RpgInventoryUI` (the inventory/equipment window — the single place to overhaul the inventory UI), `RpgWorldOverlay` (world-space drops/bullets/reach-zone). The TopDown scene/controller keeps only its movement, level, and flavor. (`Platformer` no longer uses this layer — it's a movement showcase; only `sceneTopDown` consumes RPG now.)
- **Genre UI** — `SystemMenu` (the app's single global tabbed overlay: pause + settings + system/sim controls + about + debug; opened by F1 anywhere or Esc/Start in gameplay, it pauses all sim), `StorageUI`, `BuildMode` (TopDown grid build mode — claim a buildable `Zone` at a Survey Post, then place/deconstruct wall + floor tiles snapped to the grid for wood), and the world-space overlay `RpgWorldOverlay` (item drops + bullets + the top-down reach zone, used by `sceneTopDown`); HUD + draggable inventory windows are real UI panels built by each scene and drawn on the GUI layer.
- **Renderer** (`Renderer` + `RenderPass`es: `RenderEntity`, `RenderDebugBox`, `RenderTileMap` with blob/dual-grid autotiling, debug passes) — hardware-accelerated tiles via `VertexBuffer`.
- **UI system** (`UIElement`/`UI` over `flexpanel`, the `UIComponent` widgets, plus standalone singletons `Tooltip`/`Toast`/`SlotDrag`/`UINav`/`VirtualKeyboard`/`SceneTransition`/`FloatingText`) — Flexbox-backed, keyboard/gamepad navigable.
- **Input** (`Input`/`InputAction`, rebindable keymaps) and **utilities** (`Settings`, `Color`, `I18n`, `Camera`/`cameraFollow*`/`cameraPan`, `Query`, `AABB`, `Broadphase`, `Raycast`, `Tween`, `EntityPreset`, `Level`/`TileLayer`/`Zone`, `File`, `Log`).
