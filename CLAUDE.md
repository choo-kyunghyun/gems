# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**G.E.M.S.** (GameMaker Entity & Map System) is a UI and entity management library for GameMaker on the GMRT runtime (0.20). All game logic is JavaScript, not GML. The repo is a **library first** — the engine plus two reusable kits — with the demo as its showcase. Assets live in **four** top-level IDE folders:

- **Core** — the pure engine, **zero gameplay opinion**: ECS, built-in systems, level, render, the **UI system** (`UIElement`/widgets/singletons), input, utilities. Generic streaming (`ChunkManager`/`NavGrid`/`RenderChunks`) lives here; specific content reaches it via injection (`ChunkSource`).
- **Gameplay** — the reusable **genre-agnostic gameplay kit**, extracted from the demo so a second genre reuses it unchanged. Grouped by **feature module** (component + system colocated): `Combat`, `Items`, `Inventory`, `Equipment`, `Animation`, `Lighting`, `Quest`, `Crafting`, `Party`, `NPC`, `Status`, `Survival`, `Trade`, `Interaction`. Each module depends only on Core + sibling modules — **never on `Demo`**. See ARCHITECTURE → _Gameplay Kit_.
- **GemsUI** — the themed UI **factory kit** (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`) over the Core UI system, plus the UI sprites in `GemsUI/Sprite`. A reusable kit over Core's UI, parallel to how `Gameplay` is a kit over Core's engine.
- **Demo** — the single integrated demo, subfoldered by concern like Core (`Component`/`System`/`Content`/`UI`/`Scene`/`Editor`) plus colocated art (`Sprite` + `Sprite/Tile`, `Particles`). After the `Gameplay` extraction it holds only what **names specific content or a model**: the **action-RPG** (`sceneRpg` + the `Rpg*` layer, the `Stats`/`Attributes`/`StatModel` derivation, `CombatAI`, the `WorldClock`/`Weather`/`Temperature` world-sim, build mode) consuming the Gameplay kit; the self-contained **`Platformer`** minigame in `Demo/Platformer` (an embedded guest, not a standalone showcase); the **app shell** + dev launcher (`obj_game`/`rm_game`/`demo`/`sceneLobby`/`sceneUIKit`) in `Demo/Lobby`. (The old tile/terrain + RTS-crowding showcases ship live in the RPG — terrain in the overworld, `SeparationSystem` in the slime/follower crowd.)

Lobby categories (`SCENE_CAT_*`) are independent of IDE folders — e.g. `sceneRpg` lives in `Demo/Scene` but registers under `SCENE_CAT_RPG`. The entire demo runs in a single room (`rm_game`) with `obj_game` as the unified controller — no room transitions. The app **boots into the lobby** (the dev launcher / scene catalogue, also reached via **F2**); from it the RPG + other genres open. Genres are also embeddable as **guest minigames** via the `SceneManager` **scene stack** (a host scene pauses with its context intact while a guest runs in front — the RPG arcade cabinet → platformer). See ARCHITECTURE → _Demo Layer_.

## Working Guidelines

Bias toward caution over speed; for trivial tasks, use judgment.

- **Think first.** State assumptions; if uncertain or a request is ambiguous, ask rather than guess silently. Push back when a simpler approach exists.
- **Simplicity first (KISS).** Minimum code that solves the problem — no speculative features, single-use abstractions, unrequested configurability, or error handling for impossible cases. Fail fast rather than hiding errors.
- **Surgical changes.** Touch only what the task requires; match existing style; don't refactor or reformat unrelated code. Mention pre-existing dead code rather than deleting it; remove only what your own change made unused.
- **Verify by running.** There are no tests — confirm behavior by running the game (see Build & Run). For multi-step work, state a brief plan with a verification check per step.

## Build & Run

`gm-cli` (experimental GameMaker CLI) with the GMRT 0.20 toolchain; project file `gems.yyp` (the IDE can also build/run). 0.19 is no longer supported; the **GMRT-Safe Idioms** below are the runtime quirks still live on 0.20.

```sh
gm-cli run     --toolchain GMRT@0.20 gems.yyp                 # run
gm-cli compile --toolchain GMRT@0.20 gems.yyp                 # compile only
gm-cli compile --toolchain GMRT@0.20 --errors-only gems.yyp  # compile, errors only
```

**Manual lookup — confirm any built-in API.** `gm-cli manual read "<query>"` prints the GameMaker manual page (e.g. `gm-cli manual read buffer_save_ext`, `gm-cli manual read "Flex Panel Struct Members"`) — the **authoritative** source for a built-in's signature, arguments, return, and accepted constants. Read it before relying on an unfamiliar GML/runtime function (GMRT often differs from what you'd assume). The query is fuzzy-matched, so pass the exact page name to be sure. It confirms an API's intended contract only — whether GMRT honors it is separate (see GMRT-Safe Idioms).

**Stale-cache reset.** Two ignored, regenerable dirs hold build state: `.gmcache/` (incremental compile cache — `gm-cli cache info`/`cache clean`) and `Build/` (build _output_; `cache clean` won't touch it — remove manually). When a build acts as if an asset still has its old state (renamed/deleted asset still "present", or an error not matching the source), run `gm-cli cache clean` (also re-downloads the shared runtime, so the next build is slower) and/or delete `Build/`, then rebuild. Both are git-ignored, so this is safe.

**Visual verification (screenshot).** The agent can't press F5, so add a temporary auto-capture: in `obj_game/Draw_75.js` add a frame counter on `this`, call `screen_save("<name>.png")` at the frame(s) you want, then `game_end()` a couple frames after the **last** capture so the run self-terminates. A single run can take **multiple** shots (distinct bare filenames at different frames, to compare states). Then `gm-cli run` (blocks until `game_end`), `Read` each PNG, and **revert the temp code**. Gotchas: `screen_save` does **not** create dirs (use a bare filename, not `screenshots/x.png`); a bare filename lands in `.gmcache/build-gmrt-windows-vm/build/<name>.png`, not the `%LOCALAPPDATA%\gems\` save dir (where `game.log`/`settings.json`/`save.json` live).

**Live state inspection (`debug.txt`).** To _read_ live runtime values (not pixels), use the **`Debug`** back-end (see ARCHITECTURE → _Debug_): code registers live-bound panels (`Debug.panel(name, (p) => p.watch/slider/checkbox/...)`), and `Debug.update()` (wired in `Step_0`) periodically writes a flat snapshot to **`debug.txt`** in the save dir — `Read` it after a `gm-cli run` like `game.log`. An agent can `Debug.set(panel, label, value)` / `Debug.press(panel, label)` from a temp harness to tune a value or fire a button, then screenshot to verify. This text port exists because the native ImGui overlay (`show_debug_overlay` + `dbg_*`) renders **outside** the game surface, so `screen_save` can't capture it — that overlay (`DebugImGui`, toggle **F3**) is human-only.

## Asset Creation

**Never create GameMaker assets (scripts, objects, rooms, sprites) by hand-writing files/folders or editing the `Resources` list in `gems.yyp`.** GameMaker manages asset metadata strictly — manual edits corrupt the project or are silently ignored. Two valid routes:

**A. GameMaker IDE** — right-click a folder in the Asset Browser → Add Script / Add Object / etc.

**B. `gm-cli resourcetool`** (no IDE) — for a new script `<name>`:

```sh
gm-cli resourcetool eval "RESOURCE CREATE TYPE=Script NAME=<name>"                # registers it in gems.yyp
gm-cli resourcetool eval "RESOURCE SET EXPR=<name>.scriptSource VALUE=<name>.js"  # point at .js, not the .gml stub
```

Then delete the generated `scripts/<name>/<name>.gml` stub and `Write` `scripts/<name>/<name>.js`. To file the asset under an IDE folder, **edit the asset's own `.yy`** `parent` (`path: folders/<Folder>.yy`, `name: <Folder>`) to match a sibling — safe local metadata. New IDE folders: `gm-cli resourcetool eval "FOLDER CREATE FOLDER=Parent/Child"`; its name validator rejects spaces/`&` (over-strict — the IDE allows them, e.g. `UI Sprites`), so for such names hand-add a `GMFolder` line to the `Folders` array in `gems.yyp` (this array — unlike `resources` — is safe to hand-edit; also how empty folders are deleted, as resourcetool has no FOLDER DELETE). Do **not** `RESOURCE SET` `.parent` (it mis-writes the path); left unset, the asset stays at the project root. Verify with `gm-cli resourcetool eval "CHECK PROJECTPATH=gems.yyp"`, then `gm-cli compile`.

After the asset exists, edit its `.js`/`.yy` freely. **Renaming or deleting** an asset must also go through the IDE or `resourcetool`, never by moving/removing files manually — to delete: `gm-cli resourcetool eval "RESOURCE DELETE NAME=<name> TYPE=Script"` (removes it from `gems.yyp` and deletes its `scripts/<name>/` folder).

## Tools

Repo tooling lives under **`tools/`** — standalone, run directly, never imported by the game. Today it holds two: the **pixel-art-kit** (sprites) and the **audio-kit** (sound). Both are portable **zero-dependency** Python (stdlib only) with the same shape — **author** a data file → **render** to an engine-agnostic artifact → **import** as a GameMaker asset (resource registered first; re-runs are churn-free) — and a project conventions doc (`GEMS.md`) answering the kit's "scan/ask".

**`tools/pixel-art-kit/`** — the sprite-**art pipeline**: a portable, **zero-dependency** Python toolkit (stdlib only — no PIL/installs; PNG/GIF encode+decode are hand-rolled) that generates the project's pixel-art sprites from **data files**, not inlined art. Three stages: **author** a template → **render** it to a PNG strip + previews → **import** it as a GameMaker sprite.

- **`common/`** — the engine-agnostic, style-agnostic core: `pixlib` (shared lib), `draw.py` (render `templates/` statics), `animate.py` (render `templates/anim/` frame data → strip + GIFs + manifest), `tileset.py`/`terrain_materials.py` (autotile sets + tileable materials), `quantize.py`/`preview.py`/`pack.py`. Carries **no** palette/size/subject — those are supplied per project.
- **`gm-import/`** — the GameMaker adapter (imports `common/`, writes into the project's `sprites/`): `entity_sprites.py` (the 13 RPG entities) + `terrain_sprites.py` (the `spr_terrain*` dual-grid sets). The target sprite resource must already be **registered** (see Asset Creation); frame/layer/keyframe UUIDs are **deterministic (uuid5)**, so re-running is churn-free.
- **`palettes/`** `.hex` library (db32 default) · **`templates/`** input data (`.txt` index grids / `.json` statics / `anim/`) · **`out/`** + **`local/`** are gitignored.

**This project's confirmed conventions are 16×16 cells + DB32 + foot-anchored — see `tools/pixel-art-kit/GEMS.md` (the "scan/ask" answer); full kit docs in `tools/pixel-art-kit/README.md`.** Run the generators after editing a template: `python tools/pixel-art-kit/gm-import/entity_sprites.py`, `python tools/pixel-art-kit/gm-import/human_sprites.py` for the paper-doll humanoid base + worn overlays (source template `templates/human/base.png` — see ARCHITECTURE → _Paper-doll appearance_), and `python tools/pixel-art-kit/common/terrain_materials.py` then `terrain_sprites.py` for terrain. (Some 32px sprites are out of this workflow — lobby/editor UI icons + the Platformer's debug-box art; see GEMS.md.)

**`tools/audio-kit/`** — the **sound pipeline** (the audio sibling of pixel-art-kit): a zero-dependency Python toolkit (stdlib only — 16-bit PCM **WAV** + Standard **MIDI** encoders are hand-rolled) that generates the project's audio from **data files**, not binary blobs. Two media: **SFX** (a stack of synth layers → mono WAV) and **MIDI-based BGM** (a note/tracker score → looping stereo WAV **and** an editable `.mid` — GameMaker can't play `.mid`, so the WAV is the asset and the `.mid` is the DAW-editable source).

- **`common/`** — engine-agnostic core: `audiolib` (WAV encode + buffer mix/gain/normalize/fade + paths), `synth` (oscillators sine/square/pulse/saw/triangle/noise + ADSR + filters + kick/snare/hat + note-name parsing + named instrument patches), `midilib` (minimal SMF Type-1 writer), `sfx.py` (render `templates/sfx/*.json`), `music.py` (render `templates/bgm/*.json` → WAV + `.mid`). Carries **no** sounds/tempos/notes — supplied per project in `templates/`.
- **`gm-import/`** — the GameMaker adapter (imports `common/`, writes `GMSound`s into the project's `sounds/`): `gm_sound.py` (shared `.wav` + templated `.yy` emitter), `sfx_sounds.py` (→ `snd_*`, mono uncompressed), `bgm_sounds.py` (→ `mus_*`, stereo uncompressed; `.mid` into `out/`). A GMSound `.yy` carries **no uuids**, so re-running is inherently churn-free.
- **`templates/sfx/`** + **`templates/bgm/`** input data · **`out/`** + **`local/`** gitignored.

**This project's confirmed conventions are 44.1 kHz / 16-bit, chiptune, mono SFX `snd_*` + stereo BGM `mus_*` (folders `Media/Audio/SFX`+`BGM`) — see `tools/audio-kit/GEMS.md`; full docs in `tools/audio-kit/README.md`.** Run after editing a template: `python tools/audio-kit/gm-import/sfx_sounds.py` / `bgm_sounds.py`. Runtime playback is verified on GMRT 0.20. The committed set is **9 SFX + 2 BGM loops**, played through the **`Audio`** Core wrapper (`scripts/Audio/`, ARCHITECTURE → _Utility Modules_) — a static-singleton facade with non-positional `play`, **spatial `playAt`** (`audio_play_sound_at` + a player-following listener), and cross-faded `bgm`. **Wired into the Demo**: the RPG plays `mus_overworld` (`sceneRpg` create/resume) with spatial SFX at Demo chokepoints — `snd_shoot` (gun fire, `RpgController`), `snd_hit`/`snd_hurt` (impact, `RpgScene._diffHp` — enemy "hit", ally "hurt", death-blow left to the death pass), `snd_explosion` (enemy death, `resolveHealth.onKill`), `snd_coin` (pickup, `sceneRpg._onCollect`), `snd_powerup` (consumable, `RpgInventoryUI`); the Platformer plays `mus_battle` with non-positional `snd_jump`/`snd_hit` (stomp)/`snd_hurt` (respawn). Category volume runs through the **`bgm`/`sfx` audio groups** (`audio_group_set_gain`; the assets are assigned to those groups by the importer, and loaded at boot) — the SystemMenu volume sliders drive `Audio.setMusicGain`/`setSfxGain`/`setMasterGain` live. Core UI cues round it out: `snd_ui_confirm` on activate (`UIButton` mouse click + `UINav` confirm — every focusable widget on the gamepad/keyboard path) and `snd_ui_move` on a `UINav` focus change. **All 9 SFX + 2 BGM are now wired** (one minor gap: a mouse click on a *non-button* widget — checkbox/tab/slider — is silent, since only `UIButton` has the mouse-side cue; the gamepad/keyboard path covers them).

## Code Style & Conventions

- **Language**: JavaScript (GMRT JS runtime), not GML. All scripts in `scripts/` use `.js`.
- **Script naming**: a script's directory + filename matches the identifier it exposes, cased to JS norms — **PascalCase** for a class or namespace object (classes `World`/`Camera`; namespace objects `CameraFollow`/`CameraFly`), **camelCase** for a plain function (`teardownScene`). A script exposing a _family_ of free functions (no single matching global) is a **PascalCase category bucket**: the GemsUI kit (`GemsTheme`/`GemsContainers`/`GemsWidgets`/`GemsControls`), `Utils` (`noop`/`uuid`/`rem`), `UIDraw` (`drawUIArrow`/`drawUICheck`). GameMaker-asset families keep their conventional prefix (`scene*`, `Render*`, `*System`, `obj_*`/`rm_*`/`sh_*`).
- **Global exposure**: scripts expose globals via `globalThis.Name = ...`. Components are string tokens; systems and classes use the forms below.
- **ECS bootstrap**: each scene owns its `World` (`this.world = new World(maxEntities, tickrate, opts)`). There is no `WORLD`/`MAX_ENTITIES` global.
- **Formatter**: [Prettier](https://prettier.io/) with `{ "bracketSameLine": true }` (MDN config). Working tree is CRLF (`core.autocrlf=true`); run `prettier --end-of-line crlf`. `.d.js` stubs and `Build/`/`.gmcache/` are in `.prettierignore`.

## GMRT-Safe Idioms

The GMRT JS runtime/compiler miscompiles or chokes on several standard JS forms — the quirks below are the ones still live on 0.20. Avoid them, don't "clean up" code back into them, and leave a one-line comment where one forces an unusual idiom so it isn't "fixed" back. Add new quirks here as found.

**Language / compiler**

- **No `for...of` over a Map/Set iterator** (`.values()`/`.keys()`/`.entries()`, or a `Set`) — breaks the runtime. Keep parallel arrays and index-loop (see `World._keys`/`_storages`). `for...of` over an array/string and `for...in` over a plain object are fine.
- **No array destructuring in `for...of`** (`for (const [a,b] of arr)`) — runtime `ReferenceError`. Use `arr[i][0]`. (Object destructuring and a `.forEach(([a,b]) => …)` param are fine.)
- **No empty `for` initializer** (`for (; c<n; c++)`) — crashes the compiler. Use `while`.
- **`Array.sort` comparator must return a SIGN, not a raw difference** — GMRT truncates the comparator's return to an int, so a fractional `(a, b) => a.t - b.t` over sub-1 values collapses every pair to `0` ("equal") and the array stays in its original (arbitrary) order — a silent no-op sort, not an error. Return `a < b ? -1 : a > b ? 1 : 0` (verified: `Raycast.castAll`'s by-`t` ordering of `[0,1]` hit distances). A difference comparator only happens to work when the values are far-enough-apart integers.
- **Don't cache a primitive boolean in a local across a function** — it can flip mid-function. Cache the component object and read the property live each use (see `PlatformerController.update` → `groundedComp.isGrounded`).
- **Top-level bare `const` isn't visible to other scripts** — share via `globalThis.Name`. Bare top-level `function` declarations are mostly global, **but past a certain file size GMRT stops hoisting some and faults at startup** (`cannot coerce undefined or null...`). Assign explicitly (`globalThis.X = function X(…)`) and keep files small (why the GemsUI kit is split).
- **A class with >50 methods crashes the runtime** ([#15065](https://github.com/YoYoGames/GameMaker-Bugs/issues/15065), open) — 50 OK, 51+ faults. Split a fat class into collaborators, lift helpers into free functions / a `globalThis` module object, or use composition (a flat base + `components:[]` queried by `instanceof`, as `UIElement`/`Item` do).
- **Class inheritance / `super` is broken** — `super.method()` is a compile error, and **a subclass's instance field initializers never run** (`class Foo extends Bar { label="x" }` leaves `label` undefined). Model "kinds of X" as composition (`addComponent`/`getComponent(Class)`, `instanceof` on a flat class). The genre scenes hit the field-init gap: `scene.label` is undefined, so the lobby/`SystemMenu` read the name from `SceneRegistry`, not the instance. Assign such fields in a method that runs (e.g. `create()`).
- **A `static` field initializer can't reference its own class name** — `static x = ClassName.y` throws at load. Use a literal and read `ClassName.y` from methods (hit on `Dialogue`). Referencing another already-loaded class is fine.
- **`static get` with a computed (expression/comparison) body miscompiles to a constant** — a getter reading `_modal !== null` returned `false` while `_modal` was live. Expose derived static state as a `static` METHOD (`SystemMenu`/`Dialogue`/`VirtualKeyboard.isOpen()`), never a static accessor. A getter returning a *stored* value works; instance `get`/`set` mostly work (but see the next bullet). Read-write static state stays a plain field (`UIInput.active`, `UITable.active`, `SlotDrag.active`, `BuildMode.active`).
- **An instance `get` whose NAME shadows a GameMaker built-in faults on access** — `get index()` / `get value()` on `UIDropdown` threw `cannot coerce undefined or null value into object` at the read site on 0.20 (even `get index() { return this._index; }` — a stored value), while a sibling `get name()` and `SceneManager`'s `get current()` work. The reserved-ish name (GM uses `index`/`value` pervasively) is the trigger, not the body. Expose such state as a `get*()` METHOD (`UIDropdown.getIndex()`/`getValue()`, pairing with `setIndex()`); reach the backing field directly inside the class. When in doubt, prefer a method over an accessor for any GM-flavored property name.

**Strings / serialization / PRNG**

- **`toUpperCase()`/`toLowerCase()` return garbage Unicode** (`"q".toUpperCase()` → `"ଊ"`). Map case via char codes (`String.fromCharCode(c-32)` for a–z→A–Z; see `VirtualKeyboard._upper`, `InvTable.lower`).
- **`JSON.stringify` faults on nested objects/arrays** — a flat `{key: scalar}` is fine; a value that's an object/array hard-faults. Persist only flat scalar blobs; serialize structure yourself (`ids.join(",")`, `"k=v;k=v"`) — see `SaveData`/`Profile`/`Achievement`.
- **32-bit xorshift PRNGs collapse to a constant** — the chained `s ^= s<<13; s ^= s>>17; s ^= s<<5` returns `0.5` for many seeds (different seeds, identical output). Use integer-float math with no bitwise — a Park–Miller MINSTD LCG (`s = (s*48271) % 2147483647`), see `OverworldGen._rng`/`_seedFor`. (Single bitwise ops like `IdPool`'s id packing are fine; only the overflowing chain breaks.)

**Sprites / assets / camera**

- **No SVG sprites** (`spr_choo`/`spr_play`/`spr_hana`) — `sprite_get_number()` returns `0`, so frame math can go negative and `draw_sprite_ext` throws. Use raster sprites; clamp frame count `≥1` and `subimg` `≥0` (see `AnimationSystem`).
- **`asset_get_index(name)` returns an opaque ref, not a number** — a `>=0` test is always false. Validate with `sprite_exists()` (a not-found name is `-1`, which it also rejects). See `UISlots`/`SlotDrag`, `UIRichText._icon`.
- **`view_camera[]` isn't exposed** — indexing faults. Hold the `Camera` instance and read the view rect from its own fields (`toX`/`toY`/`width`/`height`), **not `camera_get_view_*`** — the project's `Camera` drives the view by matrix, so `camera_get_view_*` returns 0. An ORTHO `CameraFollow.create2d` camera is centered on `(toX,toY)` spanning `width×height` world px. The view-culling passes (`RenderLighting`/`RenderWeather`/`RenderDebugTileMap`/`RenderGrid`) read the Camera fields for this reason.
- **`mouse_x`/`mouse_y` are WRONG under a pitched matrix camera** (probed on 0.20: ~118 world px off at the screen edge under the RPG's 35° 2.5D pitch — matching neither the flat linear mapping nor the correct one; flat matrix cameras map fine, so the level editor's `CameraPan` still uses them). Convert the cursor yourself: **`Camera.unproject(sx, sy)`** (surface px → ground-plane world, the exact inverse of `Camera.project`, pitch-aware via the up vector) / **`Camera.cursorWorld()`** (GUI mouse → unproject). `sceneRpg.step` latches it once per frame into `scene.mouseWorld` + `ctrl.cursorX/Y` (mouse positions are realtime-sampled like buttons — latch and share); consumers: `RpgController` aim, `BuildMode` cell pick, `Interactable` cursor targeting, `DebugInspector` click-pick/marker. Cursor-over-entity tests hit the ground-plane point (an entity's FEET) — pointing at a tall billboard's upper body lands behind it; screen-space billboard picking is a possible follow-up.

**Rendering / shaders / clip**

- **NaN-width guard before drawing filled geometry/sprites in a UI component** — on the first frame after a scene transition the flexpanel layout isn't computed, so `getLayoutPosition()` returns NaN width/height and drawing with NaN coords faults. Guard `!(pos.width > 0)` (test `>0`, not `<=0` — `NaN <= 0` is false). See `UIStepper`/`UISlider`/`UIProgress`/`UISelect`/`UICheckbox`/`UIInput`. **Don't add it to text widgets** (`UIText`/`UIRichText`): they self-size and draw from `pos.left/top`, never reading `pos.width`, so the transient NaN is harmless.
- **`gpu_set_scissor` is the UI clip mechanism (verified on GMRT 0.20)** — `UIElement._drawClipped` clips a scroll/viewport's children with it. It clips, doesn't crash, and does NOT leak **as long as you save/restore** (`var prev = gpu_get_scissor(); …; gpu_set_scissor(prev)`); the old "leaks globally" lore was a 0.19-era discipline issue, not a defect. Two gotchas: coords are render-target **PIXELS**, not GUI units, so convert by `k = target/gui` (the GUI layer is scaled to the window). The render target is the **window back buffer** — windowed client area, or the monitor in fullscreen — but it does **not** track `window_get_width/height()` or the application surface: those queries lag it by a frame (the OS resize arrives async via an SDL event), *and* the back buffer's own resize is **asymmetric** — a SHRINK resizes it **synchronously** (probed on 0.20: back buffer already 1280×720 while `window_get_width()` still returned 2560), a GROW lags it **one frame** (still the old smaller size while the queries already report the new bigger one). So a scissor sized from any single query overflows the target on a resize frame → a **fatal** "scissor rect not contained in the render target" validation error. Size it from **`Display.clipW/clipH`** instead — `min(renderW, _prevW)`: the intended size (set synchronously by `Display.apply()`; authoritative because the window isn't drag-resizable, `options_windows resize_window:false`) min'd with its **1-frame-lagged self** (`advanceFrame` at the end of `UI.draw`), which never exceeds the live back buffer in *either* direction (a grow just under-clips one invisible frame). **GameMaker also does not clear the scissor between frames**, so a clip's leftover rect survives — and after a shrink that leftover is bigger than the new back buffer, which the next frame's outermost clip reads via `gpu_get_scissor()` as a "nested" parent and replays *forever* (self-perpetuating fault). `UI.draw()` therefore re-anchors the scissor to the full target (`gpu_set_scissor(0, 0, Display.clipW(), Display.clipH())`) once at the start of each frame before drawing roots. And `gpu_get_scissor()` returns `{0,0,0,0}` when unset (the full-target default, **not** the target dims) — so for nesting only intersect with it when its `w`/`h` are positive, and **don't restore by replaying a saved `{0,0,0,0}`**: that doesn't re-enable drawing, it clips everything afterward to an empty rect (footers/popups/later roots vanish). At top level reset to the full render target (`gpu_set_scissor(0, 0, Display.clipW(), Display.clipH())`); only a genuinely nested clip restores its parent's positive rect. Clipping at the rasterizer means children draw **directly** to the back buffer at full window density — crisp SDF text, correct blending, no surface. **Nested scrolls (a `gemsScroll` within a `gemsScroll`) clip correctly** by intersecting the two rects — with no clip surfaces, the old "`draw_text` loses the world matrix when double-nested" bug is retired. A text-only clip (caret/overflow in one widget) can still compute the visible substring/offset itself (see `UIInput.onDraw`). **`gpu_set_scissor` does NOT flush the pending vertex batch**, so the **LAST** geometry drawn under a clip stays pending and is only submitted by a *later* texture swap (a following sibling/root) — by which time the scissor has been restored to the full target, so that last item renders **UNCLIPPED at its true layout position** (a long-list scroll leaked its 12th button's text far below the viewport; the earlier items flushed mid-loop because each button alternates panel-texture → font-texture, swapping the texture and flushing the prior item while the clip was still active). Fix: `draw_flush()` at the end of `_drawClipped` **before** the scissor restore, so the batch is submitted while the clip rect is still set. `draw_flush` is manual-flagged debug-only, but it's the only batch-flush primitive and runs once per clip container per frame (a handful), not indiscriminately. **The same "no flush on scissor set" rule also bites a PRECEDING sibling** (verified 2026-06): a clip captures the still-pending LAST primitive of whatever drew just *before* it and submits it under the clip's tighter scissor — clipping it AWAY (the System Menu's rightmost "About" tab label vanished under the tab content's scroll clip). You **cannot** fix this with a *start*-of-`_drawClipped` `draw_flush()` — flushing immediately before `gpu_set_scissor` corrupts the clip on 0.20 (`No pipeline set`/`Invalid CommandBuffer` → the clip's OWN content blanks, every overflowing scroll). Instead the preceding drawer must end with a harmless trailing UNTEXTURED primitive to force the texture swap that flushes its text (`UITabs.onDraw` re-strokes its baseline last — redundant with the one drawn first, so harmless if itself clipped). And a clip with a **non-clipped sibling drawn AFTER it in the same parent** can fail outright (the sibling renders nothing) — every clipped layout just relocates the lost primitive, so `CraftingUI` avoids any clip in its master-detail row entirely (see its comment for the full whack-a-mole).
- **A `UIComponent` must resolve `I18n.font(key)` at DRAW time, not cache the handle at construction** — two ways a cached handle breaks: (1) `I18n.font` falls back to `draw_get_font()` for an *undeclared* key, so a handle captured in a constructor freezes the wrong font; (2) a **language switch** (`I18n.load`) `font_delete()`s every old handle and `font_add()`s new ones, so a previously-captured handle **dangles** — it renders the GM default fallback (12pt Arial) or nothing (a font with no glyph for the new locale). So the text widgets take `font` **polymorphically** — a raw handle (number) OR an **I18n font KEY** (string) — and resolve it live each draw: `const f = typeof this.font === "string" ? I18n.font(this.font) : this.font;` (`UIText`/`UIRichText`/`UITabs`/`UIAccordion`/`UISlider`/`UITable`; `UIQuestTracker` stores explicit `*FontKey` fields). The GemsUI factories pass the **key** (`gemsLabel(…, { font: "header" })`, `gemsTabs`/`gemsSlider`/`gemsTable` default to `"header"`/`"default"`), never a pre-resolved handle. **Exception:** world-space **render passes** (`RenderChunks`/`RenderZoneLabel`/`RenderDebugTileMap`) still take a handle (`I18n.font("default")`) — they're rebuilt when the map/level reloads, but **not** on a bare locale switch, so a label they draw keeps the old font until the next map load (acceptable for debug-ish world labels; convert them too if it ever matters).
- **Screen-space overlay matrices: up +1 AND negative ortho height (probed on 0.20)** — a pass that resets view/projection to surface-pixel ortho to draw over the whole screen (`RenderLighting`'s composite, `RenderWeather`) must use `matrix_build_lookat(w/2, h/2, -1, w/2, h/2, 0, 0, 1, 0)` + `matrix_build_projection_ortho(w, -h, 0, 2)` — the **negative height**. The overlay path has an inherent Y-flip vs the world camera (which renders correctly with positive height), and negating the UP vector instead is a 180° ROLL, not a y-flip — up `-1` X-MIRRORS the content about screen center. That mirror is invisible for symmetric content (ambient fill, vignette, a blob at screen center), so it long passed as verified — it surfaced as the player's lantern glow flipping to the wrong side whenever the blob left screen center (camera clamped at a map border; follow-lerp trailing a fast player). Probed with two off-center axis lights (red = X, green = Y) against `Camera.project` expectations.
- **Custom `GMShader`s run, but guard them** — `shaders_are_supported()` + `shader_is_compiled(asset_get_index("name"))` before `shader_set`, with a non-shader fallback. A shader on an **untextured** primitive reads `gm_BaseTexture` as black, so compute output from uniforms only — don't sample. (`sh_alphatest` — the billboard alpha-test discard, see the next bullet — is the **first custom shader to ship** and follows this contract; day/night + the night vignette are still the `RenderLighting` light map, not a shader.)
- **The fixed-function alpha test is INERT on GMRT — `discard` in a fragment shader instead** — `gpu_set_alphatestenable`/`gpu_set_alphatestref` ROUND-TRIP through their getters (after `set(true,123)`, `gpu_get_alphatestenable()`/`alphatestref()` report `true`/`123` **exactly** — verified) but have **no effect at draw time**: a sub-ref / transparent fragment is **not** discarded, so it still writes depth. This bit the 2.5D billboards — with the depth buffer on (`gpu_set_ztestenable`), a sprite's fully-transparent pixels wrote depth and occluded whatever overlapped behind them (an entity behind the player showed the **background** through the player's empty pixels; `gpu_set_alphatestref` "did nothing" exactly because the test is inert, not misconfigured). Fix: do the cutout explicitly in the **fragment shader** — `sh_alphatest` (`shaders/sh_alphatest/`) `discard`s fragments whose `gm_BaseTexture` **texel** alpha is below a `u_alphaRef` uniform (default 0.5); a `discard`ed fragment writes no depth. `RenderBillboard` sets it around its draw loop (guarded per the bullet above, no-shader fallback). Key: discard on the **texel** alpha (sprite SHAPE), **not** the final `v_vColour*tex`, so a dimmed/tinted entity (`v_vColour.a < 1`, e.g. a downed companion) stays fully visible — only the shape is cut. `gpu_set_alphatestenable(true)` is left **commented out** in `obj_game` Create_0 as a record of the dead end.
- **Don't ease a *packed* color int every frame — ease its float r/g/b channels** — two GMRT traps make per-frame easing of a packed color int wrong, both acute at high/unlimited FPS (tiny per-frame `t`): (1) `merge_color(c1, c2, t)` floors `c1*(1-t)` and `c2*t` separately, so even `merge_color(c, c, t)` returns `c` minus ~1/channel — re-merging its own result every frame drifts the color to **black**; (2) a *rounded* packed-int lerp instead loses a sub-1 per-frame step (`round(c + 0.4) == c`), so the tween **freezes** (no hover/press animation). One-shot merges are fine (`Color.merge`, day/night ambient). For an animated color, keep the `r/g/b` as **floats** and `Tween.approach()` each channel, rounding only the final `make_colour_rgb` — float state accumulates correctly at any frame rate and rests exactly at target (see `UIButton._easeColor`, mirroring the scalar shadow ease). Symptom was button fills going black, or the tween dead at "Unlimited" FPS; text/static-color widgets were unaffected.

**Timing / input**

- **UI timers/easing use `Time.raw`, not `Time.delta`** — `Time.delta` is scaled by `Time.scale`, so UI on it freezes/slows when the sim dilates or pauses. Use `Time.raw` (wall-clock) for hover/press fades, caret blink, key-repeat, toggle easing (`UIButton`/`UIInput`/`UICheckbox`).
- **`mouse_check_button*` are sampled realtime, NOT latched per frame** — calling the same query twice in a frame can return different values. Call each edge query once at frame start and share it; don't derive edges from the button level. **`UIPointer.poll()`** (in `Step_0` before `UI.update`) latches `pressed`/`released`/`down`/`wheel` once for every widget + `SlotDrag`/`BuildMode`/`Dialogue` to read.
- **`keyboard_lastkey` lags `keyboard_check_pressed(vk_anykey)` by a frame** — on the pressed-edge frame it still holds the previous key, so a rebind handler binds the stale key. Scan the keycode range for the one whose `keyboard_check_pressed(code)` is live this frame (see `UIRebind._scanKey`, scans 8..255).

**flexpanel layout** (style mutation works on 0.20 — follow the design rule)

- **Runtime style mutation applies** (`flexpanel_node_style_set_*` + `flexpanel_calculate_layout`). `UIText`/`UIRichText` use it to self-size in `onUpdate` (so a `gemsLabel` reports a real width/height). **By choice the broader live-layout drivers (scroll, drag, slider fill) stay on the draw-time offset/clip pattern** — they work, migrating is churn — and `UIElement`'s ~45 commented-out setters stay commented (re-enabling all would pass the 50-method ceiling; enable one on demand, minding the count). Set fixed layout props **once at construction**; drive runtime change with **draw-time offset/clip math** (`UIInput`/`UISlider`); show/hide a subtree with `child.enabled`, not `display`. **Structural** mutation is reliable: `insertChild`/`removeChild` → `markDirty` reflows correctly (as `UIAccordion` does) — when a layout must change *size*, insert/remove the subtree; a same-size show/hide prefers `enabled`. Property reference: `gm-cli manual read "Flex Panel Struct Members"`; Yoga docs (https://www.yogalayout.dev/docs/styling/) cover the semantics.

**Capabilities** (work on 0.20 — use directly, don't avoid)

- **Trig + `draw_triangle_color`/`draw_line_width_color`/`draw_circle_color` work.** UI arrows/chevrons go through `drawUIArrow`, check/dash markers through `drawUICheck` (both in `scripts/UIDraw`); `draw_circle_color` draws `RenderLighting`'s light blobs. Trig (`Math.PI`/`cos`/`sin`/`atan2`) is used directly (`Temperature.diurnal` cosine curve, `RenderWeather` snow sway). **`WorldClock.tint`/`_KF` keeps its hand-authored keyframe table by design — don't "trig-ify" it.**
- **Off-screen surfaces + `surface_getpixel`, `bm_add`, and multiply via `gpu_set_blendmode_ext(bm_dest_colour, bm_zero)`** (no `bm_multiply` constant) work — the `RenderLighting` 2D light-map infra.
